# 云计算、算力租赁与基础设施投入
版本：1。适用公有云/算力服务，不将云整体与纯AI混同。
步骤 C1：按业务拆IaaS/PaaS/模型服务和一般云；看收入、增长、客户集中、合同/剩余履约、付费使用或管理层指标，分别注明期间/口径。
步骤 C2：串联客户意向→签约/预付→可用容量→部署→使用/收入→回款。订单或长期承诺可作可见度，不能推当期利用率；客户融资到账不等于服务消费。
步骤 C3：固定同模型/精度/延迟/输入输出比的成本边界。租价只是租金，完整成本还含闲置、网络、人员和电力；没有实际数据则给盈亏阈值而非客户真实净ROI。
步骤 C4：查资产购置、租赁、折旧寿命、资本开支口径、经营现金与预付款。现金支出、融资租赁增加和报表资本开支不可混加；延长折旧寿命与技术淘汰风险分别分析。
步骤 C5：与芯片/服务器交付、电网/机房项目和客户采用交叉核验；需求链有时间滞后，同一预算不可多次当新增需求。若收入增长仍现金吃紧，追资本密集度、客户期限和融资。
交付：增长驱动、容量兑现、盈利与现金的条件、最强替代解释。后续激活项目/融资/软件采用助手，具体说明哪一断点需要解决。
