# 011：E2 项目资料进入研究与引用回读

2026-09-14，FIN 0.1.4 / E2，基于 `6074e3d1`。本包继续产品实现；无模型付费调用、无部署、无版本号调整。

## 产品流程与工程决定

010只完成项目资料保存/查找。本包在项目资料页选择文件后进入研究准备页，展示项目名与所选清单，可移除选择；保存草稿或开始新研究时，BFF先校验认证owner下的项目和每份文件，再创建原生研究草稿，将所选原件和已解析页面复制到该任务附件存储，归入项目。未选文件不会进入研究；原项目文件不改动、不删除。项目选择与普通补充附件合计受原12份/80MiB边界约束。

继续采用SQLite事务、既有`TaskAttachmentStore`、原生任务元数据和现有研究工具，不新增依赖、检索平台或工作流。副本保存新的任务附件ID，同时记录原project ID、原document ID、原文件SHA-256和复制时间；批量复制先校验摘要并在目标SQLite事务内全部提交或回滚，复用已保存解析结果。任务副本不随项目后续变化自动更新。副本的来源仍为`user_upload_unverified`，正文不是指令，也没有NumericFact权限。

原生任务创建与本地资料保存不是跨服务原子事务。为防中途失败误启动，创建时标记项目资料准备中；复制和项目归类成功后才确认ready。失败返回保留的草稿ID，不发模型请求、不自动重试；启动API及前端按钮均拒绝未确认ready的草稿。故障草稿自动修复/续传尚未实现，不能称为跨服务事务或完整恢复方案。项目归类用SQLite原生事务合并，更新修订号，避免覆盖其他窗口刚保存的项目整理。

实际研究运行时原本会列出任务附件，并通过`read_source_document(source_space=uploads)`读取。本包复用该入口，新增项目出处随目录/正文输出进入专家观察记录。复查发现`CaseArtifacts`的跨Agent来源摘要白名单遗漏新出处和原文件摘要，已在其原责任层补透传，保证从底稿引用回读时仍可追溯原项目文件。

## 当前边界与下一步

产品增量：用户可选择项目资料用于新研究，副本与项目归类持久保存。工程增量：认证选择、批量快照/出处、准备失败禁止派发、跨Agent来源投影。资格证据：真实图与工具的确定性读取/引用消费，不是DS/Qwen自主取证质量、完整金融研究或原生服务器重启验收。模型调用/费用均为0，既有TokenBudgetBasis和预算策略不变。

E2仍开放远程结构化来源、成果正文编辑/检索同步、文件新版本与权限撤销、跨机存储。当前快照不承诺未来撤销会清除历史副本，撤销策略仍需随对应功能实现。下一真实工作应验证一份有原件/期间/单位的资料在受限真实模型研究中被正确使用，或推进首条可实测远程结构化数据接入；不再为资料已保存而继续追加规划。E1许可、跨研究公平性与灾备等仍归E1。
