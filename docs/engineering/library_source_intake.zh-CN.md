# 完整已解析来源与历史向量的离线接入

本组件服务于[第一版验收 S2](first_release_acceptance_execution.zh-CN.md)的来源可达性前置：把选定来源的全部已解析正文、原分段及其向量准备为独立输入包，避免只发布命中答案的摘录。它不授予组织访问权、不注册 Java 索引发布、不切换运行时投影，也不代表组织检索质量验收通过。

## 恢复与校验

历史 `build_industry_foundation.py` 把正文按 5,200 字符步长保存为 `text-part:N`，除首段外每段包含前 250 字符重叠。`retrieval.library_source_bundle` 按数字序号恢复完整文本，逐项校验：

- 来源可读、父段身份和摘要正确、序号连续且唯一、窗口长度符合原协议。
- 相邻重叠内容完全一致；不做换行、Unicode、空格或数字归一化。
- 恢复后 UTF-8 SHA256 必须等于原 `sources.digest`。缺尾段即使序号连续也会失败。
- 所有子段来自同一来源，正文与父段切片及摘要一致，保留旧 `CHUNK::`/`PASSAGE::`、locator 和父段内位置，并增加完整来源内的字符位置。允许分段器省略空白区域，非空白正文不能遗漏。
- 保留来源整条 metadata，包括原解析覆盖声明、期间、发布日期及修订关系；不重新推断财务期间或单位。保留该来源的图边、原绑定类型和 evidence index、引用位置、覆盖记录；跨来源或越界绑定拒绝。

`complete stored parsed text` 仅说明历史解析正文恢复完整。它不等同原 HTML/PDF 字节、图片、合并单元格几何或全部视觉信息已恢复；原 `document_coverage` 限制仍然有效。解析文本不是自动获得数值事实权威的数据库记录。

原始文本/JSON 的 `raw text chars start-end` 也可恢复：按数值位置排序，检查无缺口、无重叠、长度、身份和逐段摘要，最后要求完整 UTF-8 摘要等于来源摘要。此适配不自动适用于 HTML/PDF。历史导入中，HTML/PDF 的来源摘要是原文件字节，调查资料的摘要是原读取回执；层级节点可能同时保存章节、表格和子段，直接拼接会重复。不能为了让摘要校验通过而改写原摘要或把几种合同混用。

## 向量复用

源库、旧向量索引和请求缓存只读。首先核对库摘要、矩阵/映射文件摘要及模型合同，再对每个子段：

1. 取未经改写的 `context + newline + body`，保留输入 SHA256 和模型/维度/输入组成的缓存键。
2. 要求此精确缓存键存在成功请求记录及向量；失败或未知记录不能单独授权复用，更不会触发提供方请求。
3. 核对 chunk/source/矩阵行一一对应，拒绝漏映射、重复映射、越界行及错误来源。
4. 将缓存向量按旧发布方式归一化，与已发布矩阵对应行逐元素精确比较。只有维度一致或正文相似不能通过。

输出保留来源矩阵行号，同时分配本包内行号。原查询缓存、排名缓存、权限和组织身份均不复制。此过程不重新嵌入，也不改变原索引。

全量离线核验使用 `VectorReuseVerifier`：在只读事务中一次读取成功请求键及映射索引，每个子段仍检查精确输入和真实向量值。它只减少离线重复扫描，不缓存组织许可，不改变运行时每次核权。`validated_stored_chunks` 可独立验证库内父段的完整覆盖，用于尚未恢复全文的来源；该结果没有全文位置或完整文档声明，也不能当作组织发布输入包。

调用方必须明确选择来源 ID；工具始终导出该来源全部父段/子段，不接受 gold 片段列表。输出禁止写入源库目录及索引目录，已存在输出目录拒绝覆盖。每源输出 `source.json`、`vector-map.json`、`vectors.npy`；根 `result.json` 记录逐源状态、数量、摘要和文件 SHA256。个别来源失败保留原因，整批标记 failed，CLI 非零退出；中断留下 incomplete，不能作为完成产物消费。原库前后核验摘要，旧索引在完成前再次核对。

生产消费前还需验证产物摘要，并经组织发布流程获得资源身份。不能直接将这个离线目录暴露给 Agent，或把其中的公共 source/chunk ID 当作组织访问许可。

## 完整来源的组织接入

`POST /api/v1/asset-workspace/captures` 新增 `selection.kind=library_source`：请求只包含 `document_id` 和发布库摘要 `snapshot`，服务器从配置的不可变公共库恢复并校验完整已解析来源。用户不能在请求中提交正文、SQL、路径或向量。原 `library` 章节选取、财务快照和旧资料协议保持兼容。

新保存合同为 `project_library_source_snapshot.v2`，沿用既有附件事务、内容摘要、批注修订及组织独立副本发布。旧 v1 快照仍按原内容和摘要读取，不迁移或改写。包含完整正文和原分段的快照有明确 20 MiB 上限，超过时拒绝保存、不截断；旧章节/财务快照上限仍为 2 MiB。完整来源仍需遵循既有附件原件大小限制。数据包保留图边和绑定，但不声称完成图实体存储迁移或开放组织图查询。

v2 使用 `library-source-offset-bundle.v1`：完整正文只存一次，父段/子段保存原 ID、定位、字符区间、摘要和嵌入上下文，不再重复存正文。保存前逐字段无损往返校验，读取时校验整篇摘要及逐段偏移/摘要后恢复原 v1 内部结构。旧向量投影、原 chunk 身份和 Java 索引合同不变。

这种服务器从固定库构造的来源已解析、已分段，附件存储直接校验并保存原分段，不再送入通用 Markdown 解析器。普通上传仍保留 2,000,000 字符的解析限制，所有附件仍保留 20 MiB 文件限制及原项目配额。没有允许浏览器提交自定义正文、SQL、分段包或放宽普通上传边界。

内部 `AssetWorkspace.read_source` 为这种明确类型提供完整正文和原分段，普通 UI 预览仍有边界，不将全文一次传给模型。组织运行读取仍由 Java 当前项目及全部固定来源权限控制，并在存储读取后再核权；新来源按原发布日期或明确 known-at 检查研究截止日，缺失日期拒绝使用。`read_organization_evidence` 按原有有界分页返回，包括 100,000 字符之后的内容。

日期规则与公共库的 strict-as-of 一致：`dated_original` 使用发布日期；`known_as_of` 优先使用可知日；时间戳按来源日比较。`unknown`、`current_revised`、缺失日期及晚于截止日均不能作为历史来源。文件可读或有抓取时间不代表已满足历史研究授权条件。

`organization-library-chunks.v1` 为新投影：组织节点 ID 同时绑定资源、版本和旧 chunk 身份；返回正文只含原证据，embedding 上下文独立记录。原 source/chunk/parent、来源内和父段内位置及摘要在 `original_source` 返回。索引登记核对正文摘要和 embedding 输入摘要；Java 固定新增投影标识及索引/矩阵版本，旧 `organization-text-6000.v1` 不变，不把旧准备单解释为新投影。排名缓存仍绑定授权和索引版本，每次命中及原文回读都核对当前权限。

### HTML/PDF 原件重放与独立组织存取

`retrieval.library_archive_recovery` 为后续 32 份 HTML/PDF 接入提供固定解析记录。离线生产者只读取明确指定的归档根目录内文件，先核对原始字节 SHA256，再按旧 HTML 表格文本／pypdf 页文本规则重放。全部预期父段 ID、定位和正文必须与只读库逐项相等；缺段、重复段、额外正文、原件变化均失败。新目录不覆盖原库、旧索引或历史结果；失败留下 failed，中断留下 incomplete。

```bash
python -m scripts.data_retrieval.prepare_archive_recovery \
  --library <published-library.sqlite> --source-id <source-id> \
  --archive-root <explicit-local-archive-root> --output <new-recovery-directory>

python -m scripts.data_retrieval.prepare_library_source_bundles \
  --library <published-library.sqlite> --index <existing-vector-index> \
  --source-id <source-id> --output <new-bundle-directory> \
  --recovery-catalog <recovery-directory/catalog.json> --recovery-sha256 <catalog-sha256>
```

全清单工具 `audit_library_source_intake` 也支持这两个 recovery 参数。BFF 保存入口使用服务器环境变量 `FINSIGHT_LIBRARY_RECOVERY_CATALOG` 与 `FINSIGHT_LIBRARY_RECOVERY_SHA256`；两个值必须同时配置，目录版本及每源记录摘要均须匹配。浏览器仍只提交来源 ID 和资料库版本，不能指定归档路径、正文或恢复目录。读取路径不使用历史 metadata 中的任意归档路径；解析只在离线构建发生。
