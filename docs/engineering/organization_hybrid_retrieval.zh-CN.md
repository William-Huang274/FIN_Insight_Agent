# 组织授权下的已准备向量与关键词混合检索

## 2026-10-23：发布准备与查询加载的生命周期改造（实施中）

### 组织图候选：显式发布、单跳、来源绑定

完整来源包已有原公开库的 `edges` 和 `edge_chunk_links`。宿主通过 `preparation_graph(reader)` 从当前授权的固定原件生成图投影，向 `publish_prepared_index(..., graph_sources=...)` 显式提供它。发布新增 `graph.sqlite`，包含文档图摘要、实体端点、关系有效期/状态及原证据块到组织节点的映射；图文件摘要进入 `index.json`，由既有 Java `index_digest` 一并冻结。没有图的旧发布不回填，查询也不旁路读取公共图。

首次预热在核对原件正文的同时，逐文档重新生成图投影并比对摘要，防止将另一资料版本的关系套在当前正文上。图文件同样纳入加载复用的文件身份检查、完整摘要校验和未封存 WAL/journal 拒绝规则。

新图发布支持 `source_space=organization, operation=search, entity_id=<精确实体ID>`，以及单跳方向和谓词过滤。图通道沿“实体邻接关系 → 来源绑定证据块”取候选：先限制到本次获准且符合文档筛选的节点，再限制关系发布日期、有效期和审查状态，最后分配最多 12 个图候选名额；隐藏资料不能占用名额。`needs_semantic_review` 即使请求 `graph_review=all` 也不进入搜索候选，保持原公开图搜索的排除规则；其余状态（例如 announced/planned/terminated）原样保留，不改写成已确认事实。

关键词匹配优先使用该授权范围内的既有 BM25 顺序，补充候选按发布日期及稳定 ID 排序。融合保持向量 24、关键词 12，图请求额外最多 12，故正文按需读取上限为 48；无实体图请求仍为 36。使用本地 RRF，不调用公开路径的远程重排，不声称与公共 FTS/重排路径得分相同。响应 `graph_node_ids` 和 `graph_evidence` 仅表示候选来源关系，原文仍须独立回读，不能作为金融事实认证。图参数进入响应缓存，实际图候选顺序进入排名缓存；每次仍核验 Java 当前授权、原件代次及发布身份。

本批不开放组织 `related/company/data` 或两跳导航；没有发布图时显式实体搜索报错，不静默降级为公共库。前端实体发现/筛选入口尚未接入。全量离线 `s2-organization-graph-full-scope-r1` 核验 1742 来源/114028 节点、1722 关系、2922 关系证据映射；587 条待语义审查关系排除于查询。所有来源图摘要一致，30 实体×2 资料范围的60次单跳候选与独立过滤相同。这不是60道召回题，不是Java真实服务授权或性能验收。

1742 份资料 / 114028 个块的 r21 实测冷查询 248.85 秒、同问题热查询 4.27 秒、新问题 34.89 秒。主要问题是查询内建立资料投影与 BM25 数据、重复加载全量内容；不是 Qwen 查询向量生成耗时。本轮不能称在线检索性能已达标。

新发布的 v2 release 增加 `lexical.sqlite`：SQLite 保存精确词频、分块压缩倒排列、文档长度及 `rank_bm25` 的 IDF 统计。构建发生在 `publish_prepared_index`，无模型调用；倒排构建缓冲每 8 MiB 原始数值载荷写入 SQLite，不把全库倒排全部驻留内存。文件摘要、格式和块数进入 `index.json`，原有 Java `index_digest` 因而覆盖它，不增加或改写旧准备单字段。资料更新必须另建 release，旧目录不得覆盖；构建失败不能产生可用的发布标记。

查询全范围时只读取查询词的倒排列，继续调用原有 `rank_bm25` 评分。按文档、节点或顺序筛选时，以对应已保存的词频重新计算该范围的 IDF；不能直接使用全库 IDF。重复词、中文、空词表和零/负 IDF 保持原行为。新发布查询不再向临时投影写入重复词频；旧 release 没有 `lexical_index` 时保留原有精确路径，不偷偷修改旧索引。

`ReleaseLoadCache` 在一个组织导航对象内复用已验证的发布元数据：首次加载仍完整检查索引、矩阵、关键词文件摘要和冻结合同；后续检查各文件身份、大小及纳秒修改/变更时间，禁止未封存的 SQLite WAL/journal。每次返回前再次检查发布身份和当前 Java 权限。检测到文件变化、消失、加载期间变更或错误合同即拒绝；不选择另一个“最新版本”。不跨查询保留矩阵映射或原件正文。发布文件是宿主受控且不可变的存储，这不是对恶意宿主伪造元数据的防护，也不是授权有效期缓存。

完整来源的新发布还包含 `navigation.sqlite`，逐节点保存正文与来源、期间、定位、版本及引用字段；每个节点摘要和文件摘要均进入冻结发布。首轮 `VerifiedCandidateIndex` 核对全部固定原件与发布节点，然后只保留节点 ID、摘要和资料归属。相同原件数据库代次、授权合同和不可变 release 下，新问题用元数据排名，只读取融合后的最多 36 个候选正文；不再加载完整正文投影。分页、摘要、原文定位与独立原件路径保持一致。旧发布保留旧路径，新文件不回填旧目录。

宿主可显式调用 `OrganizationSourceNavigation.warm_release()` 提前完成索引及全部固定原件校验，不发起查询向量请求。原生组织运行现在由 `OrganizationRetrievalLifecycle` 在准入后、模型/阶段工具开放前调用预热；负责人、专家、审查等使用同一工厂的阶段复用已核验检索状态，各自的阅读和计算观察记录仍隔离。完整扫描发生在运行准备阶段，首次成本仍需记录。

生命周期状态为 `unprepared → preparing → ready`；完整来源发布的原件数据库代次变化后进入 `refreshing`。查询只检查代次并安排一个后台校验任务，立即返回暂不可用，期间不返回旧缓存、不等待全量扫描；后台重新核验相同固定范围，成功后原子替换可用状态。任何来源库提交（包括无关写入）目前都会触发该保守策略，不是按资源增量更新。权限撤销或发布文件变化会直接拒绝，后台失败进入 `failed`，不自动循环重试；宿主可显式 `prepare(retry_failed=True)` 再校验。运行结束关闭工作线程，关闭期间完成的校验不能重新发布 ready。

这是**每次原生运行范围内**的准备和刷新生命周期，不是跨运行/跨进程的全局热缓存，也未提供网页就绪状态接口。进程重启/新运行仍重新校验；旧发布格式保留既有查询语义。新增资料生成新索引、定时扫描或写入事件通知、后台增量构建及供新准备单选择新版本仍待接入。现有准备单始终固定旧 release；发布了新版本也不会自动迁移旧研究。

候选路径依然在调用前、付费向量生成前及返回前核对当前 Java 授权，检查原件代次和发布身份；读取原文仍访问真实原件。非命中资料的撤权、损坏或删除也不能被查询筛选掩盖。预热失败不会保留部分可用状态，候选读取期间的变化会拒绝返回；成功状态不构成持续有效的权限凭证。

## 接入与范围

Java 仍是成员、项目、来源权限及执行绑定的唯一权威，沿用现有 `/v1/runtime/organization-executions/{id}/access`。不新增 Python 成员表，不让模型指定 owner、组织、索引目录或缓存身份。

`OrganizationDataFactory` 接受可选的服务器 `retrieval_root`；原生组织入口仅从宿主环境 `FINSIGHT_ORGANIZATION_RETRIEVAL_ROOT` 注入。负责人、专家与复核经该工厂创建的 MCP 来源工具使用同一导航。没有此配置时保留原本的组织词法检索；配置后索引/查询缺失或校验失败会停止该次搜索，不回退到宿主公共库或词法结果。部署没有自动切换。

旧 v1 索引保持**已准备向量及已准备查询**的无提供方通道；新的自然语言查询会明确返回 `organization_retrieval_query_not_prepared_no_provider_fallback`。新增 v2 不可变 release 可绑定 Java 准备单，服务器显式设置 `FINSIGHT_ORGANIZATION_QUERY_EMBEDDING=qwen` 后，允许同模型的新查询向量；未配置、提供方失败或结果未知均明确失败，不自动重试或静默回退。费用回执、范围缓存、真实原生联调及并发/召回边界见[索引发布与检索验收](organization_capacity_and_retrieval_qualification.zh-CN.md)。没有启用远程 rerank。

## 数据、排序和缓存

1. Java 返回固定 manifest，Python 校验身份和摘要，并按现有原件存储校验每个 AssetRef。文档身份绑定资源和版本；索引准备使用当前组织导航的相同文本投影和节点 ID。
2. 服务器按规范组织 UUID 选择独立索引目录。发布记录模型、维度、节点/文档身份、正文摘要、向量矩阵摘要与来源说明；重复发布不覆盖旧目录，换版使用新 release root。准备工具不生成任何向量、不调用提供方。
3. 请求中的文档/节点过滤和固定输入集合共同确定可用节点。核对节点正文摘要及发布身份后，**先选取获准矩阵行，再计算余弦相似度与 top-K**。同索引内未选资料不能占用候选名额。
4. 复用现有 BM25，合并最多 24 个向量候选和 12 个词法候选，采用本地 RRF（常数 60）排序。没有远程 rerank；显式图发布与实体搜索额外提供上文的最多 12 个单跳图候选。可以搜索全部明确冻结且当前获准的候选资料，不等于无条件搜索整个宿主库。返回候选诊断只含本次获准 ID。
5. SQLite 排名缓存只保存三组 ID（向量、词法、最终顺序）。键包含当前完整授权响应摘要、执行/项目/固定输入、索引内容摘要、查询摘要、节点版本及排序策略版本。不同组织分目录，不同执行和查询范围分键。
6. 缓存命中仍须重新核权、检查原件数据库代次、发布身份和候选集合。当前查询可复用已验证的投影/响应；同一导航对象内发布完整校验按上文生命周期复用。缓存中的越界 ID 被拒绝，不做过滤后继续返回。引用读取仍逐次核权并检查原文身份；检索预览不能作为已读引用。

v2 索引 release 通过 BFF 校验原件投影和当前权限后在 Java 登记，准备单可选择 `retrieval_release_id`，固定模型、维度及索引/矩阵摘要；发布新版本不改写旧准备单。旧 v1 仍使用宿主显式配置，不能获得 v2 的发布版本保证。每次结果记录索引摘要，换 release 不复用旧排名缓存。索引目录需允许创建本地 ID 缓存；原件与源公共索引不被改写。

排序、缓存写入及最终输出前再次核权。扫描期间撤权导致整次工具失败；已返回的数据不能被撤回，也不声称消除了最后一次检查与响应之间的时间窗口。索引文件和缓存是宿主受控存储，不是模型可编辑的输入；本片不提供磁盘加密、恶意宿主防护或跨机器发布服务。

## 历史案例复现

`scripts/data_retrieval/prepare_organization_hybrid_cases.py` 从同一发布库的实际 `context + newline + body` 提取文本副本，并复用该索引的向量矩阵和成功查询回执。核验原库 SHA256、矩阵/映射摘要、候选正文摘要；源库、索引、提供方缓存只读。每题保留两个真实片段，挑选较弱匹配作为组织 A 的固定输入，较强匹配存在物理索引但未授权给本次执行。组织 B 固定另一个片段。

```bash
python -m scripts.data_retrieval.prepare_organization_hybrid_cases \
  --library <published-library.sqlite> --index <prepared-vector-directory> \
  --replay <historical-replay-result.json> --cases <historical-queries.json> \
  --output <new-case-directory>

python -m pytest -q tests/test_organization_hybrid_retrieval.py
# 按真实业务验收文档配置独立 Docker 子网、端口、jar、输出目录。
# FIN_ORGANIZATION_HYBRID_CASES=<new-case-directory>/cases.json
```

### 向量校验与排序的临时内存

固定发布的向量完整性仍按整个文件摘要核验；注册时的单位向量校验，以及查询时的授权候选校验／余弦计算，按最多 4,096 行分块处理。不会抽样、缩小候选范围或缓存正向权限。查询仅保存一维分数，避免同时构造全候选 float32 副本及整个 float64 校验数组。缓存命中仍校验全部已选向量；未命中时，参与点积的每个块再次校验有限性与单位长度。排序的前 24 向量候选、前 12 词法候选和 RRF 规则保持不变。

跨块测试覆盖打乱候选顺序、未授权行含坏值、末块零向量／NaN／无穷／非单位向量，并与原 NumPy 点积比较数值及前 24 排序。`scripts/engineering/qualify_organization_vector_blocks.py` 可用已核验输入包和固定成功查询向量逐源离线重放；输入摘要变化或排序不一致会失败并保留此前完成的来源。该脚本不是组织服务、全库排名、召回或并发验收，运行时间不能作为线上查询延迟。
