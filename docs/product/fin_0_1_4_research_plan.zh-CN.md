# FinSight 0.1.4：可持续运行的专业研究工作台

2026-09-13 更新 · 版本规划，尚未实施或发布。多用户调度、成本与质量、产品差异化为用户明确追加的核心要求；下文客户定位、商业包装和实施次序为待验证建议。

## 产品目标

面向专业用户，Agent自主挖掘资料背后的经济关系，提出有依据的竞争性假设，主动检索和交叉验证，在约定时间和资源内形成决策所需的报告。用户决定投资目标、取舍、仓位及超权限资源；Agent承担一般研究路径、局部纠错、替代证据和优先级。不能一遇材料缺口就甩回用户，也不能无限研究而不交付。

可靠性涵盖事实/金融语义正确、假设与事实不混淆、保留正确判断、主动发现有价值问题和实际完成报告。风险提示应包含假设、支持/反证、传导、已查路径与触发信号；未证实但有依据的假设是研究资产，不能统一删为“无法判断”。无依据故事不能升级为风险。

## 部署、经济性与产品定位

本版本同时验证研究质量、可持续成本和多人使用。可供真实用户试用的部署能力进入版本范围；购买服务器、正式开放服务及收费仍需以具体配置和验证结果决定。不能用本机多次成功代替多用户验证，也不能用模型调用成功代替报告合格。

建议优先服务持续跟踪少量公司或议题的独立研究者和小型研究团队：首次研究建立资料、财务计算与判断，后续披露和用户修订触发有依据的局部更新。该定位尚未通过用户付费或留存验证。通用单次问答继续作为入口，深度研究按需执行；普通追问不默认启动完整专家链。

系统需要体现连贯的使用价值：研究问题决定证据需求，资料与方法支持判断，判断绑定来源和计算，更新识别受影响部分，调度在预算内完成必要复核并生成新报告版本。队列、角色数量或专有命名本身不是差异化；开放代码可被复用，也不能承诺无法复制。需要与获得同等资料、工具和方法的通用 Agent 对比实际质量、人工时间和重复使用成本。

### 多用户试用的最低能力

- 提交后任务持久存在；断开网页不等于停止工作，重新连接可看到实际状态和已保存结果。
- 区分排队、执行、暂停、等待用户、取消中和完成；说明哪些运行阶段能暂停，已发出的供应商请求不能假定立即撤销或免计费。
- 同一研究的冲突写入、重复提交、跨 worker 接续和用户隔离有实测；任务子分支共享总预算。
- 全局、用户与供应商容量共同约束调度；长任务不无限占据全部容量，短查询也不应让长任务永久饥饿。排队等待与执行时间分别展示，排队不额外增加用户批准的总成本。
- worker 中断、连接丢失、服务重启和版本切换后能恢复或明确保留待核状态；未知外部请求不自动重发，不宣称跨外部服务的绝对 exactly-once。
- 外网试用前完成认证/TLS、持久存储、备份恢复、资源上限和可观测性验证；开发用 noop 原生接口不能直接暴露公网。

### 成本与质量共同验收

首先按历史调用逐项归因：模型及思考档位、输入/输出/缓存命中、任务阶段、重复读取、格式修复、局部修订和失败尝试。原始用量、按当时价格的估算、真实账单分开。当前约4元的用户体验是成本压力信号，不代表全部复杂任务成本；211案例记录约16.92元的已知费用估算且有2次未知请求，原生Writer未完成。不能与其他案例或后续实验混合为平均数。

核心指标为同类任务在相同质量要求下的合格交付成本，以及用户实际审阅/修改时间。全部尝试费用计入分子；零合格交付时不报告有限的每份合格报告成本。同时观察尾部费用、时延和人工介入，不用便宜失败替代昂贵失败。

建议先减少不必要的全链调用、重复读和全篇重写，再按任务选择执行者：计算/单位/去重/版本差异交给确定性工具；可验证分类和候选抽取资格化较低成本模型；关键金融关系、反证和矛盾解释使用通过该类任务验证的模型。模型自报置信度不作为唯一升级依据，重要结论保留独立检查。每个调用仍有任务特定TokenBudgetBasis和总预算余量。

缓存按资料内容、快照、方法/模型版本和权限复用：区分精确工具结果、预计算向量与供应商前缀缓存；私有用户数据不跨租户复用，相关事实或方法变化后旧判断需重新检查。摘要和阶段整理本身计费，是否净节省以实际用量验证，不把语义近似当精确命中。

商业包装建议为工作台订阅加有限研究额度及显式加量；BYOK或团队部署为候选而非本版并行承诺。开发排错造成的额外成本应与新增用户研究区分，不默认转嫁。先确认任务结构、使用频次、质量和毛利需求，再定价，不承诺低价无限深度研究。竞品套餐不等于API成本或供应商补贴证据。

## 五项研究能力

| 工作包 | 用户可感知的行为 | 核心验收 |
| --- | --- | --- |
| 适用背景与方法库 | 按问题、行业/价值链、商业模式、企业阶段、准则/法域和时间选择方法 | 相似表象而经济/制度背景不同，能选对方法；纯措辞变化不应改变已证事实 |
| 假设驱动的主动研究 | 发现产业链、报表、价格/预期之间的张力，生成竞争解释、历史机制类比及交叉验证 | 能发现未被用户明说的重要问题；支持/反证齐全，类比不直接当预测，无效假设能撤回 |
| 方法与信息更新 | 研究前和依赖变化时刷新可信来源，识别受影响结论，无需技术人员逐份改提示词 | 区分事件、披露、规则发布/生效/过渡、当地采纳和企业采用；保持历史时点可复现，专业歧义提交具体取舍 |
| 专家与有限委派 | 专家按具体交易或判断调方法，必要时派子任务，父专家整合冲突 | 委派范围/产物/来源明确，子预算计入总预算；多个模型同意不当证据，不生成无限角色树 |
| 研究收敛与交付 | 按决策影响排序，停止低价值重复，为综合/核验/导出预留资源 | 截止时交付可决策版本；一个数字缺失不能拖住全报告；实质未决项转为情景/风险，不隐去必答项 |

## 方法及专家设计

大skill负责研究目标、重要性、假设竞争、路线选择和综合；行业/制度方法提供适用背景；小skill负责一个易错推断的证明责任与检查程序。方法包包括适用/不适用条件、权威依据和版本、输入、步骤、反例、可用工具/计算、输出证据和复核触发。小不是极短；避免只增加“请谨慎”。

动态选择结合任务预配、交易/数据特征触发、模型自选与重要结论复核。不能只依赖模型自知其错。方法应教如何区分结论，而非写死“合同负债必属某现金流”“港股永久低估值”“AI增长必为泡沫”等答案。

专家开始前核定主体、报表范围、实际准则、期间、交易及证据。仅在确有独立工作时委派，不为每个科目常设子Agent；复用既有LangGraph执行与工具权限，父专家负责整体报表勾稽、跨专业冲突与报告交付。

## 更新和权限

事实更新先进入证据；经济关系变化触发旧方法适用性检查；规则变化保存发布、生效、过渡和查询时间。研究有信息截止日，禁止未来信息倒灌历史判断。来源只提供证据，不自动成为执行指令。普通资料刷新、候选方法生成和差异检查可自动完成；重大规则解释歧义由专业用户/方法负责人决定，不以工程人员手改为日常入口，也不把模型自改方法当已验证共享规则。

研究遇阻先区分本地对象/索引/SQL错误、可达检索/工具问题及真正信息限制；修复所属层的问题。用户只决策目标、投资取舍、权限、明显预算/期限变化或其专属信息，不被要求选择每次检索方式。

## 收敛与资源

模型应评估下一步可能改变哪个重要判断、与已查路径的区别及继续价值。Runtime执行任务特定总预算、分支/重复/子任务控制和交付预留；资源包含所有后代任务。软触发限制新增低价值分支，收尾阶段只补关键缺口，硬截止依靠已保存的报告版本形成如实交付，不简单耗尽tokens后杀掉唯一产物。

次数、时间和比例尚未资格，不硬编码一个通用数字。每个付费节点仍需TokenBudgetBasis。未知调用保留且不自动重发；不能为了节费省略必答研究，也不能以“仍可能有信息”为由无限续跑。

## 最小实现顺序与验证

先利用已完成调用做成本归因，并用可控的模拟供应商验证既有队列、取消、重启、跨进程去重和预算；不靠付费研究发现工程故障。核实锁定runtime版本的部署许可与费用，不因最新文档具备某功能就认定现有版本可用。接着在现有工作台做一道有原件、可核对财务关系、可形成风险假设的端到端任务，接入少量判断方法和交付触发，实际产出报告；再加入一份新披露或用户修订，检验局部更新与第二次交付。让方法选择、原文回读、计算/反证和最终文本留下可核对记录。

先区分三条件：现有方法、直接给对小方法、动态选择小方法，判断内容是否有效以及选择是否有效。用已见case开发，不称盲测；再以独立的新公司/新期间/相反适用条件检验迁移，作者看过的答案不再充当隐藏评测。规则更新用有发布/生效差异的固定资料测试，不以联网成功冒充适用正确。

验收包含：关键事实/单位/期间/推理，新增有效假设及验证，错误纠正与正确保留，无谓待核/用户介入，重复查询、总资源及按期报告；新增多用户排队/隔离/恢复、成本上限、局部更新及对通用Agent的增量价值。模型返回成功或skill被读取都不足以通过。阈值应在执行前按任务重要性冻结，不由失败后的答案倒推。

比较保留三条基线：0.1.3现有流程、同资料/工具/方法的通用Agent、0.1.4候选流程。先固定模型分离runtime效果，再资格化模型路由。初次研究与追加披露/用户修订分别记录，同等提供新资料，不剥夺基线的正常记忆、工具或skill能力。用户认可、重复使用和付费意愿需真实试用验证，离线分数不能替代。

若直接给对方法仍不能改善判断，先修方法或模型配置，不扩充动态选择引擎；若选择失败，修选择层；若主要耗时来自重复路径，先修调度。任何失败保留在同阶段、用新attempt重验，不为失败新建产品版本。

一个有界规划包之后进入最小可执行切片，不再连续扩写治理文件。此文就是本版本首个规划包；下一工作应产生可执行/产品证据，不能只再写更大的框架。

## 采用边界与遗留

优先复用LangChain/LangGraph、现有SQL/来源库/计算/工作记忆及供应商SDK，先检查成熟组件；不自造通用调度器、队列、记忆数据库或规则引擎。方法库的金融适用性与最终研究接受属于FIN，通用执行/持久化/观测交给已资格运行栈。

0.1.3的模型语义失败、错误草稿锚定、主动笔记及整份报告交付问题进入本版本验证，不声称已解决。受控多人试用的调度、隔离、安装和恢复已因2026-09-13用户要求进入核心范围；生产HA和大规模多租户运营、任意主机权限、全市场数据、模型训练、交易执行与无限专家递归仍非本轮核心承诺。

现用Agent Server已提供队列和持久化基础，FIN负责研究优先级、资源边界和交付语义。优先用原生配置和数据库事务验证，避免再叠第二套任务真相或锁服务。如果部署许可、成本或实测能力不适合目标试用，再比较一个成熟替代路径并计算迁移成本；不预先同时建设多套runtime。官方当前部署说明与项目锁定版本要分别核实，参见本次[依据记录](../worklog/fin_0_1_4/001_runtime_economics_positioning.md)。

当前无0.1.4运行时/部署/模型效果增量。版本实施起点、具体调用预算与数据范围应随第一个真实切片记录，不能从本文推导无限付费权限。
