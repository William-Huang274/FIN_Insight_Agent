# 当前研究任务与历史数据契约

新建研究任务使用 `case_profile=general_research` 和 `runtime_contract_version=research_session.v2`。研究身份为 `research:<thread UUID>`，由宿主生成；实际用户问题、专业委派和逐来源截止日期决定研究范围。任何公司都不能因历史开发案例而成为默认研究主体。

## 运行接口

### 按问题形成任务，目录不再限定拆题

普通 `standard`（完整研究）和 `auto`（自由调度）均由 Lead 根据用户问题和研究发现形成任务。完整研究表示完成研究与复核流程，不表示遍历全部目录。`branch_catalog` 是可选方向提示，既不是必做清单，也不是全部可研究问题的枚举；不规定公司、任务数量或报告章节。

`ResearchTaskSpec.objective`、`topic_title` 和 `success_criteria` 表达实际分工。保留原字段名 `coverage_obligation_ids` 兼容旧记录，但在普通研究中它是可选标签，可为空或包含多个目录标签。未归类问题不必编造新标签或挤进一个旧分支。依赖仍通过实际 task ID 绑定，已提交任务不可重复执行。研究提交与语义质量复核继续分开。

底层 `BoundBranchTask.branch_id` 保留工具/来源绑定身份，不作为研究问题边界；旧单标签任务沿用原绑定，未归类/跨方向任务复用宿主已授权的资料绑定。财务主体仍由查询明确指定，来源空间、截止日、快照、权威和能力校验保持。模型视图标示 `tool_binding_id`，依赖导航和下游底稿目录使用实际分工及可选标签，不把兼容绑定当作研究标题。无数据身份、来源哈希或旧底稿迁移。

用户显式选择的 `selected`/`single` 方向仍受限制。只有显式设置 `ExecutionOptions.require_all_branches=true` 的 standard 任务，或独立的历史资格验证入口，才要求完整目录覆盖；此选项不能从“完整报告”等自然语言隐式推断。新建研究界面提供默认关闭的“逐项覆盖目录中的全部方向”选项，切换模式清除该选项。旧客户端缺省值为 false。固定覆盖按已提交任务的语义标签统计，不按内部工具绑定推定完成。

通用研究初始化不再把第一个内部工具绑定方向注入为“用户选择的研究问题”。配置中的专题方法仅作参考，不替代当前任务的问题和验收条件；显式选择单研究者或指定专家模式的范围仍保留。

`create_research_phase_runnables` 在实际调用时绑定 `RunnableConfig.configurable.finsight_execution`，再创建各阶段；直接脚本和正式入口遵守相同规则。显式传入的工厂配置必须与实际运行配置一致，冲突在模型和资料访问之前报错，不能静默回落。恢复配置继续保留用户的 `continuation_scope` 和模型选择。旧成功结果、来源及失败费用不重写，升级代码不等于重发请求授权。

离线回放可运行 `python scripts/engineering/replay_research_continuation_scope.py --open-topics --saved-input <旧接续输入> --output <本地报告>`。它禁止网络与专家执行，检查旧成果保留、新任务注册和真实来源绑定；这是确定性反事实探针，不是模型自主规划或最终研报质量验收。

- 方法基础、投影、方法包、运行范围与绑定分别使用 `fin_ia_research_*_v2_0` schema；宿主传入研究截止时间，禁止退回参考案例的固定日期。
- MCP `get_research_source_binding` 返回本任务的方法及数据版本绑定。`get_research_method` 仍是角色方法目录，两者用途不同。旧 `get_dell_research_method` 工具名已退役，代码内调用端同步迁移。
- 新能力引用为 `capability:research:*`，新方法引用为 `skill:research:*`。旧来源读取、财务查询和已审核证据三个能力 ID 仅在输入边界作显式兼容映射；未知 ID 不会被自动授权。
- 新任务不携带旧案例的强制资料路线、固定公司列表或已审核主题要求。通过已披露的原文、财务、计算与角色方法工具获取所需证据。旧案例专用的 `request_evidence` 路线不向新任务提供。
- 新任务财务查询必须明确 `ticker`；遗漏返回执行错误，不能隐式补为 Dell。缺口与冲突记录也保留查询主体。
- 任务输入、专题任务、notebook、模型请求、工具回执和人工移交生成通用 schema/actor 名称；读取历史 schema 的兼容校验继续保留。MCP 的任务、方法摘要及版本校验仍然生效。

## 版本和历史兼容

### 接续研究权限

技术恢复复用同任务已完成底稿和未完成任务，不冻结 Lead 的研究计划。默认 `ExecutionOptions.continuation_scope=original_question`：Lead 可以在原问题、已授权研究方向和既有执行预算内补派必要任务，复用依赖底稿及其来源；已提交任务 ID 不能重复执行。保留底稿也计入任务容量，恢复不会隐式增加可派任务总数。

仅当用户明确要求“仅完成原计划、不要扩展”时，宿主通过用户执行配置设置 `continuation_scope=original_plan`。该选项沿用现有 thread execution 元数据和原生 run 配置快照传递；已有计划的接续才限制为原未完成任务，首次规划不受这个接续选项影响。Lead 菜单、服务端任务校验和排队任务执行检查使用同一权限。资料文本、模型输出、已有底稿数量及恢复动作本身均不能设置该限制；不靠关键词猜测用户授权。

旧执行配置缺少此字段时使用 `original_question`。低层 `unfinished_only` 参数为显式受限调用保留兼容，正式会话入口不再按 `bool(seeds)` 自动开启；已保存历史请求、失败用量和原报告不回写。此修复不增加研究方向权限、改变资料截止日、扩大模型预算或授权重发失败付费请求，也不代表模型会自主提出合理补查。

历史来源清单、财务快照和已经签名的审计产物保留原始身份与摘要。当前任务在其上建立独立的方法绑定，并以来源清单、实际财务库与资料库摘要构成 `research-data:<digest>`；不把旧案例名解释成整个资料库的覆盖范围。

旧客户端传入 `dell_growth_quality` 时，新任务入口将其归一到 `general_research`；公开输入 schema 只描述新值。旧 checkpoint 则按保存的运行契约继续，不能在一次继续执行时悄悄替换已有依据的哈希。历史结果正文也不回写成“新模型结果”。

真实 Dell 公司资料、证券代码、引用及必要的旧数据加载路径不做字符串清洗。现有容器/存储名称是部署兼容标识，不能进入模型的当前研究范围。Java 侧继续调用研究会话/资料服务接口，无须依赖底层历史文件名或 MCP 绑定工具名。

本次迁移不修改资料、chunk、图边或向量，不重新 embedding。工程验证使用无付费回归和正式只读 MCP 路径；没有为清理名称重新付费运行 DS。工程通过不代表新的模型规划质量已获验证。

## 首轮 Lead 规划的解释边界

首轮自然运行产出六个专题和角色建议，尚未实际调度专家。共同口径应先由 Lead 形成简明约定，再让采用质量、交付与云收入、电力兑现并行取证；资本开支基础事实也可以提前收集。收益归因和链条综合依赖这些结果，独立来源核查则随具体判断及时加入，不应统一留到最后。

这是一项对现有计划的人工审阅建议，不是写入模型的标准答案。后续观察模型能否自行给出合理依赖，并区分资料不可得、库内漏查、工具故障与证据不足。一次开发案例不能给出总体正确率。
