# 增量研究认识、论证骨架与成文断点回接

本版承接[专题研究交接](research_topic_handoffs.zh-CN.md)。复用同一研究工作区的 SQLite、原生咨询执行器、LangGraph 检查点、报告保存及上下文 surface 替换机制。当前为源码与离线工程验收，未部署，没有付费模型质量验收。

## 产品目标与验收范围

负责人持续形成、检验并更新原题的回答。成文先围绕当前认识形成暂定论证骨架，再按需读取完整材料；证据可以改变结论、标题及章节关系。已稳定的判断无需每次重新生成。写作发现断点后，能返回对应调查，保留其他有效认识，随后检查总判断是否仍与章节一致。

| 产品要求 | 实现与离线检查 |
| --- | --- |
| 新发现只更新受影响认识 | 稳定判断 ID、显式采用关系、增量 patch、不可变历史和当前状态视图；成本变化传播到总判断，另一分支逐字段不变 |
| 报告骨架有研究依据且可以改变 | 章节问题、论证作用、判断身份；主判断及各章节关联精确底稿版本；不固定标题或立场 |
| 成文材料不退化成摘要拼接 | 全局主判断与所选章节依赖进入当前视图；完整底稿、证据与计算回执按精确入口读取 |
| 多处断点不互相覆盖 | 不同 issue 身份及准确原句/原稿摘要值；分别补查、更新旧依据或澄清表达 |
| 补查更新需要落实到总括 | 局部判断更新后，依赖其原版本的主判断仍待重评；只改局部不能绑定交付 |
| 正文可追溯且保留历史 | 实际段落 → 章节 → 判断版本 → 底稿采用/限定理由 → 原始来源/计算；旧任务仍返回旧版 |

离线脚本规定发现和判断，验证协议、版本、持久化与真实工具接线。它没有测试模型能否自主发现矛盾、调查充分或作出正确投资判断。

## 增量状态

`update_research_understanding(base_revision, patch)` 更新已有当前认识。`judgments` 只提交变化条目，遗漏条目保持原样。每项含 statement、公开推断理由、条件、反证、未完成关系、精确 workpapers 及 depends_on。`lead_judgment_ids` 指向当前总判断；sections 指向其论证所用判断。暂定章节可增删排序。撤回判断保留其声明及原因，不删除审计记录。

更新采用 SQLite 事务、基础版本检查与命令幂等。完整当前状态和本次变化一并持久保存；恢复后无需沿历史 delta 重演判断。工具回执仅返回改变项、待重评项和入口，不把完整状态再重复返回。这里保存的是公开论证，不保存私有思维链。

触发分两层：模型判断新发现是否影响认识；runtime 根据登记的底稿版本和判断依赖计算需重评位置。改变某项前提后，相关判断、章节及总括标为待重评，未受影响者保留。重新确认原判断可以提交相同 statement，但必须更新对应依据及公开理由。runtime 不判定某金融结论真伪，也不能发现未登记的语义依赖。

## 成文输入与追溯

`read_authoring_context(section_ids=...)` 提供原题与截止日、主判断及依赖、选中章节的认识和材料入口、全局论证骨架、撤回解释、待重评项与断点。使用 revision 可读取历史认识。默认当前视图不包含完整底稿，也不叠加全部历次改稿。完整材料通过既有 read_research_workpaper / read_workpaper_evidence 或冻结后的 read_synthesis_material 读取。

`prepare_research_synthesis` 将认识版本与原有底稿快照一起冻结，检查所选材料覆盖当前骨架实际使用的底稿。`bind_research_synthesis(section_uses=...)` 将每个章节的准确唯一正文片段，与该版判断及底稿依赖绑定；同一判断可关联标题、摘要和结尾多个位置，field 选择 title 或 narrative_markdown。`read_current_report(field="argument_map")` 分页读取实际绑定，可由正文回到精确认识和材料版本。跨专题的新推断需要由作者保存自己的判断及依据关系，不能假托给某个原件。

已启用新认识状态的任务，绑定时检查：主判断及骨架存在、依赖版本未过期、登记的断点已处理、正文片段实际存在且唯一。没有采用新状态的历史任务继续原有整稿绑定，避免破坏恢复兼容。实际段落的语义、选材充分性、标题与正文的真实逻辑仍需要模型/人工验收；绑定本身不认证这些内容。

## 成文中的断点闭环

1. 作者保存当前稿后，用 `open_authoring_issue` 指定原稿版本、准确唯一原句、受影响章节、待解释问题及类型。支持 missing_link、stale_basis、expression、thesis_conflict、access_failure。
2. 需要调查时，在既有 `consult_research_agent` 传入 authoring_issue_id。宿主自动带入原句、原稿摘要值、原题、当前相关判断、章节目的和精确材料入口。调查者可以质疑原假设；不用复制父会话全文。继续旧专题可同时指定 topic_id。
3. 调查沿原原生工具/预算/失败恢复权限执行，成果在 workpaper assignment 保留 task_id 和 authoring_issue_id。失败请求规则不变，本版不会自动补发付费调用。
4. 主负责人读取准确结果，增量更新受影响认识。局部改变仍会提示依赖它的摘要/结论；相关正文保存后，resolve_authoring_issue 记录修改、保留或条件回答及理由。缺失推断链或访问故障必须有对应调查的已读、当前结果；其他任务结果和仅一句“没搜到”不能机械关闭该断点。
5. 每个断点分别处理。相关判断或调查结果再变时，已处理断点重新待评估。表达澄清可以直接修文，不强制新模型调查。新断点会使之前的交付绑定暂不可用；修订正文后重新绑定准确段落。

上述检查只保证调查结果、作者决定与正文位置可以关联。作者声称接受却没有真实落实，仍可能通过机械结构检查；不能将 resolve 当作独立语义审批。

## 上下文处理

复用已有子结果验收后的退出机制，新增当前认识视图的替换：只有新版本的**同一章节范围**视图确实已被读取，旧视图才可从活跃 surface 退出，留下新视图和精确历史回读。主动读取历史版本不退出；不同章节范围不互相覆盖。底稿或 issue 变化即使没有新增认识 revision，也改变 context_generation，避免把旧断点状态当作当前。

替换通过原生日志记录，保留工具调用与回执对应、完整业务检查点和数据库内容；新精简回执若更长则不替换。这里只替换已被当前视图取代的认识读取，不任意删除整段模型历史，不建立额外摘要压缩器。258k 原生压缩基准保持不变。完整的阶段会话切换、自动整段历史淘汰及跨任务长期记忆不在本版范围。

```bash
python scripts/engineering/replay_research_authoring.py --output /path/to/fresh/private/replay
python -m pytest -q tests/test_research_authoring.py tests/test_research_workpapers.py tests/test_research_handoff_replay.py
node --test tests/harness_accepted_results.test.mjs
```

虚构 AI 采购案例同时出现：客户节省到续费缺少推断环节、定价依据需更新、能源成本与价格表述混淆。两个调查通过真实咨询及工具桥交回，表达问题本地处理。回放检查局部更新后的总判断待重评、无关分支不变、保存正文后的实际绑定和交付、旧任务原版回读、重启后状态与完整成果保留。

输出 `replay.html`、完整工具参数/回执 trace、初版及当前认识、实际成文读取窗口、绑定映射、最终合成正文与 SQLite 检查点。root-tool-entry 展示通用主提示词组装及本案例实际开放工具，root-business-messages 保存完整业务消息供比较；它们不冒充已执行过的原生模型活跃窗口。native_assignment 与 native_prompt 由实际派发共用组装函数生成，均未发送给服务商。脚本拒绝覆盖已有目录。来源和研究结论均为显式虚构材料。

负例覆盖版本并发冲突、命令改参、依赖环、错误来源摘要值、未读调查结果、错误断点结果、非唯一正文定位、漏选骨架材料、旧理解快照、未处理断点及源版本变化后再次打开。权限/存储故障继续抛出，不能降为模型可忽略的建议。

下一次真实验证应检查模型是否主动识别重要断点，补查是否改变当前认识，以及它能否以自然中文给出有条件的明确判断。这些属于研究质量验收，离线结构通过不能代替。
