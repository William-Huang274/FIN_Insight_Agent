### 查询规划、持久验证与重排进展（2026-10-26，尚未完成统一验收）

`organization_query_planning=conservative.v1` 是组织搜索的显式选项，使用当前授权目录中的公司名称/标识、明确的10-K/10-Q/8-K及明确期末日期。跨公司或名称歧义不加单公司条件；财年、公告月份、一般日期不推成期末。自动规划保留元数据缺失资料，返回匹配依据、未决条件与筛除数量；显式用户过滤仍沿原严格语义。旧请求不增加空字段，不改变默认搜索。中英文别名未在目录中登记时不能凭空识别。

明确的中英文“某公司年报”短语可区分报告所属公司和问题中的交易对手；存在比较意图或多个报告所属公司时仍不收窄到一家公司。离线诊断的 `--query-planning conservative.v1` 直接调用相同规划函数，逐来源核验原始元数据和封面依据后，在所有候选通道之前限定范围，同时保留未知元数据与被排除的已知证据记录。自动规划与人工过滤对照不能混合为一次实验。

明确“年报/annual report”可限制已识别的报告种类，兼容10-K、20-F、40-F及修订件，不能由此推断财年期末。未知或未分类的文档仍保留；同时要求年报与季报时不施加单一种类条件。明确的单一表单条件仍按原精确匹配语义处理。

候选配额可由服务器显式设置 `FINSIGHT_ORGANIZATION_CANDIDATE_POLICY=dense_expanded.v1` 做受控对照：没有图查询时取36个稠密候选和12个词法候选；有图查询时仍为24/12/12，合并前预算不超过48。默认保持 `balanced.v1` 的24/12/12。策略参与排名缓存身份，返回记录配额，当前授权和固定资料范围仍先于候选选取。离线驱动提供同名 `--candidate-policy`，记录规划/配额实现摘要与数值计算线程配置；这些代码和合成配额测试不代表质量或容量通过。

新增业务开发题的向量准备入口是 `python -m scripts.engineering.prepare_organization_query_vectors`。先校验题目引用、原文摘要与截止日，再保存 `TokenBudgetBasis`；仅显式 `--execute` 提交请求。成功缓存可跨进程复用，失败或用量未知的请求不自动补发；未冻结的保留集禁止执行。开发题结果不等同于独立最终成绩。

## 向量生成预算

Purpose：验证新查询来源及新题语义检索，付费范围限定 embedding。Input scale：先小批公开文本验证回执与缓存，再按语料、题集及已存在的同模型向量计算缺口；不直接重嵌全库。Output：每段固定维度向量与模型/输入摘要，不生成研究答案。Quality risk：模型混用、截断或错误输入投影导致语义失真。Reasoning profile：embedding，不适用推理生成。Limits：每个执行批次先保存机器可读 TokenBudgetBasis；初始探针最多 10 条、10,000 UTF-8 字节、一次服务请求，SDK 重试为零。扩展批次另存实际输入规模与预算，保持低并发，避免争用同账户额度。Stop：超预算、限流、未知结果、模型/维度/健康不符即停止该批；保留失败及未知用量，不自动补发。成功缓存仅在来源范围、模型、维度、完整文本及输入投影一致时复用。

## 最终实现与测量条件

Java 新增 V10 不可变索引发布表，由可信 BFF 验证文件、原文投影及当前授权后登记。浏览器只能选择已发布版本；准备单冻结 release ID、索引/矩阵摘要、模型、维度及投影身份。所选资料及版本必须与发布输入完全一致；旧准备单不追加空字段、不改变摘要。发布新版后旧准备单仍读取旧版，错项目、撤权、损坏矩阵、投影不符均拒绝。

Python 的新查询向量仅对冻结索引启用显式服务器提供方；缓存按组织、索引、模型和完整查询隔离。8 个同时到达的相同冷查询实测全部成功，仅一次付费请求，其余 7 次等待同一持久回执；成功后进程重建仍命中缓存。失败或结果未知保留原记录，不自动补发、不解释成“没有资料”。原文读取完成后增加授权复核，防止 I/O 期间撤权后仍返回正文。

机器为 Windows 11、i9-13980HX（24 核/32 逻辑处理器）、约 16 GiB RAM，共享宿主上另有任务运行。使用独立工作树、随机端口、独立 Docker 网络/卷；未重启共享服务。原生容器上限 1.5 CPU、1,536 MiB、4 个运行槽；Java 最大堆 256 MiB。每次调度前检查可用内存，低于 512 MiB 停止新增请求，保留已发出请求结果。未继续提高到 16 并发以争抢宿主资源。

所有负载均为闭环（收到上一请求结果才发送下一条），没有模拟生产开放到达率。P95 使用 nearest-rank，失败、未发出请求和逐请求样本保留；不能把本机短批次的零失败外推为 SLA。测量代码为本分支源码；大语料、向量、题集、提供方回执和运行日志存放在仓库外。

交付源码提交 `ff261ebf`，基线 `bff7f854`；优化前后源码差异及摘要保留在 `http-context-change.json`。原生镜像固定为 `sha256:0832a1446f3c774ab0d4643ddae5b61e2eb5ffdec746311f8e15fab6edba6882`（LangGraph API 0.13.3 / LangGraph 1.2.11），没有取隔壁未结束的改动。最后补的 Java 投影正则精确匹配用定向测试复验，不影响上述合法请求负载；重打包 jar 成功。相关 Python 回归 336 项、Java 全组 31 项及最后定向 1 项、前端 22 项 Playwright、类型检查和生产构建通过；有重叠的检查不累计成新案例。
