# 项目研究接入：第一阶段 A

状态：2026-09-23 第一阶段 A 后端受理完成本地合成链路验收，项目工作区按用户确认的项目优先设计完成整合；原独立任务页被嵌入式研究准备页取代。可选 Java 服务及本轮界面尚未切换现有部署。对应 0.1.4 PRD P5/P8；跨语言边界沿用[接入合同](../architecture/java_research_service_contract.zh-CN.md)，部署与验证见[工程说明](../engineering/java_research_intake.zh-CN.md)。

## 项目工作区整合验收

项目是研究、资料、成果及后续协作的业务归属。工作空间在其上容纳多个项目。日常界面显示项目名称和说明，ID 只保留在路由和内部关联；同名项目可用说明区分。

- [x] 项目列表、搜索、名称排序、创建、修改说明、归档和恢复接现有持久索引。
- [x] 项目内导航统一概览、研究、资料、成果、项目管理；研究详情复用原生页面，并能返回原项目。
- [x] 资料库按全部项目或指定项目筛选，搜索、分页和阅读返回保留筛选条件。
- [x] Java 准备与启动嵌入同一项目工作区，保持原幂等、未知提交核对与版本绑定。
- [x] 无 Java 配置时仍可管理项目及资料；旧研究链接继续可读。
- [x] 通过持久化/双身份 API 回归、实际前端交互与桌面/移动布局检查。

本批资料库聚合现有项目资产并保留完整 AssetRef。现有文件必须归属一个项目；不把同名/同摘要文件合并为共享身份，不伪造未关联文件或跨项目共享功能。多项目引用同一受控资产、全局未归类收件箱、成员和审批属于后续合同与实施。

## 资料中心补充设计（待实现）

用户补充：全局资料入口应覆盖文件资料、知识库与数据库，并考虑团队共享空间、个人空间及团队数据库权限。上面的已完成验收仅覆盖项目资料聚合，不代表此完整目标已交付。当前页面虽然提供知识库/数据库跳转，尚未实现统一空间与授权模型。

项目继续作为研究、协作与审批的业务归属；资料可以长期存在于个人或团队空间，被有权使用它的项目引用。项目不是所有资料的唯一容器。组织是团队部署下的管理/隔离边界，空间是资料归属与默认共享范围，项目是工作归属；加入某项目不能自动获得整个团队数据库权限。

统一入口可继续叫“资料库”，其内部将文件类别称为“文件资料”以避免同名。页面分开呈现三个维度：

| 维度 | 选项与作用 |
| --- | --- |
| 空间 | 个人空间、具体团队共享空间；决定在哪个资料范围内工作 |
| 资源类型 | 全部、文件资料、知识库、数据库；知识库保留目录/原文/检索，数据库保留表格/指标/数据集查询，不强制使用同一种列表 |
| 项目关联 | 当前空间内全部可访问资源、某项目已关联资源；关联筛选不额外授权，也不把未关联资源视为不存在 |

空间内可先形成自己的资源目录。项目页“资料”展示该项目有权引用的文件、知识库范围和数据集，标明来源空间、权限及绑定版本。全局入口与项目入口读取相同授权投影，切换类型时保留有效空间/项目条件；无效组合明确提示，不回退到另一空间。

权限按具体操作表达：阅读、用于研究、修改、查询数据、导出、管理连接与分享。允许查询某个数据集不等于允许查看连接凭证、任意表或导出全部数据；上传个人资料不默认对团队可见；团队共享也不必等于全体成员可访问。关联个人资料至团队项目须有明确发布/授权行为，不能仅挂一个链接便将内容交给其他成员或团队 Agent。

用户已确认第一版为**组织内个人工作区**：资产归组织管理，默认本人可见。它与具体团队共享空间处于同一组织之下；不提供独立于组织、离开组织仍归个人的私人资产账户。团队空间可按研究组或业务小组划分，默认共享给授权成员，支持资源级例外。

组织所有权与日常阅读权限分开：同事不会因同属组织便能搜索个人区；管理员的接管、移交与读取应按管理角色显式授权并留操作记录，不能把“组织管理”隐含成人人可读。成员离开时由组织保留资产并按流程移交，个人账号失去权限；已有项目引用保留身份，按当前授权决定是否可读，不自动删除或复制到独立个人空间。具体管理角色与流程在实现前形成验收规则。

后续验收至少覆盖：同一成员对不同团队数据集的权限差异；个人资料不因加入项目而公开；项目成员没有源资料权限时不能通过 Agent/引用/导出绕过；撤销来源权限后阻止新读取与新运行；团队成果的可见范围与来源发布规则一致。先落地空间和资源权限的纵向路径，再扩展交接与各层审批。此节为设计修正，没有执行共享迁移或改变当前访问权限。

## 产品范围

- 项目选择器以真实 project_id 定位，显示名称；URL 保存项目上下文，不预置 AI 基础设施项目。
- 项目内保存研究问题、配置、所选项目资料及业务提交记录。先准备原生草稿，再由用户明确启动。
- 业务受理、研究执行分别展示。响应未知时只核对原提交；刷新和服务重启后可以重新定位业务记录及原生研究。
- 报告、来源、费用及 SSE 继续使用现有研究页面与权限。默认入口改为项目列表；保留旧研究链接，不自动迁移或共享历史私人研究。原有研究目录暂沿用最近 50 条窗口，Java 业务提交单独分页。
- 登录沿用现有身份体系，项目权限仍由 Python 当前项目规则管理。Java 不拥有第二份项目权限表。

成员协作、负责人交接、报告审核和发布属于 B 批，本批不提供这些按钮，也不把预览里的示例人物或数据写入产品。

## 验收

1. 两个同名项目在内部以不同 ID 切换，任务和资料不会串项目；界面不展示原始 ID。
2. 提交得到持久业务记录；重复提交不新建记录，同键不同内容拒绝。
3. 准备草稿不启动模型；明确启动采用原生运行能力。
4. 响应丢失显示待核对，不鼓励新建任务绕过未知提交；核对操作不派发模型。
5. 当前身份及项目权限每次重新核验；越权 ID 与旧链接不能绕过。
6. 成功关联后可打开原研究、续读原运行事件及查看结果，业务入口不复制报告或费用账本。

工程故障注入与真实金融研究质量分开。本批测试不要求付费模型请求。
