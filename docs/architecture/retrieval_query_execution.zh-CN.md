# 检索与数据库查询执行优化

2026-09-23，首轮执行优化已部署，完整研究质量验收仍在待办中。遵循[已批准方案](retrieval_optimization_review.zh-CN.md)及[Java 服务边界](java_research_service_contract.zh-CN.md)。本文区分已实现的执行优化与尚待完成的研究质量验收。

## 已实现的首批改动

- 不可变库校验按规范路径、文件身份及预期 SHA 复用。文件改变触发重新校验；并发冷启动串行校验，避免重复扫描。每个实例仍保留自己的请求环境。缓存不是访问授权。
- FTS5 使用既有 BM25 权重，在来源资格限制内选择候选 ID，再批量读取正文。没有先截全局 Top K 再过滤来源。图候选保留同分 ID 排序。
- 图证据和覆盖状态按批查询，保留每边八条子块窗口、父片段、绑定状态和动态关系回读边界。单请求深度一图结果复用；深度二保留原独立展开语义。
- 稠密与图候选先以 ID 合并，按原配额和顺序批量读文。记录各通路候选名次和重排分数；这些是检索解释，不是事实置信度。
- 指标卡直接按记录 ID、主体及可知日查询；不再预读全公司历史。财年锚点按实际期间去重。计算指标卡也应用现有口径核查说明，修复列表有说明而卡片遗漏的情况。
- 图按层批量读取邻接关系和已解析持仓，复用一次来源资格检查。可选 `graph_predicates`、`graph_direction`、`graph_review` 在边数限制前生效；方向相对于每一跳的当前主体。默认保留原查询结果与排序，未显式传入的新字段不进入旧请求序列化。达到边数限制明确返回 `graph_window_truncated`，分页总数仅代表该查询窗口。
- 向量加载缓存检查 manifest、矩阵和映射三者的文件身份；文件替换触发完整复核。精确余弦候选以有界 Top K 选择代替全排序，保持同分 chunk ID 顺序。模型、维度、向量内容不变。

未改 chunk、来源身份、已有向量及公式数值；没有付费调用或全库重建。公开资料查询仍不等于 Java 跨服务授权/快照合同已经实现。

## 当前验证及限制

工程回归覆盖时间/文档资格、模型身份、图绑定、批量展开、卡片与旧请求兼容。真实库六家公司图结果与原实现一致；核心二十家历史查询结果一致。二十张卡片逐字段对照中，十张仅新增 `review_ids` 字段，其余十张完全一致；数值、单位、期间、操作数和来源均无差异。

同一 r21 库、单并发、Docker Windows 绑定挂载中的四个开发查询：原全文 SQL 22.6–61.4 秒，修改后 1.1–1.7 秒，Top 40 顺序一致。一次完整初始化约 67.8 秒，同进程再次构造约 0.068 秒。这是一次顺序对照，包含缓存/预热影响；不是整体混合检索 P95，也不是模型答案正确率。

可复用无模型性能回放：

```bash
python -m scripts.data_retrieval.benchmark_library_queries --library <immutable.sqlite> --cases <local-cases.json> --output <local-results.json> --repeats 3
```

cases 包含 `library_sha256` 和具有唯一 `id` 的 `cases`；各项包括 `operation`（search/graph/metric/read）、相应函数 `arguments` 及可选 `expected_sha256`。回放校验固定库身份，保存每次耗时、结果摘要及分通路分位数；不调用 embedding、重排或回答模型。错误直接失败，不能转换成合法空值。生成的题集和运行结果留在本地，不能将由原实现生成的结果摘要称为独立人工参考答案。

完整四十题答案/依据评审、独立留出题、更多查询筛选下推、图类型路由的质量比较及模型消费验收仍按方案继续。原文审计已完成下述有界开发样本，正式工具与前端回读已完成本轮同版检查。本轮执行回归只证明保持现有输出，不能证明现有资料没有漏边或所有财务事实正确。

## 存储、混合检索和小范围原文审计

相同发布 SHA 的 Docker 原生卷对照已完成。固定 40 个执行用例，每项回放三次，120 次结果摘要与旧代码基线一致。最后一轮单并发本地观测：指标查询 54 次 P95 0.16 秒；全文查询 36 次 P95 0.42 秒；图查询 27 次 P95 0.37 秒。另三次为未知文档错误边界，不纳入有效原文读取性能。Windows 绑定挂载对照分别约为 5.30、2.94、6.67 秒。两轮环境、缓存和后台负载不同，不能把所有差异都归因于存储，也不构成并发 SLA。

四组已有模型缓存的混合检索及十二次原文回读通过；隔离原生卷诊断首次混合查询约 20.2 秒，其中索引校验/加载约 13.4 秒，随后三组约 0.89–1.02 秒。没有新查询 embedding、重排或回答模型调用。该四题只用于执行诊断，不能当作独立的 Recall@K 或回答正确率评测。

原生卷采用[显式复制、同版校验与回退流程](../engineering/immutable_library_volume.zh-CN.md)，不是仅修改路径字符串。正式服务上线状态以本地部署回执为准。

正式部署后的回读：74 项相关回归测试通过，活动基线及密钥扫描通过。前端 HTTP 与核心二十家历史指标/数据卡、六家公司图关系及一份原文的 47 次逐字段对照通过。正式研究工具 4 次混合检索及 12 次原文读取通过；首次检索含冷加载约 12.31 秒，随后约 1.02、1.55、0.34 秒，原文读取约 0.003–0.029 秒。embedding、重排仅允许命中完全相同请求的成功缓存，缓存未命中即停止；没有调用回答模型或新增付费请求。该诊断测到正式工具读取器路径，不能当作完整模型回答延迟或总体回答准确率。

容器使用只读原生资料卷，前端 BFF 使用同 SHA 主机文件，二者均保持 r21 和已有 Qwen3.7/1024 索引。仅重建 API，既有 PostgreSQL/Redis 容器不变。网页已实际打开并核对关系、指标页面及数据卡；本轮未改前端布局。完整四十题（含独立留出题）质量评审、通路消融和 DS 有限模型消费仍未完成，因此不标记整个 1–5 计划全部验收通过。
