# 014：E2 项目 SEC 版本进入任务财务工具

2026-09-14，FIN 0.1.4 / E2，基于 `893037a7`。用户继续授权当前实施；本包仅用013已保存SEC原件、012已保存微软公告与合成数据，新增供应商/SEC请求0、模型调用0、费用0。包版本仍0.1.3，不部署、不签整版验收。

## 产品与工程增量

项目SEC版本现在可以通过“用此数据版本准备研究”保存为研究草稿。BFF先验证当前owner/project及两份原件摘要，然后在任务自己的存储下复制原件、元数据和派生SQLite财务库，保存原项目、版本、ticker/CIK、采集时间、映射ID和摘要。原生任务元数据的准备状态继续阻止失败草稿启动；不是跨服务事务，失败原件/草稿保留、不自动重试。

新任务的专家数据组合读取这个已绑定财务库；负责人入口也收到绑定范围说明，沿用 `query_company_financial_facts`，不另造财务工具。任务查询API使用同一读取器，页面显示绑定公司与映射观测数。跨Agent通过原 `CaseArtifacts` 回读数值、公式、单位、期间和源观测；项目出处由任务绑定清单连接到原件与财务库摘要，不声称每一个NumericFact都新增了项目字段。源项目后续变化不重写已准备任务副本；任务副本损坏时明确拒绝，不改读历史默认库。

成熟栈决定为ADOPT：复用既有SEC抓取/元数据、`financial_facts.sec_companyfacts`、SQLite、`ExistingS2FinancialFactReader`、MCP和FastAPI/React。新增代码仅为任务选择与FIN金融映射；没有新依赖、解析平台、运行队列或通用版本引擎。

## 金融范围与时点修复

固定映射 `sec_us_gaap_income_usd_v1` 只接受USD的两个US-GAAP标签：收入 `RevenueFromContractWithCustomerExcludingAssessedTax`、营业利润 `OperatingIncomeLoss`；营业利润率复用既有派生公式。只接纳可由所保存Submissions关联申报身份的10-K/10-Q，保留全部可接纳vintage，由查询时点和既有期间/单位/冲突规则选择。没有猜测别名、货币换算、扩充季度差分或接纳10-K/A与10-Q/A。

发现旧财务读取仅按accepted_at日期筛选，研究发生于披露日较早时间时，可能提前读到同日较晚发布的修订。已在现有SQL查询和派生计算的申报cohort选择中加入带时区 `accepted_at_cutoff`；实际研究读取器取“查询日期UTC日末”和“研究run_scope时点”的较早值，并将截止时点计入请求身份。直接使用旧FactLookup且未传此字段的日期API保持原语义。本包资格覆盖SEC秒级时间，不宣称微秒PIT或完整历史可得性。

合成回归：同日18:00UTC收入100/营业利润20、20:00UTC修订为120/30；研究时点19:00UTC只能读100/20并计算20%，到16:00-04:00（20:00UTC）才可读120/30与25%。未来日期拒绝；缺失申报身份、未映射指标、错误期间分别留在捕获/映射/查询责任层，不称为公司未披露。
