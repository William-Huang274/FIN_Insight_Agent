# 模型、企业软件、广告与交易平台
版本：2。按用户任务与收费模式选章节。下面的数值例子均为教学假设；当前产品、价格和采用情况须另查有日期及版本的材料。

## 产品任务与持续采用
先确定一项用户实际要交付的工作、验收者和付款方。例如，生成代码、合并可维护的改动、修复生产故障是不同成果；生成视频与交付可商用的广告素材也不同。比较产品时固定任务难度、可用数据、工具权限和验收要求，再观察完成率、人工接管、返工、耗时及成本。官方演示提供能力线索，基准测试提供特定条件的比较，客户实际部署说明组织约束；三者各自回答不同问题。

把功能上线、试用、启用席位、持续使用、付费续约分开。供应商披露新增客户，能说明获取能力；是否扩大使用还要看同一群客户的活跃、付费或续约口径。席位捆绑进原订阅时，授权席位增加不必然增加收入，也不证明使用频率上升。比较对象应有可能改变解释：相近任务却不同权限边界、部署方式或收费安排，比仅列几个热门品牌更有区分力。

虚构例子：一家公司给一千名员工开通工具，三百人每周使用。访谈发现常用者主要做资料初筛，但最终交付仍需同样长的核验。此时可判断初筛环节有采用，不能由开通数断言全流程生产率提高。下一项有价值的调查是同类任务的总耗时和交付质量；若核验成本下降且持续续约，才进一步支持付费价值。若只是一次培训后的活跃峰值，则应改变采用判断。

## 用户声音与产品证据
对评论、公开工单、论坛、客户案例、调查和实测，记录它观察的是哪个产品版本、套餐、任务、用户角色及时间。优先读具体经历：输入是什么、哪一步失败、是否成功重试、改用什么产品。投诉可揭示故障机制，但没有使用人数和采样方法就不能估计故障率；赞助案例可以证明一种用途存在，不能代表普通客户收益。转载同一个客户故事只算一条证据链。

解释冲突时先比较条件。例如资深开发者认为 agent 返工多，新手认为节省时间，差异可能来自任务熟悉度和验收能力；创作者认可草图效率却不用生成结果交付，差异可能是可控性、品牌一致性或授权要求。用产品文档、版本变更、不同角色的实测和研究设计检验这些解释，而非给正负评论投票。量化调查的抽样与分母细节可按需读 public_observations 和 survey_analysis。

公开材料能够支持的调查与亲自试用应分清。若没有获准的账号、上传数据或测试环境，报告可以评价公开试验的范围，不能写成自己测试过。访问失败需要找同版本替代原件；无法取得留存或私有客户数据则保留具体未知，不从评论补出总体数字。

## 从完成任务到服务经济性
按用户验收的成果核成本，而非只看一次调用价格。设一个虚构产品每次尝试成本 0.20 元，十次尝试完成四个被接受的成果，另有 1.20 元核验成本：本组每个成果成本为 (10×0.20+1.20)/4=0.80 元。若每个成果收 1 元，这只给出已计成本后的 0.20 元差额；尚未包含的支持、渠道、闲置、研发等不能因此当作零。若失败重试增加，单位经济性可以在 token 单价下降时变差。

订阅制要看用户任务频率、套餐限额、重度使用者分布与超额收费；按调用或成果收费要看计费定义、失败是否收费、折扣、缓存及分成。API 比价需固定工作负载、质量、输入输出、延迟和缓存条件。公开 token 价格不是含训练与研发的全成本。客户节省的人工时间也不等于厂商收入：还需采购意愿、预算归属、竞争价格和续约证据。

## 收入质量与竞争价值归属
企业软件沿付费客户、席位或用量、净价格、续约扩张连接收入；RPO 还受合同期限及签约时点影响。增长中区分产品组合、并购、汇率、捆绑和补贴。ARR 是运行率口径时不能直接当年度已确认收入，融资估值也不是经营利润。集团盈利、云分部盈利与某个 agent 产品的回报必须分别取证。

竞争比较围绕可替代的工作流程：基础模型升级解决多少任务，应用仍提供哪些集成、权限、数据、验收或分发能力；用户迁移需付出什么，谁拥有客户关系和收费权。一个组件被平台免费提供，可能降低独立产品价格，也可能降低其成本并扩大需求。比较两种路径的客户选择和经营证据，不能由“平台会整合”直接判定独立应用没有价值，也不能由产品功能多推导护城河。

投资含义须另接预期与价格。产品采用改善先影响哪些收入或成本、何时兑现、谁实际获得收益，再比较公开预期及估值所要求的增长。私有公司的收入和成本披露不足时，可形成商业模式判断与条件情景，但不能声称证明整体盈利或给出有依据的上市可比定价。广告业务另拆用户、时长、展示、价格、负载率和分成；交易平台另拆 GMV、订单、客单价、变现率、自营/平台、履约补贴与回款，保持总额净额口径。

## 综合判断与专业产品机会
合并子调查时按同一关系比较任务、用户、产品版本、期间和证据类型。保留与主解释冲突的结果，说明哪个发现改变了采用、变现或竞争判断，而非把子报告逐段拼接。对主结论有影响但尚未查清的关系可委派独立调查；交接问题、已有依据与不同解释，返回可回读证据及其适用范围，不要求对方替主作者写结论。

把市场判断与自身产品选择分开：通用工具已经解决什么任务、专业流程有哪些实际损失或交接成本、谁愿付费解决。专业知识、审计能力或权限集成本身不是付费需求的证明。下一步用户验证应让目标用户完成具体工作，观察交付质量、接管时间、重复使用及真实采购约束。研究在能够回答当前决策、关键分歧已有区分性证据或具体公开边界时收束；新材料若改变前提，标题、摘要、正文和行动条件都需一起更新。
