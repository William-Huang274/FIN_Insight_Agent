# 006：E1共享研究预算与模型派发保护

2026-09-13。FIN 0.1.4 / E1，延续`9d212e4a`。用户“继续”授权实现005发现的模型重放/共享预算缺口。本包使用模拟模型，未调用DS/Qwen，不变更0.1.3默认运行配置，不发布版本。

## 实现与采用决定

沿用锁定Agent Server 0.13.3 / LangGraph 1.2.11执行与checkpoint，采用现有PG16 / psycopg3.3.4事务。PG的`SELECT FOR UPDATE`在同一研究预算行上串行完成预留和结算；网络调用在事务外，设定连接/锁/语句超时。参考[PG16行锁机制](https://www.postgresql.org/docs/16/explicit-locking.html)，没有另造锁服务、工作流引擎或调度器。

FIN只新增两张业务表及薄适配：`ModelDispatchStore`保存owner/根预算、交付预留、调用占用、已知计价和消息；`ModelDispatchGuard`在原有`CaseModelAudit`显式启用。SQL安装是隔离setup显式动作，不在派发时自动迁移，不自动修改原生内部表。父任务和所有子任务必须使用同一个可信根预算标识；不能由子Agent自建额度。

调用身份由原生thread、checkpoint namespace、原生task ID与actor组成，绑定请求载荷、模型端点、TokenBudgetBasis、价格版本及预留依据的指纹。首次调用在网络前持久保存派发身份和占用；同一步载荷变化阻止重发；结果未知保持占用且阻止重发；完整已保存消息保留工具调用、reasoning和usage供回放，使用原call ID且不重复结算。要求SDK自动重试为0；价格必须与实际请求模型一致，未资格的typed structured response和其他provider transport拒绝启用。

金额为整数币种micro，价格为每百万token的micro，向上取整；不同币种不可混算。`actual_micros`目前表示按已报告usage和固定价格计算的金额，不是供应商账单核验金额。缺失/无效usage或缓存细分时费用仍未知，不填零；实际计算金额即使超过预留/预算也记录并阻止新调用，不丢弃已发生的费用。因此预留是派发约束，不保证供应商最终账单绝不超限。

## 剩余边界与下一包

- 当前为真实中间件的可选接入，主研究、专家、摘要入口尚未统一注入可信owner/根预算；没有默认推广。PG owner参数不是认证系统，数据库账号/RLS、消息保留与删除、公开费用投影仍待产品接入资格。
- guard包在现有审计调用外：截断或审计后处理失败会保守保留占用，原始输出可能已在私有审计中但尚未进入可回放记录。该路径不重发、不释放预算；已知失败输出的自动结算/对账仍待拆清调用与接受边界。
- 未知不会超时自动释放；没有重试/自动对账/人工解锁服务。可用性因此保守，不声明已实现完整恢复体验。
- 尚未验证真实SDK流及供应商usage、真实价格/完整上下文的预留预测、跨研究月额度/公平性/供应商并发、所有产品入口、跨主机和正式账号许可。已知费用可能超过预留，不能把当前API称为严格账单上限。
- 下一包只做一次真实研究图的合成端到端接入：在可信host绑定根预算，覆盖主模型/专家/摘要、交付身份与上述失败结算，用MockTransport证明同一预算及原生子图身份无冲突，再决定是否进入小额真实供应商样本。不新增通用控制层。

产品增量：尚无用户界面或默认功能新增。工程增量：PG预算/派发适配、可选中间件及可重复测试。资格增量：真实PG和原生重启的合成证据。文档增量：本记录、技术/执行当前状态与Project OS回填。E1保持进行中，金融自主性和0.1.4全版本交付未因此通过。
