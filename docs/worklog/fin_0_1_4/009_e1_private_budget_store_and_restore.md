# 009：E1 私有预算存储权限与原生恢复

2026-09-14，FIN 0.1.4 / E1，基于 `657b3a4a`，继续用户已授权的实现。模型调用与模型费用均为0；只在每attempt新建的隔离PG中使用合成响应，不修改旧研究数据库、历史失败记录、包版本或默认部署。

## 根因与采用决定

008证明一次真实响应可保存、结算并回放，但之前PG测试使用建表账号，不能证明运行凭据有足够小的权限。现有宿主绑定还隐式使用Agent Server的`POSTGRES_URI`，把原生服务的管理权限带进预算入口。采用PG原生角色、列权限、业务不可变约束和只读视图，复用`pg_dump`/`pg_restore`；不引入IAM平台、备份服务、运行状态机或删除调度器。

宿主启用预算保护时改为显式`FIN_MODEL_BUDGET_POSTGRES_URI`，检查实际登录身份及危险权限，不回落原生管理连接。不存在budget binding时保留原行为。`ModelDispatchStore.connection`固定可信schema查找顺序；旧003建表语句也明确`public`，避免查找路径改变时建错schema。004是专用业务数据库的显式一次性bootstrap，不由研究图或模型调用自动执行。

三个NOLOGIN组区分预算授权、可信worker、费用读取。worker可以持有预算行锁并完成真实存储API，但不能新建/增大预算、删除账本或篡改已知/未知回执。`SELECT FOR UPDATE`需要列UPDATE权限，因此只授予owner_id列的锁定所需权限，并用PG触发器拒绝实际预算更新；另一个触发器禁止终态响应、费用或未知状态被改写。这些约束保护既有FIN账本，不负责队列、重试或任务推进。

费用视图只返回owner/root/currency/额度/已知/占用/未结算数量，不返回模型正文、预算依据、指纹或调用ID。映射由数据库owner维护，以数据库`session_user`识别读者；伪造应用owner变量或SET ROLE不能改变其身份。可信worker本身可以读取该库内各研究响应，仍依赖既有宿主owner绑定与应用认证；这不是所有worker按用户隔离，也不是已上线的公共费用API。

保留策略保持正文和调用/费用账本共同留存，不授予DELETE/TRUNCATE、不自动清理。正文到期删除及备份副本期限没有产品决定，本轮不凭空设定天数或实现删除；只证明权限限制与保留后的可恢复性。正式启用前仍需加密、备份访问、跨机角色重建及恢复后的付费对账。

争抢测试在受限角色下两个并行子请求争夺1000 micro根预算（交付预留200，每请求600），仅一个成功，结算已知200。权限测试实际执行并拒绝扩额、新建根预算、删账、建表、修改角色成员关系、读取原始表和终态改写；临时同名表不能遮蔽可信预算表。两个读者可通过视图看到自己的已知200/占用600，不能切换到worker或伪造登录身份。

恢复测试先保存一条已知费用响应、一条未知调用、一条已有响应但usage缺失的调用，再在无新增请求期间用原生工具导出到本attempt，恢复到同集群新数据库。恢复前后均为known200 / held1200 / unsettled2 / available8600；已知和缺usage响应仍可回放，未知仍拒绝重发，读取ACL及禁止删账仍有效。备份13456 bytes，SHA256 `1320620156343c36a36b97abcf0f67c56616420af75e206e7f1ac60f8ba80c1e`，保存在a3的`fin_budget.dump`，不纳入Git。

这是静止快照与同集群既有角色的资格。备份不包含快照后的调用，不能据此声称活跃付费系统可直接恢复、PITR/RPO已证明或外部费用绝对去重。实际灾备必须先停发，核对快照之后的不可变调用证据，再决定能否恢复执行。未运行`--clean`，未覆盖旧库；本轮容器停止，卷/网络与失败证据保留。
