# 060 DELL 动态五单元 R3：分析收敛，严格交卷表面失败

日期：2026-08-17

## 这轮真实做到了什么

R3 没有重跑自然 Planner、S1/S2、需求质量或经营表现。它只处理 R2 未完成的价值获取、现金转换和反方证据三个单元。三次复杂分析都在新的紧凑视图下自然结束，说明 R2 的“推理吃满预算、没有草稿”已经被结构性修复。

三个非思考严格 Tool Call 也都正常返回。现金转换通过本地合同；价值获取和反方证据分别在 `mechanism_atom` 与 `thesis_atom` 被拒，因此综合按 5/5 前置规则没有执行。共 6 次新调用，0 retry、0 fallback、0 外源网络、0 新 Evidence、0 candidate promotion。

## 大白话解释失败

价值获取把“10-Q”写进了机制句；反方证据把“FY27 Q1”和“8-K”写进了主判断。项目合同要求模型在判断文字里不直接写数字、日期、文件编号或引用，而是选择 Evidence／NumericFact 等结构化引用，由 Harness 最终渲染权威表面。

这条规则在模型可见消息和 Tool 字段说明里都写清楚了，因此不是规则遗漏，也不是本地校验器误杀。问题在于当前 strict Tool Schema 只用自然语言描述该限制，没有把同一限制写成 JSON Schema 的字符串 `pattern`。DeepSeek 因而满足了 JSON 结构，却仍复制了分析草稿中的文件期次标签；本地金融合同随后正确拒绝。

## 业务内容初看

- 现金转换：公司层现金桥、资本开支、应付时点和流动缓冲被区分开，且没有把公司现金改善归因给 AI 服务器，当前未见新金融 L1。
- 价值获取：原始机制文字仍把 AI 服务器组合与毛利率下降联系得偏强。即使下一次表面合同通过，也必须继续检查产品到公司利润桥缺失，不能把“去掉 10-Q”当成内容质量通过。
- 反方证据：能够把库存上升识别为风险约束而非需求已经恶化，并承认公司全栈纪录缺少 AI 单一桥梁；但它尚不是有效 Judgment，不能提前晋升为报告内容。

## 下一步

1. R1、R2、R3 与所有 captures 保持不可变，不手工清洗或追认两个被拒 Tool payload。
2. 从同一个 provider-neutral 语义合同生成服务端字符串 `pattern` 和本地 Validator；文件编号只允许留在结构化来源元数据或合格的 Evidence Route，不允许进入 Judgment atom。
3. 用 R3 保存请求和输出做零调用回放，覆盖数字、日期、货币、URL、内部 ref、口头数值带以及合法中文／英文判断。
4. 同一 runner 增加 cell 内部节点恢复：复用 R3 已成功的价值与反方分析草稿，只重新交卷两个失败 Judgment；其后才做综合分析与综合交卷，最多 4 次新调用。
5. 若仍失败，不再增加一条提示词或逐字段补丁，而是决定 DeepSeek 是否继续拥有严格 prose submission 权限。

## 边界

R3 证明紧凑分析视图有效，并把有效 Judgment 从两个增加到三个；它没有证明完整五单元、综合、完整报告 L1、八维内容质量、异质泛化、qualified-human、S3 acceptance、Workbench 发布或 release。
