# 016：E2 项目资产撤销与后续使用限制

2026-09-14，FIN 0.1.4 / E2，基于 `2543474a`，继续用户授权的产品实现。模型调用、SEC新增抓取、其他外部数据请求与费用均为0；未部署，包版本仍0.1.3。

## 产品与工程增量

项目文档、已保存报告和SEC数据版本可在项目页撤销/恢复使用。撤销保留原件与状态记录，隐藏正文摘要并禁止新下载、选择和读取；恢复不自动启动研究。任务页显示资料使用受限，已有草稿不能启动。新模型追问、修订和继续研究在BFF与模型入口检查任务所选资产；人工历史审阅和已有报告回溯继续保留。

独立任务副本不能绕过撤销。采用已有SQLite事务记录访问状态，任务使用宿主写入的原项目库位置和原始资产身份逐次检查；位置与权限字段不由浏览器或资料正文指定，库位置不进入公开来源元数据。旧文档副本可通过标准项目目录、原始文档ID和摘要核对；权限库缺失/不可读拒绝访问，不创建空库放行，也不解释为公司未披露。

新保存的报告记录原任务明确选入的项目资料/SEC依赖，后续项目报告与任务副本保留该链。原始依据撤销后，新报告复用也受限；无法通过“保存报告再读取”绕过。原生报告checkpoint仍是历史权威；报告依赖不是新运行时控制面。

成熟栈采用决定：继续使用SQLite事务、现有owner认证和MCP/LangChain入口。检查本地安装MCP SDK的 `MCPServer.middleware` / `ServerMiddleware` 后使用其标准请求钩子，拒绝受限任务的 `tools/call`，包括已有连接的SQL查询、来源计算缓存及跨底稿读取工具；未创建IAM、分布式锁或新调度器。同步负责人/专家的 `DeepSeekStructuredAgentAdapter` 与原生角色/摘要的 `CaseModelAudit` 在派发前检查，未发出的请求记 `provider_call_attempted=false`，不预留预算、不冒充未知费用。

## 接受边界与下一包

本包接受本地项目资产的新访问限制。检查发生在读取/派发边界；已经发给供应商或交付浏览器的内容无法追溯收回，正在进行的调用可能完成。历史原生报告用于审计保留；这不是删除、内容召回或分布式租约。

旧项目报告没有所选资料依赖清单，不凭正文猜测补全；可直接撤销那份报告。新记录只覆盖明确选入的项目资产，不宣称通用工作笔记、任意跨任务引用或全部外部知识来源的依赖追溯。原项目库移动/跨机恢复、旧成果依赖补齐、全角色/供应商部署、自动同步和更广资产类型仍开放。恢复依赖后由用户显式续跑；未知供应商结果仍不重发。

产品增量是撤销/恢复和既有任务读限制；工程增量是宿主绑定、SQLite状态与标准中间件；研究证据只证明工程使用边界，013分部表未检查与产品/分部概念混淆的语义负例没有关闭。文档与Project OS同步本状态，不将其写为整版完成。
