## 产品闭环与复用决定

现有报告已支持人工修改、LangGraph历史checkpoint、版本差异和导出，本包不新造编辑器或报告版本权威。新增“保存这版报告到项目”：用户选择目标项目，BFF读取服务端指定历史checkpoint或当前已完成审阅阶段的报告，核对页面报告摘要，复用Markdown导出与TaskAttachmentStore解析，在同一SQLite事务保存正文、查找文本及出处。项目页可查找、阅读、下载、打开原研究与修改记录，以及选择明确版本用于新研究。人工修改仍通过原生人工审阅路径，原版不覆盖；修改后须显式再保存，不承诺自动同步。

保存的产物标为 `project_research_artifact`，记录原任务、checkpoint、报告版本、报告摘要、当时phase、人工修改次数和修改理由。用户确认、模型草稿与原始披露不是同一种权威；后续任务副本、专家MCP观察和跨Agent来源回读保留这个标记与出处，`numeric_fact_authority=false`。导出正文保留既有引用/图表投影和来源链接，但不是完整原始checkpoint、底稿包或SQL数据库的复制。

ADOPT既有LangGraph/checkpoint、SQLite事务、报告导出、文档解析和来源导航。FIN只补项目保存适配、版本/状态身份、权限检查和UI；没有新增队列、索引服务、通用同步引擎或外部依赖。关键词查找直接使用已保存解析文本，因此提交成功即该文本可查；不是向量检索或后台语义索引同步。

## 一致性与边界

- 当前owner必须同时有目标项目与原研究访问权；浏览器只传选择标识和预期报告摘要，不能提供报告正文、确认状态、owner或来源权威字段。
- 未完成的中间Writer输出拒绝保存；页面摘要过期返回409，不悄悄保存另一版。指定历史版本继续受原研究权限检查。
- 同一项目下，同源报告版本、内容摘要、确认状态与人工修改次数相同的保存返回已有文档；并发写沿用SQLite事务。确认状态改变但正文不变时需保留新的状态快照，不能误复用原“待审阅”标记。checkpoint仍归原生报告历史所有。
- 每份保存快照占既有项目资料额度（最多12份、总80MiB）；没有自动删除旧版。解析失败不留下部分文档或成功状态。
- 项目资料和新任务输入为独立副本，原研究后续修订不会重写旧报告快照或已创建任务。撤销传播、自动刷新、更多资产类型/单独编辑假设指标、完整语义索引及配额扩展仍开放。
