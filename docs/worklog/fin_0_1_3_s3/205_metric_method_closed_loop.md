# 通用指标与六角色方法闭环（2026-09-10）

Owner 授权：扩展第一批通用指标，Agent 优先查询，报告/图表复用计算结果，跨公司/财年/盈亏变化验证；同时细化六类研究方法，检查结论与公开分析理由是否改善。仍属 FIN 0.1.3 / S3 / 205，沿用当前开发分支；旧失败和正式报告不覆盖。

## 有界实施

1. 扩展现有 SQLite + Decimal 财务执行器的同期间比率、同比/环比变化、百分点变化。定义属于 FIN 财务领域；不新造查询/工作流引擎。旧快照只读，查询时派生并保留输入血缘。
2. 将可用指标投影到现有研究 MCP 和普通问答目录；报告与图表继续消费 NumericFact，不再转抄数值。
3. 六方法维持按角色读取，补操作步骤、必要核查、纠错与退出、公开理由及边界；不提供任何真实测试公司答案，不强制每题激活六角色。
4. 先本地验证公式/期间/单位/负数、真实工具查询和引用/图表复用；再进行有上限的真实模型对照。旧错误是开发回归，不声称盲测。输出比较看数值、经济含义、期间表达、引文、完整提交，不以 JSON 合法或推理长作为质量通过。

成熟方案：继续采用 SQLite、现有财务执行器、Pydantic/MCP、LangChain runtime 与既有报告图表渲染。指标集中定义遵循语义层模式（https://www.getdbt.com/product/semantic-layer），当前规模无迁移理由。财年保留实际起止而非自然年假设（https://www.sec.gov/search-filings/edgar-application-programming-interfaces）。

付费前记录逐节点 TokenBudgetBasis、固定案例输入与模型参数；先运行已有 preflight。优先小题完成回答和可读报告的闭环，无整篇 HPE 盲目重跑。截断/未知用量原样保留，不自动加预算重试。原始 provider 推理保存在私有证据，交付公开分析理由和可核查步骤，不伪装为原始内部推理。

## 发现后修复与有界恢复

1. 真数据查询发现“历史期间选择”与“最新披露批次”混用：有历史值却返回缺口。已改为先解析实际历史期间，再用研究截止日可见版本取值。新增三年+历史重述合成回归，实际MCP旧收入和新指标都返回成功。
2. MSFT的工具上限不是无限循环：旧组逐项算FCF/增速，新组逐项查询更多标准指标。普通问答新增批量入口，补资本开支通用变化指标。finance/writer补“先列必需指标并批量查询”“没查询不能宣称缺数据”“因果/排序须有区分证据或参照”。这些是通用方法与薄接口，不含四家公司的答案。
3. `batch-fix-a2/msft-cash`：同6模型/16工具上限，真实模型使用批量查询，7次工具成功+1次图表单位拒绝，6模型/173,623tokens后无最终答复。工具次数减少但模型多轮补查仍耗尽额度；没有宣称修后新跑通过。
4. `batch-recovery-a3/msft-cash`：只读SQLite backup复制a2原生checkpoint到独立尝试，最多2模型/2工具；不注入正确答案或人工改图表参数。模型根据原失败反馈把USD(billion)修为USD+scale_divisor，1工具成功、2模型/108,069tokens，完成答案/1图/MD/PDF/Word；没有新增取数。属于失败后恢复，不是从头一次完成，也不是纯方法A/B。
5. MSFT恢复稿核心数值、FCF下降与资本开支增量桥正确，但基于CFO/净利润的比率被表述为“经营利润的现金兑现”，且用“现金转化”简称、图注混合增长率与金额桥、残留`[chart]`占位。仍不授予整篇金融通过，不人工替模型改正文后冒称自动通过。

本轮合计10条执行尝试（8原始+1修复新跑+1恢复），49真实模型调用、1,161,729已知tokens、新未知0；均无外网补研、数据库原件未变。缓存命中、输入/输出、各次模型耗时见私有`measured-comparison.json`；恢复中的历史工具数与原尝试不重复计为新调用。费用未取得新别名的账单核对，本记录不把tokens或旧型号场景单价冒充实际费用。与此前205摘要相加为559尝试、17,233,622已知tokens，历史未知仍2；仅是延续既有口径，不代表559个独立问题。
