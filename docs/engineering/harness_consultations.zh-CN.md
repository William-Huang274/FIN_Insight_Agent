# 原生 harness 按需独立调查与复核

研究范围观察、调查事项、作者版本化处置与交付反馈见[研究事项交接](research_action_handoff.zh-CN.md)。原意见、来源、预算与恢复身份保持；新事项不构成自动金融审批。

宿主在已授权执行绑定启用 `allow_agent_consultation` 后，主模型实际工具列表增加 `consult_research_agent` 和 `read_research_agent_result`。未配置时不披露能力，不以指引授权工具。现有 `answer_review_model` 支持 Sol high 独立调查与复核；也可配置 `research_delegate` 使用原生 ACP 的 Flash high 调查及草稿委派。工具描述披露实际模型，不把模型选择交给任意工具参数。

`research_delegate` 由部署端提供 model、protocol、provider、provider_endpoint、provider_key_env、reasoning、context_window、output_tokens、summary_tokens、compaction_threshold、token_budget_basis、reservation_micros、reservation_basis。当前限定已验收协议的 deepseek-flash/high；与主任务共用授权、费用账本和工具，只读来源与计算，不允许子任务递归委派或覆盖主稿。每个子任务使用独立原生会话，沿现有 ACP 历史、压缩与停止机制执行；不再实现另一套模型循环。`purpose=draft` 返回草稿和依据供主作者审核，保存完成不代表研究通过，只有主作者能决定补证及最终发布。未配置原生委派时，draft 返回明确未执行反馈。

`default_model_profile={model,reasoning}` 可为产品的 default 选择绑定主模型，例如 Sol high。从空历史由 Sol 调查、委派 Flash、审核后自行成稿，无需伪造旧会话接管。该主机绑定不能覆盖用户显式选择的模型；没有此配置的旧任务及已授权 native_model_transition 保持兼容。角色分工属于本次任务要求，不新增全局固定研究流程。

父会话故障关闭工具服务时，原生子会话的取消可能被 MCP/AnyIO 包装为 ExceptionGroup。显式恢复必须核对该子任务独立计费 lane：只有全部请求已结算且无 stop_required，才能复用其原生历史与成功读取；分组异常本身不构成恢复许可。子任务存在未知用量仍拒绝，父任务的未知请求仍受原有独立授权约束。恢复回执随同一委派交给子模型，不重写原错误或自动补发。

主作者提出具体问题、上下文、investigate/review 用途、可选方法 ID；可选择直接绑定当前保存稿，亦可在成稿前交接当前推断。任务返回编号，后续读取状态与结果，避免在原生 MCP 的 60 秒工具期限内等待整次研究。没有固定复核链、角色数量和必经次数。作者负责判断意见并统稿。

investigate入口将主作者的目标关系、已有依据与未决解释交给调查者；原作者提出的算式或比较不是约束研究结论的命令。调查者可在原目标内改变比较和取证方向，返回实际改变的判断、保留的判断及依据，不只列后续建议。schema不新增必填计划字段，来源和权限不扩大。旧的已派发咨询恢复必须保持原指令指纹；升级方法应从新的干净分支执行，不能用新系统指令重放旧付费请求。

咨询在模型派发准入处被拒绝时，保存具体 `DispatchBlocked` 原因。显式恢复可复用该咨询已经全部结算、且无 `stop_required` 的响应；这只允许重建已完成进度，下一次派发仍重新校验预算、权限与原输入指纹。余额不足仍停止，不自动加额；未知用量或未完成请求不走这条恢复路径。旧版只保存异常类型的记录也须通过相同账本检查，不能手改为取消或成功来绕过恢复。

独立检查者始终得到已授权的 `browse_context`、`read_saved_result` 入口，不必等输入压力触发后才披露。带明确回读路径的来源选择反馈、窗口及参数校验返回原工具调用，让检查者自行修正；未分类错误及带 `execution_stop` 的派发、计量故障继续停止。原始失败不改写成成功。

日期未核定或原站拒绝的候选返回网址、失败原因和出版者查询入口，不返回未核定标题、摘要或正文，不能引用；已知晚于截止日的候选仍完全排除。真实重定向的落地页按自己的网址和日期重新核定，显式域名范围与循环检测继续生效。

报告修订入口先要求作者依据复核与补证更新对原题的判断，再决定编辑范围。事实错误可局部改，中心解释改变则可重排标题、摘要、论证及结论。增量保存不限制研究范围，也不要求重做已有调查。宿主的干净回放可显式导入哈希固定的报告版本；只有空分支可接受该导入，不覆盖当前稿，也不将旧交付状态带入新任务。

修订交接明确披露 `read_current_report(field="revision_context")`。该入口从当前稿、当前版本绑定的复核、原始保存回执重建导航：实际修改批次、当前标题与结构、首尾段及可能相关的原句。标题和首尾导航不依赖相似度；词面匹配与可能相关的改动仅是候选，不是矛盾判定。已保存批次标明历史版本，当前原句使用当前版本的偏移。读取分页，保存不成为复核通过，原作者仍可有依据地反驳意见。保存回执仅保留有界改动预览与省略计数，不复制全稿或另存全部历史。

`browse_context(region="acquisition")` 在已有消息中按准确 URL 汇集访问/日期障碍、候选和实际原文窗口。保留旧失败、原来源身份、内容摘要哈希、日期与读取方式；有后续成功读取也不自动判定问题解决。不同 URL 不自动合并，部分原文不冒充全篇检查。原参数只作历史记录，不授权重试；权限和存储故障仍走现有停止机制。没有精确 URL 或唯一来源映射的错误仍留在原回执，不强行关联。

实际派发新增一份小型 `context_observation` 运维记录，支持 Chat Completions 和原生 `tool_use/tool_result` 消息。记录消息/工具定义/内容类型的字符规模、相同工具参数的摘要、返回结果是否相同；不保存思考正文、不估算 token、不据此自动判空转或缩小窗口。正常分页和变化的结果分别统计。此观测不改变原生压缩、权限、预算或失败准入，不能证明长上下文导致了判断错误。

离线回放可运行 `scripts/engineering/replay_revision_navigation.py --before <旧稿.md> --after <当前稿.md> --review <实际意见.md> --receipts <真实工具回执.json> --output <私有输出.json> [--wire <真实请求.json>]`。输入回执为 `{receipt,name,status,result}` 数组；没有原始参数的导出无法定位全部失败。回放核对原句偏移、保持输入哈希不变，结果仅证明交接和导航，不评价金融结论。内层检查点仍隔离外层 tracing；短时重复观测测试不能代替持续运行的服务内存验收。

实现复用 `answer_review_provider` 的受权只读工具、逐请求预算预留/实耗/未知费用记录；子任务业务观察保存于同一内容寻址检查点存储的独立线程。读取完成结果时，准确原文及计算回执交回作者，可继续引用和计算。子任务无稿件/笔记写权限、无递归委派，无单独预算。方法正文不能提升权限。

启用咨询时，宿主给作者与各项委派分配独立派发通道，保持同一运行身份和同一预算事务。不同通道可以同时等待供应商，同一通道仍只允许一个未完成请求；任何通道出现未知用量或失败，整个运行的后续派发均停止。通道身份来自宿主，模型不能通过工具参数自行指定；未启用的旧执行保留原串行规则。不将正常在途请求误判成失败，也不通过放松总额度换取并发。

相同任务请求及相同稿件内容重复提交返回原任务；未完成和失败记录不自动重新派发。源读取/供应商故障阻止父任务下一次付费调用，取消父运行会取消未完成子任务。已取消的咨询仅在普通恢复命令和宿主签发的单次未知用量恢复授权均通过后，使用同一任务、检查点和原请求接续；供应商适配仍逐笔验证授权范围与请求指纹，旧失败和费用预留保留。其他故障需单独核对，工具不提供自动重试授权。父任务不能在咨询尚未结束时声明完成。

验收覆盖真实 ToolNode 参数注入、无递归只读工具、资料交回、重复请求复用、失败停止及实际系统指引。确定性通过只证明接线；是否主动使用、调查深度、作者是否正确更新主判断须记录真实运行。

若恢复过程在重新启动咨询之前又被中断，按作者已保存的真实委派回执定位仍未完成的任务，并核验该任务原失败运行的签名授权；不因“上一轮”编号变化丢掉任务，也不扫描恢复其他执行的咨询。监督端仅将当前运行中新发生的咨询失败作为停止信号，历史失败继续留档。

准备阶段已结束为 error 或 interrupted、且无模型审计时，必须由运维核对预算派发账本确实为零后签发准备恢复回执；不能仅凭审计文件不存在推定未调用。它不修改原运行状态，也不清除更早运行的未知费用或替代原咨询的补发授权。

正文精确替换未匹配或匹配多处属于正常编辑冲突。工具返回 `edit_not_applied`、`saved=false`、当前版本、原文候选及回读参数，整批不写入，不增加版本，不标记交付；作者自行确认位置和重新提交。近似匹配仅用于找位置，不自动改字或替换。此类反馈不触发供应商故障锁或取消并行咨询；来源绑定、权限、存储及供应商故障仍按原停止机制处理。

多次恢复沿同一咨询的实际补发键查找最新记录，成功响应仍须逐个校验输入指纹；最新未知请求须核验其原运行的单次授权，不能拿更早一次授权重复补发。恢复准备自身失败且经账本确认零派发时，凭准备回执定位保留的上一份咨询记录，再校验该记录的付费恢复授权；不改写失败记录或将未知用量归零。

若父运行停止时咨询正在执行只读工具，恢复复用公共业务桥的只读续执行入口，完成原调用后继续回放供应商响应；已完成工具不重做。未知写入效果仍禁止恢复，咨询本身没有写稿权限。

已产生失败回执的只读工具，可在用户授权的运行恢复中按原参数重新执行；必须匹配咨询记录中的失败回执及当前只读权限。旧失败留档，不因工具恢复抹除费用或放行未知供应商请求。普通委派调用仍不会自动重试。公开网页读取统一使用 `SourceDocumentRequest` 的 100–80,000 字符窗口契约，超出范围仍返回校验反馈；外层不再附加未披露的 24,000 字符上限。
# 公开原件读取补充

新建委派将授权任务的原始题面、截止日与复核范围单独保存为 `research_task`，与作者拟定的 `question/context` 并列进入检查者输入。作者不能通过工具参数替换原题。整稿复核检查原题覆盖及论证，局部调查仍保持局部范围。历史已发请求缺少此字段时不追补以改变其指纹；新合同验证应从未派发该复核的干净状态分支。返回意见由现有 verifier 方法要求明确定位、依据、建议动作及相关判断；完成回执复用与直接报告修订相同的作者职责。程序不裁定是否接受意见，不自动改结论或把保存成功标为研究通过。

委派或其他工具参数引用未观察到的短句柄、或匹配多个来源时，返回未执行的选择反馈和当前已授权的来源/稿件回读入口；不替模型猜配来源，也不因可纠正的引用选择中断整个研究。引用身份碰撞、权限、存储故障仍停止。整稿复核需要 `use_current_report=true` 绑定实际保存稿，局部上下文咨询不构成全稿审计；作者可依据证据反驳，否则应将实质意见落实到相关全文表述。

单一 `site:host/path` 查询同时约束域名与路径前缀；备用搜索器忽略运算符时，不把域外候选交付给模型。政府原站返回 403、超时或空响应时，可以使用现有、计费可审计的 DS Fetch 获取该准确 URL 的转写。回执明确保留原站错误和 `deepseek_hosted_publication` 读取方式，不声称获得原始字节或历史存档。公开日期仍须来自正文中的公告报头或明确日期标签；未来版本继续过滤，未核定日期不成为可引用正文。检索成功不等于原站直读成功。

日期解析同时支持准确绑定当前页面的 Schema.org 文章 microdata，排除嵌套推荐文章的日期；已有修改日期继续参与截止日检查。政府转写的报头可跨越纯图片占位符读取完整年月日，不跨过正文猜日期。仅有月日、正文提及的日期或 URL 年月不构成已核定发布日期。带 Drupal `facet_*` 筛选的集合目录只保留导航身份，避免把目录当成单份公告反复送去付费抓取。

独立整稿复核多次恢复时，原复核编号用于找到已保存响应，实际失败运行用于核验补发授权，两者不能混用。中间恢复失败后仍通过同任务的明确复核 lineage 查找原失败回执；必须满足该回执自己的签名授权与原请求指纹，旧未知用量继续保留。

干净作者分支可显式导入已完成复核：部署端将原检查点中的 active_report_review 与稿件版本、意见哈希及复核者一并固定。导入逐项验证，仅初次分支命令复用该意见，不再次派发复核；恢复沿已保存意见继续，后续新命令不自动复用旧意见。模型和浏览器不能提供该绑定。原意见、费用及历史失败不改写，作者仍走现有 author_input、保存和交付入口。

## 原生最终作者接管

当原作者修订后仍不能落实重要复核意见，可由部署端明确授权更换最终作者。接管沿同一个 ACP session、业务检查点、稿件版本和材料对象继续；使用底座 `session/set_config_option` 切换模型与思考强度，由底座转换历史协议。不是把报告发给独立复核脚本再转交原作者，也不手工伪造原生消息。

`native_model_transition` 固定 session_id、from_model、to_model；任务、授权清单与执行发行版必须一致。恢复旧模型的目录仅用于加载会话；付费准入只接受新模型，新模型使用原有业务工具保存并交付。切换成功和实际选项先写回执，下一次恢复继续新模型，不自动回落旧模型。此配置是运维端准入，目前未作为浏览器通用模型选择器开放。

OpenAI 工具调用走原生 pi-ai 的 Responses 协议；代理保留原始请求、流事件和终态 usage，`max_output_tokens` 必须与准入一致。Sol 的超过 272,000 输入 token 费率按完整请求的 2 倍输入／缓存与 1.5 倍输出计算；模型容量与预留也需相应更新。异常与截断不算成功交付，未知用量继续保留。

离线验收入口 `scripts/engineering/probe_native_model_handoff.py` 使用固定原生二进制和本机模拟服务，验证 DS 读取、同会话切换 Sol、原工具结果进入 Responses、保存以及再次恢复。配合 usage/transport/session 单测验证费用和绑定。离线协议通过不代表接管后的金融判断通过，真实验收仍需检查实际正文与引用。

`read_current_report` 的字段分页统一在工具 schema 声明 offset≥0、每页 1–12,000 字符。参数越界属于可纠正的读取反馈，返回实际限制，不中断同批其他正常读取；历史笼统窗口错误恢复时保留原回执，并补充当前准确范围和分页说明。权限、存储等执行故障仍停止，分页成功不代表稿件已提交。
恢复还会核对原生工具超时与业务持久回执：以该失败运行已确认的成功回执为边界，仅在原工具和原参数唯一对应到后续已提交的读取结果时交回准确回执和回读入口；不重执行，不把待处理或歧义结果当作成功。网页导航的重复目录只在同一读取器中恢复一次，原始历史继续完整保存。

## 时点背景、取证交接与压缩配置

任务入口披露准确截止日及当前用户命令的目标。运行开始时，从既有业务回执生成小型 acquisition snapshot，明确仅统计原 URL 的候选、原文窗口和障碍事件，不推断主题覆盖完成。实际详情通过既有 `browse_context(region="acquisition")`、`sources` 与 `read_saved_result` 回读；工作认识沿用工作笔记。原生压缩不会删除业务回执。快照是 run-start 状态，后续变化以工具记录为准，不能充当一直更新的覆盖表。

任务绑定可配置 `compaction_threshold`（0与1之间），传给上游 `compaction-basic.thresholdRatio`；未配置保持0.8。模型 context_window仍描述容量，压缩阈值独立选择，不为了提前压缩伪造模型窗口。开发运行可按30万—40万token附近的行为选择比例，观察实际usage、摘要内容与接续；不是字符硬上限、调用次数限制或强制交付。摘要请求同样计费，失败/未知保留，不依赖自动重试。离线配置通过不等于真实压缩质量通过。

行情时间跨度越界属于尚未派发请求的参数反馈，返回原参数、最大跨度、时区和分页区别；模型自行选择新区间或分段，不由 runtime 截短时间。此类回执保持 error，不生成行情或来源，但不切断同批调用和下一次参数纠正。仅识别准确的行情参数反馈结构；提供方故障、身份/粒度不一致及权限故障继续停止。小时行情仍受当前适配层每次60天范围约束，这不是覆盖更早历史数据的保证。

等待独立调查时，`/calls/ready` 的传输时限独立于付费请求：一次宿主轮询允许120秒，内部正常等待20秒，余量用于权限及持久状态读取；不发送完整模型输入或预留新调用费用。同步权限检查在工作线程执行，避免阻塞正在取证的子任务。取消信号仍即时传播，断线或超时反馈包含具体宿主端点。付费预留、结算仍使用原30秒传输时限，模型自身输出时限不因等待而提高。真实等待超时仍需保存进度和检查，不以无界重试掩盖。

宿主取消子调查后，显式恢复可以复用同一请求的已结算成功响应；准入须查该子任务的实际账本，所有响应均已收到、计费且未要求停止才放行。无响应、待处理、未知用量或失败响应不能走此路径，仍保留原恢复授权要求。历史取消回执不改写，也不把子调查标成完成。

独立调查的连接、传输超时或 HTTP 故障另走有签名授权的恢复路径：仅接受该执行 scope 与委派 lane 中已知成功响应及被授权的未知费用调用，存在待处理调用或其他失败则不放行。进入提供方恢复后仍核对原请求指纹，未知费用和旧失败记录保留。授权不等于后台自动重试，普通继续或重建任务不能绕过这一检查。

重建已发送过的输入时，可纠正的参数／引句拒绝也属于既有反馈，复用原错误回执和标识，不再次执行生成新 ID；真正的执行故障不走此复用。仅回放旧响应、未产生新派发却在准备阶段停止的运行，可由运维签发零派发证明：账本必须为零，审计只能含 `saved_response_replayed` 且明确未调用提供方，证明绑定完整审计哈希。原付费失败仍使用原运行独立授权，不改写历史。

公开网页 ID 不在当前已授权候选目录时，保留原 ID 并返回定位反馈，以及最近最多三项已成功搜索回执的 `read_saved_result` 入口。模型自行回读、选择准确 ID，或重新搜索公开查询／网址；runtime 不猜配原文，也不把失败 ID 当成来源缺失。作者和独立调查者均可继续处理这种可纠正的选择，原错误仍记账。目录恢复的权限、摘要、截止日及来源完整性检查不因此放宽，费用未决或存储故障仍停止。

恢复来源绑定计算时，重新执行原引句的确定性排版兼容处理，验证转换记录本身，不能用已规范化引句代替原参数而丢掉记录。同一公开原文窗口被再次抓取时，允许抓取时间与抓取回执摘要不同；网址、文档、内容摘要、字符位置、发布日期及其他来源属性仍须完全一致。旧计算保留其原抓取身份和 CALC ID，重新计算值、算式、单位及完整回执必须一致。该处理不迁移不同版本的证据，也不修改作者选择的数字或结论。

数量绑定接受紧接数字的财务规模缩写 bn、mn、tn、trn，记录准确匹配范围；只识别词法边界，不自动换算币种、规模或期间，也不证明比较有经济含义。恢复时以回执内的业务 `status:error` 识别拒绝，即使 MCP 已正常完成传输；对原提案重新校验通过时，仍明确“重新验证、尚未保存”，保留旧失败，由模型选择是否执行，不能冒充已完成计算。

工作台回读同一检查点的报告与最终回复引用时，按保存的计算载荷或已核定的原文窗口比较身份，不直接比较两个展示对象。报告的短预览与回复的完整绑定可以共存；只有完整计算载荷一致，或原文身份、元数据及预览位置均与已保存全文一致，才返回同一份依据。计算标题、摘要长度和界面分页不构成不同证据。真正冲突仍返回409；当前权限与所选检查点照常核对，不跨研究取件或重新联网补正文。
