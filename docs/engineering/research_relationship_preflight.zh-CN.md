# 关键研究关系的运行准备与监督

本页区分提示词/方法、上下文生命周期能力和研究质量。离线通过不代表模型研究质量通过。本轮不启动付费研究。

## 主负责人和调查助手

下一次深度研究显式配置 Sol high 为原生主负责人，deepseek-flash high 为 research_delegate。主模型承担方向、关系判断、调查验收、跨任务冲突和最终表达；Flash 的 investigate/draft/review 均是工具委派，不接管总稿。复用现有 ACP 子会话、共同预算、权限与原始回执，不新增调度循环或固定 Agent 数。已有用户显式模型选择不被全局覆盖。

主入口 `final_author_guidance` 在实际配置 research_delegate 时安装持续研究职责，替换原来的“调查→委派草稿→最终审核”重复段落。主模型取得简短职责及 `lead / 重要研究关系的完整调查与验收` 章节入口；完整教学按需读，不常驻装载整套方法。普通对话不增加这套角色指令。旧接管路径保留最终作者责任。

委派沿用 question/context/purpose/method_ids：任务回答重要关系，不证明预设结论；context 交代对总题的用途、必要依据、竞争解释与真实依赖。返回结果复用 record_research_assessment 的 finding、scope_explanation、actions 和来源/计算回读。工具完成不等于主负责人接受；接受一项局部分析不等于整题完成。主负责人将验收理由、当前判断及条件写入现有工作笔记，不新增强制计划表。

## 运行监督约定

以下为运行监督者的操作约定，语义判断不由关键词拦截器代替。监督问题记录留在验收侧，不能把本案标准答案注入研究模型。

| 观察点 | 监督动作与恢复条件 |
| --- | --- |
| 输入和上下文 | 每次派发核对现有 context_observation 和原生 token 计量：角色/工具回执体积、重复参数与相同结果、交接是否复制原稿或全过程。字符数不换算成 token。Sol 原生基准保持 258,000；约 85%—90% 时结合近期增量检查下一轮风险，不能每轮机械提前压缩。合理分页和变化结果不是空转。 |
| 资料获取失败 | 参数/定位反馈由模型正常修正；关键原件访问或解析持续失败、丢失工具回执等执行障碍，由监督者暂停相关运行、检查同版官方接口/归档/合法替代件并修工具，原提案离线回放后恢复。不得静默替模型选答案、使用期后版本、绕过权限、验证码或付费访问。确实无公开渠道时登记具体障碍与调查范围，不承诺所有私有信息可取得。 |
| 边界说明代替调查 | 在子结果、工作笔记和拟交付稿观察：若重要关系被写成“不能全部/尚不确定”，而相关原件未读完、必要比较未做或已有条件足以继续分析，先停下诊断任务、工具和信息交接。不要用禁词判定，不把有依据的有限判断或明确无关的遗漏当失败。不能只让模型继续润色后发布。 |
| 重复与其他 runtime 故障 | 多轮重复无新证据、判断或有效状态变化时暂停诊断；子任务等待交给宿主，不付费轮询。核对原请求身份、预算账本和未知用量；不因本页获得额外额度或失败付费请求自动重试授权。 |
| 压缩后恢复 | 检查主问题、当前判断和条件、未通过理由、被否定解释、活跃子任务与依赖是否仍准确。缺失先回读修复；压缩成功不是任务完成，不作为交付触发。 |

资料故障恢复须保留成功读取与原失败，不用手工拼入正文取代模型使用修好后的工具。停止与恢复复用已有执行控制和账本，不另建收费循环。边界说明的语义暂停目前由运行监督者负责，未实现自动金融语义判定。

## 上下文退出的实施边界

现有能力：子任务原生历史独立、来源与计算可继承回读、主作者工作笔记、结果导入、原生压缩、输入观测。主指令要求更新简明当前认识，减少新交接中的重复。

原生委派入口新增 `assess_research_result`。负责人读取并核对后，使用任务 ID 与 `result_digest` 绑定验收，保留 finding、scope_and_conditions、counterevidence、unresolved 和关键回执入口。状态为 accepted / needs_work / reopened。无效参数返回可修正反馈；不生成付费调用，不更改子任务状态，也不自动关闭独立复核事项。

宿主从既有业务检查点读取最新验收，以当前完成结果的摘要校验其版本。原生插件在下一次 pre-step、原生压力计量之前，用底座带日志的单节点 surface replacement 替换 `read_research_agent_result` 全文，保留消息和 toolCallId。替换后计量、压缩和实际发送使用同一个上下文，不在计费后偷偷改请求。完整原生事件与业务回执均不删除。

重新打开或结果改变时，仍在活跃 surface 的已精简回执还原为历史全文，并标记验收失效。原生压缩已经合并的历史不会反向展开；新决定回执与必要原件回读负责恢复当前认识。旧结果没有 result_digest 时须重新读取，不自动追认验收。权限或存储故障继续阻断，不降格为不存在结果。

本次精简只覆盖准确匹配的子结果回执，包括同结果多次读取；不按关键词删关联原文、用户输入、主模型历史陈述或未验收任务。`read_saved_result` 的定点重读保留，以免模型主动核查时刚读到的内容立即被移走。摘要过大或遗漏条件仍需研究验收，runtime 只核对身份、版本、必要字段和入口。

验收要求：

- 验收绑定具体任务、结果和依据版本；助手自检或 status=completed 不能触发移出。
- 保留当前判断、适用范围、期间单位、必要假设、反证、未决项和准确回读入口；重要信息不能只留在被移出的长稿中。
- 原始审计留存且按权限可回读；调用与结果协议保持配对；活跃/失败/未验收任务不误删、不改状态。
- 过期验收或新冲突能重开；新旧会话恢复不把历史结果伪装成新结果。
- 通过真实工具回执离线回放和原生进程验收后才启用，不能直接修改历史 JSON 跳过原生会话约束。

## 开跑前的验收

新方法不能静默覆盖旧失败付费请求的冻结输入。后续真实验证使用新准入或明确的新分支，保留旧题原稿作对照；开跑前检查实际 Sol 主请求和 Flash 子请求的工具、角色、方法入口、预算依据及读取权限。TokenBudgetBasis 应写清：验证持续研究关系与监督恢复；输入仅包含原题和必要材料导航；输出为可验收关系分析与当前认识；风险是摘要丢条件、范围收缩、假设无依据；Sol high/Flash high；授权预算、258k 原生压缩与上述停止约定。预算金额由具体任务授权确定，不挪用旧题资金。

离线检查能证明指令与工具实际进入原生 profile、原题保留、子任务不能覆盖总稿、方法章节可读；不能证明模型会自主深查或成稿质量改善。真实验收需分别记录主模型的研究选择、助手调查、主模型验收和压缩后判断，不能只看最终状态。
