## 页面与组件职责

| 组件 | 展示内容 | 状态与交互 |
| --- | --- | --- |
| ResearchHome | 新研究输入、近期列表 | 输入为空/草稿/提交中/提交失败；失败保留字段，提交去重 |
| TaskHeader | 短标题、as-of、报告版本、报告/运行各自状态 | 详情、版本、导出；后台运行时不覆盖旧报告状态 |
| ReportReader | 原始报告、目录、引用、图表 | 目录由已有Markdown标题提取；锚点含重复标题处理；不额外调用模型摘要 |
| ContextPanel | source / calculation / conversation 三种内容之一 | 来源按钮、操作数、引用段落；关闭回焦点；来源链提供返回上一层 |
| Conversation | 历史消息、当前问题、简短/深入选项 | 长问答可展开为主阅读区；返回报告保持位置；失败不假装有答案 |
| RevisionReview | 当前目标版本、反馈内容、执行影响 | 用户确认后提交既有修订动作；若当前版本已变化，提示重新核对，不静默改目标 |
| ProgressView | 当前阶段、任务结果、需要操作、累计/本次费用 | 分离部分失败与整体结束；不能把“任务数完成”当作质量百分比 |
| MaterialsView | 已保存附件、状态、范围 | 上传中/已保存/失败/未识别；识别与上传分开；保留原PDF和图片能力 |
| VersionView | 原生版本列表、差异和阅读态 | 旧版只读，导出和来源请求携带所选checkpoint；无差异数据就显示真实状态 |

这些是视图职责，不是八个新的服务或状态机。现有服务仍是运行、持久化和账本的唯一权威。

## 交互状态规格

### 报告与来源

- 同一任务保留当前阅读版本、章节和滚动位置。来源选择不能改变报告版本。
- 来源面板先显示加载态；成功展示真实文本/定位；失败显示可重试读取以及错误类别，报告继续可读。重试来源GET不启动研究模型。
- CALC依次展示公式、结果、单位/期间、完整操作数和来源；算术/语义状态原样解释，不用单个绿色勾掩盖差异。
- 右侧区只开一个；由计算进入操作数保留回到该计算的路径。窄屏进入子视图，并把返回焦点/阅读位置作为验收项。
- 正式报告保留完整Markdown、表格、图表与长文；原型短内容只用于评审交互。

### 普通追问与修订

- 追问关联信息显式可见：任务、阅读版本、章节、被引原文。第一切片可用用户可见文本附在现有question中，无须新建后端选区锚点数据库。
- 简短/深入选项复用既有quick/deep行为；文案不能承诺质量、价格或时长。预算仍由既有任务授权与服务端约束决定。
- 修订目标为当前候选，历史阅读态下提示“返回当前版本后修订”。提交前重新读取当前目标；如需严格版本冲突保护，必须核实已有接口支持，不把纯前端判断当作原子保证。
- 普通Enter换行；显式按钮发送，可保留Ctrl/Cmd+Enter。输入法组合态不触发快捷发送。
- 运行中不提供无效发送动作。现有“补充运行中意见”如保留，应明确是保存意见、非立即执行；不新增消息队列。
- 不做模型流式输出的假打字效果；已有事件可展示执行进展，但不暴露私有推理。

### 进度、异常与成本

| 情况 | 产品表达 | 下一步 |
| --- | --- | --- |
| 没有报告且仍运行 | 当前阶段 + 已保存内容 | 查看资料/运行详情，等待真实事件 |
| 有旧报告，新的问答/修订运行 | 旧版可读 + 当前动作运行中 | 保持阅读，避免误以为旧版正在被覆盖 |
| 某任务失败 | 明确未完成项目及影响 | 已有接口允许时继续未完成项；否则解释边界，不造“重试”按钮 |
| 来源取读失败 | 当前来源未读到 | 重试读取/查看已绑定信息；不宣称发行人未披露 |
| 页面断网 | 状态暂不可更新 | 保留已渲染内容和草稿，重连后读取权威状态，不重复提交 |
| 费用不完整 | 已知估费 + 未知/待报告项 | 可以展开明细；不写0元/已结算 |
| 附件已存但未识别 | 已保存，按需读取或识别 | 用户发起相关问题；不自动新增付费分析 |

进度名称需对照真实phase、task outcome与事件映射。设计中的四阶段是表达提案，不能只靠计时器模拟。原型允许切换“进行中/失败”以便评审，其状态不是生产事实。

## 布局与无障碍

- 桌面建议：任务头约80px，导航约48px；目录约160–200px，正文限制舒适行宽。辅助区约320–400px，按可用宽度收起目录或进入独立辅助视图。
- 建议断点先用可用容器宽度验证：约1200px并排三部分，850–1199px隐藏/折叠目录，窄于850px优先正文或辅助子页。原型的适配是预览折中，不作为正式CSS数值承诺。
- 一个主体滚动容器；桌面辅助区可独立滚动，但不让聊天和报告各自嵌套多个滚动区。小屏用单列；长表格局部横向滚动。
- 明确焦点、状态文本、键盘可达、Esc返回；对话框用合适的焦点约束。正文可缩放200%，操作目标触屏约44px。
- 返回任务后恢复阅读位置，切换任务不串用来源/草稿。浏览器前进后退按可见页面一致工作；这是拟实施要求，不是当前原型已经覆盖的功能。

## 已有能力与新增工作分界

已具备并应复用：React/TypeScript/Vite、react-markdown/remark、原生研究会话与运行、已保存report/conversation/citations、source GET、附件、版本GET、差异、导出、用量。可在现有代码中整理视图，首轮不迁移runtime、不改金融合同、不引入全局状态/编辑器/工作流平台。

真正新增的是信息层级、目录定位、辅助区上下文、阅读态保留、明确的修订提交视图和进度呈现。跨刷新草稿恢复、自由选区稳定锚点、可编辑报告正文、前端自动生成摘要/修改理由，均不默认承诺。

设计评审后，若需要新对话框、菜单或路由基础组件，先核对现有能力与成熟组件的许可、兼容性和可访问性，再做一个有界集成；不提前造控件平台。本轮没有安装新依赖。
