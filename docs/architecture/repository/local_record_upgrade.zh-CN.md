# FIN 0.1.3 本地记录兼容性修复

v0.1.3 使用 SQLite 保存本地提交凭证、来源缓存及检索调用记录。本页说明已有环境的升级与恢复方式。

## 存储选择与影响

`diskcache==5.6.3` 的反序列化问题 [GHSA-w8v5-vhqr-4h9v](https://github.com/advisories/GHSA-w8v5-vhqr-4h9v) 没有可升级的修复版本。仅把业务值写成 JSON 不能阻止被篡改的旧数据库选择 pickle 读取路径，因此不采用忽略漏洞或仅切换写入序列化器的办法。

采用项目 `sec_agent.workbench.store` 等已使用的 Python 标准库 SQLite；不增加缓存服务、调度器、锁服务或网络依赖。`sec_agent.adapters.local_records` 是事务 SQL、JSON 编码和固定旧格式读取的薄适配层，SQLite 负责跨进程锁、提交和回滚。内存缓存不具备重启去重语义；另引入服务端缓存需要新的部署与持久化资格，超出本地工作台需求；原 DiskCache 无安全补丁，故退出依赖锁。

| 用途 | 保留语义 |
| --- | --- |
| BFF 提交凭证 | owner + 提交 ID 键不变；原子 claim；已收响应的状态码与字节重放；dispatching/未知结果不自动过期或重发 |
| 原文检索 provider 记录 | 模型、快照、原文、操作组成的键不变；已完成向量/响应继续复用；started/failed_usage_unknown 仍阻止自动请求 |
| scoped source capture | 原 UUID 目录及 TTL 不变；只缓存成功来源；重放仍检查 URL/DNS、重新绑定当前研究回合；64 MiB 有效内容上限 |

新文件为原目录内 `records-v1.sqlite`，内容使用 JSON 与显式二进制编码，不执行对象反序列化。64 MiB 是可复用原文的逻辑内容上限，不是 SQLite 文件物理大小承诺。提交及付费调用记录不做容量淘汰。

## 升级与恢复

1. **先停止共享这些目录的旧 BFF、Agent Server 和检索构建进程**。同目录不能同时运行新旧实现。保留包含 `cache.db`、其 WAL（若有）及外部 `.val` 文件的完整一致备份，不只复制主数据库。
2. 安装新锁定依赖，正常启动新实现。首次打开目录时，SQLite 事务锁住旧库，将其记录原子导入新库；并发新进程由新库事务串行化迁移。空目录直接建立新库。
3. 迁移保持字符串键、二进制响应、基础字典/列表、向量、过期时间和未知调用标记。旧 pickle 只允许基础数据，禁止 GLOBAL、REDUCE、对象构造、扩展注册与持久化引用；外部值不得越出目录，单值读取有界。Windows 与 POSIX 相对 `.val` 路径均按路径段解析，再定位到当前缓存目录；拒绝盘符、UNC、根路径、`..` 及解析后越界路径。旧文件不删除。
4. 发现不支持、损坏或不安全记录时，整批回滚且不写完成标志；业务操作停止，不把导入失败当作缓存未命中，不自动重发模型/研究请求。管理员核对原始运行记录后处理，不能通过清空目录“修复”。
5. 新实现产生写入后，不可只回滚代码到旧 DiskCache 实现：旧代码看不到新凭证，可能重复提交。恢复应保持新适配器，或在停机下恢复经过核对、含最新提交状态的一致备份；该版本不承诺任意旧代码无损降级。

验证覆盖合成旧格式、真正 DiskCache 5.6.3 生成的记录、两种路径分隔符、未知调用标记保留及缺失外部文件的整批回滚。另有一次实际缓存迁移：47,547 条记录与 1,361 个外部文件全部导入，旧数据库摘要不变，迁移本身未调用 provider；运行回执和完整备份保存在部署方私有记录中，不属于安装依赖。其他部署升级仍需执行上述停旧进程与备份步骤。

## 检索空间与验证边界

`local` 是冻结的原始文档树，`library` 是已发布知识库；它们有各自的来源身份、快照和向量模型。修复旧缓存路径不重建正文向量，也不把旧模型向量混入正式知识库索引。

当 specialist 的能力声明包含 `library` 时，运行时在 `task_context.source_routing_guidance` 中明确：公司、行业和最新材料发现显式使用 `library`；已返回的本地文档/章节继续用原 `source_space` 和 ID 读取。路由提示不改写已有请求的默认值或历史 ID。旧路径降级时保留词法候选并标记执行问题，另行检索正式知识库，不能据此判定公司未披露。

验收需要用历史查询检查真实召回回执、候选来源和原文回读。成功返回列表不足以证明向量参与；实际命中也不代表财务结论已核实。模型是否自然遵守新的路由提示，仍需在后续真实研究运行中观察。

## 容器软件包

固定版本的 Python OCI 镜像内 glibc 为 `2.41-12+deb13u3`；当前 Debian 镜像站已不提供相应开发包。可选 control-plane 构建补充 [Debian 2026-07-01 历史仓库](https://snapshot.debian.org/archive/debian/20260701T000000Z/)，用 Debian archive keyring 验签，只关闭历史 Release 文件的有效期检查，未关闭签名验证。

显式保留 libc6-dev/libc-dev-bin 原版本，并在构建前后断言 libc6 未改变。gcc、libpq、OpenSSL 和 OCI 基础镜像的版本不变。容器构建与依赖审计通过 GitHub Actions 检查。
