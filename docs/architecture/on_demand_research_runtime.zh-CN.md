## 3. 单一生产调度路径

新任务使用一个持续主 Agent，按用户当前目标决定直接答复、调用工具、委派或编辑成果。报告是成果类型，不是所有任务的终态。统一指共享执行/状态/权限/成果协议，不要求所有工作使用完全相同的提示词或工具全集。

调用分为：确定性工具；有范围的一次模型工作；可持久接续的子任务。第一阶段先打通现有工具和有界子任务，不另开一个不受预算和权限管理的通用模型 API。子任务创建操作只登记并交由既有原生执行设施调度，返回任务身份；不能在工具内建立新的同步长循环或复制一套恢复逻辑。

主 Agent 为委派提供问题、必要上下文/成果引用、期望交付及允许使用的已注册能力。宿主生成身份、版本、权限与预算绑定；共享根预算和并发限制，子任务不得自行扩大权限或重置费用。第一阶段只开放一层有界子任务，已有专家内部助手能力不能绕过该层级限制形成第二套递归调度。

### 完整报告与旧流程的处理

- 新任务需要完整报告时，仍由同一主 Agent 调用同一组研究、复核、修订和成文执行器；完整报告配置描述交付要求，不运行第二张具有相同职责的顶层图。
- 提取并复用已有节点实现，不复制 `research_convergence.py` 为另一个新编排器。需要复核的约定固定到本任务，未满足只能交付明确标注的草稿/未完成状态，不能伪称完成。
- 旧完整图只保留为已固定运行版本的历史任务恢复适配。新入口启用后，旧前端/API 创建入口映射到统一创建合同，不能继续默认创建旧完整图运行。
- 切换前旧路径仍是现行生产路径，新路径只在隔离验收使用；不双发真实请求做影子比较。切换后只有一个新任务默认入口。
- 历史恢复适配允许读取和恢复已有身份，不接受新任务创建；记录剩余历史任务。历史任务全部关闭或可明确归档后评估移除执行适配，历史成果读取长期兼容。
- 失败回滚只回滚新任务默认路由；已开始的新版本任务保持其执行版本或暂停，不能换引擎重放。旧 wire ID、数据身份和引用不为命名清理而迁移。

### 提示、配置和旧验收的替换

盘点上述模块实际组装的提示、`configs/research/runtime/` 配置和阶段方法，不仅修改顶层 system prompt。全局“必须进入下一阶段/必须完整报告/必须逐项说明省略角色”的指导，迁至明确要求该交付的任务配置或历史适配；新入口不再注入。

不增加每轮计划表、判断卡、语义评级或“尽快提交”补丁。分工说明由模型表达；版本、权限、执行结果等机器事实由 runtime 生成。正常读取、必要关联修改、非唯一匹配的可操作候选反馈，不等于无进展。确定性错误与研究争议分别呈现。

用户要求的检查、权限和费用上限仍严格执行。内部实验额度不作为研究任务指导反复注入。节点名字叫 writer 不意味着必须换作者；保留现有 Lead 成文职责，不用新角色重新解释全部研究。

### 5.1 组织接入不能被普通对话绕过

集成方确认可复用的合同见[原生启动](../engineering/organization_native_start.zh-CN.md)、[原生接续](../engineering/organization_native_continuation.zh-CN.md)、[成果读取](../engineering/organization_research_reads.zh-CN.md)、[Java 生命周期](../engineering/java_intake_recovery.zh-CN.md)。复用的是身份、幂等、固定配置、派发与当前核权机制，不能假定已有命令已授权任何新工作。

现有组织首次命令仅允许 orientation；既有 begin_research 接续是一条固定的预研究→正式研究命令，不是任意修订/工具子任务的通用授权。第一阶段 A/E 必须先列出新入口需要的动作与现有命令映射，对无法表达的创建/接续动作由集成方扩展版本化合同及准入测试；禁止挪用首次启动凭证、重复 begin_research 或直接从普通对话绕到 SDK 创建组织 run。

必须保留：thread/run/checkpoint/配置摘要各自身份；Java 持久命令一次派发与 unknown 只读核对；工作负载身份不替代用户；主任务/子任务/读取/引用/导出均受当前项目与全部固定输入权限约束；组织成果不回退个人端点。子任务若创建独立 run，必须有可审计的委派授权和运行绑定，不能复制父 run 准入凭证。材料与配置变更采用显式新版本，不重算或覆盖已冻结摘要。

需要同步的 API/存储增量先完成字段映射和迁移评审，再编码；尚未确定具体新增 endpoint/schema 名称。本设计不会把“需要增加授权命令”误写成已支持，也不因这项缺口改建第二套调度服务。

子任务输入必须是显式固定版本且不超出父任务可委派范围；父任务后来新增材料或换配置，不得静默改变已派子任务。父任务停止/撤权如何传播至已派子任务、未知派发如何只读核对、调用费用如何归属根预算，均须有持久状态与可恢复操作，不能仅靠给主 Agent 发一条消息。已经发生的调用保留用量/未知状态，不承诺撤销外部调用；停止传播阻止后续未获授权动作。

### 5.2 成果与输入投影

复用现有 task/outcome、成果和版本合同，只补缺项：用户目标及当前范围、成果引用/版本、任务关系、检查对象/范围、可用能力引用。目标与交付可用自然语言表达；不要求每个回答生成底稿全部结构。底稿、报告等专业格式保留各自格式校验。

执行成功不等于成果审核通过；保存成功不等于用户请求完成；检查结果仅覆盖所读版本及范围。普通回答允许表达假设，金融数字和计算继续保留来源、期间、单位及操作数。runtime 不替模型选择原文、改变分类或修改研究结论。

每轮输入包含当前目标、当前工作对象与必要材料、最新成功结果、准确回读入口。历史原始操作独立保存，不通过“全部归档正文”再次塞回。跨任务交接只共享授权成果、条件与来源，不传子任务私有思考历史。任务改变/稿件换版时历史要求退出当前指导，必要材料独立复用。分批保存后按照未完成修改维持工作集，不按任意一次工具调用清空。

### 5.3 研究质量支持：先盘点已有指引，不再增加同义要求

本节中的“设计者引导”是产品研发提供的系统职责、方法资源、输入投影和评测机制；不是用户反复纠错或运维人员手工接续。保留人机协作能力，但它不替代自主研究能力的验收。

现有 `research_foundation/methods/research_loop.md` v3 已要求竞争解释、区分解释的观察、结果改变哪个前提和明确更新；`counter.md` 已要求替代机制与改变判断的条件；`research_contracts.py` 的任务/完成条件已有“解释什么、对总题的意义”；`working_memory_tools.py` 已支持自然语言笔记。不能将这些能力写成“过去没有指导，现在增加一句就解决”。

待改的是可消费的衔接：当前判断在哪里、什么时候进入实际请求、方法为什么值得选择、观察怎样连回判断，以及如何证明模型作出了更新。研究全面性、解释价值与观点正确性仍须行为验收，不可由某字段非空或工具被调用过自动认定。

### 5.4 当前研究理解的持久表示与输入投影（A/D）

复用已有工作笔记、底稿论断、来源/计算记录和 checkpoint。持续研究的工作理解以选定的版本化笔记为载体；正式成果仍由既有稿件/论断版本负责，不建立平行的“判断真值库”。笔记是可纠正的分析，不是原文证据，不能自动覆盖正式稿件。

| 内容 | 语义责任 | 保存与输入方式 |
| --- | --- | --- |
| 原问题、当前范围和当前待解释的问题 | 用户目标由宿主保留；模型可解释并提出相关展开 | 引用当前任务；范围真正变化才更新，不复制旧阶段义务 |
| 当前解释、重要假设和相关替代解释 | 模型表达，可以尚未形成判断 | 现有笔记自然语言，允许局部写；不强制列固定数量或每轮填满字段 |
| 依据、反常观察、能区分解释的未知信息 | 模型判断材料的意义；宿主保留材料身份 | 原文/CALC 引用与读取结果独立存在，摘要不能替代原件 |
| 判断发生了什么变化及简要理由 | 作者决定保留、收窄、改判或暂不决定 | 保存新笔记/成果版本；旧版可回读，不继续作为当前指导 |
| 眼下值得进行的动作 | 模型选择查询、计算、实验、委派、审阅或交付 | 复用现有工具调用；不要求先保存计划才允许实际执行 |

宿主新增的应是**引用和投影能力**，而不是强制研究表单：当前工作笔记的 ID/版本、目标成果版本、已消费的观察位置与方法引用可放入既有 checkpoint/context manifest。正文继续使用原笔记/成果存储；具体字段在实施时与现有同职责字段合并。无笔记时保持“当前尚未明确形成/保存解释”，不能由 runtime 根据搜过的关键词编造主张。

新观察进入时，输入中同时可见当前工作理解及这次结果；由模型判断是否改变解释。只发生一次读取不触发清空必要材料；已消费与仍需使用不同，不以“读过”自动推断可归档。模型写回理解后用最新版本替换当前投影，旧版进入历史；未保存输出和冲突回执不能默默丢失。源修订只标出哪些引用版本变化，不能由代码推断某个金融结论已被推翻。

`working_memory.py/tools` 复用保存/版本/回读；`model_context.py`、`context_navigation.py`、`conversation_handoff.py` 负责单份当前投影和历史入口；`research_contracts.py`、`task_outcome.py` 复用任务/论断/结果身份。现有 `DecisionArtifact` 不能作为每轮必填表机械套入。普通短回答不必创建笔记，保存失败不使有依据的回答失效，恢复时必须如实显示未保存。

### 5.5 设计者指引与 skill 披露（B/D，内容基线已确定）

2026-10-28将[基本指引](research_agent_guidance.zh-CN.md)与[七项方法](research_skill_curriculum.zh-CN.md#7-第一批内容范围)接入维护代码。普通对话、研究作者/Lead、复核/成文消费共享职责；方法目录和准确章节读取已接入个人/组织MCP及原生专家。确定性真实消息循环与模拟SDK验证输入，不等于付费研究效果或部署完成。

模型是否想到要检索，首先取决于它怎样理解问题和现有解释的不足。不能只提供检索按钮，再等待模型自发发现所有盲区。以下为指引职责的分层，不是新增多套 harness：

| 层次 | 给模型什么、在哪里给 | 用户与开发者可见性 | 明确不做 |
| --- | --- | --- | --- |
| 稳定职责 | `conversation_agent.py` 与共享作者指引中，简短说明对问题形成解释、寻找会改变答案的信息、据观察更新解释并选择下一步 | 用户看到工作方式说明；开发者可核对准确版本 | 不注入行业答案、固定解释数量或强制全篇核查框架 |
| 当前理解 | 5.4 的当前笔记/成果、必要新观察及准确回读入口，置于任务上下文 | 用户可看简要研究进展和版本变化 | 不回灌旧纠错全文，不要求展示私人思维过程 |
| 方法目录 | 复用 `get_research_method`：短摘要说明能解决什么困难、适用条件及局限 | 默认不在报告罗列目录；可查看采用的方法 | 不只写角色名，不把所有方法全文常驻输入 |
| 选择的方法 | 同一资源的相应章节/全文及版本；与当前问题关联 | 用户可展开方法依据；开发者可查实际加载内容 | 不复制到多个提示文件，不因已加载就宣称已运用 |
| 工具反馈 | 精确结果、范围、正常消歧、确定性错误与可执行回读参数 | 用户看到必要阻碍或成果；技术细节可展开 | 不靠工具报错强迫研究模型猜协议，不代写研究判断 |

建议在统一入口提供最小研究职责与可用方法的轻量索引，避免“必须先想到查目录，才知道有方法”的循环；模型据问题选择方法，相关全文按需读取。已加载内容以资源版本/摘要引用避免重复；如果正文退出输入，不能仅标为“曾读过”并假定模型仍记得，应保留同源简要要点和实际回读入口。方法摘要/章节与全文来自同一维护源，不单独手写一套相互漂移的摘要。

原METHOD_TOOL_GUIDANCE通用纠错/首次必读、research_loop固定核验/复核顺序、WORKING_MEMORY_GUIDANCE切题前必写笔记已在本片撤下。来源协议保留，章节成为可选知识。旧图的实际阶段调度尚未更改，B/C继续处理。

研究方法采用教材式编排：知识结构、机制与推导、完整算例、对比例和实际分析入口。通用方法详细解释如何由问题走到可判别的观察；专业方法按基础概念、领域机制、专题推导/案例及有日期的市场变化分层。模型已掌握的基础概念简述即可，容易混淆的机制和关键分析桥梁展开讲透。限制与误用集中在相关例子的解释中，权限规则由宿主管理，不在每份skill反复写“必须/禁止/注意”。最新市场材料与稳定方法分开版本化；材料日期、来源、已查范围与待刷新内容明确可见。具体教材与消费位置见[方法资源编排](research_skill_curriculum.zh-CN.md)。维护代码已接入，尚未部署。

例如“解释增长来源”的方法可指导：先提出相关的竞争解释，选择一个结果不同就会改变判断的观察；若现有资料无法区分，选择补查、计算、可行实验或给出条件性解释。它不应要求每次必须写出三个假设、读五篇财报、找一项反证才允许提交。首批打包方法已按此实现，具体效果待实际研究验证。

### 5.6 检验解释、研究审阅和系统兜底（B/C）

检验判断不等于寻找支持引文。模型需要自行选择能区分竞争解释的观察，检查来源是否有资格回答它；相关材料可以来自授权库内外、技术/历史/市场资料或可执行分析。不存在可观察判别条件时，可保留为暂不可检验的工作假设，不允许捏造精确概率或将未找到资料当反证。平台提供工具和状态，不替模型指定每个题目的正确拓展路线。

复用既有 verifier/counter 的节点能力，区分事实检查与研究视角审阅。后者获得原问题、作者当前解释、关键支持/相反依据和来源入口，可以指出作者未选中的相关机制；不能只拿旧任务清单逐项验收，也不能因审阅者提出一种可能性就自动判作者错误。作者仍须自行评估意见并更新成果。检查目标/版本/范围复用已有合同，修改后的检查不能自动扩成全案。

按需选择存在“模型没意识到就不调用”的盲区。需与用户确定的是**产品默认的研究审阅策略**，不是要求终端用户每次监督：候选方案包括由作者选择、对约定深度研究在首次完整解释后提供一次独立视角、或只在模型提出重要分歧时调用。默认策略与预算须验证后确定；不将任何候选方案先写成必经新流水线，不依赖 confidence 自评分或关键词分类器假装发现全部重要遗漏。

设计者的系统性兜底包括：确定性协议纠错、合法状态恢复；有明确预算的不同方法/模型或独立检查选择；无法完成时保留可用成果与具体未决。它不包括开发者代选来源、改研究结论后继续伪装自主运行，也不等于无限循环直到意见一致。对语义困难是否升级及升级后能否改善，需要行为证据，不能由字段校验担保。

## 6. 验收矩阵

先运行离线/确定性检查，再在双方确认的统一服务版本验证真实产品入口。付费验证另行确定任务范围、TokenBudgetBasis、上限及停止条件；本文不是付费授权。既有 AI case 用于材料/历史恢复回归，不全量重跑。

| 编号 | 场景 | 必须可观察的结果 | 不足以证明什么 |
| --- | --- | --- | --- |
| T1 | 普通问答 | 无研究/复核子任务，无报告自动包装 | 不证明金融推理正确 |
| T2 | 查资料并计算，只交底稿 | 保存真实底稿类型即可结束；来源/CALC/期间/单位可回读 | 不把未复核写成已复核 |
| T3 | 同一底稿继续追问并按需委派 | 复用成果，子任务有独立持久身份；重复请求幂等，重启后不重复执行成功工作 | 不要求模型必须委派 |
| T4 | 明确要求独立核查的报告 | 同一执行路径消费既有成果和检查结果；未完成指定检查不能冒充合格报告 | 不以复核通过代替报告质量 |
| T5 | 只改一处并局部检查 | 保存差异/版本及影响范围；必要关联检查允许，未改对象不自动重跑；旧检查不伪装新版通过 | 不硬编码只许修改一个字段 |
| T6 | 期间变更、人工编辑、父子任务取消/撤权/重启、未知调用 | 子任务输入固定且不超父授权；父更新不静默改子输入；停止传播与根预算归属持久可恢复，unknown只读核对；失败/未知用量保留；权限收回仍拒绝 | 不允许恢复脚本代写研究动作；不以主 Agent 收到消息代替停止传播 |
| T7 | 同输入投影回放 | 无旧阶段义务重复注入；成功材料与入口可用；分批保存后继续；稳定内容不重复携带 | 字符下降不等于材料充分 |
| T8 | 新旧入口与历史恢复 | 所有新任务只有一个调度入口；历史适配不能新建；旧 ID/版本能读；不双发模型请求 | 不以两个路径都通过算统一完成 |
| T9 | 浏览器连续使用 | 问答→底稿→追问/可选委派→成文→局部修订真实闭环；前后端显示同一身份/版本 | 不接受只跑 Python 诊断脚本 |

确定性回放保存：调用轨迹、输入投影、成果/检查版本、成功和失败回执、权限与预算行为；不手工修改模型原提案。发生工具问题先修实现，从干净停点复验。真实模型试验与工程回放分开计数。

费用/效率单列：每步实际输入/输出、缓存命中、重复读取、有效修改及模型调用数。冻结资料和比较口径再与现有路径对照，不预设必然省费，不削掉必要研究来过线。产品验收看是否完成用户工作；研究质量看推断和证据、取舍、文章价值，独立于运行成功。

### 研究判断的行为验收（待运行，不是模型必填表）
