使用已配置的工作台和保存结果即可演示，无须再跑一遍完整研究。每份报告的审阅状态会单独显示。公开截图来自实际产品，完整报告和原始资料并未随截图发布。

## 演示路线

| 时间 | 操作 | 说明 |
| --- | --- | --- |
| 0:00–0:25 | 打开起始页，查看项目侧栏与问题入口 | 研究问题是起点；侧栏分组保存在浏览器，任务和报告保存在服务端。 |
| 0:25–1:00 | 打开研究地图，总览 → 专题 → 判断 | 从内容结构进入，不需要把执行图当报告目录；选中判断后可继续追溯来源。 |
| 1:00–1:30 | 展开来源上下文，查看计算或原文 | 检查期间、单位、操作数和引用位置，区分算术正确与金融解释正确。 |
| 1:30–2:00 | 查看报告的修订对比，再收起 | 定向反馈包含目标和基线；实际修订保留旧报告，运行完成不等于人审接受。 |
| 2:00–2:30 | 打开研究配置，选择角色和 Skill | 查看可编辑方法、专家并行数和双审查顺序。保存版本会进入原生服务，再应用到任务；展示时不必写入。 |
| 2:30–3:00 | 查看运行记录，播放/暂停历史回放 | 阶段卡片与公开事件对应，费用保留整次运行用量；回放不调用模型。 |

## 工程讲解的三个切入点

**前端节点如何触发真实修改。** 报告章节负责导航，判断节点绑定产物 ID、版本、摘要和 checkpoint。BFF 校验基线，原生图执行修订；结果回到新的报告版本和实际差异。不会凭标题中的公司名选择硬编码修订逻辑。

**方法编辑如何生效。** 复用原生 Assistants 保存独立配置快照，每次运行固定读取。方法进入角色提示和 MCP 读取；专家上下文在请求摘要生成前绑定，保持已有回执校验一致。编排只开放已支持的顺序和并行设置，保留必需复核。

**证据与上下文如何共存。** 原始消息和产物保留在 checkpoint；下一次请求可以清理旧工具正文，再按 ID 回读。保存的计算保留来源及操作数，不因被重用而变成数据库权威事实。自动摘要仍关闭，缓存率不能当作压缩率或整体节费率。

实现入口见[架构](architecture.zh-CN.md)。实际失败与开发样本成本见[证据说明](sharing-scope.md)，没有用后续成功覆盖旧失败。

## 外部测试与反馈

没有完整研究数据时，按[快速开始](quickstart.zh-CN.md)运行源码检查和合成浏览器测试。它们可用于验证界面与接线，不能代替真实报告质量评估。发现问题请提供具体页面、操作步骤、预期/实际结果和代码版本；不要提交私有模型上下文或上传原文。

可展示的工程成果包括证据绑定、原生状态与人工修订、配置消费、费用可见性和多格式交付。生产高可用、全公司覆盖、无人辅助准确率与普遍降本比例仍未得到验证。
