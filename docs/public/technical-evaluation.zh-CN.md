# FinSight 投研 Agent 工程与实测报告

2026-09-11 · FIN 0.1.3 · 本地产品评测

[English](technical-evaluation.en.md) · [复现入口](quickstart.zh-CN.md) · [实测指标 JSON](evaluation-metrics.json)

FinSight 将投研过程组织为可接续的任务、带来源的财务计算、角色工作底稿和可人工修订的报告。此次评测围绕一个实际交付问题：模型已经取得资料或交出底稿后，解析、上下文、证据路线或审查环节不应使成果丢失；需要人工判断的地方应保留完整依据，并在产品中继续完成交付。

本报告分别呈现检索质量、真实对话表现、工程恢复与权限验证。候选命中率不等于答案正确率，人工完成不等于全部模型审查通过，开发机身份服务也不等于生产多租户验收。

![人工完成的 HPE 研究报告，保留版本、角色底稿和修改次数](images/hpe-reviewed-report.png)

## 系统分工

| 层次 | 实现与职责 |
| --- | --- |
| 工作台 | React 前端和 Python BFF；新研究、普通多轮对话、运行活动、直接编辑研究要求、角色底稿、人工修改及文件导出 |
| 执行 | LangGraph Agent Server 0.13.3、PostgreSQL、Redis；节点执行、并行、checkpoint、interrupt/resume 和运行状态 |
| Agent 工具循环 | LangChain 原生中间件；模型/工具调用限额、按需摘要与最终交付；Hermes 用于限定能力范围的会话与工作记忆对照 |
| 工作记忆 | 自然语言底稿、版本化追加、乐观并发检查、按 owner/thread 分区；来源原文、计算回执和对话保持独立定位 |
| 研究资料 | BM25、Qwen text-embedding-v4、qwen3-rerank；原文定位、固定快照、已完成调用缓存 |
| 财务数据 | 既有 SEC companyfacts 解析器与 SQLite fact mart；标准指标按需派生，保留主体、期间、单位、公式及来源凭证 |
| 身份与边界 | OIDC、PKCE、签名会话、服务端资源归属检查；Docker 隔离及原生审批恢复测试 |

FIN 代码负责研究范围、财务对象和交付语义，通用执行和持久化交给已有运行框架。工程日志与自然语言工作底稿分开：前者用于审计和排错，后者供研究者阅读、修改和检索。底稿或摘要不会自动变成来源事实。

## 真实任务与交付

| 场景 | 实际观察 | 验证口径 |
| --- | --- | --- |
| HPE FY2025 收入、利润、现金和并购可比性 | 保留报告 v2、人工修改 2 次；角色→底稿→全文差异可展开并滚动；MD、PDF、Word 实际下载 | 人工确认的完成版；独立模型审查的未完成记录没有被抹去 |
| MSFT 数据查询与跨主题对话 | 收入/CFO、现金资本支出/派生 FCF、工作底稿、HPE 人工版、HTTP 缓存、范围撤回、假设题和交接 | 17 个同窗口用户回合包含 5 次有原因的局部恢复；重启后再完成 2 个新窗口回合 |
| 非金融问答 | 读取 RFC 9111，解释 no-cache、no-store 等缓存指令，并从真实界面导出三种文件 | 使用实际来源和工具，不要求所有问题进入多专家投研流程 |
| Hermes/原生对照 | 同一三轮假设题：CFO 120、capex 40，随后更正 capex 为 50；保存新版并回读原始更正，最终 FCF 70 | 两种执行方式均完成；不是长历史、多 Agent 全流程或严格等工具消融 |
| 自定义研究方向 | 实际保存方向名称、方法与任务配置；检验 MSFT 六项两财年数字的研究路径 | 已修复双入口数据快照分裂；完成 v2/人工修改 2 次、两份角色底稿、数据图表、三格式导出和个人研究记忆保存 |

19 个真实用户回合共记录 **81 次模型请求、1,231,464 tokens、0 个用量未知请求**。这些成本包含失败、摘要和局部恢复，不能仅报告最终成功回合。12 个原始意图和 2 个交接意图最终获得回答；不是“19 个独立用例全部首遍通过”。

Hermes 三轮为 **8 次请求、44,961 tokens**，原生同题为 **10 次请求、65,713 tokens**。原生额外使用了计算器，工具集合不完全相同，因此这组结果只证明有限工作记忆闭环可用，不据此宣称 Hermes 节费比例或整体替换优越性。

## MSFT 自定义研究的最终交付与成本

该题现已完成 **报告 v2、人工修改 2 次、两份角色底稿、一幅数据图表**，并在前端保存到个人研究记忆。完整财年 FY2024→FY2025 的 CFO 为 118,548→136,162、现金资本开支 44,477→64,551、派生 FCF 74,071→71,611，单位为百万美元。图表复用同一数值凭证及公式，不由作者再手写数字。

工程数据绑定修复后，两份底稿取得正确数值。后续仍遇到两类问题：旧案例已审阅路线被当作当前用户题目的必需条件，以及模型错误解读比较财年并把超出本题的口径资料列为交付前提。修复当前问题的路线投影后，使用已有 checkpoint 人工接续：逐项处理审查请求、保留原审查与底稿、仅将修订后的正文交给写作节点。最终人工确认又明确区分四项原始财务观测和两项派生 FCF，并校准图表说明及条件表述。

| 执行段 | 模型请求 | 已知 tokens | 估算费用（元） |
| --- | ---: | ---: | ---: |
| 初次运行，错误数据快照导致缺口 | 43 | 1,542,624 | 1.573728 |
| 修复数据后，交出两份底稿 | 27 | 927,019 | 1.091936 |
| 范围确认后独立审查 | 38 | 1,321,253 | 1.214529 |
| 人工修改底稿后写作与报告核验 | 17 | 672,006 | 0.752876 |
| 最终前端人工确认与保存记忆 | 0 | 0 | 0 |
| **合计** | **125** | **4,462,902** | **4.633069** |

用量未知为 0。价格按请求当日及时段的公开费率估算，不是账单。修复后实际交付窗口为 82 请求/2,920,278 tokens；必须同时保留首轮成本，不能以窗口拆分隐藏失败。这组实验证明了修复后人工参与交付的闭环，但**不能作为小题低成本、高效或首遍自动通过的样例**。审查的重复读取和范围判断仍偏重；没有继续整题付费重跑。

![MSFT 最终报告与已完成研究工作区](images/msft-reviewed-report.png)

HPE、MSFT 自定义研究、普通数据问答和非金融问答均从真实前端下载 MD/PDF/Word。PDF 已渲染检查；Word 的 ZIP/OOXML、表格和图片结构已检查，当前机器无可用的 Word 渲染器，未宣称逐页 Word 视觉验收。导出附录保留来源与计算凭证，复杂报告仍可较长。

## 同资料检索对照

资料包括 HPE、MSFT 财务材料与 RFC 原文，共 **739 个来源叶节点、1,105 个检索片段、1,456,098 字符**。28 条查询分为开发 14 条和验证 14 条；每组包含 12 条有答案问题及 2 条无答案问题。正例指标按已标注的原文锚点计算，标注不保证穷尽全部相关段落。

| 方法 | 开发 Hit@5 | 验证 Hit@5 | 验证锚点 Recall@5 | 验证 MRR@20 |
| --- | ---: | ---: | ---: | ---: |
| BM25 | 5/12 | 7/12 | 0.4037 | 0.4608 |
| Qwen 向量 | 8/12 | 9/12 | 0.5565 | 0.5759 |
| BM25 + 向量 + Qwen 重排 | 11/12 | 12/12 | 0.8494 | 0.8056 |

合并 24 个正例，混合检索 Hit@5 为 **23/24（95.8%）**，BM25 为 **12/24（50.0%）**。这里的含义是前五个候选中存在标注支持段落，不能写成金融回答准确率。4 个无答案问题没有混入这个分母，也不据此宣称拒答正确率。

向量使用 text-embedding-v4、1,024 维；BM25 与向量候选合并后交 qwen3-rerank。中文查询曾被 ASCII 分词误判为空，修复采用 jieba 搜索分词；修复后重放使用既有缓存。由于已查看验证输出，此次评测是公开标签的工程验证，不是盲测，也不宣称统计显著性。

检索共 **167 次已完成 API 请求**：embedding 317,882 tokens，rerank 370,916 tokens，总计 688,798 tokens；重复同请求使用缓存，不新增 API 调用。按核查时两项模型均为 0.0005 元/千 tokens 的价格，估算 **¥0.344399**，未扣免费额度，不代表账户实际扣款。[阿里云知识库计费说明](https://help.aliyun.com/zh/model-studio/billing-for-knowledge-base)

## 发现的工程问题与修复

| 问题与影响 | 已采取的修复 | 证据 |
| --- | --- | --- |
| 人工改过报告，但后续工具仍读取旧底稿 | 当前读取应用版本化人工正文；原始 claims/source 保留 | 基于已保存 HPE 报告的两次追问，7 请求、112,863 tokens；正确保留人工口径并拒绝无依据反向改写 |
| 重写整篇工作底稿耗尽输出后导致保存失败 | 支持只追加新增自然语言内容，使用基线版本 CAS；旧版本不变 | 追加、版本冲突与角色归属回归；真实长对话底稿迭代至 v5 |
| 已读工具结果和参数反复进入上下文 | 通过原有回读工具，将已读历史投影为定位符；保留未读内容、错误和原 checkpoint | 零模型失败回放中请求消息从 208,296 字符缩至 21,544 字符；只代表结构压缩，不是语义准确率 |
| 生命周期摘要次数耗尽后，后续正常回合无法继续 | 使用原生摘要中间件，每个新用户回合最多一次按需摘要；不把摘要当事实 | 同窗口接续及实际服务重启后的跨窗口原文回读 |
| 工具限额或模型工具协议文字被当成成功答案 | 最后允许的模型调用转交付；禁止继续超额工具；已识别非答案标记需处理并禁止导出 | 局部接续交付成功；原失败、未知状态及原始响应保留 |
| 浏览器断流后重试可能再次提交 | owner、请求键、正文指纹绑定的持久化回执；结果未知时不自动重发 | 浏览器断流回归；实际服务重启前后 3 次请求对应同一草稿、0 模型运行 |
| 新研究与普通对话使用不同公司数据池 | 合并兼容的已捕获来源，用同一只读快照绑定两个入口，来源冲突拒绝 | 5 公司 2,274 行；5 公司×2 财年的 10 批查询，数值、期间、单位全部一致，0 模型 |

数据池包括 DELL、HPE、MSFT、MU、NVDA。10 批查询各比较 CFO、资本支出与 FCF；这些检查证明入口一致，不替代所有 SEC 标签和金融定义的独立质量审查。原研究失败的 **43 请求、1,542,624 tokens** 保留计入实验成本，不能归为模型知识问题或从成功指标中删除。

## 身份、隔离与故障验证

实际 Keycloak 身份服务完成两个用户的浏览器 PKCE 登录与退出，并验证安全会话 cookie。39 项真实 HTTP 资源检查覆盖研究、附件、底稿、上下文、人工历史、导出和配置归属；另做 8 个并发只读请求。原生用户边界由服务端提供，不能由模型参数或浏览器自行决定。

Docker 隔离完成 3 个真实容器场景；原生 checkpoint 重开后，经 HTTP MCP 到 Docker 的审批链验证 4 个权限场景。随后操作者手动启动本机 18796 服务，宿主与 native 容器鉴权/工具目录/挂载凭据一致性检查通过。**真实产品前端四个场景全部通过：标准模式拒绝后零容器、标准模式批准后执行、代我批准、完全访问。** 两个标准模式场景批准决定前均无容器活动；后三种执行各创建并清理一个禁网、只读根目录、非 root、无宿主挂载容器，返回固定打印结果。共 8 个真实模型请求、45,609 已报告 tokens、未知0，产品计价估算 ¥0.01205（非账单）。新窗口只读回看四份结果通过。此前策略拒绝/解释器错误保留为部署过程证据；当前完成的是本地 native 对话接入，仍需保持操作者终端开启，不包含生产服务托管或 Hermes sandbox 接入。

公共前端回归此次评测 **36 项通过**，覆盖 390、1,024、1,440 像素视口；最后一组集成 Python 回归 **104 项通过、5 项私有材料条件跳过**（先前 85 项组与之有重叠）。另有针对数据入口和研究路线的定向检查，与这些集合存在重叠，不能相加成独立测试总量。人工图表说明新增桌面/移动两项检查亦通过，与上述回归不相加。公共前端测试使用明确的模拟 API；上述身份、导出和重启结果另以实际服务验证。

## 复现与适用边界

[题目、来源清单与逐题结果](evaluation/README.md)保留了公开标注和前五候选，可用于核对已发表的检索指标。记录不包含完整私有原文；重新排名需要相应资料或重新标注的新语料。

当前代码的可复现检查见[本地验证指南](quickstart.zh-CN.md)，涵盖检索、配置、修订、导出和界面交互，不要求模型凭据。历史评测使用当时的实验实现，重放方法见[评测记录说明](evaluation/README.md)；不把已归档脚本列作当前启动入口。

真实沙箱服务的配置、连接检查和使用条件见[本地沙箱](../architecture/local_sandbox_operator.zh-CN.md)。原始资料、账户配置及模型原始响应不随源码提供。

当前证据支持受控本地使用、可审计的人工完成及有限跨主题接续。生产身份运维、sandbox 生产托管及 Hermes 接入、跨机器幂等与配额、长期多 Agent 全局重排、无限长记忆保真仍不在已验证承诺内。模型可能继续出现过强归因、口径混淆、呈现偏好不遵循；产品应保留来源、角色底稿和具体修改历史，允许人类修订，而不靠反复整题重跑追求一次生成完美。
