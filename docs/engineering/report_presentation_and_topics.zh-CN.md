# 报告阅读、版本与研究议题

报告展示复用已保存的正文、引用和图表，不调用模型重写内容，也不表示研究结论已经通过复核。

## 阅读与成文

- Markdown 表格使用语义化表头、行分隔和交替底色；宽表在自身区域横向滚动，不挤压页面或把公司名逐字拆开。
- 引用默认展示来源标题、网站及已有期间信息。正文仍使用数字引用；点击读取当前选中稿件绑定的快照。内部定位符放在展开信息中，身份不变。
- 作者可以使用 Markdown 表格、紧邻相关段落的附注，以及已有的来源绑定图表。图表新增可选 `after_heading`，填写正文中唯一的标题文字，显示在该节末尾。未填写、重复或找不到的标题不会丢图，保留在文末。模型自己决定是否需要图表；平台不从文字猜造数据。
- 网页、HTML、PDF、Word、PowerPoint 和 Markdown 导出复用同一位置语义。图片与公式仍保留原有来源和单位。

## 连续会话和历史整理

普通追问、复核和修订继续使用当前研究会话，沿用原生检查点和稿件版本。成果页的“查看版本与本轮变化”支持历史正文、与当前版本比较，并使引用、图表及导出对应所选版本。旧版检查结论不会自动变成新版通过。

研究输入按显式 `topic_id` 归组。新议题默认以自己的输入 ID 为议题身份；只有明确创建实验分支时传入 `parent_draft_id` 和 `revision_note`，继承原议题。改变输入、截止日或独立实验应说明本轮变化。普通接续不需要复制研究输入。

已有独立记录可以通过“整理到已有研究议题”关联。相同标题不自动等于同一研究；归组不拼接原生会话、不覆盖问题或固定资料版本、不删除旧运行。成果页可比较同议题独立研究的当前保存稿，并明确标为跨研究对照。列表按页加载，组内数量明确是本页数量。

## 接口与兼容

Java 的 V15 迁移添加 `topic_id`、`parent_draft_id`、`revision_note`。旧记录默认独立，不修改输入 manifest 或其摘要。`PUT /v1/workspaces/projects/{project}/research-drafts/{id}/topic` 接受 `target_draft_id`、`expected_topic_id` 和 `revision_note`，检查项目写权限、双方输入权限及并发版本，保留审计记录。BFF 使用同一委托和 CSRF 入口。

组织成果在现有路径 `/api/v1/organization-projects/{project}/research/{execution}` 下增加：

- `GET /report-versions?before=checkpoint`：原生历史分页，只向浏览器返回版本目录。
- `GET /report-versions/{checkpoint}`：读取指定保存稿。
- `GET /report-diff?before=checkpoint`，或 `?before_execution=execution`：实际正文差异、引用和图表变化状态。
- `GET /report/charts/{index}.png?checkpoint_id=checkpoint`：该版图表。

这些读取仍经过当前项目及资料权限校验，不因归组而扩大授权。历史版本尚无报告时明确返回不可比较，不生成虚构差异。

## 验证边界

Python 用例覆盖引用权限、历史检查点、版本差异、图表位置及导出；Java 用例覆盖议题继承、关联、并发和输入不可变；浏览器用例覆盖桌面/移动宽度、可读引用、历史版本及来源权限撤销。无模型验收证明交付链路，不证明作者一定会选择有价值的图表，更不替代金融结论复核。
