# 研究上下文：完整档案与当前工作台

## 修订来源的准确回读

修订引用导航中的 `saved_reads` 从该作者原生日志的成功回执生成：仅匹配包含完整原文、数值或计算对象的准确身份，并提供 `ReadResearchHistoryAction` 的完整参数。模型无需从 `WEB::` 等 ID 猜测 `source_space`。找不到完整原件时明确列入 `unlocated_source_ids`，不把候选元数据或失败回执变成原文，也不跨作者读取；引用语义及原稿状态不因此获得批准。

历史工具的 `section=operation` 必须填写 `tool_call_id`，不能填写 `index`；`source_ids` 仅筛选该操作回执内的原始对象，不能独立定位或跨操作搜索。`turn` 和 `lead_assistance` 才使用 `index`。工具说明与参数错误均说明这一条件。旧参数及日志身份保持兼容，原始回执不改写。

## Lead 负责最终成稿

默认研究配置由同一研究负责人接续自己的综合判断、成稿，并处理独立复核后的修改。节点的 `writer` wire ID 保持兼容，但启用 `authoring.enabled` 时职责为 Research Lead，不再是接收底稿的独立作者。旧运行的冻结配置可能关闭该开关；接续时必须显式核对并记录迁移，不能只凭仓库默认值声称已启用。

已有 Lead 综合稿时，`prepare_writing` 只绑定当前研究状态，不再调用模型重复生成写作摘要。绑定保留原问题、截止日期、当前底稿版本、综合稿及完整来源、最新复核结果。模型输入提供当前判断与准确来源回读入口，完整来源对象和历史修订留在原生状态。没有综合状态的直接成稿路径仍由 Lead 自行准备，不凭空生成宿主判断。

这是显式恢复负责人的有效研究状态，不声称新请求自动记得旧对话。正文依据当前研究解释发现与意义；修正融入当前论述，工具故障与复核轮次保留在审计记录。表达问题回到 Lead，实质研究问题仍回到对应作者；独立复核与真实未决检查不会因成稿责任变化被跳过。

Lead 的准备与成稿阶段复用原 `synthesis:report` 工作笔记身份，不再写入独立 Writer 的笔记空间。既有综合笔记可继续回读；独立复核者及历史独立 Writer 的笔记身份不变。

工程验收覆盖同一综合状态直接成稿、最终复核退回后同一负责人局部修订、恢复旧报告时保留最新反馈和资料限制、底稿版本变化后旧绑定失效。真实案例成文质量另行检查，测试通过不代表研报质量通过。

原生 LangGraph checkpoint / notebook 保存完整历史。模型请求是从档案重建的工作视图，不等于完整运行日志。FIN 负责来源与研究状态语义，不另建消息持久化系统。投影不修改原件、引用权限、调用计数或付费回执。

Lead 在一批委派任务实际返回后也有明确的上下文边界。下一次请求以图中当前问题、任务计划、全部已提交底稿、未提交任务的公开状态、累计额度，以及已执行的公开规划动作和全部规划来源观察重建。旧的委派调用与回执、旧计划快照和旧思考内容保留在原运行档案，不再逐批叠进下一次输入。这里没有额外摘要模型，也不由宿主重写研究判断。来源观察沿用既有语义投影，完整来源身份、原文与必要条件仍保留；底稿内容不做语义裁剪。

这个边界只发生在委派或继续任务的结果已经收齐之后。普通来源读取、无效参数反馈及尚未完成的工具循环仍保留供应商要求的消息和思考配对。新请求从当前状态开始一个完整的对话片段，不发送缺少前置调用的孤立工具回执。研究权限、任务依赖、已用轮次、未决事项和费用账本均不重置。测试通过只证明交接与协议正确，仍须用真实研究结果检验 Lead 能否继续判断和成文。

独立复核在本地输入保护或同批停止时，保留已完成消息与工具结果的恢复状态；没有发送供应商请求的停止不应丢弃已读资料。继续执行仍走明确的恢复入口，原错误与累计用量保留。付费请求失败或响应不完整仍不自动重发。本地恢复状态不是复核提交，也不是金融结论通过。

恢复时一并保留已接受摘要、其原历史边界与失败标记。可选压缩失败只拒绝该摘要，保留上一次工作视图，不触发同批其他复核器停机，也不自动再次压缩；主要研究请求继续受自身输入校验约束。复核文本中的 `NUMFACT::…=数值` 是引用标注，不应仅因 ID 尾部数字触发新增算术校验。

复核器提交完整替代稿后，模型请求只保留最新候选与对应校验反馈。更早且已有失败回执的提交参数转为替代关系标记，原调用仍在档案；未完成调用、成功提交、来源读取和已登记发现不做这种替代。无需让模型每次修改都继续携带所有旧版整稿。

## 当前版本的职责

每轮提供原任务与用户修正、最新工作状态、当前材料及历史回读入口。来源、期间、单位、修订及 actual/guidance 身份保持原样；工作笔记是作者判断，不自动变成可引用证据。

新派工的 `objective` 描述需要回答的问题及其对总题的用途，`success_criteria` 验收回答、决定性依据、竞争解释和未决项的影响。资料核对是支撑工作，不能要求一个初始假设永远保持“待核”，也不能以来源齐备代替问题已回答。Lead 的交接保留当前回答与理由，供后续评估，而不只给审查清单。窄取数／审计任务保留其范围；旧运行的任务和验收原件不回写。新的从空历史运行不加载旧分工、底稿、笔记或修复清单，新的实际请求须单独核对。

有正式知识库权限时，完整研究的 Lead 与专家使用同一来源空间说明，并向 Lead 提供 `source_space=library` 的目录入口。`local` 保留为冻结文档树及其原有 ID 的读取空间；其目录数量与公司构成不能定义总题范围，也不代表整个知识库。局部目录回执说明这一范围并给出已授权的知识库入口；参数校验错误不证明数据库未加载。旧请求的默认值和序列化保持兼容，不重写归档原件。

- 模型维护当前认识：已有发现、当前判断、关键未决项和下一步。无需每次工具调用后写笔记。
- runtime 保存完整结果，合并精确重复，替代旧状态并组织回读入口。相似文字不做语义合并。
- 只有当前共同核对的来源放入 `retain_source_ids`。旧发现、旧计算或旧草稿引用过一条来源，不再意味着它永久驻留输入。
- 未完成调用及没有可靠回读方式的结果保留。没有作者明确选择时，保留最新**实际返回可引用原文／数值**的材料批次；一批新的完整材料仍在当前未消费回执中时，额外保留紧邻上一批，仅供下一轮跨来源核对。目录、搜索候选、方法和其他导航回执不会替换当前原文。更长的共同核对仍由 `retain_source_ids` 明确选择，或按原操作回读。恢复 observations 与实时 ToolMessages 使用同一规则。
- 输入压力提醒不关闭工具，也不因两次笔记错误终止研究。

专家若仍触发发送前的输入体量保护，其未完成状态交回 Lead；其他已分配、依赖满足的任务仍可继续。调度排除已经尝试过的专家，不自动重发该请求或重置其额度。供应商执行失败、用量未知及执行额度耗尽仍保留原停止规则。Lead 必须在交付中说明未完成项，不能把任务隔离当成问题已经解决。

专家输入可接受的宿主配置上界与运行配置保持一致（48 次模型调用、96 次工具动作），默认值不变。每项运行仍须事先设置自己的额度和 TokenBudgetBasis；到达额度保留未完成状态，不自动扩容、重置或重试。历史付费 shadow 的授权上限保持原样。容量可配置不意味着需要把每项任务都运行到上界。

外部资料发现、检索、正文读取与计算使用外部工具额度。`PrepareWorkpaperAction` 只把已经取得并选定的材料绑定到本地写作上下文，不派发外部请求、不增加外部动作计数，也不能因外部读取额度已满而被拒绝；后续引用、范围、数值与底稿提交校验照常执行。这样额度停止的是继续取数，而不是阻断已有研究材料进入可校验的交付阶段。

## 状态更新与局部修正

### 已接受底稿的分批修订工作视图

这一阶段的执行窗口由宿主状态投影，不增加作者需要填写的计划。默认显示第一条尚未保存本轮答复的复核问题、按准确 `claim_id` 定位的当前论断，以及原文引句在当前正文中完全匹配的位置。不做模糊匹配，也不按宿主猜测金融关联。全文、各字段、全部论断 ID、复核要求和当前错误仍有准确入口；作者可读取并修改关联内容，当前焦点不是字段白名单。

宿主继续保存并执行节点、共享调用和输入体量硬上限。修订视图不再重复展示剩余轮数倒计时，只说明当前请求是否有额度、耗尽时保存未完成状态，并提供精确预算回读。该投影不增加额度，不预留或承诺后续调用，不允许省略最终校验。普通首次研究仍保留其预算视图。

`SaveWorkpaperEditsAction` 的保存次数、版本摘要和最近变更字段直接作为修订接续状态；不再向此阶段注入 `working_state_guidance` 或体量触发的额外写笔记提醒。可选笔记工具保持可用，已有失败提案和错误不会被抹掉。删除重复的 `submission_to_repair.revision_guidance`，修订职责只由现有 `revision_instruction` 与保存／提交契约负责。旧档案中的重复指导仅退出请求视图，原始日志不改写。

保存后重新投影当前稿件。只有本轮草稿实际保存、且不同于已接受基线的 finding response 才计作作者已答复；旧答复不能自动完成新复核。答复存在也不代表内容正确，仍须显式最终提交并通过完整校验。保存成功不能因 `accepted=false` 被误判为保存失败；局部失败保留已保存版本和具体错误。材料继续依照修订工作集生命周期保留，不因一次保存、读取或计算自动退出。

离线回放 `scripts/engineering/replay_revision_material_lifecycle.py` 默认验证三次实际请求，也支持 `--expected-requests 1 --initial-materials-wire <最初七份材料的SDK请求>` 验证单次停点。使用真实记录的副本验证连续保存、序列化接续、坏批次、最终校验拒绝与共享额度为零时禁止模型执行；逐项核对材料、字段回读和原始文件哈希。脚本禁网，不将合成修改发布为研究成果。离线通过不代表模型已停止反复权衡或实际费用已下降。

`UpdateResearchStateAction.working_state` 替换当前叙述、发现、未决问题和已排除解释。旧版本保存在原生历史，不自动追加回来。取消旧笔记的 24 条合并上限及当前列表的条数门槛；实际请求和执行预算仍生效。模型负责保留有意义的剩余问题，不要求逐字抄写旧描述。

子任务按稳定 `task_id` 更新。省略字段保持不变，显式 null 清空可选字段；新任务仍需目标和状态。父子关系、循环、完成项依据结构检查保留。未知来源改为下述引用标记，不拒绝整份作者状态。`migrated_questions` 只是可选历史说明，不再要求精确字符串迁移才能移除旧问题。

完整 working_state 被误放到动作外层时，仅在没有嵌套 working_state 且关键字段齐全时自动归入该字段，继续执行同样的结构与来源检查。混合新旧位置、未知字段和语义缺项仍反馈具体问题。省略保存理由采用固定操作说明；不补写研究内容。原始模型动作仍留档。

### 引用拼写修复与错误标记

工作状态中的长引用 ID 在本任务成功返回的结构化身份集合内解析，不搜索原文里的任意字符串。相同命名空间、至少16位身份尾部的唯一前缀，或单字符插入／删除／替换，能唯一匹配时自动修正；回执逐项记录原 ID、修正后 ID 和字段路径。多候选、短标签、跨命名空间及未见引用不猜测。原模型动作和原观察记录不改写。

无法修复的引用保留原值，并由 runtime 重算 `reference_issues`，状态仍接受。标记随状态进入后续模型请求；不把未解析引用提升为可用证据，也不绕过最终底稿的原文／引文／数字校验。这解决的是工作进度保存被标识符笔误阻塞，不是自动证明金融论述正确。

### 模型主动释放已读内容

`UpdateResearchStateAction` 可单独提交 `release_source_ids`，不需要提交整份 working_state、写笔记或声明研究完成。选择已经返回的文档、段落、公司或计算 ID；runtime 保存释放时的模型轮次，之后仅对该时点以前成功且可准确回读的结果做请求视图投影。正文、目录行或计算值被替换为曾经读取的身份及原工具／参数；存档不删除。指定某个文件只释放该文件卡，指定公司可释放该公司资料菜单。失败、不明结构、没有回读入口的结果不隐藏。

后续重新读取相同资料正常展示，不受旧释放命令持续压制。正常运行和恢复运行使用相同规则；恢复绑定原 observation 和轮次，缓存回读记录新的打开轮次，现有原生缓存回读不重新调用外部检索。财务／计算默认仍保留，仅在显式释放时使用同一回读机制。释放与研究状态保存分开，待修草稿不会被一条释放命令丢弃。

校验失败保持接受状态不变，将草稿保存为 `pending_working_state_update`，返回具体错误及 `pending_update_digest`。模型可在同一个工具中省略 working_state，提交 digest 和 `edits: [{path, value}]`，只修正相应字段。路径采用 JSON Pointer，由现有 jsonpatch 库执行；修改后整份草稿重新校验。过期 digest 不生效，也可直接提交替代草稿。

待修草稿跨恢复保留。原子性仅针对当前更新，不暂停其他研究工具，不默默保存部分修改。接受后清除待修草稿。保存成功不代表研究完成或金融判断正确。

## 去重、归档与周期整理

### 提交结果必须留在对应的工具回执中

原生工具接口的单条提交、修订与交接也经过同一个 ToolNode 执行入口，不再把有效的单条提交解包到不产生工具回执的另一条路径。引用校验拒绝时，紧跟该调用的结果明确保留 `accepted: false`、具体反馈和错误位置；当前状态可移到统一工作视图，操作结果不能随之变成空对象。旧 checkpoint 的直接提交由宿主实际保存的拒绝状态恢复同样的结果，不把作者正文中的“已提交”视为成功。

这只修复反馈交接。原文、期间、单位和引用校验仍然执行；需要作者修改的转述及错误来源绑定不会自动接受。离线 SDK 回放覆盖“引用被拒绝 → 明确回执 → 作者修正 → 接受”，不代表真实模型一定会正确修复或报告判断已通过。

### 资料目录与正文的请求视图

公司／文档发现返回的是导航候选；读取才返回可引用原文。完整 observations 和审计回执继续存储，模型视图由 `source_result_view.py` 统一处理，供 Lead 预研究、专家实时工具结果及恢复后的 SDK 请求使用，不改变外部数据接口或来源身份。

已识别的公司 sources 菜单不附带完整资料卡、地址、上市核查过程和其他数据库频道统计。每条文件保留标题、日期、期间、类型、预览、身份、覆盖限制、修订关系和明确 outline 入口；总数、分页及未知范围信息保留。详细解析过程留在原观察／实际文档读取中；这不是减少候选数，也不是把读不到的内容标为未披露。明确请求的正文不在投影层截断，模型仍可按章节、节点或窗口展开。

菜单中各文件完全相同的覆盖说明提升为 `shared_document_coverage` 一次展示，差异继续留在对应文件。文件 URL 留在原记录中，菜单通过 document_id 及实际 outline/search/read 路由打开；不把导航记录赋予正文引用权限。

对于明确的 `retrieval_candidate` / `source_bound_passage`，将 JSON 字符串形式的 `metadata` 与嵌套 `routing_metadata_v1` 解码成对象，只去掉完全相同的副本，以及解析器名称、资料卡实现版本。顶层已有相同值的日期、URL、覆盖说明不重复展开。来源期间、发布时间与可知日、修订关系、单位、读取限制和未知字段保留；冲突值并列保留，无法解码的元信息原样保留。正文字符串不解析、不改写、不截断，不减少候选数量。

既有宿主回执过滤仍生效；不能把存档体积当作模型实际输入。SDK 投影对旧消息同样应用上述处理，保留 tool_call_id 配对和供应商要求的思考字段。模型输入中的精简不会删除原生存档，也不会赋予目录证据权限。`test_source_result_view.py` 覆盖元信息冲突、未知格式、正文／回读／修订身份，以及 mock HTTP transport 上新旧状态的相同输出。

流程为：保存原件 → 精确去重 → 模型更新认识 → 归档已完成历史 → 继续研究。

原生专家会话由 `research_context_view.py` 从完整调用日志生成单一当前视图。该路径替代旧的逐条 Human 归档消息、历史上下文快照与重复参数回读通知；不会再依次运行旧自动保留规则。当前任务、用户指导、执行额度、已接受状态和宿主待修稿只保留当前版本。初始化时恢复的 observations、旧动作与旧反馈退出默认输入，可用 `ReadResearchHistoryAction(section="operation", tool_call_id="runtime:initial-context")` 回读。

工作材料由最新明确选择的 `retain_source_ids` 和一个短暂的相邻材料交接构成。模型提出的完整来源选择可以在工作笔记局部校验失败时更新材料视图，但不接受其判断或状态。没有明确选择时，runtime 保留最新实际返回完整原文／数值的批次；若该批次尚在当前未消费回执中，再带上紧邻上一批，供模型完成一次比较。模型作出下一步动作后，较早一批退出默认输入；一次目录、搜索、方法或其他导航动作不会让当前正文退出。当前未通过的笔记、字段错误和宿主待修稿保持可修复；后续读取不把尚待修的笔记吞掉。未知引用仍标记为未观察；后续已取得对应原件时只更新请求内的可用性提示，不宣称该主张已验证。不同来源版本、期间、单位和权限不按名字合并。

当前原文、财务事实和计算对象不在请求投影层被任意截断；必要的引用绑定随对象保留。同一完整对象已经位于最新原生工具回执时，材料区不再复制它。专家经 `source_space=web` 读取网页时，单次窗口上限为 24,000 字符，保留同一 document ID、offset、完整捕获档案与 `next_offset`；这不是删除正文，而是要求按实际所需范围分页。旧材料、早期目录和已消费回执只保留公开操作目录：原调用 ID、工具名、用途和状态。财务与计算回执不因类型特殊永久留在输入；未选中的对象保存在日志并可原样回读。显式释放操作仍生效，释放后的新读取仍可见。

委派子任务沿用同一读取和归档接口：`ReadDelegatedWorkAction` 默认返回概览，`sources` 分页列目录，`handoff` 按来源 ID 取原件，`analysis` 按判断 ID 或字段取作者分析。显式 `workpaper` / `source` 保持兼容；旧调用省略 section 时，历史回读入口补明 `workpaper`，不会把原来全文读取变成概览。作者分析中的引用不把整份底稿永久固定在工作视图中。无效来源选择返回局部反馈，可继续读取准确目录；已存底稿及成功原件不受影响。

`ReadResearchHistoryAction(section="operation")` 按目录中的 `tool_call_id` 回读本专家原生日志中的公开参数和结果，包括失败状态。小记录直接返回；较大的旧记录默认返回最多 12,000 字符的导航窗口、可用来源 ID 和 `next_offset`，避免把整页历史网页再次塞回模型输入。作者可用准确的 `source_ids` 取得选定的完整原文／数值／计算对象，或按 `next_offset` 继续读取；原生日志始终保留完整对象。接口不重新派发原工具，不调用模型，不消耗原请求的补发授权，不返回私有思考；普通工具次数预算仍适用。旧 `turn`、`lead_assistance` 的 `index` 方式继续兼容。未接线返回运行环境错误，未知 ID 返回定位错误，两者都不是来源未披露。

最新原生调用批次及尚未完成的调用保留完整配对和供应商要求的思考字段。来源读取在工具层按下述完整条目分页；最新批次保留的是实际返回的页，不自动展开其余页。已消费批次整体退出请求，公开参数、结果与私有思考仍保存在原日志。SDK 请求投影不得覆盖 `_agentic_history` 或私有审计中的 canonical messages；重启恢复同一作者后仍可读回旧回执。普通用户消息和系统指令保留，来源正文不作为运行指令。

### 首次交接与当前目录

`ReadDependencyWorkAction` / `ReadDelegatedWorkAction` 的 `handoff` 返回所选来源的完整条目，精确去重同一条目，避免附带同批观察中的其他数值或段落。宿主来源登记仍使用未改动的原始观察，显示视图以 `original_observation_digest` 指回原观察，不能冒充一份重新签名的完整回执。原文、期间、单位、条件和公式依据不截断；目录 `sources` 仍不返回正文或授予引用权限。

`max_characters` 默认 16,000，是每页完整来源条目的目标体量，可显式设为 1,000–128,000；不是新的执行或提交门槛。单条来源超过目标时仍完整返回，并标记 `oversized_single_source`。`next_read` 保留同一任务、来源选择、偏移、条数和体量参数；读完各页可以取得所有所选条目。大量并行读取仍可能形成较大批次，分页也可能增加工具交互次数，不能仅用首页变小宣称总费用减少。

原生专家从首次输入起使用当前工作视图。首次请求没有已消费操作边界，已交给该请求的原文、数值与当前错误仍直接保留，不因目录精简提前退出。财务指标目录保留所有指标 ID、名称、单位类型和直接／衍生类型；公式、解释边界与逐公司覆盖通过逐项 `details_id` 回读。阶段方法保留版本、标题、摘要和 `core_semantics`，正文按需读取。子任务保留原目标、执行与审查状态、作者摘要、问题及未决项，详细验收映射、变更记录另行回读。原任务、当前研究判断和待修状态保持完整。

上述详情使用 `ReadResearchHistoryAction(section="operation", tool_call_id="runtime:context:/...")`，复制给出的定位即可取得该作者原生日志中的当前宿主字段。它读取本次运行绑定的方法和状态，不用一个可能已更新的全局方法替换；不同作者不可跨域读取。它不重新执行工具、不清除错误、不扩大资料权限。实际研究指令及必要语义条件仍优先于目录信息。

工具菜单继续按 graph 的 `allowed_actions` 选择。离线统计复用相同的菜单选择函数，不能把所有研究、提交、修订和复核工具同时计入某个研究轮次。`scripts/engineering/replay_research_input_delivery.py` 同时验证原请求、同阶段菜单、新交接首页及后续页、逐项详情回读和原件不变；在禁网环境执行，不调用模型。

统一目录的读取复用已有原生消息档案，不新建一套材料存储。恢复前已经只有导航而无完整结果的历史，不会被伪称为完整原件；没有原生专家历史接口的其他运行路径保留各自原有的准确回读方式。对无法解析的旧定位，保持原输入，不猜测目标。

离线验证脚本 `scripts/engineering/replay_research_working_view.py` 读取用户本地审计索引与基准 payload，禁止 socket 网络连接，检查真实 SDK 请求体积、当前任务与待修批次、来源原件和财务身份、操作结果实际回读及任务隔离。字符数不等于供应商 token 或费用；固定历史回放不能证明未来研究质量或材料选择最优。

接近阈值时提醒模型在合适边界整理状态，`checkpoint=true` 表达整理意图。提醒不收窄工具菜单。硬输入上限和累计预算仍阻止真实超限，它们不是笔记条数校验。持续多轮必须携带大量不同证据时，考虑已有委派能力和问题拆分；不能靠重复写笔记或复制大上下文解决。

默认整理提醒从估计 140,000 token 前移到 48,000 token，仍是建议，不关闭读取或强迫提交。接受工作状态、成功准备成文或收到宿主保存的可修订稿后，尚未累积一段达到提醒阈值的新工作时，不因保留的工作材料仍大而重复催写；真正接近输入硬上限时仍提醒。提醒与历史归档共用相同的阶段边界识别。供应商实际 token 与估计值分别记录；这个设置不是模型上下文容量，也不是研究质量或节省用量的保证。

## 底稿、恢复和兼容

完成准备成文或局部校验反馈后、没有待执行动作的停点也可接续；这些原生状态可能仍标记为 `model_action_selected` 或 `typed_feedback_ready`。恢复仍核对同一 invocation、任务、资料版本和原累计额度。有待执行动作时拒绝通过此入口恢复，避免漏执行或重复执行。已经返回的完整付费响应单独回放，不再次请求模型；没有完整回执的付费请求仍需明确重发授权。

同一 invocation 在完整工具结果返回、没有待执行动作的边界可恢复，沿用原始模型/工具总额度及已用计数；不会因为重建 graph 再获得一份额度。未完成工具派发不能走这个入口。跨 invocation 的主动继续仍要求原生交接状态，按该次明确配置的额度执行，并保留历史累计计数与原调用定位。已返回模型响应须入账并复用，不能将恢复当成自动重发付费请求。

提交或修订底稿被拒时，反馈与正常工具批次使用同一个 `current_context` 信封，保留原调用 ID、工具名称、具体错误和当前候选稿。旧记录中未包装的终结动作反馈，仅在实际调用配对及完整运行上下文字段均匹配时，于请求副本中转换为同一格式，使已有去重规则也覆盖错误后的接续；不改原日志、不把拒绝变为接受，也不解释来源正文里的相似 JSON。

当前候选稿属于可替代状态：新的、带版本摘要的候选稿替代请求中的旧候选稿副本；旧位置保留版本身份、历史校验错误和最新稿位置。版本变化不要求同时携带每份历史全文。原始日志和来源正文不变，替代本身不代表修改正确或提交成功。

从已接受底稿启动新修订时，同时清空上一轮修改目标并标记当前跟踪版本；不能再次从早期失败动作迁移旧目标。未完成的同一轮恢复仍保留原目标，新一轮反馈和实际编辑仍正常校验。已接受历史不应要求作者为满足旧字段变化检查而改动本轮无关内容。

同一作者修订底稿时保留已接受候选和 digest；研究视图提供实际回答及缺口，写作视图恢复完整候选。压缩不改变引用与提交校验。状态更新使作者准备失效时，仍按原生流程重新绑定。

成功准备成文，以及宿主保存完整候选稿并返回版本摘要的提交／修订回执，也是工作视图的整理边界，即使候选稿仍有校验错误。当前请求保留作者工作状态、必要来源、最新读取、完整当前稿、具体错误和待修编辑；已完成的历史操作转为档案记录，先前每份整稿引用过的来源不会永久钉住全文。这个整理边界不代表提交成功或质量验收。没有完整宿主候选、尚未返回的调用及来源正文中的相似 JSON 不触发它。

收到完整可编辑稿后，先前研究笔记的固定原文集合不再自动延续为修订阶段的永久保留集合。修订依据使用当前具体反馈涉及的来源及最新读取，其他成功结果保留精确回读入口；完整当前稿、错误和作者工作状态仍在。准备成文而尚无完整稿时，仍保留研究阶段所选原文。这是阶段切换，不改变来源记录、引用效力或研究判断。

成功提交底稿仍另行表示完成边界：保留已提交版本、后续修订反馈、后续新读取与准确回读入口，释放此前取证工作集。上述两种边界都保留原生历史、私有思考、工具调用配对、来源和计算依据；输入投影不更改原始日志或执行计数。

取证、准备写作、写作后补查属于同一研究会话。准备材料变化不再清空 SDK 消息历史；当前阶段指引更新，原任务、原文和工具调用／结果配对交给相同的投影、去重和归档流程管理。阶段变化本身不是遗忘依据的理由。是否启用独立准备阶段仍由运行配置决定。

`SaveWorkpaperEditsAction` 的完整修改批次若因定位失败，保存在 `pending_workpaper_revision`，已保存草稿保持不变。回执给出具体编辑索引、错误及 `pending_revision_digest`；模型可仅提交 `edit_corrections: [{edit_index, edit}]` 修正错误项。其余修改保留，重新对当前草稿原子校验和保存。待修提案跨恢复保留，保存成功后清除；过期摘要、不同基础版本和重复修正索引不生效。它不同于已经保存的 `workpaper_draft`；最终提交失败不清除草稿。没有编辑批次的 24 项上限，正常请求预算仍生效。此机制不猜测相近原句、不替模型写答案、不把失败批次中的部分修改悄悄应用。

## 原文读取的可恢复反馈

复核后交回原作者的反馈可能引用原底稿未收录的新来源。交接保留原始来源 ID、核查原句和问题，标注 `requires_original_source_read`，由作者通过原文或财务工具取得完整绑定后引用；反馈本身不成为证据，不向作者来源库凭空增加记录。已存在的底稿别名仍映射到原始身份；身份冲突继续报错。单个新来源不在旧目录中不会让整个作者修订在启动前失败。

本地／上传文档的整块正文超过读取预算时，返回不可引用的导航记录及明确 `readback`，而非空结果和笼统重试提示。显式 `character_offset` 可分窗读取指定节点；结果保留零起始、右开区间字符范围、整块与当前窗口的哈希以及 `next_readback`。分窗记录标注 `read_scope=character_window`、`truncated=true`，不代表完整表格、注释或全文已读。引用身份绑定范围；原有完整读取的 ID 不变。

正式资料库支持分页 `outline`，返回章节／chunk 定位及读取参数，不将目录提升为证据。已经由工具返回的完整 `passage_id` 可在同一文档内准确回读；别名不绕过文档范围、研究截止日和来源可读性检查。优先复制返回的 `readback`，不要推算节点 ID。正式 chunk、向量索引及原始文档均不因这些读取修复而重建。

已接受底稿替代旧提案时，只投影可识别的对象形式动作。历史无效工具调用及字符串、空值等未解析参数保留原样，不重新解析为已执行动作，也不阻断后续修订。原始失败回执和用量记录不变。

旧状态、checkpoint 标志及 wire ID 继续可读。旧 `context_checkpoint_required` 字段仅作存储兼容，不再强制禁用工具。恢复请求中的宿主 working_state_guidance 使用当前合同，旧临时通知由接受状态取代；用户指令与来源文本不被改写。

## 验证范围

修订后的独立确认以 `findings_to_confirm` 指定的底稿为必查范围；模型若另增底稿评估或新发现，该底稿也必须实际读取。未改动、未分配的底稿不因通用全库校验被隐式加入复核。仍逐条确认已分配发现，并核对当前稿与来源；确认不是全专题重新验收。确认工具同时支持 `read_review_location` 按字段和窗口回读当前原文，已归档的导航不代替原文。

确认导航只展开本次分配底稿的改动和作者答复，优先使用当前版本匹配的原生最近一次修改记录；旧记录缺失或过期时退回原始稿与当前稿的差异。全案例版本身份和按需回读保持，未列入导航不代表已通过复核，历史记录不删除。

Lead 可对明确标为 advisory 的已有发现选择 `carry_advisory`，说明其为何不阻碍回答，以及综合稿如何避免或限定相关措辞。发现及处置继续传给综合、写作和后续核查，不将其标为已修复。material、未分类及新发现不得使用此处置；不允许借此把未完成的独立复核标为通过。

原作者进入修订时，已接受底稿的宿主交接也构成上一研究阶段的完成边界。恢复历史可能只有提交调用而没有成功工具回执，因此以原生校验后注入的 `accepted_revision_baseline` 识别该边界；相同底稿反复出现在逐轮上下文时只处理首次交接，不释放本轮新读材料。旧研究资料在请求视图中转为准确回读入口，已接受底稿、新反馈和后续读取保留，原始日志与来源均不变。工具结果中的相似 JSON 不构成交接；这项归档不代表底稿研究结论正确。

独立复核使用 `record_review_checks` 分批保存当前稿件版本的核查记录。同一版本、字段、维度及语义目标的新记录替代旧记录；原始消息仍留存。最终提交仅需新增或更正的检查，运行时合并已保存记录后执行完整覆盖与来源校验。移除与动态检查范围冲突的整份清单条数上限；输入与运行预算继续生效。恢复旧会话时只从有成功回执的提交迁移记录，不把失败候选当已核查；过期稿件版本不能满足当前覆盖。

分批记录按条核验，保存有效条目并返回无效条目的索引与原因，局部更正不重交成功条目。复核模型的当前输入由原任务与用户接续指令、已有工作摘要、已保存发现、剩余检查位置及最近两轮完整工具交互组成，替代不断累积的旧请求视图。完整原生消息仍用于校验与持久化；`read_review_history` 分页读取本复核者的公开历史，`read_saved_review_checks` 回读检查记录，不暴露私有思考字段。此视图复用已有摘要，不额外触发付费摘要或重试失败请求。

`research_limitations` 表示完成核查后仍存在的研究资料边界，随审查交接；`unresolved_data_requests` 表示影响本次复核完成的必要检查仍未做完。前者不会独自阻止提交，后者仍要求 incomplete。字段分离不允许把未核实的重要主张伪装成资料限制；完整提交仍逐项验证所需检查、来源及当前版本。

退回底稿存在带版本摘要的宿主完整候选时，该候选为当前可编辑原件；已完成的提交／修订参数在请求中保留原调用 ID 和当前候选的准确位置，不反复携带旧整稿或旧编辑批次。当前版本、校验反馈及待修编辑保持完整；归档后的位置仍可直接解析。旧回执缺少版本摘要时沿用精确副本去重。存储中的原调用、正文和来源均不修改。共享引文未被主张引用时，错误反馈列出具体引用 ID，供作者局部修正，不替作者增删研究主张。

旧存档的 `replace/old_value/new_value` 调用仍可回放；原值不匹配时返回字段路径及当前值摘要，小字段（JSON 编码不超过 4,096 字符）直接返回完整值，大字段指向当前候选。新原生模型请求不再提供这个操作，避免作者重复抄写旧字段。旧存档的原子性、版本冲突和原值检查仍生效，不自动猜测或应用不匹配编辑。

新修订以 `base_submission_digest` 绑定当前完整稿件版本，提供以下操作：

- `update_claim`：提供精确 `claim_id` 和 `changes` 中的变化字段；runtime 定位论断、保留未给出的正文与来源字段。不能新增或更名论断，不按相似 ID 猜测。`[]`、`{}` 表示显式清空，省略表示保留；仅原本允许空值的说明字段可显式传 `null`。引用数组和引文映射在显式提供时整体替换。
- `set_field`：其他已有内容字段只提交 `path/value`，不再抄回旧值；不能以此绕过按 ID 修改论断。长正文中只改一段时仍可用 `str_replace`，避免重写完整章节。
- `upsert_coverage`：按原始 criterion 更新一项覆盖评估，不重传整份旧数组。

一次请求可以同时更新论断及其关联正文、复核答复和缺口。作者仍负责语义一致性，runtime 不根据新材料自动改写研究判断或宣布旧缺口完成。完整版本冲突检查、拼装后的结构、引用和来源校验继续执行；保存失败批次后仍可仅修正具体错误编辑。兼容层保留旧调用解析，新请求菜单不叠加旧的抄值格式。

当前材料的原始绑定及 `writer_citable` 等标志保持不变，模型视图另给出按引用 ID 定位的 `current_reference_usage`。PASSAGE 进入 `evidence_ids`；S2 和来源绑定 CALC 进入 `fact_ids`。CALC 的 `writer_citable=false` 只禁止原文证据通道，不禁止作为 `calculation` 使用；它的 `numeric_authority=non_authoritative` 仍表示算术回执不证明操作数的金融含义。

- `test_working_context_lifecycle.py`：漏填父级保留、显式清空校验、拒绝后继续读取、跨恢复局部修正、29 条当前判断可保存、schema 错误修正。
- `test_restored_context_lifecycle.py`：恢复/实时读取与连续四轮整理、准确结果回读、原件不变、最新材料保护。
- `test_research_context_checkpoint.py` / `test_revision_continuation.py`：真实 SDK 的 mock transport、压力提醒不限制工具、不再两次错误强停、硬上限仍禁止传输。
- `test_workpaper_partial_edits.py`：待修编辑批次局部更正、原生恢复后继续修订、版本冲突与原子性、旧 action 序列化兼容。
- `test_source_read_correction.py` / `test_library_chunks.py`：超长节点分窗覆盖、同文档引用回读、正式库目录、截止日期约束。
- `test_authoring_context.py`：取证、准备写作与再次取证之间的 SDK 消息连续性及工具调用／反馈配对。
- 核验交给 Lead 或写作节点时，仅传递当前版本、作者响应、正式核验结果、已记录发现、未决检查与执行计数。核验者的恢复消息、私有思考和未提交输出保留在原生记录中，只供原核验者恢复，不进入其他角色输入。未完成核验仍标为未完成；缩减交接体积不改变验收状态。

# 连续修订的来源保留

Lead 的当前进度保留未提交任务的公开交接结果，包括停止原因、作者说明、候选稿状态与校验位置。不能仅显示 `needs_attention`，也不能只依赖上一条临时工具回执；独立任务继续或恢复会话后，原阻碍仍应可见。已提交底稿沿用现有交接，不在进度中重复全文。交接说明是待处置的执行状态，不是完成的研究成果，也不自动授权重发失败的付费请求。

首次整稿提交兼容顶层 `citation_quotes` 默认摘录；序列化后引文归属于各论断。某条论断已提供自己的摘录时保留该摘录，错误摘录不能被默认值悄悄替换。修订指导不再要求建立顶层公共引文或禁止跨论断重复引文：现有候选稿不一定含该顶层字段，相同原文也可支持不同论断。未修改的引文由 runtime 保留，变化的引文按论断更新，来源 ID、原文匹配及必要引文检查保持。

离线脚本 `scripts/engineering/replay_workpaper_identity_edits.py` 接收保存的原生审计、SDK 请求和对应源代码基线，在禁网环境刷新当前工具、修订指导及引用通道视图。它比较材料与来源绑定、候选稿、问题与复核、权限与预算，并逐一验证历史操作和背景回读；在真实候选副本上用明确标识的机械探针比较新旧编辑的组装结果。不保存新金融底稿，也不把字符减少或合成节点通过当作模型行为、费用或研究质量改善。

## 修订问题与修改建议的交接

局部修订以当前复核问题、实际校验错误及其影响的判断、正文和来源绑定为范围。原任务、验收项和未完成来源检查保留为研究背景与权限，不自动重新成为本次修订的前置清单；发现相关重大错误仍可补查，无关旧缺口保留真实状态交给 Lead。恢复请求会替换旧修订指导，不在旧指导后追加相反要求。历史编辑目标未改变只是待说明的提示，不再误称必然阻止提交；正文有变化也不代表金融判断已核验。

这一区分在原生专家的请求视图中执行：已接受底稿进入修订后，`revision_task` 指向本次复核发现、当前校验错误和候选稿，包含必要关联修改；原分派的目标与验收句、旧准备提纲及其依据、旧版本全文移入 `research_background` 的准确回读入口。原始总问题、身份、期间、来源权限、真实余额和当前候选稿仍保留。首次成稿的校验重试不适用此转换。宿主仍保存完整准备状态并核对其有效性；请求视图不修改原始日志或稿件。

修订中的历史操作目录保留调用 ID、工具、状态、接受／错误信息与来源 ID，完整参数及回执按原调用 ID 回读；不再把旧 `reason_summary` 作为当前指导展示。当前未完成调用、错误和待处理编辑继续按原规则呈现。可用材料表示证据供给，不意味着其中所有旧缺口成为新任务。底稿内的旧缺口与覆盖记录保持原样，作者可以修改必要的关联字段，也可以让无关可选调查继续未完成；runtime 不新增语义字段白名单，也不自动把缺口标为解决。

`scripts/engineering/replay_revision_task_handoff.py --audit <原生审计JSONL> --wire <对应SDK请求JSON> --call-id <请求ID> --output <私有输出目录>` 禁网回放真实请求及其体量提醒，经 SDK 组装核对原文、计算回执、来源绑定、候选稿、复核要求、权限和额度未变，并验证背景及操作回读。相关字段编辑与未完成可选项的提交另由原生图测试覆盖。离线验收不证明模型已停止扩大范围，也不代表金融结论或实际成本通过验证。

有共享运行额度的调度器通过 `open_specialist_receipted_composition(remaining_model_requests=...)` 提供实时读取函数。每次模型决策前，显示的可用轮次取节点余额与共享请求余额的较小值，同时分别保留两种余额；共享余额包含当前请求、并非为该作者预留。余额为零时保留未完成状态并停止，不能静默省略核查或宣称完成。传输层仍须原子计数并执行总额度检查，尤其在多作者并发时；显示快照不替代传输闸门。不配置共享额度的调用者保持原节点限制。

复核的原始 `requested_change` 保留；Lead 的建议另存为 `lead_requested_change`，不覆盖原缺陷。Lead 新发现的事实或推理问题单独记录依据，不把来源标识修复扩大成新增论断的必做项。旧存档若已覆盖原要求，只在父运行保存的原发现与其 ID、作者、问题摘录、诊断及来源检查唯一匹配时恢复两者的分工，原存档不改。缺失或不匹配时不凭空还原；修改要求仍是待评估建议，不当作来源证据。

原作者收到引用问题时，runtime 从当前稿与本稿来源目录生成 `reference_navigation`：准确字段位置、版本、原标识、完整候选来源身份。旧记录即使类型为 `other`，也只按当前稿中的精确标识匹配提供导航；多候选保持歧义，不自动选择，不构造原文 ID，也不修改作者底稿。此导航不是新增原文读取或金融正确性认证。

修订指导替换旧的逐条强制重读要求。仅修复标识时保留原断言及其已读／待查状态，不必将缺口升级为正式论断。“保留”指当前稿中已有且正确的内容，不要求补入只出现在复核意见里的数字。来源身份、事实支持或修改后的推断尚不清楚时，仍须读取相应原文；先执行必要读取，再根据返回结果修改受影响的正文和绑定。引用修复不免除实际事实错误的核验，也不自动关闭独立复核。

## 当前对象去重与请求前缀

修订材料交接建立当前修订工作集。后续读取、计算、体量提醒、分批保存及局部校验失败，都不表示此前原件已经用完，不按工具调用次数将其退出。新取得的原件加入工作集；作者通过现有 `retain_source_ids` 明确重选（空列表也有效），或通过 `context_release` 释放已消费材料。完整原件仍存于原生日志，按原调用 ID 回读后可以重新进入工作集。保存一批修改不等于完成全部关联修改，不能根据保存次数自动释放依据。最终提交接受或进入新的阶段后，该工作集结束；普通研究阶段仍采用原有近期材料策略。

已存在修订候选且启用字段编辑时，工具菜单提供 `SaveWorkpaperEditsAction` 与 `FinalizeWorkpaperRevisionAction`，替代原来应用修改即提交的 `ReviseWorkpaperAction`。首次成稿及未启用字段编辑的兼容路径保持原协议；旧调用保留历史回放兼容，新模型菜单不再提供它。

保存使用当前 `base_submission_digest`、唯一 `operation_id` 和一个编辑批次。runtime 检查版本、定位和字段结构，将整批原子保存到独立 `workpaper_draft`；失败不改先前草稿。相同操作 ID、相同内容重送返回既有回执，不重复应用；同 ID 不同内容被拒绝。跨字段完整性可暂未满足，草稿明确标注待最终校验，不授予引用权限，也不替换已接受底稿。原生图检查点保存草稿、版本及操作回执，恢复继续使用；本轮输出截断的半份 JSON 不自动变成保存动作。

最终提交只发送 `draft_digest`，无需重发正文、论断及来源。runtime 拼装整稿并执行原有完整结构、引用、必要检查及复核答复校验；通过后才接受并结束节点。校验失败保留草稿，反馈绑定提交版本，作者继续保存局部修正后再提交。保存次数不等于提交次数或研究完成；模型请求仍消耗正常预算，不自动增加额度。

保存后请求视图保留当前版本、最新变化、论断 ID、校验反馈与准确的完整草稿回读入口；完整内容存于宿主检查点。一个响应允许一次保存与输入已知的独立读取／计算同时返回，逐项执行并保留各自回执；独立工具失败不撤回成功保存，坏保存批次也不阻止独立读取。依赖新结果的修改须在取得结果后另行保存。两个写入、保存与最终提交混用仍不执行；最终提交必须单独调用。必要的关联正文和判断仍由作者负责更新，可以分批完成，最终整体校验不等于要求模型一次生成所有修改。

当前修订的整稿回读默认返回正文、论断、来源、分析摘要和当前复核问题的答复。旧 `task_note.coverage`、`issues` 及历史修改记录通过 `task_record_read` 独立回读，不重新作为当前验收清单；`view=record` 可取完整原件，明确读取历史字段也保持可用。当前任务要求由 `revision_task` 提供，正文内的事实限制和缺口不删除，原稿与完整校验不改变。该投影同时用于新读取及恢复历史读取，并在分页前完成，后续游标固定视图。已保存于本次修订的修改记录继续显示。

待修改稿件不再仅保留论断 ID：修订视图提供当前候选稿的准确论断原句、ID 和逐条字段回读入口；当前复核点对应的完整论断只在 `current_fragment` 放一份。论断索引不携带整稿正文、引文全集或旧验收清单，也不是新增研究任务。正常稿件读回仍可按字段或完整记录读取，原件不变。

明确成功读过的候选字段形成临时编辑区，从原生读取／保存回执推导，不要求模型另填计划或笔记。新鲜读取仍在当前工具回执中；该回执归档后，尚未改完的字段继续在编辑区保留。中间读取、计算、来源材料交接及失败保存不会让它退出；对应字段成功保存后退出，当前论断索引和已保存字段显示新值。若稿件值或索引位置已经变化，旧值不复活。新修订阶段释放上一阶段编辑区。整稿或整个 claims 集合的读取不会永久展开整份稿件；旧任务清单只保留历史回读。分页字段只保留实际读取的窗口和下一页入口，不把部分读取提升成全文。

这替代了“稿件按普通历史操作退出后只剩 ID、当前修订只看首个复核目标”的执行视图。历史档案保留规则不变，编辑区不修改稿件、不推断关联修改范围、也不把保存视为最终提交。`tests/test_revision_manuscript.py` 验证跨工具保留、坏保存隔离、成功保存刷新与退出、分页和准确回读。模型是否据此直接保存仍需真实运行观察。

保存结构校验先安全纠正、再验证：仅对 `task_note.finding_responses` 对象中被 schema 明确拒绝的多余空元数据（空列表、空对象、空字符串或 null）移除，并在 `automatic_repairs` 中记录位置和原值。原始请求和幂等身份仍按模型原提案保留，不自动改写观点、引用、身份、已知字段、非空未知字段或错误类型；其余结构错误仍拒绝该批次并保留之前的草稿。复核答复的实际字段 schema 随修订合同提供，来自同一 Pydantic 模型，避免让模型从其他对象猜字段。

每次保存回执与接续视图提供绑定修订基线和当前稿件版本的 `change_status`：实际变化的论断 ID、内容字段、正文是否改变，以及作者声明尚未独立核实的状态。对“正文已改写”这类明确肯定表述而正文与基线完全相同的情况，发出非阻塞差异提醒，保留作者原话、不替其完成修改；这不是通用语义审查，也不要求每次修改都改正文。正文发生变化也不等于声明全部正确，完整校验和独立复核仍负责最终提交。该提醒在后续保存后按当前版本重新计算，不从累计操作数推断完成。`tests/test_draft_validation.py` 覆盖空字段纠正、不可安全纠正字段、原生保存、幂等重放、失败隔离和版本状态对照。

这项修复移除了整稿读取重新带入旧任务清单、保存被当作终结动作的冲突。runtime 只执行模型实际返回的工具调用，不能从尚未结束的思考中推断决定并代为保存。离线测试覆盖两种调用顺序、局部失败、版本限制及额度停止；不能据此认定模型会停止长时间起草，行为与费用仍待真实验证。

验证入口：`tests/test_workpaper_draft_lifecycle.py` 覆盖保存、序列化恢复、幂等、坏批次隔离、最终校验失败再修正与成功结束；`scripts/engineering/replay_workpaper_draft_lifecycle.py` 对外部指定的真实记录做禁网回放，不修改原运行或推广截断响应为正式成果。

宿主离线确认旧修改计划污染接续时，可在 `restore_author_history(..., material_handoff=True)` 明确请求材料交接。适配器先补齐实际工具回执，再在成功读取批次后建立边界：当前可见原文与计算对象成为本次修订工作集，已完成模型轮次退出请求正文，完整历史仍可按原调用 ID 回读。未配对调用、最新工具错误或待处理提交／状态操作不能用此入口隐藏。默认恢复不执行该交接；进入交接后，材料按上述修订工作集规则保留与退出，替代旧的“仅首次边界保留、下一工具动作后按近期批次轮换”逻辑。该入口不回退记录、不修改稿件、不重置已用轮次或共享余额，不能将历史失败响应提升为成功。

来源注册修复后，不能仅凭后端恢复完成，就让模型猜测旧计算失败是否仍有效。宿主可显式调用 `tool_recovery.recheck_failed_calculation(state, tool_call_id)`：核对同一作者、任务、调用及已结束的工具边界，使用原计算请求和当前已保存来源，执行本地正式计算器。它不请求模型、不联网、不重新检索、不重发付费请求；同请求、同来源快照重复调用复用检查回执。原失败回执和费用记录始终不改。

新的 `task_context.tool_recovery_checks` 记录执行范围、原调用绑定、来源快照摘要及本次成功或失败。成功结果追加为可复用的非权威 CALC 观察；模型轮次和工具动作预算不重置，宿主检查以独立回执计录。调用者应持久化返回的新状态，再走正常作者恢复入口。来源仍缺失或计算失败时只保存新失败，不生成恢复成功。该检查只证明这一请求在这一来源快照上执行的结果，不代表全局工具健康或财务推断成立。

模型视图在旧失败旁显示本次执行状态及回读入口，旧 `ToolMessage.status=error` 保留其历史含义；不会伪造模型调用或把旧失败改成成功。原件和完整新回执可从 `ReadResearchHistoryAction(section="operation", tool_call_id="runtime:context:/task_context/tool_recovery_checks/0")` 回读。输入精简保留检查与原调用的绑定，避免恢复结果在后端存在却未实际到达模型。`tests/test_tool_recovery.py` 覆盖准确执行、历史不变、幂等、身份隔离、来源变化、失败状态及正常模型投影。是否因此改善实际保存行为仍需另行真实验证。

`scripts/engineering/replay_revision_material_lifecycle.py --audit <原生日志> --wire-dir <三轮实际SDK请求目录> --state <原作者状态> --output <私有输出目录>` 禁网回放真实连续请求，核对七份原始对象、完整 SDK 投影及准确回读入口。在副本上执行分批保存、序列化恢复、坏批次与最终校验拒绝，再验证明确重选可退出材料，历史原件仍可读。测试编辑不推广为研究成果；模型是否更快完成修订、实际 token 与费用是否改善仍须真实运行验证。

分批保存的行为指导与最终验收分开：关联论断、正文和来源须在最终提交前一致，不要求每个保存批次覆盖全部关联位置。作者可先保存已有依据支持的一个字段或论断，再处理其他关联位置；依赖新结果的修改先请求结果，不预写整个后续稿件。独立读取／计算只合并当前步骤确有必要的动作，不能把节省调用次数变成收集可选检查、等待一个大批次的要求。工具仍允许必要补查和关联修改，最终校验不降级；这些指导是否改善执行必须查看真实保存回执，不能以提示词存在代替行为验证。

原生专家的单一工作视图按“当前原文、来源绑定、当前任务、动态进度与历史入口”排序；任务内的工作状态、准备成文内容、阶段方法等放在较稳定字段之后。排序不改变值，材料选择／释放仍按研究进度生效，不为缓存保留过期原文。

实际专家组装中的权限检查包装器须保留被包装适配器的身份，使 `ReadResearchHistoryAction` 能找到同作者的原生操作日志。仅测试独立适配器或取消包装器不足以覆盖此路径；组装层回归同时检查准确回读、跨作者隔离及撤权后禁止模型调用。此修复保留权限检查，不重新查询已经取得的资料。

再次读取同一历史操作沿用已登记的动作摘要，返回保存回执，不重发原始请求，也不往唯一动作账本追加重复项。新历史读取仍受原工具额度约束；相同已登记读取不会因追加重复摘要而令整个研究节点异常退出。运行次数及原模型调用继续保存在完整历史中。

已接受工作状态只在当前任务中完整保留一份。成功工具调用参数、成功回执及准备成文的依据中，完全相同的字段可以用 `current_value_at` 引用当前工作视图内的 JSON Pointer；仅在引用比原值更短时替换。已接受的准备提纲同样只保留一份。不同内容、未接受提案、当前错误及待返回调用不按成功状态折叠。此操作只改变请求副本，不改原生消息档案、思考字段、调用 ID、来源、期间、单位或准备内容的绑定摘要。模型可沿原 `tool_call_id` 使用 `ReadResearchHistoryAction(section=operation)` 回读完整原始参数和回执，引用不代表金融判断通过。

研究图已有 `authoring_instruction` 和 `stage_methods` 负责阶段切换；适配器不再于同一作者成文时另换整段系统身份，也不再清空该阶段的原历史字段。共享职责和权限保持，当前阶段提示由图更新。专家工具先放共有读取／状态工具，再放阶段相关动作，顺序固定；只展示当期实际允许的工具，不通过扩大工具菜单来追求缓存。

`scripts/engineering/replay_current_context_cache.py --audit <原生审计JSONL> --wire-dir <原请求目录> --output <私有输出目录>` 可对同一作者已有请求进行禁网回放：逐项展开新定位并核对原值，检查完整原文和来源绑定、原档案不变、操作回读、工具集合和重复投影，同时比较完整 SDK 字符量、用户内容及工具列表的公共前缀。系统提示按同作者研究阶段的已保存基线复用；真实适配器的 mock transport 测试另覆盖研究→成文→继续研究的提示及调用配对。此回放不是实际模型行为或供应商缓存测试，阶段权限导致的工具集合差异仍然存在。

技术恢复中的计划权限与材料复用分开：保存了底稿不代表用户要求冻结计划。正式会话以用户 `ExecutionOptions.continuation_scope` 控制是否仅完成原计划，默认保留原问题下的补查与补派权限，见[接续研究权限](current_research_contract.zh-CN.md#接续研究权限)。这不重新执行已提交底稿，也不修改其来源、报告或失败请求。离线 `replay_research_continuation_scope.py` 可对真实保存输入作规划边界探针，比较普通恢复与显式限制；探针任务不是模型实际研究决定，零模型/零专家执行不能当作研究质量验证。

原作者的修订结果包含当前底稿和本次新增的来源映射。发布下一版底稿时，runtime 必须合并此前已接受修订的来源映射与逐项反馈记录，不能用本轮的增量覆盖整份记录。相同来源 ID 内容冲突时仍报出执行问题；不得改写 ID 或根据相似数值替换来源。后续 Lead、复核与报告读取的是同一份累计来源绑定。

旧运行若已经遗漏映射，应从同任务原作者保存的完整 observation 回执离线恢复，并核对主体、期间、单位、版本和底稿内容未变；不能将它归为资料缺失，也不需要重新付费查询。恢复来源可读性不等于通过研究质量复核。

中断中的作者修订必须在打开数据工具之前选定一个接续 checkpoint。主机可调用 `author_continuation_options`，把同一份状态交给数据 composition、原生图初始化和作者历史恢复；沿用原 invocation、候选稿、已保存批次和累计额度。不得先按旧底稿打开计算工具，再通过 `graph.update_state` 单独替换研究状态，这会造成模型已读而计算器未登记来源。继续未完成的修订也不能再次传入“开启新修订”的 `revision_feedback`，否则初始化可能从旧验收稿重置候选。已有反馈保留在当前 checkpoint 中。此入口不增加请求额度，不重发失败请求，也不把未提交稿视为完成。

恢复检查应包含真实失败计算请求：旧状态下复现来源缺失，新状态下用完全相同的来源 ID、原文引句和表达式通过计算器；禁止联网、重新读取或调用模型，保留旧失败回执。只证明算术与来源恢复可用，不证明金融推断正确，亦不能证明模型下一轮会及时保存修改。

`read_current_source` 可按准确的 `Pxx:claim_id` 读取当前底稿的论断及来源绑定，无需先把论断写进报告引用表。已有报告的引用仍优先读取其保存的版本；尚未被引用的论断从当前底稿解析。分页只限制展示文本，完整绑定留在工具回执中。不存在的 ID 不按相似名称替换，来源绑定也不代表已经完成语义核查。

综合稿和最终报告的再次复核均提供上一版审阅与文本／图表变更对照，重点验证已报问题、修改内容及新引入的影响。未改动内容只有明确的实质理由才重新打开；复用已有原件及计算绑定不等于自动接受旧审阅结论。当前稿确实需要、且尚未完成的检查仍须如实记录。

综合稿和最终报告各自按已接受稿件版本计算写作修订次数。此前的底稿修订不消耗首次综合稿的纠错机会；全局轮次仍保留运行顺序，研究作者修订的原上限不扩大。写作层问题只回到对应综合／写作节点，新的实质研究问题仍按原责任路由处理。达到该写作阶段的修订上限时保留最新稿与未决发现，不能视为验收通过。

综合稿与最终报告的复核也沿用底稿复核的 `research_limitations`：记录已知资料边界，并传给后续写作和复核。`unresolved_data_requests` 仅记录当前保留的重要主张仍不可缺少、尚未完成的检查。前者不会单独阻断有明确范围限制的回答；后者仍阻断交付。分类由复核者根据当前主张决定，runtime 不按关键词把旧阻塞项自动清空。旧审阅记录缺少新增字段时按空列表读取；完整审阅历史和独立复核状态保持不变。

启用 `runtime_context_binding` 时，`context_digest` 不属于模型工具参数，由 runtime 将已完成响应绑定到发起该请求的上下文。模型偶然回显的旧值只保留在原始响应审计中，不能覆盖执行绑定，也不应令成功响应后的整个流程崩溃。请求／回执摘要、图执行上下文、数据权限及引用校验继续生效；未启用此模式的显式绑定仍严格校验。旧运行已收到完整响应而尚未执行时，可保留原回执并通过离线回放恢复，不重新生成模型答案。

原生专家的已消费历史按上述单一工作视图退出输入，不以“笔记先通过”为前提，也不因失败结果或计算类型永久保留全文。当前未修草稿与错误仍完整呈现，旧错误保留状态及准确回读。其他不具备该日志读取能力的运行路径继续采用其原有安全归档方式。若剩余当前材料仍超限，原硬上限继续生效，不能靠隐藏必要材料宣称问题解决。

底稿交接在宿主状态中保留原作者的 `authoring_context`，包括准备内容、原始依据及其摘要。原作者接收复核后沿用有效准备，直接获得局部修订入口；旧准备在模型修订视图中提供准确回读，不再作为当前写作提纲展开。新增来源或复核发现由作者按本次问题评估。原有作者、任务、依据摘要校验仍执行，缺失或无效准备不会被自动伪造。旧存档若已丢失该字段，应从同一作者、同一任务及同一已接受底稿版本的原始状态核对恢复，不能把再次生成准备当作必要研究工作。

已接受底稿进入首次修订时，适配器先用实际成功回执闭合原提交调用，再将当前修订作为独立的任务消息加入原生日志。边界须匹配已接受版本、原作者轮次和未提交修订状态；真正的提交拒绝仍作为当前工具反馈保留。请求投影将边界前已完成的提交与思考移入历史目录，保留完整调用及回执的准确回读入口，不再将旧成功回执排列在新修订任务后。来源、当前候选及复核要求仍由当前工作视图提供；未完成的工具批次不能跨边界归档。后续读取、错误与修订继续遵守原有保留规则，恢复日志时同样保留阶段边界。此调整不接受任何新的研究判断，也不改变已保存原始审计。

离线验收使用 `scripts/engineering/replay_context_retirement.py`，输入本机保存的基准 `replay.json` 与此前完整 SDK 请求投影目录。脚本禁止网络，核对同一原始记录摘要、完整请求字符数、保留正文与财务对象哈希、定位指针、原生调用配对、保存的回读参数，以及重复投影的一致性。回读核验复用原回执，不宣称外部服务已验证；字符下降不是供应商 token、实际费用或研究质量的实测改善。
