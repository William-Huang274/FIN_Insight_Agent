## 结论与反思

真实专家图已通过项目快照读取微软官方公告、来源绑定计算、精确引用底稿提交和项目出处回读。季度、单位、GAAP/恒定汇率口径及三项利润率计算正确；这比011的确定性模型驱动前进了一步。

**整体研究质量只接受局部结果。** 原底稿`counterevidence[2]`称“公告未提供分部利润率分解”，但同一保存资料后部含分部收入与营业利润，具备进一步计算分部利润率的输入。模型读取正文块`1:0`、`1:1`、`1:2`，没有读取含分部表的`1:4`。它在open_gaps中也写“未读取”，却在反证中使用“未提供”，把未完成检查写成了资料边界。是否逐项印出比率不等于能否从已披露组成项计算；这不是外部公共信息缺口，也不是解析/对象/检索缺失。

原底稿/用量/PG记录不改写。宿主通过原任务资料工具读回`1:4`并单独保存复核证据。本包强化专家公共提示：对未披露断言先检查对应剩余章节/表格，检查组成项能否计算，未检查就明确说未检查；同时在上传资料工具notice中说明本次块/窗口不代表整份文档覆盖。没有新增披露裁决引擎或以关键字拒绝稿件。离线验证证明提示进入实际SDK请求、后续资料可达，**不证明提示修正后真实模型已改善**；该根因保持`live_behavior_revalidation_open`。

## 样本、授权与运行方式

原件：[微软FY2025 Q4官方业绩公告](https://www.microsoft.com/en-us/Investor/earnings/FY-2025-Q4/press-release-webcast)，公告日期2025-07-30；下载时刻2026-09-14 08:03:58 UTC。534352 bytes，SHA-256 `86c2993ee593176ee843741af357758d6bd3f18aae2c8523af75cae02b34fda1`，既有解析器得到4节/23649字符。保存HTTP原件、来源URL、摘要和解析结果，不用网页后续变动替换本次输入。该网页不是最新季度声明，只用于固定历史样本。

通过现有BFF选择项目资料并生成任务副本；BFF测试原生元数据为stub，实际专家图、MCP、原资料读取/计算器、DeepSeek结构化适配器和PG派发保护均真实执行。研究在宿主运行，一个专家工具循环，没有负责人/完整Writer/全题研究或原生服务跨进程研究恢复。既有Docker资格fixture只提供隔离PG等基础服务，容器合成图`fixture_graph_model_calls=0`不否认宿主五次调用。没有另建runner、队列或provider transport。

任务要求：对比两期截至6月30日三个月的收入和营业利润，明确百万美元，计算两期营业利润率与同比百分点，区分季度/全年、GAAP/恒定汇率，给出来源绑定中文短底稿及局限；不访问项目外历史财务数据或外网。问题只提供对象、要求和任务文件清单，预检确认没有先注入目标数值；不是盲测，宿主用同一公共原件作开发复核。

付费前保存逐节点`TokenBudgetBasis`、实际问题、原件摘要、资格代码摘要、价格和停止条件：非思考Pro，最多6次供应商请求，单次128000 UTF8 payload bytes与4000输出tokens，120秒超时，SDK重试0；原生图最多6模型回合/12工具动作。根预算8元，交付预留0.1元；每次预留1.296864元，依据128000 UTF8 bytes加4096 framing token余量、4000输出及高峰未缓存价格。这是保守场景，不是全模型tokenizer/供应商账单硬保证。质量需求未为压价而删除，超限/截断/未知停止，不重发。
