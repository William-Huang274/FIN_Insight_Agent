# 组织检索查询与评测一致性

此文描述查询约束及候选处理的维护规则。实现和确定性检查不等于检索质量通过；发布须另行记录全量来源、来源版本、题集标注、实际服务质量及并发证据。

## 分块重建与模型辅助标注：设计约束

本节是原文抽样后确定的下一轮实施约束，不表示新的分块、标注调度器或全库索引已经交付。旧的细分单元全量付费生成保持停止；不能以完成旧批次数作为目标。保留原件、旧引用和既有发布，在新的结构表示上验证方案。

### 先修结构，再决定是否派给模型

异常判定的对象是来源中的元素或依赖关系，不是整篇资料。每份资料可以同时包含可自动处理、需要恢复结构和待语义复核的部分。以下现象不能直接触发模型任务：短文本、复杂行业、没有全局文档坐标、局部表格、HTML `table` 标签、未命中已有正则。

- 纯解析标记和零宽空白保留在原件中，但不独立检索；数字零、负号、单位及短事实不按长度删除。
- 已有完整原文及可信位置时，从完整小节/表格重建单元。不能让旧检索块的边界继续限制新单元；新单元可以引用多个旧块的原文区间，仍保留各自来源和坐标空间。
- 标题、页眉、列表可能以HTML表格排版。先区分元素角色，再决定是否需要财务表格行列处理；标记完整不代表其为数据表。
- 完整表格按原表或有明确分组的行组处理。跨组拆分时继承真实多级表头、单位、期间和主体维度，不将不同科目、GAAP/non-GAAP或发行/偿还方向混为一类。
- 编号脚注按局部作用范围绑定，允许一组脚注同时指向两个比较日期表。进入下一标题/表格组后不能因编号相同继续沿用；无唯一依据时保留待核对。
- PDF多栏混排、缺失行列几何、OCR异常先回到原页和解析器。语言模型不能从残缺的纯文本补造人员任职关系、表头或数值。
- 只有原件完整、解析/规则处理已经执行、仍存在明确语义歧义时，才建立模型辅助任务。任务须写出无法由规则确定的具体关系，以及支持不同解释的原文位置。

短块/脚注等探针是发现线索，不是语义标签。需要对未触发探针的资料继续抽样，覆盖解析器、格式、版本、行业和文档长度；发现新类问题后回扫整个冻结范围，不能只修命中的公司。所有处置使用来源证据，不能向切分模型传评测问题、正确答案或检索排名。

### 与辅助模型的交接

先由主代理审阅每类多个完整结构样本，写出规则修复方式、模型可处理边界和反例；再冻结任务协议。辅助模型只提出边界与关系建议，不直接改正文、数据库或索引。

输入包包含：任务ID、源版本和摘要、明确坐标空间、带稳定ID的原文元素、当前规则结果、要解决的具体歧义、必要且完整的同表/同小节上下文及固定输出协议。读取包应自足；不要只给破碎片段让模型自己搜索仓库。大表或缺上下文必须重新划定合理结构包，不能为满足预算截断证据。

输出只包含元素ID范围、主单元/附属上下文关系、原文依据ID和明确的未决原因。禁止抄写整篇、重写数字、自由生成公司/期间/单位标签或为凑答案制造关系。程序按ID取回原文并计算坐标，不能让模型手工数长文本字符。

调度采用一次性小批次，不复制完整对话历史，不让子代理反复调用工具、外部模型或访问全库。相同来源版本、元素包、协议与模型配置按摘要复用已接受结果；相同资料的不同查询不重新标注。每个片段的原文在包内只保存一次，依赖关系使用引用。

首轮模型资格拟限定为3个歧义包，输入目标每包约6,000 tokens、结构输出目标不超过1,000 tokens；这是待量化的计划额度，不是已执行用量或工具强制上限。生成派工包后必须重新计算实际规模及TokenBudgetBasis，记录模型、目的、输入尺度、输出需求、质量风险、推理配置、预算与停止方式。内置子代理未提供可靠硬上限或费用回执时须明确这一限制；不得用字符估算冒充实际计费。大包需调整结构边界或单列评估，不静默扩大总预算。

模型出现格式错误先由程序定位；最多安排一次针对同包错误的修正，不重复发送整个年报。语义无依据、原件不足、费用/调用用量未知或出现相同根因的连续失败时停止扩批，交回主代理处理。付费请求失败或未知用量仍遵守逐次恢复约定，不自动重发。

本地读取显式使用UTF-8，并核对输出完整性；编码错误或工具截断后停止标注。经主代理确认的读取恢复单独记账，不能抹掉失败，也不能把重新传入的材料算作零成本。首次模型结果、原始审核标准、修正说明和修正结果分别封存；同包监督修正通过不等于未见资料的资格通过。

结构角色与查询相关性分开：资格包中的编号脚注定义标为附属上下文，完整保留解释和数值；这不等于永久禁止有独立证据价值的脚注按自身检索分数进入主结果。表格仍归表格单元，已识别的页码归导航，不能作为证据不足的未决项。缺失原文和角色已知但无需独立检索是不同状态。

上下文链接必须提供支持端的原文依据，不能只列目标表格的元素ID。共有小节标题、单表说明和实质正文应分别表示：共有标题可支持多个子表，但“按业务类型分解”等专用表说明不能传给地域表；也不能为继承标题而把整段收购等正文自动附加到表格。程序验证覆盖、角色、自指和证据端点，主代理另行核对每条关系的语义及附带内容，防止必需关系全部命中却仍混入错误上下文。

首轮监督修正仍出现元素遗漏或同一根因未修正时，停止模型扩批。下一版交接优先改为程序维护完整元素及覆盖账本，模型仅提交待判边界/关系的增量建议；未被建议涉及的内容保持原状态，不能凭缺席被删除或视为已审核。此方案须另做资格验证，不能用主代理补齐模型输出来追认原批通过。表级脚注关系通过也不证明单元格行列归属、SQL事实绑定、跨页表恢复或全库检索质量。

### 覆盖与验收

覆盖账本先登记全部来源、原始节点和坐标空间，再登记新的结构元素。每个元素具有一个主处置状态：待规则处理、规则已接受、待恢复原件/解析、待模型处理、模型建议待复核、模型建议已接受、保留为非独立检索结构。附属引用可多对多，但不重复计算覆盖量。没有命中探针的内容仍须经过结构检查，不能默认进入已接受。

自动校验元素ID存在、源摘要不变、边界合法、正文覆盖与重复计数、表格行列/脚注引用及返回状态完整。数字/事实绑定仍须核对原文或SQL来源，不由模型自评决定。机械通过后，主代理复核首批全部建议；语义错误单列，不能以JSON合法率代替标注正确率。

每批报告来源数、结构单元数、规则处理数、模型派工/接受/拒绝数、未决数和原因、实际输入输出用量及重复输入比例。所有输入必须有终态或明确未决项；不得把未决资料移出分母。无来源/版本/坐标冲突、完整覆盖有账可查之后，再生成变化输入的少量向量并评估Precision@10、nDCG、完整证据覆盖、延迟和成本。标注验收与检索质量验收分别记录。

## 查询条件

`conservative.v5` 保留完整原问题供语义检索和审计使用，同时生成正向条件视图。明确的“不要／不包括／excluding／not”不应生成正向文件类型或财务概念；询问“是否排除了某项”也不应把该项的证据屏蔽。未知语义不能通过猜测变成硬筛选。

多公司比较按公司出现的位置保留各自主题。某一公司的主题没有被财务词汇表识别时，仍保留其字面检索需求，不能继承另一家公司的已识别指标。单公司多个明确主题同样不能因识别到其中一个指标而丢失其他主题。

请求“日期列、计量单位、原文引用”属于证据上下文要求，不是额外的财务指标，不单独占用概念召回或覆盖名额。“business units”“units shipped”及未限定的“units”仍是业务词，不按计量说明丢弃。带明确核查指令的待核验断言保留在完整语义与字面问题中，不因断言的陌生词另造一个必须覆盖的业务需求。未知业务主题在覆盖选择时也保留重排次序，不能仅凭 BM25 顺序重新提权。

`organization_filter.company_name` 使用资料原有名称和明确封面名称的空格、标点、法律后缀兼容规则。其他字段仍按各自原始身份校验；显式 `issuer_id` 与名称条件取交集，不因名称相似合并公司 ID。缺失和冲突须在回执中体现。

明确封面名称存在时，旧 ID 的尾部不再额外充当公司别名。跨解析 ID 的兼容查询须有单一注册主体、原始 SEC 身份及目录内一致性证据；共同注册主体、同名不同 CIK、同一本地 ID 被另一名称复用时不能合并。原始封面名称与确切 SEC 原件路径可共同恢复 CIK，原始元数据若冲突则保留冲突状态。查询回执保留兼容依据，不改数据库和引用 ID。企业更名、控股重组或不同注册主体仍须按原件身份区分。

报表年度和事实期间不同。`10-K 2023` 与 `2023 10-K` 的显式报表年度等价，但不推断段落数字的期间。明确的多个余额日期、财政年度、起止区间和财政季度分别保留；没有原始财政日历不能把 `FY2025 Q1` 变成自然季度。

原始 XBRL 事实的日期偏好还须匹配事实主体标识及标识系统。无法核对主体时，不因日期相同提高该事实的优先级；保留候选以供回读。原件中只有多个冲突主体或共同注册主体时，不挑选一个主体充当全部事实的归属。

前置事实期间筛选同样核对 XBRL 主体，而不只在重排补选时核对。原始资料提供单一可核验的注册主体及标识后，原块、细分单元和离线适配器都保留这份绑定；指定子公司的条件不能借集团的 CIK 证明。缺少绑定、标识系统不同、联合注册人或原件身份冲突时保持未知，由 `unknown_policy` 决定是否保留探索候选，不能记为已验证匹配。冷加载与验证凭据恢复采用同一规则。

`organization_evidence_filter.fact_periods` 提供明确的事实条件，例如 `[{"concept":"cash_equivalents","kind":"date","value":"2025-12-31"}]`，或带 `start`、`end` 的 `duration`。多个条件取并集；其他业务条件必须在同一原始事实区间成立，不能把甲表的主体与乙表的日期拼起来。日期来自原始句子、可信列归属或 XBRL 上下文，不来自文件发布日期。筛选在向量和词法配额前执行；每个单元只使用与自身坐标重叠的事实。默认 `exclude` 要求已核验的匹配，`retain` 明确保留未确定的候选。旧扁平表若缺少列几何，不能为了命中而猜测期间。

自然语言只对单一余额概念及明确的余额日期生成此类条件，混合指标或不明确的日期角色仍保持宽范围。条件筛选证明某个原始事实满足要求，不表示返回块内其他数字也同属该期间或口径。现金加证券的流动性合计不能充当现金等价物单项余额的期间证据。

## 结构上下文

完整原件的明确报表标题允许正常换行；紧邻表格的独立单位或审计状态说明可以归入结构上下文。任意括号段落、其他公司的说明或跨表格正文不能因“离得近”而继承。

表格行与对应表头、单位、明确标号脚注的关系来自原始坐标。业务条件决定哪个主块进入结果；授权范围决定能否读取附属上下文。一个不含查询指标的表头可以补给同一份已授权原件的表格行，但不会因此占据独立排名。原件当前权限、版本、坐标和摘要仍逐项检查，撤权后不得从旧缓存返回内容。

一个检索块包含多个表格时，已匹配的表格不能把另一主体或口径的表格一起变成相关证据。评分视图只引用满足条件的原始区间，并记录区间摘要；原正文、向量及回读引用保持原身份。只有在相同原始区间重叠的事件、报表和主体条件才能组合；宽泛事件范围不能覆盖其内部已知的主体冲突。

重排启用表格补全时，各候选独立取得自己的表头、单位和脚注，不能因为另一候选包含表头就省略本候选的上下文。补全有总量上限，未能绑定的字段明确记录；预算超限不静默截断原文。补全内容用于解释主块，不作为独立前十结果。

独立重排文档的上下文限额按候选分别计算，避免先处理的候选耗尽后续候选的补全额度；整次提供方输入仍受总字节上限限制。正文外及表格内部的明确报表标题均需识别，包括权益变动表和财务状况表。换行拆开的 SEC Item 标题仍是事件边界；正文明确宣布发布业绩新闻稿时，只将该公告原句绑定为新闻稿及业绩事件，不把其他附件继承为同类事件。

部分旧资料只有已验证的索引节点，没有完整文档坐标。这类资料使用原始节点 ID 和节点内部位置；两个节点的相同数值坐标不代表同一原文位置。规则识别完整、矩形的 Markdown 表格时，可以绑定其表头、单位和连续标号脚注；缺少分隔行或存在歧义的表格不推测列归属。节点坐标有效不意味着完整文档已经恢复。

结构解析代码变化会使旧来源验证凭据失效；随后需重建凭据并验证真实服务，不修改已冻结原文、原向量或引用身份。

## 在线与离线

候选通道配额、RRF 合并和邻接候选扩展由 `retrieval.candidate_pipeline` 维护，组织服务和离线诊断共用。相邻块本身没有加分，只有在独立评分达到相应位置时才进入主排名。附属上下文不改变前十名额。

`trace_retrieval_channels.py` 校验固定导航文件和原坐标，记录实际扩展后的候选集，并对每个词法需求输出完整的截断前 BM25 匹配排名文件。界面回执仍保持有界；全量诊断保留在调用者指定的本地结果目录，带摘要和条目数。完整向量分数与其候选范围顺序一起保存。业务侧未知元数据、通道候选缺失、融合截断、重排失准和结果不足须分别归因。

质量验收必须使用相同代码、元数据、完整结构上下文和候选阶段，不能把缺少服务阶段的离线分数当作服务结果。历史题集为回归集；已用于修复的题不能再次称为独立保留集。

`prepare_retrieval_context.py` 从冻结原件恢复完整结构，并逐节点核对原导航摘要；产物绑定结构实现摘要。`qualify_unit_rerank.py` 与产品共用组织候选准备及提供方输入构造，预检输入摘要必须与实际调用一致。旧结构实现产物不能静默用于新评测。该离线适配器不提供 Java 授权，不能替代真实服务的撤权及并发测试。

评测摘要中的旧 `provider_calls` 字段只表示成功返回排名的新增调用，另由 `provider_receipts` 读取本轮持久账本，区分已确认提交、已完成响应、失败且用量未知、提交状态未知和明确未提交。鉴权在付费返回后撤销时，成功响应仍计入账本；缓存重读不新增提交。旧 `started` 记录不能推断为未发送，失败记录也不能因没有有效排名而记作零成本。审计只读账本，不改旧回执、不触发重试。

## 资产、附件和发布日期

养老金、退休后福利、核退役信托等资产范围只能来自原表紧邻的明确标题或介绍句。公允价值和资产配置表属于补充明细，不能仅因包含“现金”成为集团主报表。混合块按原始区间组合这些条件；未经分类的正文仍按 `unknown_policy` 处理。候选保留不表示块内每张表都可回答问题。

附件的业务角色来自附件行的原始描述；`99.1` 等附件编号本身不等于新闻稿。明确标注的 CUSIP/ISIN 可以作为交易标识，不用票息或年份猜测交易身份。发布日期 `publication_date`、`published_from`、`published_through` 与报表 `period_end` 分开；缺少原始发布日期时返回未知，不能替换成财报期末。

原件将贷款、信贷协议或证券发行明确定义为一个简称后，该原件内的公告与附件描述可按这个精确定义解析融资事件。单独出现的 `Facility` 不足以认定融资；制造设施、冲突重名定义、其他文件中的定义均不适用。业务表格介绍与原表之间只有完整页码／目录／重复附注页眉时，可以恢复紧邻关系；遇到新的正文或其他表格则停止，不向后搜索方便匹配的表。

## 相关性边界的校准

`retrieval.relevance_boundary` 提供离线校准与验证组件，目前不改变现有服务默认返回。它只接受逐问题／原文审核的 0–3 级标签，并以至少 2 级作为相关；未知标签不能自动视作负例，同一对问题和正文的重复出现不增加样本量。拟合前需声明最低保留条目、问题数和精度下界要求。若高分错误与正确结果无法通过统一阈值分开，拟合失败，不能按公司、题目或正确块 ID 例外放行。

在线候选分数和离线校准分数采用相同数值约束：必须是 0–1 的有限数值，拒绝布尔值、数字字符串、缺失值与非有限值，不把 `true` 当作 1.0。校准阈值、精度要求和样本数量同样校验；条目数、问题数及请求上限必须是符合下限的整数。部署加载空候选时仍校验校准参数，不能等首个查询才发现非法阈值。此输入校验不替代真实相关性校准。

启用阈值前还须使用问题和原始文档都不与校准集重叠的评测数据，绑定相同模型、策略和索引身份。分数不解释为正确概率，名义 Wilson 下界也不代表相关样本之间独立，更不代表生产保证。排序不足请求条数时不补入低分候选；未纳入主结果的候选保留独立身份与不确定状态，空结果不解释为资料不存在。固定 K 的 Precision 仍把空位留在分母中，另报实际返回数量，不能因返回更少而虚增 Precision@10。

## 服务策略

维护者通过 `FINSIGHT_ORGANIZATION_SEARCH_PROFILE=research.v1` 为普通组织查询统一选择 `conservative.v5`、`sec_cover.v2`、`needs_window.v4` 和 `bounded.v1` 表格补全；调用方不必拼接这些实验参数。回执记录配置策略与实际生效条件。与策略冲突的服务端覆盖值会在初始化时报错。

默认 `legacy.v1` 保持已有部署兼容；启用研究策略是显式部署动作。策略本身不启动付费调用，远程重排仍须单独配置 `FINSIGHT_ORGANIZATION_RERANK=qwen` 和提供方凭据；研究策略对应 `qwen3.7-text-rerank`。部署验收必须记录策略、模型、索引与代码身份，不以默认兼容路径的测试替代研究策略验收。

带区间单元的发布使用 `research.v2`，对应 `needs_units.v1`：两路主要配额发生重复时，优先从各路后续独立排名补足最多 48 个不同原始候选，不用相邻块填充这部分名额。回执保留主要配额、补入的候选及实际考察的通道前缀；RRF 不把补入候选的原始通道名次改成第一名。此策略要求已发布单元组件，缺少组件时在任何新查询向量请求之前报错。

## 原始区间索引

宽块向量不能代表排除错误表格之后剩余的正文。新的可选 `semantic_units` 发布组件按已验证表格、业务范围边界及正文段落建立区间单元；每个单元保留原始节点、原件摘要、坐标系、起止位置和逐字正文摘要。规划器校验分割覆盖全部字符，不把相邻表合并成一个检索单元，不截断长段落。无内容空白保留在规划中，不生成向量。

只有输入文本及模型完全一致的完整原块才能复用向量；改变输入的单元需要已完成的独立向量回执。发布函数本身不调用提供方，拒绝缺失向量、错模型、错输入、错原件及不完整父节点范围。单元向量、词法库和元数据文件作为同一发布组件纳入索引摘要，因此 Java 准备单冻结的 `index_digest` 同时绑定它们。旧发布文件不改写；创建新发布后才可选用这条查询路径。

`original-retrieval-units.v2` 和 `published-original-unit-index.v2` 使用 `document-identity-only.v1` 输入上下文：仅保留文档标题及有明确格式的原始定位信息。旧 `embedding_context` 可能包含前一块的表格行，不能继承给每个新单元，也不能作为当前候选的独立重排正文。现有父节点正文、引用与旧向量身份保留；新向量必须按新的精确输入准备。`research.v2` 在调用新查询向量之前拒绝旧版单元发布，旧版发布仍可按原兼容路径校验和读取，禁止原地改写。经过验证的同表表头、单位和脚注继续通过独立的结构上下文提供。

查询时先按当前授权父节点及其可信原始范围筛选单元，再分别计算向量与 BM25 分数。向量按同一原始候选内的最高合格单元分数汇总；词法路线先按父节点去重再分配名额，防止一张大表的几十个单元耗尽一路配额。BM25 只统计单元正文，不把文件标题或其他表的正文计入本单元。返回的引用仍是原始节点；通道回执另列命中单元的位置、摘要与分数。细分单元通过工程校验不意味着向量或排序质量已经通过。

`plan_retrieval_units.py --index <固定发布的 index.json> --output <新目录>` 只做逐文档规划和成本规模统计，不调用模型、不产出可查询发布。全量检索单元需要通过真实组织服务、权限撤销及质量题集验收，不能以规划文件存在代替。

付费准备使用 `prepare_retrieval_unit_vectors.py prepare --catalog <units.sqlite> --scope <冻结父节点范围.json> --output <新目录>` 生成任务清单与 `TokenBudgetBasis`；显式 `execute --output <该目录>` 才提交。每批最多 20 个原始输入，按提供方模型和精确输入摘要保留回执。完成的批次可以恢复读取；失败或结果未知的批次保持阻断，不因进程重启重新提交。执行过程中检查输入漂移、内存、磁盘及用量上限，不缩短原文来规避预算。

重新规划可用重复的 `--reuse-receipts <已完成准备目录>` 排除已有精确输入回执；新计划记录复用输入及回执文件摘要，执行前复核。新分批方式不会重新提交这些输入。任何引用目录含未完成或未知结果的批次都会阻断准备，不能通过换批次绕开未知计费记录。

期间补选同时检查原问题的文档约束。目录字段未知的资料仍可参加召回，但它的某个匹配日期不构成“满足指定年报／文件身份”的证据，不能仅凭这个日期把它提到指定文件的候选之前。金融事实期间与文件身份在回执中分别记录。明确声明的融资新闻稿按公告对象识别，不能因它和业绩新闻稿都使用 Exhibit 99.1 而混为同一事件；同一公告含多种对象时保留不确定状态。

`build_retrieval_unit_overlay.py` 只读取已完成回执，在新目录构建指定父节点的全部单元，并校验原件、输入、模型、矩阵与组件摘要；它不调用提供方，也不激活 Java 准备单。`trace_unit_retrieval.py` 使用生产单元排序函数与冻结查询向量，输出完整的截断前单元向量分数和逐需求 BM25 分数。规划器选中的范围超出已发布诊断范围时立即报错，不能静默缩小范围。此候选阶段诊断仍须接最终服务页、当前授权和完整题集验收。

离线评分驱动保留并校验全目录元数据，以便规划器仍能发现范围外资料；逐节点结构仅驻留本次诊断发布中的文档。选中的范围超出发布时仍阻断，不用少加载结构偷偷缩小题目范围。评分计划同时冻结驱动与上下文适配器代码摘要，防止只冻结产品代码而遗漏离线处理逻辑的变化。

## 图和重复结果

联合申报封面可能在同一个注册人说明之前连续列出多个完整法人名称，也可能使用表格。目录保留这些名称作为文件查找别名，不把最后一行当作唯一注册人，不用归档 URL 的 CIK 给每个法人赋予同一事实身份。联合申报中，文件查找名称与报表主体约束分开：问题明确写出完整法人名称，或仅省略法律后缀且在全部联合注册人中唯一对应时，可以绑定该主体。`North Energy` 可以对应唯一的 `North Energy Inc.`；但 `North` 同时对应 `North Inc.` 与 `North L.P.` 时仍未确定。只做法律后缀兼容，不猜缩写、不按公司名单合并身份。较长的完整名称先于其局部别名，比较问句中的各主体仍保留独立指标和覆盖需求。重排文档说明列出联合注册人并提示它们不是可互换的报表主体。

检索标注同样区分主体身份与具体指标的等价关系。若原文明示某些主体的特定资产、负债金额相同，需要记录原件版本、说明位置和适用指标；不能推广到权益、利润或其他期间，更不能只因数字相同就认为等价。缺少该关系说明的候选不计作独立完整答案。修订已暴露题目的判断时保留旧版、逐项更正原因和原文依据，重算旧结果的指标变化不算检索质量提升。

内存受限时，可用 `python -m scripts.engineering.prepare_unit_rerank_isolated` 准备整套复测输入，参数与 `qualify_unit_rerank.py prepare` 相同。它按原题集顺序，每题使用一个退出后释放内存的独立进程；保留完整的索引范围、候选生成和 800 MiB 内存保护，不执行付费请求。所有题完成前不生成可执行的统一 `plan.json`。显式 `--resume` 会校验代码、原始题集、索引清单、结构清单、配置、已完成题目和各通道轨迹的摘要，只复用同一冻结版本的完整输入。失败进程的产物保留，新的准备尝试单独存放；这不是付费请求的自动重试，也不能作为真实 Java 授权或并发能力验收。

历史候选审核使用 `score_retrieval_review_pool.py --pools <分批候选目录> --judgments <已审核判断目录> --output <新结果文件>` 汇总。判断必须同时匹配问题文本摘要、候选 ID 与正文摘要；新问法不会继承另一问法的标签。缺审核的候选保持未知，整批只要有一道题前十未审核，就不输出整批确定的 Precision。Precision@10 的分母固定为 10，另列按实际返回数量计算的精确率，空返回的后者为未定义。nDCG 与池内召回还要求整个冻结候选池全部审核；不能只审核前十，再把池中未审核的更好答案排除出理想排序和分母。即便候选池审核完整，这两项也不能表示全库全部等价证据。工具同时检查正文变化、重复排名及前十名次缺口，防止统计时把第十一名补到遗漏的位置。

每题同时输出 `candidate_diagnostics`，保留各候选的原文身份、审核理由、各阶段排名及已保存的 BM25、向量、重排分数。历史未保存的分数保持空值，不能用排名反推，也不跨问题直接比较不同量纲的分数。各阶段的 `ordering_diagnostics` 单列“前十无关候选排在直接证据之前”的已审核候选对，并区分直接证据未进入该阶段的情况。未审核项和仅提供背景的片段不当作无关项；池未审核完整时，这些局部诊断不替代整批质量指标。

原始候选审核入口 `review_retrieval_rankings.py` 采用相同限制：其他通道前十和已知证据组成冻结审核池，其中未审核的候选也会阻断 nDCG 与池内召回。复用判断文件中不属于本次审核池的候选不进入分母，防止两种工具因分母不同给出不可比较的结果。

同一 SEC 原件的多份解析可以在当前已授权目录内补齐缺失的报表类型、报表期末、发布日期和自然年年报标记。连接键必须是经过校验的完整 SEC 原件路径，包含 accession 和文件名；附件与主申报文件不合并。发现已知字段冲突或原始封面冲突时，该字段保持不确定，并记录解析来源和冲突。该兼容逻辑不合并公司身份、不复制财务事实，也不扩展权限；自动范围规划、显式资料筛选和重排文档元数据共同使用它。

非自然年年报可从原件前置部分的独立 `Fiscal 2025 Annual Report on Form 10-K` 标题恢复 `fiscal_report_year`。它要求同一原件已有可信 SEC 封面，限定正文 Part I 之前的前置区域，不读取目录文件名、下载日期或正文中引用的历史报告。财年标签可以不同于期末日期所属自然年；这不是从日期推算财年。多个标题、表单冲突，或同原件的自然年标记与明确财年标题冲突时保持未知，不择一补齐。查询筛选、证据覆盖和重排使用同一标签，重排中明确区分它与段落内事实期间。没有明确标题的非自然年报告仍保留未知，不能因此断言资料缺失。

问题中的 `10-Q 2025-11-19` 等字面文件标签日期用于文档选择：与已知申报发布日期或报表期末匹配，并记录采用这一兼容约定。两种日期均已知且均不匹配才明确排除；有未确定日期时保留未知。它不等于现金等财务事实的日期。事实期间解析单独排除这种紧邻文件标签的日期，再处理后文的目标日期。多个不同标签日期不收窄成其中一个，显式结构化日期字段的原有含义不变。

日期可以紧邻文件标签的任一侧，支持 ISO、英文完整月份和中文年月日，例如 `June 30, 2026 10-Q`、`10-Q 2026-06-30`、`2026年6月30日的10-Q`。同一识别结果同时用于文件选择和事实日期排除，保留原始文本位置；不跨越正文推断日期归属。无效日期、多份不同日期文件和修订表单保持各自边界，`10-Q/A` 不作为 `10-Q` 的字面标签匹配。此规则不从文件发布日期猜测非自然年财年。

事实期间的正向证明必须完整落在当前候选或检索单元的原文区间内。只有部分重叠的句子或单元格不能证明该候选包含完整数值与期间，筛选和重排采用相同的包含规则；严格事实筛选将其视为未确认，探索模式仍可保留并回读原件。这个判断不修改原文、不推断缺失数值，也不禁止独立的可信结构上下文补全。

正文事实绑定在原始段落和句子内完成。空行与 Markdown 标题前的句末是边界，不能把上一段的财年和下一段的债务等概念绑定；普通行内换行和小数点保持完整。证明区间去除首尾空白并同步调整坐标，避免段落前的空行使完整事实被误判为截断。中文事实日期同样支持数字与年月日之间的空格。

`conservative.v5` 可以为明确的关系类问题使用查询规划已经解析出的公司 ID 作为图起点；未解析身份不猜测，普通报表数值问题不自动分配图名额。图仍只使用已发布、已审核且当前授权的一跳原文证据，不保证关系覆盖完整。空图结果不占向量名额。

自动图起点只检查正向关系需求；“现金余额，不要供应商关系”不会因为排除项出现关系词就分配图候选。“是否不存在供应商关系”仍是需要查证的问题，不能屏蔽相关证据；调用方显式提供的实体起点保持既有行为。

结果分组只合并同原件版本、同坐标系、同区间和同正文的重复投影，并保留可回读的另一节点身份。仅数值或正文相同不足以跨表格、期间、修订版本合并；分组后由原排序中的后续候选补位，不凭邻接关系提权。

## 公告查询的分散表达

旧公共节点导入时，节点上的 `company` 等文档声明必须保留到来源元数据，不能只留下 `import_origin` 而让组织筛选误判公司未知。新发布与旧捕获恢复共用 `indexed_source_metadata` 规则：校验节点所属文档、原件 URL 与原文摘要，全部节点的公司字段完整且一致才用于公司筛选。字段缺失保持未知，来源行与节点、或节点之间冲突时记录原声明并停止用该公司声明收窄范围；不取第一项、不从标题或网址猜测。旧资料无需修改原件或重算向量，但需刷新受实现摘要保护的元数据投影。

节点上的股票代码及旧 `issuer_id` 作为带来源的声明保留，不自动改写成统一公司 ID。恢复文档公司名称也不能证明其中基金、子公司或交易对手的财务事实属于集团；事实主体和当前组织授权仍分别检查。元数据范围诊断只能证明候选保留或排除情况，不能用它替代重新检索、重排后的 Precision 或 nDCG。

自然语言中的公告主题不要求紧邻“公告”二字。例如，“业绩所对应的季度”和“新闻稿、附件”共同构成明确的业绩发布需求。规划和词法需求使用同一正向事件识别；排除的融资公告不作为正向主题。问题同时要求业绩与融资，或只有未说明主题的新闻稿时，不猜测唯一事件。新闻稿、附件、财报季度与发布日期采用通用导航译词，保留原始字面检索路线。

原公告紧接着明确表示“该新闻稿的副本作为附件附上”时，副本说明保留同一公告的业务归属。否则，过滤融资公告首句后，其 `Exhibit 99.1` 指代可能错误地变成未知业绩候选。该绑定只覆盖直接相邻且句式明确的副本引用；遇到空段、其他陈述、新 SEC Item 或另一新闻稿时停止。它不将整份文件归为单一事件，也不替代原文当前授权。结构区间发生变化后须重新生成结构与单元清单，不能沿用旧分段向量或原地修改旧发布。

待核验断言后跟明确的查证请求时，断言中的并列分句不再额外分配“必须覆盖”的独立业务名额。原始完整问题继续用于语义检索和重排，断言文本及位置另行记录；后面的客户集中度等未知业务主题仍保留。没有后续明确查证请求时，不自动删去用户陈述。这一处理只调整需求拆分，不宣称已验证陈述真假。

## 向量准备的显式故障恢复

`original-retrieval-units.v3` 保留完整原文区间，但纯空白、表格标记 `[TABLE:…]`、`[/TABLE]` 及仅有空单元格分隔符 `|` 的区间不进入向量或词法索引。它们没有财务证据，文档标题却可能使其向量获得高分，再通过子块最高分抬高父块。该规则不按长度删除片段：表头、单位、数字、脚注、表示零值的短横线和目录文字仍保留，需分别判断用途与相关性。

新发布使用 `published-original-unit-index.v3`，记录没有可检索正文的父块身份及正文摘要。发布时逐一回读原件验证；缺失实质正文不能冒充纯标记。整个范围没有证据单元时拒绝发布。历史 v1/v2 发布可校验和归档，但新的单元检索策略要求 v3；需要创建新发布，不能修改旧向量文件。向量复用仍要求输入摘要与模型完全一致，旧计划不能越过代码和格式摘要检查继续执行。

空单元格还可能含零宽空格 U+200B 或 BOM U+FEFF。这两个字符仅在判断纯结构内容时忽略，原文、坐标和摘要不变；带数字 `0`、短横线或单位的单元仍保留。发布与检索测试同时覆盖这种空父块，防止它凭文档标题获得检索分数。

`scripts/engineering/audit_structural_unit_scores.py` 可用已保存的全量单元分数验证纯标记对父块最高分的影响，无需付费调用。它核验轨迹摘要、单元身份以及问题/正文标注，只输出保存分数下的排名变化；没有重新运行候选融合和重排，不能据此宣称 Precision 或 nDCG 提升。

单元排序入口统一校验并归一化查询向量，离线保存的供应商原向量与在线已归一化向量遵循同一余弦计算契约。零向量、非有限值及维数错误拒绝计算。历史未归一化的点积分数仍保留，不原地改写；同一查询的正常数值缩放不改变排序，不能把归一化误差修正计作相关性提升。

费用评估前可给 `plan_retrieval_units.py` 指定 `--scope`，以固定原发布摘要和父块清单规划隔离的诊断范围。范围必须包含所选每份资料的全部父块；缺失节点、重复节点、部分文档和旧版本范围均拒绝。默认仍规划完整原发布。诊断目录记录范围摘要和资料数量，不标为全库发布；向量缺失继续报错，不能靠删去缺失块、补零向量或自动付费调用完成发布。

失败或用量未知的向量批次默认禁止重发。操作员取得该批次的明确重试授权后，可向 `UnitEmbeddingPreparation.embed` 传入 `retry_authorization`，包含唯一授权 ID、理由和 `receipt_digest` 计算的原失败记录摘要。恢复通过原子比较更新领取一次执行权，保留全部历史失败和未知用量；授权不能复用，正在执行的记录不能据此重试。重试再次失败需要新的明确授权，不把旧未知用量记为零。准备摘要分别记录成功调用、实际提交次数及失败用量未知次数；重启后的摘要只统计本轮执行，历史回执继续保留。

重新规划时可以复用已完成计划或中途停止计划里的成功向量；未提交的工作仍需生成，但遇到任何失败或待定回执即停止，防止通过重新分批绕开重试限制。复用按实际输入摘要与固定模型匹配，缺失向量不回退到在线调用。结构变化后的新目录和旧计划分别保留，生成发布仍须验证新目录内所有需要的向量。

## 相关结果与不确定候选

`FINSIGHT_ORGANIZATION_RERANK_INSTRUCTION=financial-evidence.v1` 是服务端可选的证据相关性任务说明，仅支持已验证参数协议的 `qwen3.7-text-rerank`。它要求按文件、主体、资产归属、事实期间和公告对象判断直接证据，不含公司名单、答案或分数阈值。说明文本冻结到导航实例和付费回执；更改说明不得复用旧评分。该选项默认关闭，启用仍须完成独立质量评测。

`FINSIGHT_ORGANIZATION_RELEVANCE_BOUNDARY` 可指向部署持有的校准及独立验证 JSON。文件包含 `calibration` 和 `validation`，必须与实际模型、说明摘要、服务策略、补全配置及查询/检索代码摘要一致；验证题及资料必须与校准集分离。未通过验证或配置不匹配直接拒绝启用，不回退到任意固定阈值。文件在导航实例创建时冻结，更新需要新建实例。

服务与离线验收共同使用 `ResultBoundary`：完成去重后筛选主结果，不补满请求数量；不确定候选 ID 单列，不能作为“未披露”的依据。即使零个主结果，顶层 `organization_relevance_boundary` 仍保留筛选回执。缓存回读保留该回执，并继续执行当前组织授权及存储版本检查。筛选不授予任何读取权限，也不意味着返回内容已经形成正确金融结论。固定 K 的 Precision 分母仍为 K，空槽位不能计为正确；返回结果精确率、覆盖率、池内 nDCG 分开报告。
