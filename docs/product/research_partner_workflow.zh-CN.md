# 研究伙伴：连续工作与按需研究

状态：设计已记录，尚未实现或验证。2026-10-28。

本文件是连续工作产品边界的维护入口；具体模块、旧逻辑替换和验收见[第一阶段技术设计](../architecture/on_demand_research_runtime.zh-CN.md)。它取代 0.1.4 早期方案中“进入研究即默认走完整研报交付”的产品假设，不追溯修改历史成果或验收结果。

## 用户需要的连续工作

用户可以从问答、阅读、调查、计算或底稿开始，在同一工作空间继续追问、补充材料、要求检查或形成报告。不要求先选择研报与非研报两种 harness，也不要求模型把每个问题升级为完整研究。

研究报告是一种可共同维护的成果。交付底稿可以结束当前请求，未形成报告不等于任务失败。用户下一次要求扩展时复用已有材料、计算和成果版本。资料库是研究基础设施；外部检索受实际可用工具和授权约束，不因库内无结果就认定世界上无资料。

主 Agent 可以直接使用工具，也可以按需要委派独立连续任务。多 Agent 是工作选择，不是产品要求的固定组织。必要时可安排独立复核；用户明确要求的检查不得被模型自行省略。检索到来源、算术正确、复核完成和投资判断正确分别展示，不能相互替代。

## 第一阶段承诺与不承诺

- 打通“问答 → 资料/计算 → 底稿 → 追问 → 可选子任务 → 成文 → 局部检查/修订”的连续工作；各中间成果都可以正常交付。
- 用户只需描述目标和需要的交付。系统不要求用户或模型为每一步填写新的计划、证据等级或验收表。
- 用户可查看进展、停止或改变目标；已经发出的调用固定原输入，后续工作采用新要求，不静默覆盖历史。
- 明确要求经过复核的报告，须完成约定检查才能如此标注；探索性回答可以带未决问题交付，不假装已核验。
- 第一阶段不新增交易执行、通用回测平台、任意递归团队或自动生成任意技能，不承诺语义推理自动正确。

## 产品验收

1. 只问一个普通问题时，不自动创建专家、报告或复核链。
2. 只要一份底稿时，能交付底稿并结束当前请求，不强制包装成报告。
3. 从该底稿继续研究时，能够保留来源与版本，不要求用户复制粘贴历史重建任务。
4. 确有独立任务时可以委派；子任务返回后主 Agent 能解释它对用户问题的作用。
5. 用户要求成文和后续局部修订时，复用已有成果，检查状态绑定具体版本和范围。
6. 当前请求完成、成果已保存、检查是否完成分别可见；运行故障不会显示成资料不存在或判断已通过。

以上只是待验收要求，当前普通对话、动态派工、来源计算和版本修订等基础能力已存在；新的统一工作链尚未验收。实际研究质量仍需以回答是否切题、推断是否成立及最终成果的可用性评估。
