## 固定下来的处理范式

```text
来源/版本核实
  → 按文件格式＋原件用途选择路径
  → 保存解析库原生输出与坐标、角色证据
  → 统一结构（段落、标题、列表、表格、图像、表单字段）
  → 建立章节范围、逻辑表与附属关系
  → 结构状态驱动的预分块 / 结构化记录
  → 全量自动核验＋分类型源先验质量审核
  → 按能力与用途发布；保留原件和旧引用
```

解析器负责提供其擅长的原生结构；FIN 适配负责保留、对齐、消除已证明的表示损坏并表达不确定性。财务事实层另外负责主体、期间、单位、修订与计算口径，不让章节模型或表格角色直接决定财务真值。

每个结构单元至少应能追到：原件摘要、原坐标命名空间、原生节点、原始角色/层级、FIN 采用的角色/父子关系、依据、处理版本、检查范围及状态。缺失字段可以明确未知，不能靠猜测补齐。原件 DOM、解析器节点路径、Markdown 行号、PDF 页面坐标不是同一种定位。

**修复选择顺序：**先检查库已有能力是否未消费；再补结构族适配；确有局部歧义时才进入受限辅助识别或人工修正。新工具不是自动胜过旧修复；同原件逐层对照后选用。通用角色规则要有原结构证据，不能以公司、题号、答案词或字符串长度代替。

**单份补丁边界：**目前没有证据表明上述大类必须靠公司专属补丁解决。坏锚点、源文件自相矛盾、缺失图片/字体、不可消解的局部版式等，经常规路线和类型适配尝试后仍不能处理时，允许保存原件摘要＋局部坐标限定的修正记录。记录原值/新值、证据、审核人或模型、依赖版本、失效条件。原件变更立即失效；不修改原件、不重用到同公司新年报、不直接修改 SQL 数值。同一结构问题重复出现时再考虑上升为类型规则。

**异常资料不是“正则没匹配到”。**异常由契约失败触发：原文或关键单元格丢失、冲突范围、无法定位、必要结构不支持、角色证据矛盾等。无章节但本来是表单/目录可以是正常类型结果；原件可读而复杂表格未核可给予限制用途，不必整份永久阻塞。未知不是错误的同义词，但不能被隐藏成 ready。

**模型仅做可定位的补充。**如后续启用，只提交疑点区域、必要祖先/邻区与候选 ID，返回角色/关系建议，不全文改写、不创造数据。显式范围和 TokenBudgetBasis、复用输入摘要、有界尝试、失败/未知费用留档；规则与独立资料资格验证后才能自动采用。本轮没有调用模型。

混合排版表中，标题可以只占首个非空行，后续行仍有正文。此时保留物理表和所有单元格；只有原件首行的 Item 编号与原生分区一致、两格文字均为完整粗体、原件与解析单元格完全对应、非目录链接且分区唯一时，记录行级标题定位。标题不能把整表变成结构占位符，也不改变正文所属范围。原件摘要、行 XPath、解析行号、列索引和父产物均进入证据；重新审核必须从原件重建证明。

同一标题的大小写差异不构成语义冲突。标题匹配允许 Unicode casefold，显示仍保留原文写法；多个出现位置全部保留。真实不同的标题、位置无法证明、表内跨行或多重分区仍保持未决，不能用宽松字符串匹配选最近的一处。此修复同时进入当前原件处理入口和既有产物的增量适配。

未知层级需分清作用域：当前548个可见未知级别中，547个为物理表格内部局部标题候选，1个为文档章节父级未确认。局部标题可能是新闻稿主副标题、表内小标题或其他强调文字，不应为了消除 null 而统一填入文档级章节树。审计新增两种作用域计数，同时保留原548总量，不将重新分类当成修复数量。
