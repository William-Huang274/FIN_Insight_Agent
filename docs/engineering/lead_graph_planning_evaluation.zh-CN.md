# Lead 图辅助规划：工具引导、反馈和诊断测试

状态：2026-09-23 设计固化；未修改 runtime、部署、资料、向量或模型配置，未启动付费测试。本文新增反馈字段、动作和评分为待实现合同。

依据：[产品约定](../product/lead_graph_research.zh-CN.md)、[分段资格路线](runtime_flow_qualification.zh-CN.md)、[检索优化](../architecture/retrieval_optimization_review.zh-CN.md)及 [Java/Python 边界](../architecture/java_research_service_contract.zh-CN.md)。

## 1. 已有接入点与范围

- `src/sec_agent/agent_runtime/research_orientation.py` 的 `ORIENTATION_SYSTEM_PROMPT`、`OrientationLibraryReadAction` 和 `SubmitResearchOrientationAction` 是预研究入口。复用 findings、topics、scope_map、next_evidence、success_criteria、依赖及 next_wave/deferred，不重建另一种规划结果。
- `deepseek_structured_agents.py` 在 `orientation_only` 时实际选择上述提示词。新引导须通过这一消费点接入验证，文档不代表模型已收到。
- 当前预研究限 `source_space=library`，允许 catalog/search/read/related/observations/company/data；未开放外网获取。首轮可验收提出具体新增信源需求，不能称外部取证完成。开放取证需独立接入既有授权与请求账本。
- `bind_orientation` 校验来源回读引用、专题引用及依赖环，不判断金融语义正确。保持事实发现需原文回读的约束；未探索范围可进入 scope_map，不伪造已读事实。
- 首轮止于初步认识与专题规划，不启动专家或最终报告。全库修复、完整40题检索验收不作为开始条件，仍保留其独立验收范围。

## 2. 待注入的使用引导

加入现有 Lead 提示及相应工具描述，使用真实 wire ID，不把文档逻辑能力名注册成重复接口：

> 对产业链、交易对手或资金联系问题，优先用局部关系建立方向，再按研究需要结合独立文本搜索和结构化数据。图不是答案范围或事实保证。无需逐边使用、核查或搜索。
>
> 先读与判断相关的证据窗口，限定条件不足时扩展。区分导航候选、证据支持的事实和研究假设，保留主体、期间、单位与实际/计划状态。不要把平台接入、合同、规划、交付和实际收入混为一谈。
>
> 围绕用户问题组织有意义的专题，说明重要性、依据、下一步证据、优先级和依赖。必要但未探索的范围继续保留；不要因现有材料方便而缩小原题，也不要把全部邻居扩展成专题。
>
> 图不覆盖、材料陈旧、关系受质疑或存在反证时，按需补查图外文本、指标或其他信源。搜索未命中不等于未披露；缺少外部获取能力时提出具体取证需求。
>
> 数据疑点可简短记录后继续。未读全文不妨碍提出待核疑点，但不能宣称已证伪。新关系保留主体、方向、状态和证据，作为候选，不直接写正式图。不要为反馈额外遍历所有关系。

结果保留来源/记录/边 ID、版本、命中通路、关系限定条件、证据锚点、截断及续读信息。复用已有字段，摘要与按需详情分开。排名分数与审核标签不是金融事实概率。

## 3. 质疑与新发现记录

反馈是研究运行产物，不修改只读发布库。兼容扩展时保留旧请求合同，避免向 `extra=forbid` 的旧模型直接加字段。

| 字段组 | 内容与约束 |
| --- | --- |
| 定位 | edge_id（已有边）或候选关系、source/chunk_refs、snapshot_ref；不得虚构已有 ID |
| 类型 | 主体范围、方向/角色、状态/时间、证据不足/冲突、缺失关系；区分质疑与新增发现 |
| 说明 | 简短可公开问题陈述、已见依据、待核内容；不索取内部思维过程 |
| 阅读程度 | 仅关系卡、摘录、支持段落、扩展上下文；宿主关联实际 read_ref，不仅凭模型自述 |
| 本次影响 | 暂不采用关系、独立补查、计划变化、未影响；区分模型显式说明与轨迹推测 |
| 建议 | 可选修正或核查行动，未验证建议不能提升为事实 |

宿主绑定运行、调用、资料版本及实际返回/已读记录，验证引用权限；其他来源新发现先保留候选状态。未知 ID、越权和旧版本覆盖须明确报错。

支持批量及幂等提交；提交身份与同一版本/边/问题类的聚合分开，不丢不同依据。区分待核、已有支持的疑点、已解决、未成立；模型提交不直接变为已解决，多次质疑不是事实投票。

暂不采用只影响本次推理，不删原边，不屏蔽原文检索。修复发布新版本并保留问题生命周期，本次运行继续固定快照。

## 4. 反馈卡与决策弹窗

普通反馈持久化并返回回执，研究继续。用户主动点开活动卡，可选记为待核/本次暂不采用关系/安排补查，并输入文字。

需要决策时单独提交 decision_request，携带问题、选项、影响、阻塞范围和 run/checkpoint/快照关联。反馈提交成功不等于用户已回答。

同步决策复用可持久恢复机制；无关分支可继续。不得超时默认批准、重新创建 run 恢复等待或自动重放付费请求。用户选择不能认证关系为真或直接全库删边。

Java 负责用户交互、业务身份及意见提交的业务适配；Python/Agent Server 保留研究反馈、证据身份和 checkpoint。正式字段及界面接入需同 Java 任务对齐。当前无新端点、弹窗实现。

## 5. 先自然观察，再诊断

先完整提供使用方法，再处理真实问题；模型输入不含审计缺陷、应有专题清单或标准答案。方法引导与独立评审标准分离。

首个自然案例采用资格路线的 AI 采用与资本投入总题：需求、交付、云收入及电力兑现的证据联系。按实际运行日固定 research_as_of，检查归档时效，不为迁就旧资料回退日期。只要求第一轮有依据的研究计划。

随后按表现选择三类已知开发回归：微软/OpenAI 多类权利关系、Talen/Amazon 合同与探索/输配电角色、腾讯云平台接入与基础设施边界。这些不计独立正确率。

另准备至少四个未参与提示词调整的案例：关系丰富但非全相关、图稀疏而正文有事实、指标与经营解释结合、材料陈旧/期间差异。先核实可用依据与工具路径，参考答案不交给被测模型，不按它的回答反推评分标准。

出现值得诊断的问题后，才对选定案例做受控对照：固定模型、题目、提示、资料/日期及预算，只改变图线索可见性或提供已定位证据。保留随机性和成本边界，不把一次差异全归因于图，也不要求先跑完所有消融才能观察第一轮。

每次付费前保存 TokenBudgetBasis：目的、输入规模、所需规划输出、质量风险、模型/推理配置、上下文与输出上限、轮次/工具/费用上限及停止行为。触顶保留未完成产物，不缩小原题伪装完成；失败和未知用量不自动重发。本文不是具体付费批次。

## 6. 观察与验收

复用 orientation 公开结果，不要求长篇逐工具自述。宿主保存请求、返回 ID/版本、窗口、候选通路、耗时和已报告用量；模型只说明重要专题选择、补查需求和疑点。

| 维度 | 核查问题 | 不作为成功目标 |
| --- | --- | --- |
| 理解聚焦 | 保留用户目的、范围、时点和重要条件？ | 复述长度 |
| 有效发散 | 提出相关、可验证的替代解释、风险或依赖？ | 邻居/主题数量 |
| 专题组织 | 有触发依据、边界、优先级、依赖及完成条件，避免重复？ | 每公司一专题 |
| 图的帮助 | 减少重复发现工作，帮助提出更好的问题？ | 用尽所有边、遍历率 |
| 图外探索 | 按真实缺口补查，必要时从正文发现新事实？ | 强制每题外搜/找新边 |
| 证据纪律 | 保留限定、识别反证后调整？ | 引用数、工具调用成功 |
| 成本体验 | 有效取证、无效阅读、耗时、用量、不必要弹窗如何？ | 单独追求最少 tokens |

逐维记录有证据支持、部分满足、未满足、不可评估及依据，不用模型自评替代审核，不急于合成总体正确率。“已返回→已读取→引用/采用”分开记录；未采用不天然是失败，也不能仅凭先后顺序断言某边造成错误。

## 7. 归因到最早可复现环节

| 现象 | 初步分类与检查 |
| --- | --- |
| 原文未入库或陈旧 | 数据覆盖/时效，先查来源可得性 |
| 原文有事实但关系漏记或过宽 | 提取/归一/关系语义，保留文本补查 |
| 资料存在且可访问，查询未返回 | 检索/过滤/排名/证据绑定，回放相同请求 |
| 返回截断、定位失效、工具报错 | 工具执行合同，不计作公司未披露 |
| 信息已返回仍漏关键专题或沿错误方向 | 先检查引导与展示，再检查模型选择/理解，必要时对照 |
| 事实理解正确但专题重复、无优先级或偏题 | Lead 规划组织，不靠补边掩盖 |

允许多因素和未定因；记录最早故障及后续影响。高 token 是待解释现象，不自动等于图无效或模型能力差。

## 8. 实施顺序

1. 复用预研究入口注入工具引导，接最小反馈合同、引用校验和持久化，不改发布库。
2. 验证反馈非阻塞、必要决策可恢复、重复提交及引用身份，再接活动卡/弹窗。无付费 fixture 只证明合同。
3. 跑一个预算明确的自然 Lead 案例，读取真实轨迹与规划；按表现选择开发回归及独立案例。
4. 交付规划质量、数据/工具/模型问题分类及成本，再决定修复项和扩大范围。

工具/提示未被实际消费前只称设计完成；真实运行和依据评审前不称 Lead 能力通过。资料及向量不变，无需重做 embedding。
