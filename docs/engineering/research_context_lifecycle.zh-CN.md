# 正常运行与恢复运行的上下文生命周期

完整研究记录保存在原生 checkpoint；发送给模型的是可重建的请求视图。缩小请求不修改原件、研究任务、预算或工具计数，不授权重发失败查询。

## 接续边界

运行框架在接近输入阈值时要求作者提交工作状态。只有 `UpdateResearchStateAction` 被原生图接受后，才允许释放旧结果。显式 checkpoint 校验原未决问题及被否定解释的连续性；拒绝的笔记不产生释放边界。

以下内容保持可直接读取：当前任务及用户修正、有效接续状态、重要发现的原始依据、草稿引用、计算及财务操作数、当前指定共同核对的来源、最新读取批次、失败记录。其余成功读取只有在存在准确回读入口时才可离开当前请求。普通阶段完成可释放可回读旧结果，但旧笔记替代只在连续性已校验的显式 checkpoint 后进行。

## 恢复包与实时工具结果

恢复专家任务时，历史 observations 位于初始语义消息；实时结果位于工具回复。两种表示遵守相同的接受边界、引用保护和最新批次保护。

原生状态持久化最近工作状态是否为已接受 checkpoint。恢复后的第一条请求直接应用该边界，不要求模型再次提交相同笔记。旧版本状态仅在保存的成功 checkpoint 回执与当前工作状态完全相等时补认该标记；拒绝的提案、普通笔记及不匹配回执不能建立边界。新的普通笔记更新会清除该标记。初始恢复包里的历史笔记提案指向当前接受状态，原始记录和累计额度均不重置。

恢复入口根据原生 notebook 的动作记录、原调用所属 invocation 和 action attempt 匹配成功 observation。只有现有 `_saved_read_observation` 路径能准确返回相同 observation 时，才提供原工具名及参数。模型使用当前执行绑定回读，原生图返回保存结果，不重新派发数据工具。失败、未绑定、当前工具不可用、导入记录无本地匹配等情况保留原文；不根据来源 ID 猜测读取参数。

财务及计算记录不因导航清理而删除。恢复后的最新成功批次受到保护；后续出现新的实时读取后，由新的批次承担最新读取保护。

计算工具的新 MCP 会话也恢复同一任务原生 notebook 中成功取得的操作数：实际原文、S2 财务事实、已核对证据及已有计算回执均沿用既有类型适配器。预览、失败、未知权限不登记为操作数。恢复由宿主传入，不向模型开放“注册来源”工具；不会因此重新查询、重算或增加工具额度。原公式、引用原句及数值匹配检查照常执行。

工作笔记可以引用工具返回的公司来源菜单 `sources[].id`、`parent_readback` 和 `context_readbacks` 中的导航身份。它们只证明导航位置已被观察，不升级为已读正文、计算输入或最终引用。工具生成的结构字段与原文、预览里的 ID 字符串区别处理。

## 目录按条目保留

引用某个候选条目不应永久保留整个目录。只对明确标注 `retrieval_candidate`、`writer_citable=false`、`numeric_fact_authority=false` 的导航行实施条目投影。被引用的行逐字保留，同时保留 typed gap 提示和完整结果回读入口，并显式说明这不是完整目录。

正文、数值、未知结构或无法对应到具体行的聚合引用均不按导航行拆分。普通工具回复和恢复 observations 使用同一投影函数。来源、期间、单位及修订不会被重写；未展示条目不代表来源不存在。

库内检索的非引用权限有时记录在原生 `references` 中，而非候选行本身；仅当候选 ID 精确匹配且该引用明确为非正文、非数值权威时，采用同样的导航行规则。明确可引用的行、未绑定的行或权限冲突仍完整保留。移除无关导航行时，同步移除它们未被保留的纯导航引用目录；完整原件和引用仍可通过原结果回读。在接受 checkpoint 后，最新检索的未选中导航候选也适用；最新实际正文仍完整保留。

历史错误回执保留错误内容及状态，但不重复携带过期计数和动作列表。任务与研究方法中完全相同的字段保留首次全文及稳定回指，最新交接仍完整；不同版本不合并。已接受笔记的提案副本指向实际接受回执，避免同一笔记在请求中重复两份；历史提案保留于原生记录。

原生 SDK 还会在接受回执的 `current_context.task_context.research_working_state` 中携带同一笔记。仅在与 `result.working_state` 完全相等且接受成功时，交接中的副本改为指向同一回执原件的定位；保留最新动作列表、任务、计数及其他指导。不同笔记、拒绝或失败回执不适用。这条规则也作用于最新交接，避免刚整理完又因回执重复膨胀。

## 工作笔记替代

已接受且通过连续性检查的新 checkpoint 同时替代旧笔记的来源保留集合。草稿与计算操作的来源仍独立保护；拒绝的提案不增加永久保留项，普通笔记更新不能释放历史原件。否则即使旧笔记文字已退出请求，旧引用仍会令大量历史候选永久驻留。

导航保留按候选自身的 `candidate_id`／`node_id` 等身份判断。章节行的父文档、父章节及公司 ID 是所属范围，不代表选中了该范围下全部候选。文档行本身仍可按文档身份保留，其他章节有精确回读入口；正文与财务记录不适用这种目录裁剪。

恢复 observations 和实时工具 observations 内完全相同的行，可以在当前请求中共用一份原件。行内容、引用权限绑定、来源范围及修订均须完全一致；不同读取回执及回读入口各自保留。后续副本给出同一请求内的精确位置，复用首次全文以保持前缀稳定，不需要额外模型总结。失败和未知结构保留，近似文字不做语义合并，重复结果不计为独立证据。原生历史不修改。

接受新 checkpoint 后，旧笔记和旧笔记提案在请求视图中改为最新接受状态的定位提示，保留原工具调用身份及错误回执。最新笔记仍是工作记忆，不是证据，也不改变原用户与 Lead 指令的优先级。原笔记、原模型操作及私有推理继续留在原生历史中。

显式 checkpoint 中，历史 `rejected_interpretations` 由宿主逐字继承，新增条目按顺序追加并精确去重。工具回执列出继承条目；模型省略或改写旧限制不会将它删除，也不会因无关括号说明的差异拒绝整份笔记。超过既有 24 项限制仍拒绝且保留原状态，不做语义合并。旧未决问题可迁入下述子任务；未迁移的条目仍须保留或通过带实际来源的 `resolved_questions` 明确处理。未知来源仍拒绝，历史限制仍只是作者判断，不升级为证据。

## 模型维护的逐步子任务

沿用 `UpdateResearchStateAction`，工作状态增加可选 `subtasks`，旧 checkpoint 缺省为空，兼容已有保存状态。每项包含稳定 `task_id`、可选 `parent_id`、目标、状态、实际结果、来源和下一步。状态支持待做、进行中、部分完成、完成、受阻、已拆分。它们是当前专家任务内部的进度，不创建新专家、不增加额度、不替代 Lead 的派题。

模型每次只提交新增或变化的完整子任务记录；宿主按编号更新，未提交的任务保持原样。遇到需要细分的工作，模型把父项标为 `split`，新增子项并继续做研究。来源已核查、取消条件未核查时，应更新为部分完成或拆成对应子项，不能继续把整个问题写成“均未读”。无需每次工具返回就写笔记，计划或状态变化不算新证据。

旧自由文本问题通过 `migrated_questions` 一次性映射到子任务，保留原范围及未完成部分。该字段是历史迁移身份，不是当前待办描述；接受迁移后对应旧文字退出 `open_questions`。多条重复旧问题可以映射到同一个任务，但是否同义、是否已经完成由模型负责判断，宿主不做财务语义推断。历史笔记与每次更新仍在原生记录中。

宿主只检查结构和已观察来源：编号重复、缺失父任务、循环结构、没有子项的拆分、未知来源等会拒绝且不改原状态。完成项须有实际结果及来源；还有未完成子项时不能把阶段标成完成。任务完成不是研究复核通过，也不会自动生成底稿或触发下一专家。子任务的依据参与现有原件保留机制。当前列表最多 64 项，应更新已有编号而非反复追加同义任务。

`tests/test_research_subtasks.py` 通过原生专家图验证“读资料 → 迁移旧问题 → 部分完成 → 再拆分 → 保存恢复 → 只更新剩余子项”，同时检查任务计数、引用保护、旧状态兼容以及错误更新的原子性。此为离线运行契约验证，不能证明真实模型已学会维护进度；后续 W2 实际接续须检查是否自然使用工具并交付底稿。

## 验证及边界

`tests/test_restored_context_lifecycle.py` 验证四轮恢复/读取/接续循环、状态与证据保护、导航逐行一致性、禁用工具的保留行为，以及新 invocation 中通过实际原生图回读旧结果时没有新增数据派发或工具计数。

开发案例 138 使用已停止专家的真实历史离线回放；原请求在既有 140,000 token 估算阈值下触发 `research_context_checkpoint_insufficient`。本轮同时验证恢复定位及旧笔记替代，未提高阈值、未触发模型或向量服务。离线通过不代表专家已完成取证或底稿；后续真实运行的研究质量须单独验收。

开发案例 139 接续同一 W2，未重新派题或重置累计额度。两次真实接续新增 8 次成功模型调用与 12 个原文片段，累计 19 次模型、42 次工具动作，仍无底稿。第二次接续实际接受两次 checkpoint，中间完成五个原文读取，但下一请求被输入压力检查拦截。完整回执交接的离线复现从 431,837 字符／估算 142,175 token 降为 411,915 字符／估算 135,617 token；修复后未再付费试跑。只回放 `result` 而不附加原生 `current_context` 会漏检该问题，不能作为真实发送路径验收。剩余历史导航与引用保留规模仍大；此次局部修复不表示整个长任务上下文生命周期或财务研究已经通过。
