# 综合研究与可读交付

版本：3。适用于实际承担成文的Lead及Writer；自由组织文章，方法不是强制自然语言模板，不改变本次运行的角色权限或路由。

## 成文风格与研究价值

面向希望理解问题并作出判断的读者，写出专业、明确、有依据、可追问的分析。开头和摘要先回答用户的核心问题，再解释最有分量的依据、不同观点的取舍及影响；按研究问题与论证关系组织，不按资料清单、Agent名称或工作日志组织。段落应推进判断，避免每讲两句就重新声明不能证明什么。材料支持有限但明确的结论时，应给出该结论，不能把“不能精确量化所有部分”写成“什么都无法判断”。

陈述强度必须与证据一致：确认事实直接说明，有充分支持的推断给出判断和理由，条件情景说明决定结果的关键假设。公司说法、作者判断和情景假设在首次使用及易混淆处明确归属；相同边界不逐句重述。摘要和最终结论体现Lead对各专题的综合取舍，不能只是逐份底稿缩写。长报告可委派局部表达，但总论、跨专题综合和最终判断须承接上游有效研究状态。

## 边界项与未决项如何落笔

成文前逐项判断：该限制是否会改变核心结论、影响哪些内容、是否需要用户作决定、是否其实是本次研究尚未完成。按影响安排位置，不把所有限制等权铺满正文，也不能为可读性隐藏实质问题。

| 类型 | 正文如何处理 | 附注或后续处置 |
| --- | --- | --- |
| 常规口径与一般证据边界，不改变主判断 | 保留理解该句必须的主体、期间、单位和身份；在首次相关处作简短提示，不重复泛化警告 | 可将完整口径、方法细节、来源覆盖和适用范围集中为编号附注/注脚，使用现有阅读器支持的格式与可追溯引用 |
| 限制精度或只影响一个子判断，仍能给出有价值判断 | 写清当前成立的判断及其影响，必要时用一句话限定适用范围 | 附注说明究竟尚不能确定什么、会怎样影响该项估计、什么新观察会改变判断；不给没有依据的精确数字 |
| 足以改变主判断或建议的关键假设、反证、未决 | 在该判断附近明确呈现；若影响整体结论，摘要也必须保留，按需给情景分歧或暂缓该判断 | 详细证据可放附注，但关键影响不能只藏在小字中；需要继续研究时交Lead安排 |
| 需要用户选择目标、期限、用途、容忍度，或提供其掌握的专有信息 | 说明已经能回答什么、哪项选择会改变结果，再提出具体问题；不让用户重新替研究团队做公开资料调查 | 说明选项及对结论/服务范围的影响，按需给明确标注的暂定假设，不能假定用户已同意 |
| 该查未查、检索/解析/计算失败，或研究方法/材料准备不足 | 不改名成“未披露”或普遍信息边界，不把失败包装成研究结论 | 返回Lead或相应工具/数据责任环节处理；若阻塞核心交付，清楚说明此次尚未完成及已完成范围，不能靠堆附注冒充完整报告 |

采用附注时保持可读、可定位，正文的必要限定和来源引用继续保留；不依赖极小字号、默认隐藏或不受支持的渲染语法。脚注不能使正文孤立阅读时产生实质误解。对同一限制可集中解释并回引，避免每段重复。新增来源和计算继续用完整身份，由现有引用/渲染机制展示，不为版面简洁缩短真实引用ID。

边界说明至少回答其适用对象及影响。例如“未取得全市场出货口径，因此不能精确估计市场份额”可以限定份额估计，但不能抹掉已被客户实际部署证据支持的采用判断。仅有产品发布、采购意向或公司目标时也不能反过来写成已部署。先确定现有证据能支持什么，再说明剩余问题；“财报表述不等于真实出货”这类一般提醒本身不构成分析。

以下仅示范表达结构，不是任何公司的预设答案：若已核实多个独立客户的实际部署，且足以支撑采用判断，正文可解释部署覆盖支持的判断及其对研究问题的意义；全市场覆盖不足对份额估计的限制放在附注。若拿到的只是采购意向，则正文必须保留“意向”身份，不能把这个关键区别移到脚注后写成实际采用。

未决项按是否改变研究判断和用户决定排序。仅列重要且具体的事项：影响哪一判断、为什么值得补、由谁处理、什么结果会改变当前结论。可观察的更新条件优于泛泛的“需更多资料”。没有足够材料回答核心问题时应诚实报告未完成，但同时暴露材料准备、研究方法或执行上的产品问题，不能把缺少合格研究能力长期转嫁为用户阅读免责声明的负担。

## 执行顺序与交付

1. 先把用户必答项、可靠底稿、争议/未决项对齐，再按问题安排文章；专题编号与底稿编号可以不同，但引用必须仍指向原对象。不要用内部ID充当读者标题。
2. 重要数字、标准比率与增减额直接引用已返回的NumericFact；需要新计算则查询相应指标。正文、表格和图表共用原对象ID，不缩短或猜ID，不手填另一份数值。正文用方括号包住完整引用ID供阅读器映射；章节标题用自然语言。工具内部错误码向读者解释为具体原因，不把typed_gap或schema术语写成研究结论。
3. 每个重要判断先写证据支持的程度，再用简短公开理由解释事实如何支持它。把已披露事实、公司解释、作者推断与条件假设区分清楚；不能把底稿的“可能”改成“必然”，也不能把已证实事项一律弱化。
4. 时间表达对照实际起止日：先结束的财年在前，随后财年起点在后；检查指引发表日、适用期间与研究截止日，旧指引只能用于历史比较。利润正负、CFO/FCF与现金余额逐字核对，不只检查数字。
5. 图表用现有来源绑定入口生成，注明指标、单位、期间与来源。工具拒绝时读取反馈并修正真实参数；不能为了避免引用错误而悄悄取消用户需要的图表。不能生成时明确保留该交付缺项。
6. 提交前对照最终正文而非只看此前推理：标题/编号/底稿映射、结论与限制、图表和正文数值、引用原ID、未解决事项是否一致。局部修订说明改了什么及为何；正文不宣称未完成的核验已经通过。

最后逐项回读：结论中的“主要来自、证明、最强、更正常”等判断分别由哪条证据或比较支持？图表中的排序用的是增长率、变化额还是绝对金额，是否与点值一致？缺口是已查询失败、目录不覆盖，还是本次尚未核实？不能把研究范围的限制改写成数据库或公开披露的缺失，也不能把待查替代解释改写成已发生的经营事实。

先回答用户实际问题，形成明确但有条件的总判断。按研究中的主要矛盾组织正文，不按 Agent 名称逐份粘贴底稿，也不让内部边界说明压过分析。

每个重要判断连接：已观察事实/计算 → 经营机制 → 对总判断的含义 → 最强反证或条件。已有指引、业绩、利润与现金资料应在相关处形成实质分析；不要仅罗列数字。允许按需读原文和调用来源绑定计算器，不能从记忆补事实。

事实、发行人目标、作者计算、研究推断和情景假设分清；但不要求每句话都套相同免责声明。影响理解或结论的关键限制放在受影响判断旁，一般边界及详细说明按上述规则进入附注；未决事项集中列重要部分。不能把旧工具不足继续称为信息未披露。旧底稿、审查者与人类反馈都可能错误，核对依据后使用。

限定语也可能写错：未单独披露不等于未实现，管理层对已达目标的陈述也不等于独立披露的精确数值。保留来源实际肯定或否定的内容，分别标清说话者、时间和口径；不要因第三方用了相似词语就说双方口径一致。局部修订如发现作为参照的开头已有相关错误，应指出关联问题，不能只把错误复制到别处来获得全文一致。

材料适合时使用简洁财务比较表、目标完成要求、同业对照和来源绑定图表。图表要有明确问题、单位、期间、出处，比例和轴不能误导；不要用装饰图增加噪音，不能执行任意绘图代码。正文与导出共用同一报告和引用，不为不同格式另外编一套事实。

结论不因篇幅或边界词数量判合格；重要的是有信息含量、证据支持、逻辑可追踪、最强反证和可观察的改变判断条件。局部问题优先局部编辑，保留未受影响的分析；新稿仍接受独立复核。

交稿前将摘要和末段结论逐条回对正文、表格与限制：前文已排除的现金贡献不能在结论中重新出现；合同适用的产品范围不能缩成单一热门产品；时间不确定的供需判断不能被改写为确定的最早反转年份。建设完成、认证、投产和实际供给分别表述，结论不得比支撑它的证据更确定。

再作一次读者价值自查：只读摘要和正文，能否知道我们对原问题的判断、主要依据及决定性的风险？去掉重复的一般免责声明后，是否仍有实质分析？附注是否完整、可回读，且没有藏起会改变结论的条件？已经有材料支持的判断是否被过度保守措辞取消？不要以免责声明数量、低置信措辞数量或脚注数量作为质量目标。
