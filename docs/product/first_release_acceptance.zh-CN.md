# 第一版复杂投研工作台验收包

状态：2026-10-21；S1 无付费工程证据已归并，但当前容器到宿主授权连接复发超时，环境交接阻断，S1 尚未全部收口；S2–S6 尚未通过，本验收包未完成。真实研究执行保持关闭。起始代码基线、S1 范围矩阵、实际组件与后续门槛见[执行计划](../engineering/first_release_acceptance_execution.zh-CN.md)。

## 目标与边界

延续[0.1.4 PRD](fin_0_1_4_prd.zh-CN.md)和[图辅助研究](lead_graph_research.zh-CN.md)的方向：用户提出复杂投研问题，Lead 自主组织研究，专家取证与分析，Lead 综合、复核并交付可追溯报告；用户随后可以追问、质疑、补充资料和修订。第一版不改成单公司问答产品，不预设固定专题名单或标准结论。

本文件是产品与工程验收指导，不是给研究模型追加的 prompt、评分表或强制工作步骤。研究任务仍由用户问题和正常产品配置驱动，不把测试答案、剩余调用次数、开发诊断或人工选好的证据注入模型。

第一版需要交付：

- 普通网页入口上的研究启动、公开进度、报告与准确依据读取、HTML/PDF 导出。
- 用户意见触发的真实追问和必要修订，保留版本、来源、计算及已有成果。
- 同一套已确认前后端版本上的完整研究记录、检索评测和工程可靠性证据。
- 可演示的操作过程和如实披露失败、费用、人工介入及研究质量限制的结果。

本版主验收路径固定为组织项目网页，经 BFF、Java 持久命令与授权进入 Python 原生研究。新研究和后续追问/修订必须使用同一项目路径。联调开始时组织内尚无报告追问/修订命令，个人任务的既有能力不能视为组织能力已完成；该接入列为必要工程缺口，在新研究启动前就绪。不得通过放开个人路由读取组织任务来绕过权限，也不因本验收新增人工批准每个研究步骤的门槛。

不以任意行业覆盖、全库关系无遗漏、零模型推理错误、生产持续容量、机构级直接发布质量为前提。不把图的使用次数或专家数量当作研究质量指标。

## 六步收口顺序

1. **统一版本工程联调。**确认网页、BFF、Java、Python、持久队列与存储使用同一已核对构建；复用成果检查报告、引用、权限、导出和版本流转。剩余工程缺口先离线定位、真实服务验证。
2. **RAG 评测及检索对照。**核对已有题集与基线，先检查来源可达性和候选覆盖，补缺失分层，记录质量与延迟。不能用 SQL 单阶段提速代替整体检索质量。
3. **新完整研究 A。**从普通页面启动，固定代码与资料，检查报告是否回答问题、重要事实与推理、实际调用和费用，以及是否需要开发者介入。
4. **后续交互。**优先解释、质疑与局部修订，再验证资料更新、扩展和问题切换；正常读取与必要关联修改不能被监督机制误判为无进展。
5. **冻结后独立研究 B。**沿相同产品路径运行，检查是否只对 A 有效。若因 B 的结果修改实现，保留其首次结果并改记回归复测，不继续宣称未见独立测试。
6. **结果归档并结束本版。**汇总已通过、未通过和下一版事项，交付演示、报告及实测证据。不能为了得到更好看的结论无上限重试或追加案例。

各步骤的离线准备可以提前进行，但不能越过未解决的实质阻断启动后续付费研究。遇到缺口不自动扩展全库、重嵌向量、换模型或新建一套框架。

## 人工参与与后续交互

| 场景 | 用户行为 | 通过条件 |
| --- | --- | --- |
| I1 解释判断 | 询问结论原因和依据 | 找到当前判断及证据，必要时补读；不无故重跑研究 |
| I2 质疑推断 | 指出可能的期间、主体或因果问题 | 模型自行核查、接受或有据反驳；接受后关联内容一致，旧版保留 |
| I3 新资料 | 提供更新披露并要求重新评估 | 明确使用新版本与期间，识别受影响判断；旧来源与旧报告不被覆盖 |
| I4 扩展范围 | 增加公司或子问题 | 自行判断新增工作，复用旧成果，不要求固定任务数 |
| I5 相关新题 | 在同一研究背景下问另一个问题 | 复用相关事实但重新审视假设，不把旧结论直接套用 |
| I6 无关新题 | 切换到新的研究主题 | 通过正常新任务入口建立正确范围，旧结论与权限不串入 |

正常用户质疑、补料、改变范围不是失败。对实质歧义请求澄清也可正常发生，但须记录必要性。开发者修改 checkpoint、人工改模型提案、补绑来源、注入临时指导属于工程救场，不能统计为自主完成。用户要求与金融证据分开，用户意见不自动变成事实。

研究模型自行选择来源和结论，runtime 承担身份、权限、版本、计算与确定性结构校验。正常保存和恢复走维护代码；运维导入、诊断回放、私人账本不进入普通用户操作步骤。

## 产品完成标准与问题分级

每个报告须回答原问题，围绕经营变化及其意义组织，不止列资料。检查全部核心判断与重要数字的来源、期间、单位和推理，允许有依据且条件明确的分析；不要求每句话带引用，不把未能精确量化一律认定为不能判断。

- **阻断本场景：**越权、错任务/错版本、成功成果丢失、重复付费派发、不可追溯的核心依据，或未处理且改变回答的实质事实/推理错误。保留失败，定位修复，不带病进入下游。
- **需要修正并复测：**重要解释不清、局部引用或关联内容不一致、会影响用户使用的页面/导出问题。由原责任模块或模型处理，不让其他专家无关重跑。
- **可登记后收口：**不改变判断的冗长、排版偏好、尚不支持的可选扩展。明确限制，不反复付费润色。

工程错误优先复测受影响范围；只有权限、公共状态或交接合同变化才扩大必要回归。修复后从有效干净状态继续，保留真实成功成果；不得把离线诊断读数或手工研究结论伪装成模型执行结果。

六步均有证据、两个新研究及六类交互均有结论、阻断问题关闭、剩余问题明确登记后，才能称本验收包完成。失败后可以结束本版评估并给出“未通过”的如实结论，不以扩大开发强行获得通过。若 B 暴露问题且已用于调试，独立性已消耗；是否增加新的独立样本是新范围决策，不能暗中追加。
