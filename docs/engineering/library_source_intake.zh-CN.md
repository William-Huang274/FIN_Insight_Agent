# 完整已解析来源与历史向量的离线接入

本组件服务于[第一版验收 S2](first_release_acceptance_execution.zh-CN.md)的来源可达性前置：把选定来源的全部已解析正文、原分段及其向量准备为独立输入包，避免只发布命中答案的摘录。它不授予组织访问权、不注册 Java 索引发布、不切换运行时投影，也不代表组织检索质量验收通过。

## 低内存条件下的逐源分批验收

组织／本地导航的关键词评分使用 `retrieval.query_bm25.lexical_scores`：逐块分词，保留全部候选的长度和全词表文档频率，仅保存本次查询词的逐块计数。评分和负 IDF 的 epsilon 处理仍交给 `rank_bm25.BM25Okapi`；非查询词仍参与平均 IDF，空节点仍参与语料统计，重复查询词不被去重。此适配器绑定单次查询，不作为跨查询索引或权限缓存复用。原实现会同时保留全部分词列表和每块完整词频字典；新路径减少这部分常驻对象，不减少候选范围。全库正文投影和授权检查仍需独立实测，不能据此承诺全链路内存或延迟。

`s2-query-lexical-memory-r1` 以完整固定输入核验 1,742 来源／114,028 分段：固定关键词 `cash flow revenue` 的逐源评分及词项命中集合与原版完全一致；新实现另以同一个全局词表完成全部分段评分，结果均有限。该全局步骤未同时运行旧版全量分配，因此不标记为新旧全局分数对照通过。离线进程 RSS 采样峰值约 198 MiB；原始数据按源逐份加载，没有组织投影、Java 授权或服务并发，不能外推服务容量。2,000 分段合成对照的 Python 跟踪分配峰值分别为 46,339,060／1,066,852 字节，评分完全一致；该数值不是全进程 RSS 或真实服务节省比例。128 项相关回归通过，2 项需显式联网授权的网页探针未运行，提供方调用 0。

来源可读、摘要及原向量匹配，仅证明历史输入可恢复。例如原始 API 响应 `[]` 可以原样保存和回读，但不是有效的业务事实或“该公司没有相关产品”的证据。导航在授权范围内无任何分词词项时返回空的关键词结果并明确提示；仍允许已授权、已固定的向量候选导航和精确原文回读，不扩大范围、不制造正文、不因空词表初始化 BM25 而崩溃。普通非空语料沿原有 BM25 计算，不删除混合语料中的空节点以改变评分统计。此类输入需在后续召回评测的数据质量清单中单独列明，不能将存储链路通过当作语义召回正确。

串行启动可显式启用 `FIN_COMPLETE_SOURCE_SERIAL_PROFILE=1`：仅本轮 JVM 使用 32/256 MiB 初始/最大堆、Serial GC、48 MiB code cache、160 MiB metaspace 和 32 MiB direct memory 上限，Tomcat 1–8 工作线程，Hikari 1–2 连接；同一个完整 BFF 应用使用单 worker、8 并发连接限制和 16 backlog。独立 PostgreSQL 使用 32 MiB shared buffers、2 MiB work memory、16 MiB maintenance memory、20 连接、禁用并行查询与 JIT，容器 256 MiB/1 CPU。未启动原生研究图；不改变共享服务或生产默认配置，不移除路由、鉴权或资料检查。运行时读取并断言 fsync、synchronous_commit、full_page_writes 均开启；保留 Flyway 迁移和真实事务。小资源配置只验串行正确性，不得作为并发容量结果。新配置属于新执行基线，不复用旧基线成功收据；800 MiB 运行中止线不变，低于常规 4 GiB 余量的首批属于资源诊断，需记录实际峰值、剩余内存和失败。

`scripts/engineering/source_intake_batches.py` 将完整已核验清单按原顺序划分为可续跑批次，默认每批最多 32 份、输入文件合计预算 16 MiB。超过预算的单份来源独立成批，禁止裁剪正文、分段或向量。文件预算不是进程 RSS 上限；服务启动内存和单份超大原件仍需实际观测。

该入口分开保留两项验收义务：

1. **全部来源的独立链路**：每批启动自己的 BFF／Java／PostgreSQL，经原有生产捕获、组织发布、准备单、索引、MCP 搜索、缓存、原文回读和撤权路径执行。批内索引仍按现有 12 条重点资料合同分组，每个来源都执行独立搜索和回读；沿用正文、归档和节点来源各自的读取边界，不把节点目录称为整份原文。
2. **同一组织的统一候选范围**：全部来源还要在同一授权准备单／索引下验证全局排序、跨批来源缓存及非重点候选撤权。批次各用隔离组织，不能拼成统一范围通过证明。现有 `FIN_COMPLETE_SOURCE_GLOBAL_PROBE=1` 入口保留；其全局后回读是合同抽样，逐源覆盖由第一项独立提供。两项均完成前不得宣布 S2 收口。

用法（路径由执行环境提供，产物放在仓库外）：

```powershell
python scripts/engineering/source_intake_batches.py plan --intake <完整输入包> --output <新计划.json>
python scripts/engineering/source_intake_batches.py run --plan <计划.json> --output <独立执行目录>
```

首批资源观测使用 `run ... --max-new-batches 1`；成功收据保存后，在启动下一批之前记录 `paused_batch_review` 并退出。检查首批结果和内存后，用同一命令去掉此选项继续；已过批次不消耗本次批数额度。每五秒记录宿主可用内存及本轮验收进程、Java／BFF 等宿主子进程的 PID、创建时间、RSS 和 Windows private commit，不读取其他任务的进程内容。RSS 包含共享页，不可相加冒充独占物理内存；private commit 也不是驻留内存。Docker 内部 PostgreSQL 不属于宿主子进程，需单独观测本轮容器，不能声称该记录已经包含数据库或 WSL 全部占用。

继续使用全量验收的 `FIN_COMPLETE_SOURCE_QUESTIONS`、`FIN_COMPLETE_SOURCE_LIBRARY`、`FIN_COMPLETE_SOURCE_QUERY_CACHE`、`FINSIGHT_INTAKE_TEST_JAR`、`FINSIGHT_TEST_JAVA`、`FINSIGHT_TEST_DOCKER`、`FIN_NATIVE_LICENSE_ENV`、`FIN_PROBE_IMAGE` 及恢复目录环境配置；不继承共享服务状态。每批选择不重叠的 Docker 子网、随机端口和新卷，结束后停止自己的服务，保留证据和数据。默认启动前连续三次检查至少 4 GiB 可用内存；`--min-available-gib` 可用于明确的较低余量诊断（最低 2 GiB），不是已测得的最低需求。运行时保持连续两次低于 800 MiB 则中断的保护，不降低底线强跑。

续跑要求干净的同一 Git 提交、相同 Java 包和完整清单摘要；每次重新核验全部输入文件摘要。只有来源集合、逐源分段数、完整逐源回读数、缓存／撤权结果、零模型调用和结果文件摘要全部匹配的成功批次才能跳过。失败批次需要显式 `--retry-failed`，新建尝试目录，不覆盖失败证据。独占 `runner.lock` 防止两个窗口同时执行同一目录；异常退出留下的锁只能在确认对应进程已结束后处理。

`progress.json` 分别记录总来源、已验来源、成功批次、暂停／失败原因，批次全部通过也只标记 `per_source_passed_unified_scope_pending`，保持 `S2_passed=false`。此实现的确定性测试不替代真实服务执行，不提供性能或金融质量结论。

## 恢复与校验

历史 `build_industry_foundation.py` 把正文按 5,200 字符步长保存为 `text-part:N`，除首段外每段包含前 250 字符重叠。`retrieval.library_source_bundle` 按数字序号恢复完整文本，逐项校验：

- 来源可读、父段身份和摘要正确、序号连续且唯一、窗口长度符合原协议。
- 相邻重叠内容完全一致；不做换行、Unicode、空格或数字归一化。
- 恢复后 UTF-8 SHA256 必须等于原 `sources.digest`。缺尾段即使序号连续也会失败。
- 所有子段来自同一来源，正文与父段切片及摘要一致，保留旧 `CHUNK::`/`PASSAGE::`、locator 和父段内位置，并增加完整来源内的字符位置。允许分段器省略空白区域，非空白正文不能遗漏。
- 保留来源整条 metadata，包括原解析覆盖声明、期间、发布日期及修订关系；不重新推断财务期间或单位。保留该来源的图边、原绑定类型和 evidence index、引用位置、覆盖记录；跨来源或越界绑定拒绝。

`complete stored parsed text` 仅说明历史解析正文恢复完整。它不等同原 HTML/PDF 字节、图片、合并单元格几何或全部视觉信息已恢复；原 `document_coverage` 限制仍然有效。解析文本不是自动获得数值事实权威的数据库记录。

原始文本/JSON 的 `raw text chars start-end` 也可恢复：按数值位置排序，检查无缺口、无重叠、长度、身份和逐段摘要，最后要求完整 UTF-8 摘要等于来源摘要。此适配不自动适用于 HTML/PDF。历史导入中，HTML/PDF 的来源摘要是原文件字节，调查资料的摘要是原读取回执；层级节点可能同时保存章节、表格和子段，直接拼接会重复。不能为了让摘要校验通过而改写原摘要或把几种合同混用。

## 向量复用

源库、旧向量索引和请求缓存只读。首先核对库摘要、矩阵/映射文件摘要及模型合同，再对每个子段：

1. 取未经改写的 `context + newline + body`，保留输入 SHA256 和模型/维度/输入组成的缓存键。
2. 要求此精确缓存键存在成功请求记录及向量；失败或未知记录不能单独授权复用，更不会触发提供方请求。
3. 核对 chunk/source/矩阵行一一对应，拒绝漏映射、重复映射、越界行及错误来源。
4. 将缓存向量按旧发布方式归一化，与已发布矩阵对应行逐元素精确比较。只有维度一致或正文相似不能通过。

输出保留来源矩阵行号，同时分配本包内行号。原查询缓存、排名缓存、权限和组织身份均不复制。此过程不重新嵌入，也不改变原索引。

全量离线核验使用 `VectorReuseVerifier`：在只读事务中一次读取成功请求键及映射索引，每个子段仍检查精确输入和真实向量值。它只减少离线重复扫描，不缓存组织许可，不改变运行时每次核权。`validated_stored_chunks` 可独立验证库内父段的完整覆盖，用于尚未恢复全文的来源；该结果没有全文位置或完整文档声明，也不能当作组织发布输入包。

## 完整来源的组织接入

`POST /api/v1/asset-workspace/captures` 新增 `selection.kind=library_source`：请求只包含 `document_id` 和发布库摘要 `snapshot`，服务器从配置的不可变公共库恢复并校验完整已解析来源。用户不能在请求中提交正文、SQL、路径或向量。原 `library` 章节选取、财务快照和旧资料协议保持兼容。

新保存合同为 `project_library_source_snapshot.v2`，沿用既有附件事务、内容摘要、批注修订及组织独立副本发布。旧 v1 快照仍按原内容和摘要读取，不迁移或改写。包含完整正文和原分段的快照有明确 20 MiB 上限，超过时拒绝保存、不截断；旧章节/财务快照上限仍为 2 MiB。完整来源仍需遵循既有附件原件大小限制。数据包保留图边和绑定，但不声称完成图实体存储迁移或开放组织图查询。

v2 使用 `library-source-offset-bundle.v1`：完整正文只存一次，父段/子段保存原 ID、定位、字符区间、摘要和嵌入上下文，不再重复存正文。保存前逐字段无损往返校验，读取时校验整篇摘要及逐段偏移/摘要后恢复原 v1 内部结构。旧向量投影、原 chunk 身份和 Java 索引合同不变。

这种服务器从固定库构造的来源已解析、已分段，附件存储直接校验并保存原分段，不再送入通用 Markdown 解析器。普通上传仍保留 2,000,000 字符的解析限制，所有附件仍保留 20 MiB 文件限制及原项目配额。没有允许浏览器提交自定义正文、SQL、分段包或放宽普通上传边界。

内部 `AssetWorkspace.read_source` 为这种明确类型提供完整正文和原分段，普通 UI 预览仍有边界，不将全文一次传给模型。组织运行读取仍由 Java 当前项目及全部固定来源权限控制，并在存储读取后再核权；新来源按原发布日期或明确 known-at 检查研究截止日，缺失日期拒绝使用。`read_organization_evidence` 按原有有界分页返回，包括 100,000 字符之后的内容。

日期规则与公共库的 strict-as-of 一致：`dated_original` 使用发布日期；`known_as_of` 优先使用可知日；时间戳按来源日比较。`unknown`、`current_revised`、缺失日期及晚于截止日均不能作为历史来源。文件可读或有抓取时间不代表已满足历史研究授权条件。

`organization-library-chunks.v1` 为新投影：组织节点 ID 同时绑定资源、版本和旧 chunk 身份；返回正文只含原证据，embedding 上下文独立记录。原 source/chunk/parent、来源内和父段内位置及摘要在 `original_source` 返回。索引登记核对正文摘要和 embedding 输入摘要；Java 固定新增投影标识及索引/矩阵版本，旧 `organization-text-6000.v1` 不变，不把旧准备单解释为新投影。排名缓存仍绑定授权和索引版本，每次命中及原文回读都核对当前权限。

### 全量扩展的固定分母

### 发布快照与隔离恢复验收

完整输入验收可用 `FIN_COMPLETE_SOURCE_PAUSE_AFTER=N` 在第 N 份保存、发布、关联和原文核对成功后停下，生成 `publication-checkpoint`。这次退出只有 `publication_checkpoint_only`，不会写 `complete-source-result.json`，也不是 S2 通过。N 是同一输入范围的累计位置；恢复后必须向前推进。也可用 `FIN_COMPLETE_SOURCE_WRITE_CHECKPOINT=1` 在全部发布后保存快照，再继续后续阶段。

快照先停止本轮 BFF/Java 写入者，使用 PostgreSQL 16 的 [pg_dump 自定义归档](https://www.postgresql.org/docs/16/app-pgdump.html) 保存业务数据库，并逐文件压缩两份静止的原件 SQLite 数据库。存在未清理的 WAL、未知文件、写入中摘要变化或打包失败时，不发布最终 manifest。快照位于显式私有验收输出目录，不包含服务环境变量或凭据，也不进入 Git；它仍包含资料及业务状态，应按原验收数据管理。

每次命中前后仍请求 Java 的当前完整授权；命中时也完整核验固定索引合同和向量文件摘要。原件存储采用同一只读 SQLite 连接的 [PRAGMA data_version](https://www.sqlite.org/pragma.html#pragma_data_version) 检测其他连接的提交，并比较数据库和 WAL 文件身份、尺寸与时间戳，检测替换和文件变化。该观察连接不持有读取事务，也不写入数据库。数据库变化使缓存失效；命中过程中发生变化则拒绝返回。不能用它缓存授权成功、忽略撤权或跳过索引完整性检查。

当前资料正文、解析页、来源快照和本地访问状态都在该原件 SQLite 中。将来若原件移至外部对象存储，必须扩展变化检测合同后才能继续使用这个缓存。相同导航实例用锁保护连接和缓存；这不是共享缓存或并发容量优化，任何无关数据库写入也会保守失效。响应中的 `response_cache_hit` 标记本次页结果复用，提供方调用计为本次的 0；原有来源、排序和回读身份不变。全范围验收同时检查冷/热原件读取次数、结果身份等价和驻留缓存的撤权拒绝，不能只凭缓存命中标志验收性能。

### 同一研究内跨问题复用检索投影

投影暂存于索引根目录下的 `.session-cache` 临时目录，每实例压缩载荷上限 256 MiB，单项上限 32 MiB、解压 JSON 上限 128 MiB；目录元数据开销另计。章节与检索叶子继续共享压缩正文和元数据，避免持有整库解压字符串。缓存的常驻状态只保留文件摘要、大小与位置；查询时仍需加载节点用于排序，每次读取核验摘要。进程内对象回收时清理临时目录，进程崩溃可能留下无效文件，但新实例不会读取或信任这些文件。容量不足、磁盘余量不足或写入失败时停止接纳新条目，未缓存来源继续走普通授权读取，不能跳过来源。

投影有效代际绑定完整 Java 授权摘要及同一观察连接的原件 SQLite `data_version`、数据库/WAL 文件身份。代际变化清空旧投影；当前请求读取前后仍校验授权，排序前和返回前检测存储变化，防止已变化原件进入查询向量调用或返回结果。SQLite 观察连接先读取版本再记录文件身份，避免它自己打开 WAL 时造成误判；真实 WAL 提交仍使缓存失效。每次重新排序继续核验固定索引和向量完整性。

### 复用精确分词统计

同一导航实例的临时投影同时保存压缩词频及完整词项数。词频由原分词器生成，保持每个词的首次出现顺序；查询时仍交给现有 `rank_bm25.BM25Okapi` 计算 IDF、epsilon 下界和评分。完整词表统计保留，不能只缓存当前问题涉及的词，否则会改变其他词对 IDF 平均值的影响。资料筛选仍先于统计总体和排序；重复查询词、零/负 IDF、空词表的既有行为保持。

词频与正文一起受临时文件摘要、当前 Java 授权和原件存储代际保护，不复用历史权限。每次只解压当前分段的词频，避免驻留全库展开词表；总压缩载荷仍计入每实例 256 MiB 上限。首次构建投影需要分词，后续新问题免于重复正文分词；独立原件路径仍重新分词，作为等价性对照。缓存格式仅用于本实例临时文件，不修改发布索引或迁移历史原件。

完整来源的原文定位映射从节点元数据重建，临时文件只额外保留覆盖项和原键顺序，减少重复序列化；对外来源、引用身份与回读字段保持相同。压缩词频、候选排名和实际服务性能分别验证，不以对象尺寸或离线通过代替真实服务验收。
