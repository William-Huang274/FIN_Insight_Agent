## 1. 执行原则与当前起点

以0.1.3已验证代码为起点。已有成本公式、一个历史MSFT费用核算和计价定向测试；这些不是0.1.4预算、数据服务或研究质量的实现证明。三份文档构成第一版工作基线，不再维护另一套当前总规划。

下面是依赖顺序，不是固定日历。每次只细化将要执行的工作包，产出代码/测试或真实产品证据后再调整下一步。技术细节可根据实践修改；影响产品范围、兼容性、费用或上线条件的变化记录依据并确认取舍。

## 3. 第一包只细化到可开工

E1先审计现有运行栈和费用记录，确认锁定版本的许可、共享写入位置和已有测试覆盖；保留当前队列为首选，不先建设新平台。

随后使用一个可控的模拟模型/工具，通过原生任务入口运行长短任务、重复提交、取消、checkpoint接续及worker重启。验证任务状态、已保存结果和模拟费用累计，区分共享预算与每进程上限。该切片不需要真实金融模型调用。

出场条件：可重复演示成功和故障路径；已知/在途/未知费用明确；查清哪些原生能力可用、哪些FIN薄适配需补。若根本约束来自许可或运行栈能力，比较一个成熟替代并报告迁移成本；不得为证明现有方案而不断加自研控制层。

服务器购买、外网开放及新增付费研究在方案和费用具体后执行；本路线不构成无限调用授权。

## 4. 最小产品切片

E2–E4共用一个持久项目、一条远程结构化来源、一种文档导入、一份可编辑成果和第二用户。Wind无可用账号时不计为真实连接，采用可实测来源继续验证通用接入能力。

先使用户在前端独立完成连接/导入、字段与时间预览、项目检索、成果编辑及正确版本回读。再接入一项有原件、可核对计算且能形成竞争解释的研究，保存报告后加入新资料或用户调整，验证影响识别和局部更新。同步滞后、源权限撤销及并发编辑作为同一切片的实际场景。

E3先选已知容易出错的期间/单位、现金流关系、正常化盈利和估值条件中的少量方法，不一次铺满行业。直接提供方法无改善时修方法/工具/模型；直接有效而动态选择失败时修选择，不扩建方法平台。模型路由和额外专家需各自证明质量收益及总成本。

## 5. 验证方式与推进判断

| 验证层 | 证据及推进条件 |
| --- | --- |
| 工程 | 原生入口、数据连接、故障恢复、权限与费用定向测试；模拟通过不等于真实供应商或部署通过 |
| 金融 | 固定资料核对事实/单位/口径、隐含假设、反证和纠错；方法被读取不等于正确使用 |
| 产品 | 前端首次交付及追加更新、用户编辑/分享、第二用户和恢复；报告保存不等于质量合格 |
| 价值与成本 | 0.1.3、同资料/工具/方法通用Agent、0.1.4对照；先固定模型分离runtime作用，再验证模型分工 |

每包执行前补充负责人/代码范围、固定输入、质量门槛、调用预算与停止条件、退出方式；只细化该包。现阶段不虚构省费比例、队列容量、P90或固定工期。成本包含失败和所有后代任务；真实人工审阅/修改时间单列。保持首次研究与局部更新分组，保留反例与未通过结果。

关键错误未改善、局部更新遗漏重要影响或比公平基线更贵且无质量收益时，停止扩展并修责任层。连续工作只有规划而无可执行结果时，缩小切片进入实测。一次失败不产生新产品版本，也不通过降低既定门槛变成成功。

## 6. 试用与变更管理

E5是有限用户、明确资源上限的网页试用，不等于生产HA。先验证认证/TLS、外部接口私有化、持久数据、备份恢复、许可、费用和运行观测，再决定服务器规模及是否扩大试用。使用与付费反馈检验客户定位和商业包装，不能用离线分数代替。

每包结束回填：实际交付、测试/样本、成本、未解决问题、采用决定和下一包变化，详细过程只进入工作记录。PRD维护用户范围；技术方案维护模块/选型；本路线维护依赖、状态和下一步。

本版尚待确定的事项：服务与账号、首个任务和数据范围、容量及预算、首批方法、试用用户。已有0.1.3数据和报告保持可读，新能力用隔离配置逐步启用；未通过候选可退出，重大迁移先验证兼容和恢复。
