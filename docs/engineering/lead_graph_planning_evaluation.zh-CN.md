# Lead 图辅助规划：工具引导、反馈和诊断测试

状态：2026-09-23 已实现预研究 runtime 接入、反馈工具、意见持久化和前端卡片，完成一个正式 runtime 自然议题开发试跑。发布资料与向量未重建。下文保留目标设计，已实现范围和验证边界见第 8 节；尚未完成独立质量评测或自动外部取证授权流程。

依据：[产品约定](../product/lead_graph_research.zh-CN.md)、[分段资格路线](runtime_flow_qualification.zh-CN.md)、[检索优化](../architecture/retrieval_optimization_review.zh-CN.md)及 [Java/Python 边界](../architecture/java_research_service_contract.zh-CN.md)。

## 1. 已有接入点与范围

- `src/sec_agent/agent_runtime/research_orientation.py` 的 `ORIENTATION_SYSTEM_PROMPT`、`OrientationLibraryReadAction` 和 `SubmitResearchOrientationAction` 是预研究入口。复用 findings、topics、scope_map、next_evidence、success_criteria、依赖及 next_wave/deferred，不重建另一种规划结果。
- `deepseek_structured_agents.py` 在 `orientation_only` 时实际选择上述提示词。新引导须通过这一消费点接入验证，文档不代表模型已收到。
- 当前预研究限 `source_space=library`，允许 catalog/search/read/related/observations/company/data；未开放外网获取。首轮可验收提出具体新增信源需求，不能称外部取证完成。开放取证需独立接入既有授权与请求账本。
- `bind_orientation` 校验来源回读引用、专题引用及依赖环，不判断金融语义正确。保持事实发现需原文回读的约束；未探索范围可进入 scope_map，不伪造已读事实。
- 首轮止于初步认识与专题规划，不启动专家或最终报告。全库修复、完整40题检索验收不作为开始条件，仍保留其独立验收范围。

## 2. 已注入的使用引导

加入现有 Lead 提示及相应工具描述，使用真实 wire ID，不把文档逻辑能力名注册成重复接口：

> 对产业链、交易对手或资金联系问题，优先用局部关系建立方向，再按研究需要结合独立文本搜索和结构化数据。图不是答案范围或事实保证。无需逐边使用、核查或搜索。
>
> 先读与判断相关的证据窗口，限定条件不足时扩展。区分导航候选、证据支持的事实和研究假设，保留主体、期间、单位与实际/计划状态。不要把平台接入、合同、规划、交付和实际收入混为一谈。
>
> 围绕用户问题组织有意义的专题，说明重要性、依据、下一步证据、优先级和依赖。必要但未探索的范围继续保留；不要因现有材料方便而缩小原题，也不要把全部邻居扩展成专题。
>
> 图不覆盖、材料陈旧、关系受质疑或存在反证时，按需补查图外文本、指标或其他信源。搜索未命中不等于未披露；缺少外部获取能力时提出具体取证需求。
>
> 数据疑点可简短记录后继续。未读全文不妨碍提出待核疑点，但不能宣称已证伪。新关系保留主体、方向、状态和证据，作为候选，不直接写正式图。不要为反馈额外遍历所有关系。

结果保留来源/记录/边 ID、版本、命中通路、关系限定条件、证据锚点、截断及续读信息。复用已有字段，摘要与按需详情分开。排名分数与审核标签不是金融事实概率。

## 3. 质疑与新发现记录

反馈是研究运行产物，不修改只读发布库。兼容扩展时保留旧请求合同，避免向 `extra=forbid` 的旧模型直接加字段。

| 字段组 | 内容与约束 |
| --- | --- |
| 定位 | edge_id（已有边）或候选关系、source/chunk_refs、snapshot_ref；不得虚构已有 ID |
| 类型 | 主体范围、方向/角色、状态/时间、证据不足/冲突、缺失关系；区分质疑与新增发现 |
| 说明 | 简短可公开问题陈述、已见依据、待核内容；不索取内部思维过程 |
| 阅读程度 | 仅关系卡、摘录、支持段落、扩展上下文；宿主关联实际 read_ref，不仅凭模型自述 |
| 本次影响 | 暂不采用关系、独立补查、计划变化、未影响；区分模型显式说明与轨迹推测 |
| 建议 | 可选修正或核查行动，未验证建议不能提升为事实 |

宿主绑定运行、调用、资料版本及实际返回/已读记录，验证引用权限；其他来源新发现先保留候选状态。未知 ID、越权和旧版本覆盖须明确报错。

支持批量及幂等提交；提交身份与同一版本/边/问题类的聚合分开，不丢不同依据。区分待核、已有支持的疑点、已解决、未成立；模型提交不直接变为已解决，多次质疑不是事实投票。

暂不采用只影响本次推理，不删原边，不屏蔽原文检索。修复发布新版本并保留问题生命周期，本次运行继续固定快照。

## 4. 反馈卡与决策弹窗

普通反馈持久化并返回回执，研究继续。用户主动点开活动卡，可选记为待核/本次暂不采用关系/安排补查，并输入文字。

需要决策时单独提交 decision_request，携带问题、选项、影响、阻塞范围和 run/checkpoint/快照关联。反馈提交成功不等于用户已回答。

同步决策复用可持久恢复机制；无关分支可继续。不得超时默认批准、重新创建 run 恢复等待或自动重放付费请求。用户选择不能认证关系为真或直接全库删边。

Java 负责用户交互、业务身份及意见提交的业务适配；Python/Agent Server 保留研究反馈、证据身份和 checkpoint。非阻塞反馈端点及弹窗已实现；阻塞式 decision_request 和外部取证授权尚未实现，不能把普通反馈意见当作执行许可。

## 5. 先自然观察，再诊断

先完整提供使用方法，再处理真实问题；模型输入不含审计缺陷、应有专题清单或标准答案。方法引导与独立评审标准分离。

首个自然案例采用资格路线的 AI 采用与资本投入总题：需求、交付、云收入及电力兑现的证据联系。按实际运行日固定 research_as_of，检查归档时效，不为迁就旧资料回退日期。只要求第一轮有依据的研究计划。

随后按表现选择三类已知开发回归：微软/OpenAI 多类权利关系、Talen/Amazon 合同与探索/输配电角色、腾讯云平台接入与基础设施边界。这些不计独立正确率。

另准备至少四个未参与提示词调整的案例：关系丰富但非全相关、图稀疏而正文有事实、指标与经营解释结合、材料陈旧/期间差异。先核实可用依据与工具路径，参考答案不交给被测模型，不按它的回答反推评分标准。

出现值得诊断的问题后，才对选定案例做受控对照：固定模型、题目、提示、资料/日期及预算，只改变图线索可见性或提供已定位证据。保留随机性和成本边界，不把一次差异全归因于图，也不要求先跑完所有消融才能观察第一轮。

每次付费前保存 TokenBudgetBasis：目的、输入规模、所需规划输出、质量风险、模型/推理配置、上下文与输出上限、轮次/工具/费用上限及停止行为。触顶保留未完成产物，不缩小原题伪装完成；失败和未知用量不自动重发。本文不是具体付费批次。

## 6. 观察与验收

复用 orientation 公开结果，不要求长篇逐工具自述。宿主保存请求、返回 ID/版本、窗口、候选通路、耗时和已报告用量；模型只说明重要专题选择、补查需求和疑点。

| 维度 | 核查问题 | 不作为成功目标 |
| --- | --- | --- |
| 理解聚焦 | 保留用户目的、范围、时点和重要条件？ | 复述长度 |
| 有效发散 | 提出相关、可验证的替代解释、风险或依赖？ | 邻居/主题数量 |
| 专题组织 | 有触发依据、边界、优先级、依赖及完成条件，避免重复？ | 每公司一专题 |
| 图的帮助 | 减少重复发现工作，帮助提出更好的问题？ | 用尽所有边、遍历率 |
| 图外探索 | 按真实缺口补查，必要时从正文发现新事实？ | 强制每题外搜/找新边 |
| 证据纪律 | 保留限定、识别反证后调整？ | 引用数、工具调用成功 |
| 成本体验 | 有效取证、无效阅读、耗时、用量、不必要弹窗如何？ | 单独追求最少 tokens |

逐维记录有证据支持、部分满足、未满足、不可评估及依据，不用模型自评替代审核，不急于合成总体正确率。“已返回→已读取→引用/采用”分开记录；未采用不天然是失败，也不能仅凭先后顺序断言某边造成错误。

## 7. 归因到最早可复现环节

| 现象 | 初步分类与检查 |
| --- | --- |
| 原文未入库或陈旧 | 数据覆盖/时效，先查来源可得性 |
| 原文有事实但关系漏记或过宽 | 提取/归一/关系语义，保留文本补查 |
| 资料存在且可访问，查询未返回 | 检索/过滤/排名/证据绑定，回放相同请求 |
| 返回截断、定位失效、工具报错 | 工具执行合同，不计作公司未披露 |
| 信息已返回仍漏关键专题或沿错误方向 | 先检查引导与展示，再检查模型选择/理解，必要时对照 |
| 事实理解正确但专题重复、无优先级或偏题 | Lead 规划组织，不靠补边掩盖 |

允许多因素和未定因；记录最早故障及后续影响。高 token 是待解释现象，不自动等于图无效或模型能力差。

## 8. 实施顺序与当前交付

1. 复用预研究入口注入工具引导，接最小反馈合同、引用校验和持久化，不改发布库。
2. 验证反馈非阻塞、必要决策可恢复、重复提交及引用身份，再接活动卡/弹窗。无付费 fixture 只证明合同。
3. 跑一个预算明确的自然 Lead 案例，读取真实轨迹与规划；按表现选择开发回归及独立案例。
4. 交付规划质量、数据/工具/模型问题分类及成本，再决定修复项和扩大范围。

工具/提示未被实际消费前只称设计完成；真实运行和依据评审前不称 Lead 能力通过。资料及向量不变，无需重做 embedding。

### 已实现的接口和行为

- `ResearchRequest.research_stage=orientation` 经正式 source composition 进入 Lead，只保存预研究结果后结束；默认 `full` 兼容原流程，不启动任何新专家分支作为预研究副作用。
- `ReportResearchIssuesAction` 每次提交 1–4 条疑点或取证需求。宿主绑定实际 observation、资料版本、运行和用户身份；证据可以是未读原文的线索，但必须标明。未知引用/边 ID 被拒绝。
- 独立反馈 SQLite 位于配置的 audit root，按 owner/thread/run 隔离；同内容幂等，内容版本冲突返回错误。用户意见单独保存，既不是事实证据，也不直接更新图或发起模型调用。
- BFF `POST /api/v1/research-sessions/{thread_id}/start-orientation` 仅接受未启动的研究草稿；`GET .../{thread_id}/research-feedback?run_id=...` 返回本次反馈及匹配运行的最终规划；`POST .../{thread_id}/research-feedback/{record_id}` 保存意见。写请求遵循工作台同源标识与归属校验。
- 意见请求字段为 `content_digest`、`submission_id`、`choice`、`comment`；choice 为 `keep_pending` / `avoid_inference` / `request_check`。重复提交使用同一 submission_id；不自动重发。Lead 后续调用读取意见，本轮已结束时保存意见不会自动创建新运行。
- `RunWorkspace` 展示总体认识、议题与顺序、待探索范围和按需展开的原文依据；普通反馈为非阻塞卡片，用户打开对话框给出意见。尚无阻塞 decision_request 或自动开放外网的入口。
- 发送给模型的工具结果剔除重复的底层 `mcp_receipt_chain`，完整回执仍保留在 checkpoint/审计记录中；正文、限定条件、来源/期间/单位与导航身份保持。提示和校验错误明确列出可用于 finding 的原文引用、无效引用及依赖错误。

### 首个自然议题的开发观察（2026-09-23）

题目为 AI 采用、资本投入、需求、芯片/服务器交付、云收入和可用电力之间的证据联系。未把应有主题、已知缺陷或答案交给模型。使用 `deepseek-v4-flash` 和正式只读发布库 r21，运行前记录 TokenBudgetBasis，12 次模型请求上限。

最终成功保存 9 条初步判断和 6 个专题，未启动专家或最终报告。实际发生 11 次模型请求、19 次资料操作（其中 9 次原文读取），另有工作笔记保存；没有外部获取或反馈工具提交。所有模型请求均有成功用量回执；3 次规划提交被本地引用/依赖校验拒绝，不是服务商失败重试。

| 层面 | 观察与后续处理 |
| --- | --- |
| 工具 | 原文回读、独立文本检索和局部关系均实际使用；底层回执重复占上下文、校验错误不够具体，已修正，需后续自然运行验证收益。 |
| 数据 | 对“缺少更新”的抽查发现，库内已有较新的 CoreWeave、Talen、微软可读资料。不能把一次未读到归为数据未入库或公司未披露。 |
| 模型决策 | 能区分合同/已投运、担保/交付、使用量/变现，并形成可研究的专题；部分概述数字缺少对应原文支撑，部分专题仅因共同口径就串行依赖，仍需观察和改善。 |
| Runtime | 预研究结束点、版本与引用追溯有效；旧案例 ID 污染了模型对资料库的表述。后续迁移为独立的当前任务契约，见[运行契约说明](current_research_contract.zh-CN.md)，历史结果保留，不能以说明文字代替修复。 |
| 反馈与外部取证 | 卡片权限、幂等、保存与窄屏交互经无付费 fixture 验证；自然运行未主动提交疑点，尚不能证明自然使用质量。外部需求先核库内新材料，再确定具体缺口与开放范围。 |

本轮模型用量累计输入 725,398、输出 31,042 tokens，其中输入缓存命中 633,344。运行记录按配置价格估计模型费用约 ¥0.458，非账单，也不含尚未汇总的查询 embedding 成本。不能把累计输入当成唯一资料长度。对同一已保存工具结果的离线投影，从 415,935 降至 230,036 字符（约 44.7%），仅说明剔除重复回执的载荷变化，不代表已实测的新模型 token 或速度提升。

原始轨迹、用量、规划和逐层审计保留在用户本地运行记录，不纳入 Git。当前只有一个开发案例，不提供总体正确率，也未验证 GraphRAG 相对于纯文本检索的因果增益。

### 同题开发对照（2026-09-24）

在相同 r21 资料上创建新会话，使用当前任务契约和工具投影；未输入前轮答案、指定专题或必读文件。研究截止日随新任务更新，因此这是同题开发观察，不是单因素对照或独立测试集。实际完成 12 次模型请求、14 次资料操作（8 次原文读取）；3 次规划提交未被接受，最终以 `research_needs_attention / lead_turn_ceiling` 停止。没有专家执行、最终报告或自然反馈提交。底层运行请求显示 success 仅表示流程正常返回，不能当作预研究产物验收成功。

新的 `research_session.v2 / general_research` 身份已生效。模型读到了微软较新的季度电话会，但 CoreWeave、Talen 和持仓仍使用较旧材料；草案允许电力与设备取证并行，仍把采用侧研究依赖于电力专题。末次草案还存在“判断自述仅依据图元数据，却引用另一原文”的证据支持问题。这些是待评审草案的观察，不能作为已接受的研究结论。

可复现的提交阻塞是 ID 不一致：定义使用完整 finding/topic ID，引用却使用缩写。原有校验只报首个抽象错误；现在字段说明要求精确引用，校验同时返回所有无效交叉引用的位置、实际值和可用 ID，不猜测匹配或改写模型计划。离线回归验证拒绝与修正后的合法提交，尚未付费重跑验证改善。

本轮输入 665,975、输出 21,804 tokens，缓存命中输入 578,944；配置估费约 ¥0.372，非账单且不含查询 embedding。所有12次模型请求有用量回执。任务总耗时约141秒；不能将其与模型请求耗时之和混同。另记录配置 `tool_calls=24` 尚未在该 Lead 路径形成实际总量限制；生效边界为12轮模型请求及单批最多4次资料读取，不能把配置24报为硬上限。历史结果保持原样。

### 工具时效元数据与实际预算边界（2026-09-24 后续）

回放发现搜索候选仅有片段、文档ID和上下文标题，缺少独立的来源发布日期；目录按ID排序，不能表达新旧。现在库内搜索候选增加 `title`、`publication_date`、`source_vintage`、`source_known_at`，通过候选文档ID批量读取，不逐条打开原文。发布日期未知仍为空，已知时间不冒充发布日期。目录保留实体导航在前，文档按截止日前可用性、发布日期降序、ID降序稳定排列；未来/不可用资料仍有原状态，不成为可引用证据。目录翻页应从 offset=0 重新开始，不跨代码版本沿用位置。

原文搜索分数不改为日期分数；公司资料 `company_section=sources` 已提供按日期排序的资料入口。Lead引导明确用这个入口核查重要的当前公司判断，不因一次相关性搜索未命中新文件就宣称库中缺失。新资料仍需判断相关性和回读；没有预置公司名单、应读文档或应有专题。引用提示同时明确，不能用不支持该论点的合法 read_ref 绕过原文要求。宿主只验证身份，不能把这些提示说成已完成语义验真。

`lead.limits.tool_calls` 现接入预研究和研究分派两条运行路径。每个进入工具批次的调用尝试计数，包含本地校验拒绝、工作笔记和提交；超额批次在任何工具副作用前整体拒绝，不部分执行。模型可见总上限和剩余次数，触顶进入 needs_attention，保留结果且不另发一次模型请求。正好在上限提交成功仍正常结束；模型轮次上限独立生效。直接调用构图函数未指定工具总限时保留每轮最多4次的原有包络，正式 runtime 使用配置总限。
