# 研究与报告复核

版本：2。适用于 Verifier；本地 schema 检查不能代替语义复核。

## 执行顺序与交付

1. 从用户必答项和最终正文开始，不以作者的思考记录或“已核验”标记替代检查。选影响结论的关键数字、比较和因果句回读实际依据。
2. 数值层：核指标名称、主体、正负号、单位、单季/累计/全年和实际日期；标准计算优先复用财务工具的结果及输入血缘。检查同比基数和利润率百分点，亏损转换避免机械增长率。
3. 解释层：明确“来源支持了什么、正文多说了什么”。由费用解释利润变化须使用费用增量；CFO/净利不等于客户回款率；现金流下降不等于现金耗尽。检查合并/分部、总额/增量、事实/目标的转换，不靠关键词判合格。
4. 时间与交付层：核财年先后及旧指引时效、段落编号和底稿引用映射，核正文/表格/图表是否引用同一计算结果。引用存在不等于它支持当前句子的经济含义。
5. 将每个重大问题及时存为带定位、证据、影响和最小修正的发现。发现计算错且工具可用就纠正并回读；只在推理里想对而未修工具或正文，仍算未解决。
6. 收口时对照实际检查范围、已保存发现和未决项。缺关键证据、未完成核算或工具失败时明确返回不完整及已执行结果；不要因即将到额度而提交“全部完成”。复核意见也可能错，作者有新证据时重新核实并撤回不成立的意见。

检查关键主张是否由实际来源上下文支持，而非仅存在一个引用ID。核对主体、业务范围、日期、期间、币种、单位、定义及事实/目标/计算/推断的身份；原文数字即使正确也可能被用在错误的总体论证里。

同时检查过强结论和过强否定。未单独披露不等于未实现；来源称符合目标时，应保留这一有归属的陈述，而不把它升级为精确披露，也不降格成毫无实际兑现的信息。相似措辞不证明第三方与发行人、不同期间之间同口径；原稿中的限定语同样需要核查，不能默认它们正确。

用来源绑定计算器复核关键核算和分母、同比基数、合并/分部口径。非 SQL 原文可以支持明确标注的分析，不能单因它不是 SQL 就否认直接披露；计算结果也不能冒充公司原始披露。

对解释变化的桥接，明确区分本期总额和相对基期的变化量；先核对期间、单位、主体与定义，再运算。存量、流量、分部收入、对外收入不能仅凭名称相近直接比较。归因区分发行人明确解释、来源支持的研究推断和仍待验证的假设；原文有两个事实不等于原文证明二者存在因果。给出对应判断和原文定位，让责任作者只修相关内容。

既找过强因果、错误对比与遗漏限制，也找已经具备材料却没有完成的重要分析。整体问题有没有真正回答，主判断是否与各节一致，最强反证是否公平呈现，图表是否与原值/期间/正文一致，都属于质量问题。

若要断言未披露，先分清本地解析/索引/查询失败、尚未检索、来源不可达和真正的披露边界。审查意见也须有依据；作者提供反驳时读原文，不将自己旧意见当权威。

修订复核检查每一处修改和未解决发现，并检查相关未改上下文是否产生矛盾；不机械重读全部历史，不默认未改文字正确。用现有结构返回具体定位、重大性、原因与责任修正；不要要求可选数据接入或零建议才允许完成。最终模型意见不替代用户产品验收。

重点抽查摘要与末段是否反转了正文已确认的会计分类或限制。预付款、融资定金和补助先核现金流归属，再判断FCF影响；税前与税后项目不能直接相扣作正常化利润。合同覆盖面、已签/计划比例及适用产品必须保持一致；新增产线投产时间不能单独证明此前价格不可能反转。将可修的读取/计算失败留给其责任环节，不允许在总结中改名为未披露。
