## 1. 产品定位与保留内容

工作台服务于研究者的连续工作：找任务、理解报告、核对来源、提出意见、跟踪修订、审阅结果。默认研究图保持“报告总览→专题→判断与依据”三层跳转；原文并排/整页阅读、基线绑定的修订预览与既有研究执行接口继续保留。导航和美术调整不替换Agent架构。

界面应让研究者始终回答三件事：我在哪项研究中、正在核对什么、下一步可做什么。长文字进入阅读页，图节点只承载必要概括及状态。运行轨迹保留在运行页，不占据主研究空间。

## 2. 全局结构与侧边栏

| 区域 | 入口 | 主要行为 |
| --- | --- | --- |
| 顶部固定区 | 品牌、折叠、新建研究 | 218px完整侧栏可收为62px图标栏；新建进入独立表单 |
| 全局工作区 | 工作台、全部研究、待审阅 | 找回最近工作、按公司/题目搜索、处理待核对判断 |
| 最近研究 | 公司简称＋研究题目＋状态/版本 | 切任务时保留原任务阅读位置；同公司任务靠题目与版本区分 |
| 当前任务子导航 | 研究地图、研究报告、研究资料、修订记录、运行与费用 | 只展开当前任务的目录，避免每个任务都生成大树 |
| 底部 | 外观与偏好、个人工作区 | 动效、侧栏偏好；账户区域不重复研究信息 |

顶部任务头只展示公司、研究题目、期间/版本和真实状态；面包屑表示研究内容层级。原型移除了与侧栏重复的顶部同功能标签，避免两个入口同时争夺当前状态。

侧栏规则：

- 全局入口和任务内入口分区，高亮当前页面；父任务保留选择标识，子页面有独立高亮。
- “研究地图”返回上次图层及选择；阅读报告不覆盖图位置。原型以本页状态演示，正式版应按任务保存导航状态。
- 切换任务不提交、不丢弃已填意见；正式版草稿按任务/引用/基线隔离。执行中的研究继续运行，离开页面不等于取消。
- 收起后保留图标及可访问名称；完整任务目录由展开侧栏恢复。桌面阅读图可主动收起侧栏。
- 窄屏提供明确“导航”按钮。原型为可展开面板；正式版可用有焦点管理和Escape退出的成熟抽屉组件，关闭后回到原控件。
- 搜索无结果、空任务、历史只读、正在执行等状态给出就地解释；不以空白或无反应按钮代表功能。

## 3. 页面及操作流程

| 页面 | 信息与主要动作 | 返回位置 |
| --- | --- | --- |
| 工作台 | 最近研究、需要审阅的任务、继续阅读 | 进入上次专题/判断 |
| 全部研究 | 公司/题目搜索、状态过滤、简洁任务列表 | 保留关键词与过滤条件 |
| 新建研究 | 题目、问题/范围；正式版补期间、资料与执行确认 | 保存草稿返回任务，确认执行才调用模型 |
| 研究地图 | 总览/专题/判断三层、明确来源/CALC及待核问题 | 面包屑、上层选择和位置保持 |
| 研究报告 | 稳定阅读排版、章节目录、可追溯引用 | 返回引用对应判断或之前图位置 |
| 研究资料 | 当前任务的披露、资料和计算；显示期间/来源类型 | 原文返回打开它的上下文 |
| 修订记录 | 未提交草稿、提交运行、基线/结果与实际报告差异 | 继续编辑或打开相关判断 |
| 待审阅 | 明确目标的审阅项，区分待核、修订失败、待接受 | 直达判断及依据，不去空对话页 |
| 运行与费用 | 实际阶段、已执行步骤、失败原因、审阅等待、已知用量与未知项 | 回到关联研究或修订 |

完整主流程：研究列表→新建/继续→研究总览→专题→判断→原文核对→写意见→预览目标与范围→确认执行→实际运行→新旧内容比较→研究者审阅。原型只演示到本地意见预览；正式已有targeted revision接口可复用，不能把原型提交按钮接成无目标的自由文本动作。

图语义保持：组织关系与依据关系分开，待核问题有文字/虚线标识。可拖动视图不是改研究事实；不提供任意改线。不存在可靠关系时显示边界，不能用美观的箭头制造因果。原型的短标题与6专题是演示编排，正式需忠实于已有产物，保留原完整主张与报告表述的差异。

## 4. 统一视觉系统

视觉方向：冷灰底、白色阅读面、石墨文字、研究蓝强调。移除绿色主题及原型中的松石绿备选。蓝色用于当前路径/主要动作/链接；琥珀用于待核对；错误需文字与明确错误样式，不把颜色单独当状态含义。明暗外观跟随系统，但两套都保持相同语义和布局。

| 元素 | 规则 |
| --- | --- |
| 主色 | 研究蓝，浅色参考#315ACB；大面积背景保持中性 |
| 字体 | 英文/数字Inter优先；中文PingFang SC / Microsoft YaHei UI回退；原型使用系统已装字体，不声称下载了Inter |
| 阅读字体 | 正文与表格使用易读无衬线；长文标题允许少量衬线，正文不套代码或Markdown编辑器外观 |
| 字号/字重 | 页面标题22–24px，节点13–15px，正文14–16px，次要标识11–12px；正文400、强调500，避免整卡加粗 |
| 数字 | 财务数字等宽数位，值/单位/期间分层，表格对齐；未知值写未载入或未知，不显示0 |
| 图标 | 单一Lucide线性图标语言，常规16–18px、统一描边；无表情符号拼贴，图标配文字或可访问名称 |
| 空间 | 以4/8px为间距基础；侧栏218px/62px，内容24–32px边距；节点10px、阅读容器12px圆角 |
| 层级 | 背景、内容卡、当前选中、阅读面板四层；细边框和轻阴影，不靠大量彩色卡块填充 |
| 图节点 | 短标题＋必要数字/描述＋状态/动作；原文、计算、判断、问题有清楚类型标识 |

所有视觉值应形成共享设计变量；后续改页面使用同一套控件、图标和字体，不能逐页复制CSS形成不同审美。

## 5. 动效与阅读连续性

- 侧栏展开/收起约220ms；布局重排后连线依据实际端点更新。
- 图层与页面过渡约280ms轻位移；卡片悬停约150–180ms、2–3px浮起，重点是表达可进入。
- 来源从研究上下文进入阅读面，关闭回到原位置；正式版可让选中卡片与阅读标题形成连续过渡。
- 载入长任务用实际步骤和静态占位结构；不制造假百分比，不让连接线永久闪动。
- 支持prefers-reduced-motion；动画不能延迟操作、遮挡焦点或成为唯一状态提示。
- 桌面保留正常字号并优先横向层级；小屏顺序重排，不能把整个大图缩成不可读缩略图。

## 6. 状态、权限及数据衔接

复用现有报告版本、引用、checkpoint、来源读取、run及diff接口。用户点击只导航；保存草稿不调用模型；确认执行携带目标和基线；基线变化提示重新核对。重复提交、未知提交状态与失败恢复沿现有后端边界处理。

完整状态：没有研究→草稿→执行中→等待审阅→修订中→执行失败/可恢复→运行完成待审阅→人工接受。产品版本、报告版本、执行attempt不得混用；运行成功不等于研究内容接受。

历史报告/来源只读；当前已保存主张与修订后报告表述可能不同，应可见。费用仅显示真实已知项、未知项与统计口径；页面不能为美观填入虚构成功率、置信分或账单。

可访问性：可见焦点、键盘可进入节点、按钮文字或名称、可恢复焦点的面板、无仅悬停操作、明暗对比、窄屏无正文截断。正式路由应支持浏览器返回与可分享的任务/内容定位；原型本页导航不宣称实现这些持久能力。

1. 统一应用框架与设计变量：侧栏/头部/列表/字体/图标/通用控件；接真实任务导航，验证不丢阅读位置与草稿。

3. 全流程补齐：新建任务、运行/失败、费用、修订记录与历史差异统一页面；新旧入口行为一致。
4. Owner体验后做几个有界小case：导航与来源回返、过期基线拒绝、一次真实目标修订及费用和报告差异审阅。真实模型测试需单独记录预算依据与停止条件。
