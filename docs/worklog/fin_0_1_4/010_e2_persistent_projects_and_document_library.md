# 010：E2 持久项目与项目资料回读

2026-09-14，FIN 0.1.4 / E2，基于 `ff8eb4f6`。本轮开始用户可见产品切片，模型调用/费用均为0；没有部署、包版本变更或旧资料删除。

## 产品问题与实现

0.1.3的项目/归类/置顶只存在浏览器localStorage，附件归属单个研究thread。新浏览器无法恢复项目整理，也没有独立项目资料入口。本包将项目整理保存到当前工作台服务，侧栏项目可打开资料页，完成创建项目→上传→按文件名/正文关键词查找→阅读已保存正文/下载原文件→新浏览器重新读取。

复用现有SQLite和`TaskAttachmentStore`解析器，在原附件根目录的同级`project-library/attachments.sqlite`保存项目索引与资料。项目索引按认证owner分开，保存使用修订号及SQLite事务；旧窗口收到409后重新载入，不静默覆盖。迟到的旧读取结果不能降低客户端修订号。原浏览器记录不删除，首次空服务端可显式导入；已有服务端项目与另一浏览器旧记录的自动合并未实现。

API通过现有身份中间件取得owner，不接受请求体owner。项目UUID与owner共同决定独立附件命名空间，即使两个owner使用相同项目UUID也不能串读。新增任务归类/置顶先调用既有研究会话归属检查；项目整理不授予原任务/报告访问权限。原研究和报告版本继续由既有服务持有。

项目资料复用20 MiB单文件、12份/80 MiB项目总量边界和原解析器，正文关键词查找扫描这个有界集合，不建新检索引擎。图片/扫描页标明需要识别，未接付费OCR。上传内容始终为`user_upload_unverified`；预览以纯文本展示，原文件按下载返回，文档内脚本/指令不执行。查找不是语义检索，也不等同财务事实核验或新的研究结论。

原上传适配器在并发时使用列表最后一项作为本次返回值，可能返回另一文件；现在按本次object ID返回。没有更改旧附件归属、正文或历史标识。

## 边界与下一步

产品增量：服务端项目整理及独立项目资料页可用，跨浏览器读取不依赖localStorage。工程增量：薄SQLite项目适配器、认证API、修订号冲突和原解析器复用；无新依赖。资格证据：上述本地合成API/浏览器/持久化场景。文档增量：PRD当前状态、技术和执行路线、Project OS同步。
