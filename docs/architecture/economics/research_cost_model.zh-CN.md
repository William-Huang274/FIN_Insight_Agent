# 研究任务成本模型

2026-09-13 · 内部估算口径 v0.1，尚未接入0.1.4预算执行或自动校准。复用既有用量记录、`usage_pricing.py`和供应商账单，不建设新实验追踪或计费平台。

## 实际用量计价与总服务成本

对请求i，以非重叠的未缓存输入U、缓存输入H、计费输出O计价：

`C_model_i = (U_i * p_u_i + H_i * p_h_i + O_i * p_o_i) / 1_000_000 + C_other_i`

价格单位为该币种每百万tokens；倍率、长上下文阶梯、分时价格等进入该请求适用单价，并记录价格版本/时间。推理tokens若已包含计费输出不再相加。图像/音频等非token项用供应商对应计费单位计入C_other。供应商input字段若含cache_hit，U=input-H；字段定义未知时不强行换算。

`C_variable_task = sum(all attempts and descendants C_model_i) + C_embedding + C_rerank + C_search/data/OCR + C_compute/storage/egress`

各项互斥归类，embedding/rerank若已在请求总账中不能再次加总。失败/取消中已发生支出保留，未知支出单列，不能计为0。多币种先分别汇总，需要统一币种时记录汇率及日期。实际账单、按历史公开价估计和优惠/赠送额度分别保存。

`C_service_task = C_variable_task + allocated_fixed_cost`

固定连接器/数据订阅/runtime许可/服务器待机等按明确的月度使用或用户分摊策略一次计入，不能既按请求收费又完整分摊同一费用。用户BYOK自付费用与平台承担费用分列。用户审阅/修改时间单独记录，不假装平台已支付这部分成本。

同类任务的`C_quality = sum(all attempted task costs) / accepted_deliveries`；记录是否人工完成。分母为0时不报告有限成本。该指标不能代替质量、时间和介入率本身，也不能跨不同任务/报告标准混算。

## 预测和执行中预算

`C_forecast = sum_stage N_stage * E[cost_per_call | model, input_scale, corpus_state, workflow_version] + expected_nonmodel_cost + fixed_allocation`

初期N、输入/输出/命中率为有依据的任务场景参数，保持普通查询、首次研究、资料增量更新和用户修订分组。不能把研究结束后才知道的调用数用于声称事前预测准确。

`C_expected_total_at_t = C_known_so_far + E[C_inflight_unsettled] + E[C_remaining_work]`

未结算请求与已知费用不重叠；后续仍必需的综合、核验和交付计入剩余工作。调度入场使用保守资源预留而非均值预测，多worker共享任务/用户预算；已完成后以实际计价结算释放余量。价格预估、供应商在途请求和未知用量意味着事后费用仍需核对，不能声称软件能让外部已经发生的费用消失。

## 校准规则

每个完成或失败任务保留执行前预测、预测版本、实际用量、价格版本、质量结果与人工耗时。按任务类型和runtime/模型版本比较预测偏差、绝对误差及区间覆盖率；达到样本要求后用最近同类完成记录更新阶段调用数、长度、命中率和升级/失败频率。价格变化更新单价表，行为变化更新预测参数，二者分开。

样本少时显示保守场景和样本数，不伪造P50/P90。定期回放已保存的事前预测；不得覆盖旧预测或丢弃贵的失败任务。校准模型先用分组统计，只有预测误差证明必要时才引入更复杂方法。自动化校准未实现，本文件定义的是下一步接入要求。

该样本总tokens为4,462,902，输入中缓存命中比例为72.85%。它证明已有请求虽有较高缓存命中仍有显著总用量；不能据此得出提高缓存无用、某阶段费用全部可避免或能节省固定百分比。首次运行包含正常工作与工程错误，不能全部归为浪费。

这是一个包含人工修订的历史任务，未知用量为0；不等同用户所述不含人工重跑的约4元成本，不作为所有复杂任务的平均价。基础设施/订阅分摊和人工时长缺失，完整服务成本与自动合格交付成本不可计算。当前核算只复核既有证据，无新供应商调用、无新性能改进。
