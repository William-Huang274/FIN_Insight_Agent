# 组织授权下的已准备向量与关键词混合检索

## 查询需求、双语词法入口和原文上下文（conservative.v2）

组织搜索可显式指定 `organization_query_planning=conservative.v2`。旧 v1 行为及已冻结的回归策略保持可复现；没有切换现有部署或改变原文、块 ID、向量和索引发布身份。

- 对明确比较、且每个公司别名可唯一解析的查询，使用授权目录中的公司并集。单一明确年报所有者与交易对手分开处理；同名歧义和未知资料仍保留，不凭标题猜公司或财政年度。
- 中文金融概念通过维护的导航词表形成单独的英文词法路线，中文原词路线保留。该词表只供候选检索，不把收入、现金流、承诺、实际支出当成可替代指标；未覆盖词语保持原文，不宣称任意句子翻译。多个明确需求分别分配词法候选，不能让整句中的公司名和日期独占额度。
- `both X and Y`、明确的“同时找出 X 和 Y”以及多公司比较生成可审计的检索需求。拆分子句继承原问题的明确公司，未知归属的资料不能填充这个公司需求。在固定候选集合中，按对应需求的检索顺序各保留候选，再保留原排序尾部；同一片段可同时满足多个候选入口，不为了凑数量强选另一片段。回执报告未覆盖需求；“选中候选”不等于问题已有完整答案。没有解析出的隐含复合问题仍走单查询，不能宣称通用任务规划。
- 对仅写“2025 report”一类年份的情况，不推断期末或文件类型。若只有一个明确年份，需求选择可优先使用封面已经核实该报告年度的候选；其他候选继续保留，非自然年资料没有被硬转为自然年。这个偏好不是语义充分性判断，也不是对旧版本正确性的保证。
- 短脚注、明显断头或断尾的片段附带相邻原文的 `context_readbacks`。关系来自已验证的同一版本原件坐标；只允许同一坐标系内相接或重叠片段，不跨缺失页或不同原始节点猜关系。正文与向量输入不改写，单位不自动传播，不能把拼接字符串当成新引用。当前处理是原文上下文关联，不是语义重切块或全库重新生成向量；大表格超出相邻范围时仍需继续原文阅读。

各词法路线及需求覆盖出现在检索回执中；新词法顺序参与排名缓存身份。返回搜索和读取上下文仍经当前 Java/本地权限检查，邻接关系不授予新权限。查询候选读取上界不再只含融合块，还包括不完整块的最多两个相邻块；不重新加载所有原件正文。

评测用 `scripts/engineering/retrieval_evidence_sets.py` 表达“一个事实要求的多种证据组合”：组合内所有片段必须齐全，组合之间可以替代。每个替代组合须有明确审阅依据、同版原件、正文摘要和精确引文。机器只能核对来源和引用，不能代替语义审阅。原严格块 ID 指标保留，修订标注的结果单列，禁止悄悄改分。

## 2026-10-25：缺失表类型的原件补取与筛选诊断

显式筛选接入后发现一个实际误排除入口：Coherent 的2024/2025/2026年10-K已完整入库，原始元数据具有公司身份与期末，但没有 `form`。直接增加 `form=10-K` 会把这些来源排除。因此新增 `sec_cover_metadata`，仅对 `category=filing` 且 URL 为 SEC Archives 原件的来源，从开头2048字符内的 SEC 封面识别独立 `FORM 10-K/10-Q/8-K` 行（含 `/A`）。SEC 标识需出现在前1000字符，表类型行与标识间距不超过300字符；多处表类型或没有明确封面时不补取。不会从标题、链接文件名、正文中的其他报告、附件父表类型或发布日期推测。

## 数据、排序和缓存

1. Java 返回固定 manifest，Python 校验身份和摘要，并按现有原件存储校验每个 AssetRef。文档身份绑定资源和版本；索引准备使用当前组织导航的相同文本投影和节点 ID。
2. 服务器按规范组织 UUID 选择独立索引目录。发布记录模型、维度、节点/文档身份、正文摘要、向量矩阵摘要与来源说明；重复发布不覆盖旧目录，换版使用新 release root。准备工具不生成任何向量、不调用提供方。
3. 请求中的文档/节点过滤和固定输入集合共同确定可用节点。核对节点正文摘要及发布身份后，**先选取获准矩阵行，再计算余弦相似度与 top-K**。同索引内未选资料不能占用候选名额。
4. 复用现有 BM25，合并最多 24 个向量候选和 12 个词法候选，采用本地 RRF（常数 60）排序。没有远程 rerank；显式图发布与实体搜索额外提供上文的最多 12 个单跳图候选。可以搜索全部明确冻结且当前获准的候选资料，不等于无条件搜索整个宿主库。返回候选诊断只含本次获准 ID。
5. SQLite 排名缓存只保存三组 ID（向量、词法、最终顺序）。键包含当前完整授权响应摘要、执行/项目/固定输入、索引内容摘要、查询摘要、节点版本及排序策略版本。不同组织分目录，不同执行和查询范围分键。
6. 缓存命中仍须重新核权、检查原件数据库代次、发布身份和候选集合。当前查询可复用已验证的投影/响应；同一导航对象内发布完整校验按上文生命周期复用。缓存中的越界 ID 被拒绝，不做过滤后继续返回。引用读取仍逐次核权并检查原文身份；检索预览不能作为已读引用。

v2 索引 release 通过 BFF 校验原件投影和当前权限后在 Java 登记，准备单可选择 `retrieval_release_id`，固定模型、维度及索引/矩阵摘要；发布新版本不改写旧准备单。旧 v1 仍使用宿主显式配置，不能获得 v2 的发布版本保证。每次结果记录索引摘要，换 release 不复用旧排名缓存。索引目录需允许创建本地 ID 缓存；原件与源公共索引不被改写。

排序、缓存写入及最终输出前再次核权。扫描期间撤权导致整次工具失败；已返回的数据不能被撤回，也不声称消除了最后一次检查与响应之间的时间窗口。索引文件和缓存是宿主受控存储，不是模型可编辑的输入；本片不提供磁盘加密、恶意宿主防护或跨机器发布服务。

### 向量校验与排序的临时内存

固定发布的向量完整性仍按整个文件摘要核验；注册时的单位向量校验，以及查询时的授权候选校验／余弦计算，按最多 4,096 行分块处理。不会抽样、缩小候选范围或缓存正向权限。查询仅保存一维分数，避免同时构造全候选 float32 副本及整个 float64 校验数组。缓存命中仍校验全部已选向量；未命中时，参与点积的每个块再次校验有限性与单位长度。排序的前 24 向量候选、前 12 词法候选和 RRF 规则保持不变。

跨块测试覆盖打乱候选顺序、未授权行含坏值、末块零向量／NaN／无穷／非单位向量，并与原 NumPy 点积比较数值及前 24 排序。`scripts/engineering/qualify_organization_vector_blocks.py` 可用已核验输入包和固定成功查询向量逐源离线重放；输入摘要变化或排序不一致会失败并保留此前完成的来源。该脚本不是组织服务、全库排名、召回或并发验收，运行时间不能作为线上查询延迟。
