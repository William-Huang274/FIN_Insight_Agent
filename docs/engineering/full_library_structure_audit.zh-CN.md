# 全库结构识别与预分块验收

本轮先验收文档结构，暂停召回、向量生成和重排比较。范围是已冻结组织资格库的全部来源绑定；不将旧向量索引替换成新的分块，不改变运行服务。该工作与[解析器选型](document_parser_selection.zh-CN.md)、[上游归因实验](parser_upstream_ablation.zh-CN.md)衔接，继续复用完整表格单元格、唯一原段落恢复、完整句子分块及已接受的标注记录。

## 范围和结果含义

一条来源绑定不一定等于一份原始文件：同一原件可能有全文、摘录、节点恢复、人工转录等表示。必须分别记录来源绑定、唯一 URL、原件摘要、保存版本、原件可用性和衍生内容。URL 相同只提供候选关联，不能替代版本摘要。

当前冻结范围为 1,742 条来源绑定、1,591 个 URL。选定捕获库中，1,333 条绑定各有一个同 URL 原件候选，去重为 1,187 个原件摘要；409 条需要额外原件定位和衍生表示检查。上述数字是清单覆盖，不是结构准确率。

检查按资料类型进行：

| 类型 | 检查路径 | 不能据此作出的结论 |
| --- | --- | --- |
| SEC HTML/iXBRL | EdgarTools 文档对象、申报类型驱动章节检测；Datamule 原生层级作为独立对照 | 两个解析器都输出标题，不代表标题角色、层级或金融主体正确 |
| 新闻、公告网页 | Trafilatura XML 的标题、段落、列表、表格，回看原 HTML | 页面所有 H 标签不一定属于正文；侧栏、相关推荐被排除可能是正确行为 |
| PDF | 已有轻量文字和书签诊断，保留页号 | 不能替代版面标题、小标题、跨页表格或扫描件 OCR 资格 |
| Markdown/普通文本 | 已保存标题标记与段落内完整句子 | 已扁平化文本不能证明原件的标题、表格和读序完整 |
| JSON/XML | 保留原生对象/元素，区分接口记录与文章 | 不能要求财务接口对象具有文章章节，也不能把对象序列化后当普通正文切片 |
| 恢复节点/人工衍生内容 | 核验冻结捕获摘要，保留原节点身份、章节路径和正文 | 恢复节点的存在不等于原 HTML/PDF 结构已验证 |

“执行成功”“结构疑点”“人工确认的识别错误”“预分块无损”分别统计。脚本输出的短标题、层级跳跃、DOM 标题未匹配等仅是审核线索，不能直接当作准确率分母或错误率。

## 已修复的适配问题

1. 导出 EdgarTools 节点时，先处理完整 HeadingNode，保留 level，再遍历其他容器。标题内部的样式子节点不再取代整个标题。
2. 显式传入 `ParserConfig.form`。优先使用来源声明和原件 DEI DocumentType；相互冲突时记录冲突，不擅自选一种；没有两者时才记录目录标题提示。保留原生章节识别的 part/item、方法、置信度和警告，不能把置信度当人工验证。
3. Trafilatura 序列化元素可能附有尾部正文。将其作为 XML 片段解析，尾部正文另存，不通过删除尾部来消除解析错误。
4. 文本以方括号开头不等于 JSON。无 JSON MIME 声明时，仅在实际解析成功后使用结构化对象路线；链接、标注和普通 Markdown 仍按文本处理。
5. 缩写判断保留原规则，只扫描句号前的字母/点号后缀。过去逐句扫描整个文档前缀会使长篇扁平文本出现近似平方级开销。新逻辑没有固定长度截断，不改变缩写规则、原文或句子位置。

前五项是解析/预处理适配，不解决集团与基金资产归属、事实期间、数值单位或脚注适用关系。数值和 SQL 的既定分工保持不变。

## 原容器与统一章节树

结构资格适配增加了以下约束；它们尚不切换产品索引，也不改既有引用 ID。

- EdgarTools 的完整段落、列表项和标题先作为容器导出。只有内部包含另一个段落、标题或表格时才继续展开。保留解析树中的序号路径、父容器和原生角色，避免把同一段落的行内 span 再拆成文字碎片。
- 原 HTML 另存容器账本，使用原件 SHA-256 与原 DOM XPath 定位，保留 HTML ID、父容器、所属物理表格、文字摘要和角色依据。原件位置与解析器路径属于两个命名空间。完整文字唯一对应才能指定原位置；同文重复保留全部候选，不按距离选一个。
- 原 HTML、粗体候选和金融意义分别记录。粗体单元格通常只得到表格标签候选；显式 H/ARIA 标题、较大字体标题候选和段落候选也分别保留依据。含数字的物理表格不自动成为财务数值表。排版或混合表格内的标题留在同一章节对象集合中，但作用域限制在原容器，避免把整个表重新作为正文复制。
- SEC Part 与 Item 使用统一父子关系，8-K 的 `2.01`、`2.02` 保持不同。重复 Part/Item 页眉记录为同一节点的再次出现，当前小节不会因此被清空；不同 Part 的同号 Item 不合并。只有完整内部链接对应得到证明时，才按导航引用处理。无法确定的目录、页眉和封面角色仍需审核。
- 网页提取启用元数据，文章主标题与原 DOM H 元素核对。唯一对应时保留原 H 文本和位置；站点后缀留在元数据中。侧栏、导航和页脚不因存在 H 标签就进入文章标题树。
- 预分块引用统一章节树，保存原容器身份；重复标题、表内标题不会复制为普通正文。字体和解析器级别仍是结构推断，不能当作已核验的金融主体或事实归属。

`validate_source_structure_audit.py` 对冻结清单逐份核验产物摘要、容器/章节唯一性、父子关系、引用可达性、完整正文区间以及表格记录数量。缺收据、执行失败或引用断裂都使完整范围验证失败。完整执行与这些工程约束通过，不等于所有章节语义准确；原件缺失、PDF 版面和不确定表格角色继续单列。

扩大原件抽检还发现两种结构变体：HeadingNode 自身只包含一个短标题的前半段；Item 标题是一个完整的单行排版表格。`refine_document_chapters.py` 是解析后的独立阶段，绑定每份输入产物摘要与实现版本，不要求重新调用解析器。

- 短标题只在同一原生父容器内拼接，且必须完整对应唯一的原标题候选；不同段落、仅数字和同文多位置不合并。
- 单行表格必须完整匹配原件、仅含一条 SEC Part/Item 标题，才建立文档章节关系；多行目录、页码列、展品目录和数值表不凭一个 Item 单元格成为章节。原表内容不变，在预分组中作为结构保留。
- 完整原段落与原生章节标题交叉支持时，可恢复未导出为 heading 的 Item 标题。重复多 Item 页眉与正式章节标题分别保留；展示名称优先使用有原位置的完整标题，保留全部标签出现记录。
- 修订后的章节树和预分块对全部冻结输入重新构建，输出记录父阶段摘要。恢复执行同时核对输入、输出与代码身份，不能把不同规则的部分结果拼成统一通过。

## 预分块合同

- 正文在已识别结构内按完整句子组成有界块；每块保留原文本区间和标题路径。超长单句保持完整并报告，不强行切断。
- 标题作为结构记录，不单独包装成正文证据。解析器给出的层级仍需审核，不能自动变成可信章节归属。
- 表格保留完整单元格、表头、表尾和跨行跨列信息（解析器支持范围内）；预分块输出引用该结构，不把数值表当普通句子，也不替代 SQL 取数。
- 已恢复节点保留已有身份和路径；父章节不与子节点重复生成正文块。缺原件时明确标注无法验证源结构。
- 分块区间必须连续、无重叠、覆盖对应正文块。此检查证明没有再次损坏已提取文本，不证明解析器从原件中提取了全部内容。
- 原子片段还需按已有正文聚合方式组成预分组：同一标题路径内聚合完整句子片段，正文上限 10,000 UTF-8 字节，标题路径变化或遇到表格时断开。超长完整句子显式保留。分组仅引用原子记录，不启动向量生成，也不把未经审核的标题路径升级成可信结构。

## 执行与恢复

在独立的可选解析环境中固定实际包版本。普通安装和 CI 不依赖私人语料或本机目录。

```text
python scripts/engineering/freeze_document_structure_audit.py --inventory <bindings.jsonl> --database <captures.sqlite> --output <new-manifest.json>
python scripts/engineering/run_document_structure_audit.py --manifest <new-manifest.json> --output <private-output> --batch 12
python scripts/engineering/audit_derived_document_structure.py --manifest <new-manifest.json> --context <frozen-context.json> --database <attachment-captures.sqlite> --output <new-derived-output>
python scripts/engineering/summarize_document_structure_audit.py --manifest <new-manifest.json> --directory <private-output> --output <private-summary.json>
python scripts/engineering/finalize_structure_prechunks.py --directory <private-output> --output <new-private-prechunks>
```

原件库和捕获库只读；逐原件验证摘要，逐文件压缩保存结构、原生对照和预分块。单个可回收子进程按批处理，有资源暂停和超时记录。输入、实现或包版本变化后，原输出目录拒绝直接继续，不能混淆不同实现的结果。

兼容复用需要显式逐项证明：原件摘要、包版本和相关解析实现一致；若仅句子边界实现改变，全部已生成正文边界必须重新比对。改变 XML 片段处理后，网页路线应重新解析，不能用其他路线的兼容检查代替。旧失败与诊断记录保留。

## 尚存的结构问题及核查依据

1. **正文标题与封面、页眉、目录角色混淆。**Micron 原件中地址、`OR`、`None` 等进入标题集合；Microsoft 季报的重复页眉也进入标题树。不能把短标题一概删除，真正的章节名称、单位和脚注同样可能很短。
2. **章节层级与标题层级不一致。**109 份原件出现 Item 没有嵌套在前一个 Part 之下的诊断，累计 1,282 处；部分由目录或页眉重复引起，不能直接当作 109 份全文错误率。原生 section 信息与普通 HeadingNode.level 需要统一解释，不能只按数字 level 拼树。
3. **标题藏在物理表格中。**HPE 新闻稿的主标题与财务摘要处于同一排版表格，解析器将整块判为 FINANCIAL；粗体的季度财务/分部小标题又被当作 text。表格里含有数字不代表整个容器都应该作为数值表处理。
4. **网页文章标题、正文小标题与侧栏需分别处理。**NVIDIA、SK hynix 的文章标题没有进入当前正文标题树；AMD 的文章标题及财务结果小标题能识别。核查发现当前调用未启用 `with_metadata`，导出又只保留正文节点；对三份原件另作本地探针，启用元数据后均能得到标题，但 SK hynix 元数据标题还含站点后缀，不能直接拿它代替原 H2 文本。81 份 HTML 有显式 H 标签未进入结果，其中还包含被正确剔除的 Related Content、侧栏等，不能把这个数称为漏识别文章数。元数据标题与原 DOM 标题的统一尚待全路线接入。
5. **容器边界仍可能丢失。**适配遍历会将部分列表、行内样式展开为细碎文本；HPE 中项目符号、`Gross margins`、冒号分成多个原子片段。Microsoft 原件的同一个 `p#income_statements` 内，两个样式 span 分别为 `INCOME STA`、`TEMENTS`，输出仍是两条 text；`BALANCE SHEETS` 也有类似情况。现有段落恢复保护了长正文，但短标题未被恢复，不能靠后面的句子分块重新猜词。唯一原段落恢复已产生 83,888 条修复收据；下一步需要保留原容器身份/角色，不能直接降低长度门槛合并相邻数字或文字。
6. **PDF 结构资格未完成。**45 份 PDF 的文字可执行提取，不代表章节字体、读序、表格和扫描件 OCR 已通过。当前路线明确保留这一缺口，没有用正文分块通过代替版面验证。
7. **Markdown 和衍生文本仍有表示边界。**模型卡的 YAML 元数据仍会进入普通文本；ATX 标题检查不能代表 Setext、代码块、列表嵌套都已合格。已扁平化正文或恢复节点仍需原件支撑，不能从文本反猜完整原版层级。
8. **定位坐标仍分层。**原段落恢复收据有原 DOM XPath；普通 parser_path 与预分块位置是解析结果内的位置，不是全部原 DOM/PDF 坐标，不能直接替换旧引用身份。

自动疑点还包括：55 份较长原件没有识别到标题，391 份有层级跳跃，510 份有短标题，5 份网页提取表格数少于原 DOM，5 份原件出现 6 个超长完整句子。它们需要结合原文角色核查，不能全部计为错误，也不能用无执行失败掩盖它们。

## 原容器修复后的全范围复测

同一冻结范围的 1,187 个原件重新解析，覆盖 1,333 条来源绑定；另外 409 条衍生表示、10 个本地候选原件及 4 个关联捕获也全部重新处理。解析阶段与章节修正阶段分别冻结实现，通过逐份父产物摘要连接。没有重新生成向量、调用模型、发布索引或切换服务。

完整原件范围的容器/章节身份、父子关系、引用和正文区间校验通过。与修复前逐原件比较，完整表格字段有变化的原件为 0，字母数字字符计数减少的原件为 0；字符计数不能独立证明读序正确。章节修正阶段恢复 351 个标题容器，产生 2,026 条角色修正记录。最终保留 398,332 个正文原子区间，聚合为 85,968 个正文预分组；表格章节标题作为结构保留，原单元格仍在。

使用同一版诊断器重查前后结果：Item 没有位于前置 Part 之下的层级线索，从 296 份原件降为 0。该检查同时覆盖带说明文字的 Part 标题；这是已识别节点的层级约束，不是全部章节召回率或语义准确率。

剩余诊断必须继续保留：36 份较长原件未识别到标题，45 份 PDF 仍仅通过文字/书签路线；191 份有层级跳跃线索、60 份有未知标题级别。不同问题可以出现在同一文档，不能直接相加为失败数。

84 份非 SEC 网页中，27 份元数据标题与原 H 元素唯一对应；1 份有多个对应位置，2 份没有显式 H 标题，54 份元数据与 H 文本不同。其中 43 份是目录已标记的企业官方入口页。首页、法规页、目录页与单篇文章不是相同结构，不能把这 54 份统称为漏识别文章标题，也不能用元数据强行替换页面标题。原容器账本仍保留这些 H 元素与位置。

125 项相关回归通过。工程一致性、原文保留和剩余结构疑点分别记录；本轮没有形成金融语义、召回效果或产品上线结论。

本轮结果是**原容器保留、统一章节树及全范围预分块复测完成，结构识别质量尚未通过整体验收**。后续应复用本轮产物，逐项处理剩余标题角色、层级和定位疑点；PDF 和缺原件的衍生表示分别验证，不以 HTML 路线的通过结果替代。之后才适合冻结可发布分块。此次没有调用模型、重新生成向量、切换产品服务或报告检索指标。

## 残余问题分流与标题级别保留修复

后续全原件诊断由 `scripts/engineering/diagnose_document_structure_residuals.py` 输出逐项案例，保存来源、父产物摘要、角色/级别依据和待处理动作；没有线索的文档也不默认质量通过。输入输出路径均显式传入，不依赖私人文件。该工具属于资格检查，尚未连接生产入库任务。

## 现有资料库优先收口

当前交付对象是冻结清单中的全部 1,742 条已有来源绑定。上传流程是后续复用这些能力的入口，不替代既有资料的批量处理。一个原件关联多个来源时，原件只解析一次，但每条绑定单独记账。缺原件的衍生来源保留在分母中；补查到候选文件仍须确认版本和身份，不能直接把 URL 相同视作同一原件。

`build_library_structure_completion_ledger.py` 生成逐绑定账本，分开记录执行状态、质量待核查状态、解析路径、剩余诊断及下一步动作。读取时校验实际产物摘要；有修复覆盖层时同时核对父产物身份。修复失败继续保留父产物和失败原因，不使用失败结果替换原结果。没有诊断项只表示没有触发当前检查，不能自动标记“解析完成”。PDF 版面资格和原件缺失分别记录。

提供 `--derived` 时复用已有衍生解析结果，核对冻结清单、来源摘要、绑定身份和原件未验证标记。旧衍生收据没有保存产物内容摘要，因此账本记录本次快照摘要，不声称已经与历史内容摘要比对；后续复用可以据此检查变更。衍生 JSON、文本和恢复节点不会被提升成原件结构已通过。

第一类批量修复针对 SEC HTML 中被空白排版容器打断的粗体标题上下文。只跨同一父节点下无可见文字、无媒体、无锚点和无可能生成内容的样式类的空白节点；表格、图片、可见尾文本与未知结构均构成边界。保留跳过节点及后续正文的原 XPath。修复工具复用已完成的段落恢复和章节修正，只为发生变更的原件保存新的派生产物，不覆盖旧原件、旧引用或产品索引。

修复资格包括原文摘要、完整块文本及顺序、表格除章节关联外的全部字段、章节父子关系和预分块覆盖。表格标题、元数据、单位说明也属于守恒检查；仅比较数字字符或行数不够。恢复标题不独立证明标题的语义层级正确，也不能解决图像式演示稿、复杂 PDF 读序或财务主体识别。

```bash
python scripts/engineering/repair_library_blank_heading_context.py --manifest <frozen-manifest.json> --baseline <qualified-parent-directory> --output <new-repair-directory>
python scripts/engineering/build_library_structure_completion_ledger.py --manifest <frozen-manifest.json> --baseline <qualified-parent-directory> --overlay <repair-directory> --derived <existing-derived-directory> --output <new-accounting-directory>
```

所有输入路径显式传入，原件数据库只读；生成产物、逐项账本与运行记录保存在 Git 外。本阶段不生成向量、不评测召回、不发布索引，也不将分批检查通过包装为全库最终质量通过。

本轮完整清单复验：818 个 HTML 原件执行该项检查，228 个 SEC 原件恢复 4,720 个具有完整原容器依据的标题节点，590 个 HTML 原件保留父产物，执行失败为 0；369 个其他格式原件按原路径保留。228 个修复产物逐份通过完整块文本顺序与表格字段守恒检查、结构引用及预分块覆盖校验。恢复节点数量不是人工审核后的标题准确率，推断的层级仍须继续核查。

最终账本覆盖全部 1,742 条绑定：246 条关联本轮修复产物、1,087 条关联保留的原件解析、409 条关联既有衍生解析。全部选用的 1,187 个原件派生产物核对了收据摘要；衍生结果按前述快照方式登记。Marvell 原先无标题的公告恢复 5 个小标题，无标题长文诊断从 36 份降到 35 份；剩余 31 份 PDF、4 份图像式 HTML 演示稿仍需对应解析路径。层级跳跃仍为 172 份，显式标题未进入结果仍为 78 份，短标题提示为 525 份；这些诊断可重叠，且不是相同含义的失败数。60 项相关回归、活动基线和秘密扫描通过。

第一次扩展扫描暴露出 HTML 注释节点被当作普通元素读取的错误，已修正为显式边界，并保留失败记录；第二次完整扫描使用修正后的同一实现完成。没有将第一次未完成的结果拼成最终完整扫描。

## SEC Item 内层级与签署区边界

后续检查发现，没有 Part 的 8-K 中，字号规则会把 Item 下的小标题重新设为根级。例如 Item 5.02 下完整的 `(b)`、`(c)` 条款节点虽已恢复，却丢失 Item 父节点。这不是标题文字缺失，而是规范章节树和预分块继承范围错误。

现在先确定当前 Part/Item 的结构范围，再在该范围内部比较字体或保留解析器层级。小标题不得因字号更大或没有 Part 而越过当前 Item；新的 Item/Part 和有依据的签署区可以结束原范围。原解析器级别继续独立保存，正文、表格和原定位身份不变。

签署区要求完整、唯一定位、非导航/非表格内的原签署标题，再由以下之一提供佐证：解析器已有签署分区，或紧随标题的完整原段落包含报告授权签署声明。后者同样要求唯一原容器匹配，不跨过其他非空内容寻找远处声明，也不将正文中的引用当作签署依据。上轮派生边界标记在重建时重新验证，不能脱离原依据长期沿用。规则不包含公司名称。

`repair_library_section_scopes.py` 从上一轮逐绑定账本选取实际产物，核对全清单绑定关系和每个原件产物摘要后执行章节修正。只保存有变化的文档，其他原件及衍生资料沿用既有结果；每个新产物记录直接父产物路径和摘要。完整文本顺序、表格内容、章节引用和预分块覆盖继续校验。该阶段仍属于离线解析资格，不切换产品或索引。

```bash
python scripts/engineering/repair_library_section_scopes.py --manifest <frozen-manifest.json> --ledger <previous-bindings.jsonl> --output <new-section-scope-directory>
```

完整清单最终复测覆盖 1,187 个原件，410 个 SEC 原件更新章节层级或边界依据，对应 435 条来源；其他原件及 409 条衍生表示继续保留，总账仍为 1,742 条。独立比较覆盖全部 734 个 SEC 原件：原容器账本、正文和表格、非章节块字段及章节节点身份不变；3,234 条父节点关系、3,504 个级别发生变化。两者可能重叠，不能相加作为修复数量。层级跳跃诊断从 172 份变为 104 份，属于结构诊断变化，不是识别准确率。

复验中补齐了两类通用表示：解析器的 `part_ii_signatures` / `part_iv_signatures` 分区标识，以及原签署声明中的法条前缀。最终完整实现没有新增签署标题误挂父节点的候选；仍有 51 处既有签署范围需要核查，另有 1 个物理表格内部签署标签单独保留，不强行提升为文档章节。67 项回归、活动基线、秘密扫描通过；失败中间版本与最终版本分别保存，不合并计为通过。
