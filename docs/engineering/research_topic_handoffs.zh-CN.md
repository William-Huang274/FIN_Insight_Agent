# 专题研究交接、上下文退出与成文快照

后续增量认识、章节论证绑定和成文断点回接见[增量研究认识与成文断点](incremental_research_authoring.zh-CN.md)。下文记录第一阶段的底稿和整稿快照合同；后续已启用当前认识状态的任务使用新增章节绑定，历史任务保持原协议。

本次实现沿用原生 ACP 会话、现有咨询执行器、LangGraph 检查点与预算账本。SQLite 保存研究成果和版本关系；没有第二套模型调用循环或调度服务。当前状态为代码接入及离线验收，未部署、未进行本版付费研究验证。

## 产品行为

总负责人维护原问题、方向、跨专题关系和最终判断。`consult_research_agent(topic_lead=true)` 启动与总负责人同配置的独立专题模型；普通调查继续使用配置的 Flash。专题负责人可使用同一委派入口处理局部关系，完整父会话不作为专题的新消息。模型自行决定是否值得分层，小问题可直接处理。

每次派发有独立任务身份；同一专题的后续任务通过 `topic_id` 关联已有成果。任务父子关系与观点采用关系分开，允许跨专题采用和反驳。初版最多三层专题委派、全族最多八项活跃任务及三项活跃专题负责人；这是资源保护，不是研究充分性的标准。负责人达到上限时提示使用普通执行者或完成现有专题，避免所有名额都由等待下游的负责人占用；任务总数满时宿主等待已有工作释放容量。共享预算和权限继续由原账本与访问检查控制，专题负责人没有额外额度。

`read_next_research_result` 消费指定任务中已完成的一项；均未完成时宿主等待首个完成项，不派发付费状态查询。现有按任务读取仍可用。`research_updates` 按游标读取底稿更新和待重评专题，模型在工作交接时选择处理；没有新增按每个工具事件唤醒模型的消息服务。

## 完整成果与身份

`publish_research_workpaper` 保存完整公开论证、当前判断、关键条件、反证、剩余问题、继续或停止理由和本次变化。保存成功才交接。最终一句回复不能代替底稿，保存失败不能变成已完成任务。这里不保存或传播私有思维链。

普通调查/草稿委派用这一份底稿交付，不再额外要求重复登记同内容的调查评估表；复核任务保留已有的具体意见与动作记录，用于稿件落实检查。任务结束反馈不能代替该保存步骤。

每版绑定根题、专题、当前派发任务、截止日、修订号和内容摘要值。采用关系包含上游专题的精确版本、采用/限定/反驳/背景用途及理由。来源和计算保存已成功取得的原回执，保持原始 ID、期间、单位及版本；研究摘要不能作为新原件归档。同一回执再次使用不会变成第二条独立证据。

SQLite 事务提供写入原子性、命令幂等和基础版本冲突检查。完整历史保留，本次仅新增工作区文件，不改旧稿或旧账本。旧咨询记录没有新底稿身份时继续原交接协议，不重新计算旧结果摘要值。

底层版本更新后，传递采用它的成果标为需要重评；原文和原判断仍按旧版可读。运行时只指出版本依赖已经变化，负责人决定结论是否改变。不同专题的观点并存，最后到达的消息不能覆盖另一个专题。当前采用关系拒绝环；互相引用的共同前提应单独形成成果，实际研究往返通过新版本表达。

## 实际进入模型的内容

| 环节 | 活跃输入 | 持久保存及回读 |
| --- | --- | --- |
| 派发 | 原题、局部问题、必要背景、按需方法、准确工具入口；不注入父会话全文 | 派发请求、成功来源/计算的业务检查点 |
| 子任务交接 | 精确版本、当前判断、条件、反证、未完成关系及入口；默认没有底稿全文和子会话日志 | 完整底稿、最终回复、检查点、原件 |
| 主动核查 | `read_research_workpaper` 的明确窗口；`read_workpaper_evidence` 的原回执窗口 | 原回执恢复到业务状态，供现有计算和引用解析使用 |
| 局部验收后 | 已接受版本的验收判断及回读；先前读入的对应论证/原件窗口可退出活跃 surface | 原生替换事件记录来源，业务检查点和数据库原件不删除 |
| 成文 | 精确版本目录，再按关系读完整论证窗口；不拼接所有旧稿 | 冻结快照、选择理由、已读取窗口、稿件绑定 |

上下文退出通过已有原生 surface 替换扩展到工作底稿和证据窗口。只有负责人明确接受且版本仍有效时才可退出；未通过或争议中的关系继续保留。验收后的新回读不立刻移走。前提变化或重新打开验收时，还在活跃 surface 的已退出窗口恢复并提示重评；原生压缩已移除的历史按持久入口回读。Sol 原生压缩配置保持既有 258k 基准，本次不另造摘要压缩器。

## 成文一致性

`prepare_research_synthesis` 选取当前成果并冻结其传递依赖，包含原题范围说明。`read_synthesis_material` 按该版本读取；`bind_research_synthesis` 将保存后的报告摘要值与快照关联。交付工具检查绑定存在且未过期。底稿之后变化会要求刷新快照并重评，不能静默换入新版本。

本版绑定粒度是整份报告及其选定成果，未实现自动判断每个段落受影响程度。任何目录版本变化都要求重新确认选择，可能保守地增加一次确认；无需因此重做全部研究。读取记录表示窗口已提供，不表示模型全部读懂；系统不以读完字数认证研究。重要条件是否遗漏、原题是否充分覆盖，仍由模型与实际正文验收承担。

支持性附注使用显式 `[!NOTE]` Markdown 标记，报告和版本对照显示可展开、有色说明；普通引用段保持原样。不会根据“不是、不能”等词隐藏内容。写作方法要求把影响方向与行动的条件留在正文。

## 离线案例与复现

虚构题：AI采购能否增长，收益由客户还是供应商获得？脚本化代理沿真实工具执行两个并行分支：供应商竞争先完成，客户采购专题再委派成本调查。根负责人采用两项成果形成总判断；随后反转底层成本观察，检查采购和根判断进入重评、竞争分支保留、旧任务仍回读原版，以及最终成文按新版本读取。

```bash
python scripts/engineering/replay_research_handoffs.py --output /path/to/fresh/private/replay
python -m pytest -q tests/test_research_workpapers.py tests/test_research_handoff_replay.py tests/test_research_result_acceptance.py tests/test_harness_consultations.py tests/test_harness_delegate.py tests/test_harness_business_tools.py tests/test_organization_harness_session.py
node --test tests/harness_accepted_results.test.mjs
```

生成 `replay.html`、实际工具参数及结果、成文窗口、版本状态和SQLite检查点。脚本拒绝覆盖已有回放目录。材料全部虚构，没有联网或模型调用；输入投影是实际工具输出与委派序列化，不是服务商真实请求。工程回放证明存储、身份、恢复检查和交接协议，不证明模型会自主调查充分、选对基准或写出好报告。

补充负例覆盖：未读论证就采用、重复命令变参数、并发覆盖、来源身份碰撞、权限失效、过时快照交付、未读选中论证就绑定、旧记录恢复后遗漏未完成任务。下一步真实验收应观察分支停止理由、跨专题反证是否推动调查、压缩后重要条件是否保留，以及最终正文是否表达更新后的判断；另行登记模型预算与输入规模。

## 草稿落地与明确边界

| 讨论事项 | 本版落点 |
| --- | --- |
| 更广探索；A—B—C—D持续推进；停止取数与完成研究分开 | lead、research_loop 方法与委派/交接入口 |
| 高能力模型专注关系与方向；Flash 承接调查 | 原生专题角色、共享执行器与预算、独立上下文 |
| 多层任务不按波次一次汇合 | 首完成读取、宿主等待、游标更新 |
| 完整成果先保存；摘要不成为唯一记忆 | 版本化SQLite底稿、精确来源回执、事务与幂等 |
| 跨专题采用、前提改变与新旧版本 | 显式依赖、待重评状态、原任务版本绑定 |
| 验收后退出上下文；需要时回读 | 原生 surface 投影、受影响窗口恢复、按需读取 |
| 成文选材与整篇综合 | 冻结目录、完整论证窗口、当前报告绑定、writer 方法 |
| 附注呈现 | 作者显式标注，桌面和移动端验证 |

尚未宣称自动完成：语义保真审计、逐句影响传播、跨独立研究任务的自动记忆复用、优先级推送服务。现有公开来源工具故障仍走原执行恢复流程，本版没有重新验收外部网站可达性。不能把这些后续能力混写成已经落地。
