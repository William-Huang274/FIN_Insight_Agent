## 从失败修复的实际运行行为

之前可选摘要失败会把整个接续直接抛错。这是工程边界缺陷：一个派生摘要没写出来，不应自动等于原始工作记录不可用。本轮修改共享 `RequestSummaryMiddleware`：

- 对已知截断、空/工具式摘要、输入上限和Provider/超时异常，保存 `request_summary_failure`；不接收部分正文/推理，不覆盖已有合法摘要或完整消息。
- 保留原始视图，或上一份合法摘要加所有后续消息。原有实际输入/调用上限继续生效，不扩大预算或偷偷裁掉所需证据。
- 同窗口后续步骤不会自动重试摘要；只有可信宿主明确清除此失败标记后才允许重新评估。当前尚未新增前端重试入口，不能描述为用户已经能点击恢复。
- 模型请求中注明可选摘要失败、原文保留和边界。无法在既有上限内恢复时应请求具体交接；前端自动完成交接尚未实现。未知程序/合同错误仍抛出，不统一吞掉。

使用与a1一致的`length`/空content/1600reasoning响应形态经过实际SDK MockTransport→审计→摘要中间件→原生对话checkpoint本地回放，证明截断未晋升、原始数字保留、第二轮不重试。该回放不是新的真实模型运行。已有摘要后的第二次失败也保留上一合法视图；未知ValueError仍报错。
