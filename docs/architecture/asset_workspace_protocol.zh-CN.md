# 资产工作区与研究交接协议 v1

## 原地资产对话与记忆（058）

项目资产侧栏复用原生单 Agent 对话组件、SSE、审批、停止和 checkpoint，不维护第二套会话引擎。对话链接保存到资产页 URL，项目对话目录从原生 owner 元数据投影；完整对话入口保留详细工具、工作底稿和上下文管理。资料选择变化不会静默改变既有对话，用户沿任务资料更新入口明确选版。

资产对话每次发送由服务端固定 `finsight_asset_revision` 和 `finsight_asset_memory` 到原生 run 配置及元数据；排队后改变偏好不会追改已提交输入，审批恢复沿用原调用快照。worker 复用 `TaskAssetView`，目录、原件工具与财务快照读取同一版；模型及摘要派发前检查原项目权限。个人记忆复用 WorkingMemory 的 owner 隔离、乐观并发及历史版本，用户主动编辑/清空，支持查看最近版本并取为修改草稿；助手不擅自从聊天推断或覆盖个人信息。清空影响后续发送，历史调用和已准备研究保留原快照。

`POST /conversations/{thread}/research-context` 要求已保存 checkpoint 与当前版本一致、无正在运行或待审批操作。服务端保存公开消息和已读来源凭证为同项目不可变文档，明确标注讨论未核验，原资料单独保留；不保存模型私有推理，不将回答升级为事实。相同快照重复保存幂等，来源已撤销则拒绝。快照上限2MiB，最终引用最多12份；超过明确拒绝而不静默截断。按需通过既有资料工具读取，整段讨论不直接塞入初始 prompt。返回既有 `asset_context.v1`，前端用原研究草稿接口交接，不自动开始研究。

工程验收和真实金融质量验收分开：脚本模型验证原生节点、资料回读、个人记忆快照与前端多轮交接；模型金融理解及研究闭环留到非研究侧完成后的真实任务统一验证。当前个人记忆仍由用户确认维护，不宣称自动学习已资格化。

## 已有研究采用明确新版本（057）

用户可以在研究右侧资料栏阅读新版，点击“下次运行采用所选版本”。服务端仅允许更新任务已经绑定的同一项目、同一资产，重新核对AssetRef、原件、权限和选择容量；不扩大任务来源范围，不自动移动研究截止日。旧项目草稿可根据真实副本来源补建绑定；绑定不唯一则要求重新明确选择。未接入此流程的通用对话仍固定原交接版本。

采用边界为**下一次原生运行**，不是某个正在进行的工具调用。准备操作不启动模型。HTTP请求中的request_id与base_revision分别用于幂等和并发检查，同一ID不能换内容；复制失败保留failed记录，未知/准备中请求不自动重试。后端中断后可明确“放弃未完成的准备”，保留abandoned记录和现场，再作新选择；旧进程迟到也不能发布已放弃集合，ready/已采用集合不能用此入口撤销。最多保留64次更新记录；每次当前选择加任务直接上传仍限12份/80MiB。历史副本额外占磁盘，不计作已释放，也不自动清理。SEC映射沿用既有两项USD指标及原始披露，不能因版本接续宣称覆盖更多财务指标。

复用任务附件SQLite中的`task_asset_updates`保存不可变输入集合及preparing/ready/failed状态；每个集合使用独立资料命名空间，SEC原件及派生mart同样独立。`task_asset_runs`只记原生run与输入修订的绑定，不调度运行，也不取代checkpoint。BFF在提交run的config中固定`finsight_asset_revision`，runtime启动时登记；排队期间的后续编辑不会改变已提交运行。同一run不能切换版本。

当前工具目录仅列当前项目选择和原任务直接上传；旧文档仍可通过完整ID回读，继续使用原任务下载地址与权限校验。研究、复核、Lead分诊、收敛修订及交互写作入口得到当前选择和检查要求：比较原依据，检查受影响主张、数字/期间/单位、计算及上下游结论，并在任务说明记录实际处理。旧报告、底稿与引用不会机械改写；来源撤销后，包括可能仍在历史上下文中的旧副本也阻止新模型请求。

前端区分“已保存，待下次运行采用”“已采用资料”“影响尚需复核”，记录实际run与采用时点。输入r编号不是报告版本号，也不是研究通过状态。版本准备及来源绑定已经工程验证；自动识别全部受影响底稿、定向重算、逐项关闭金融影响及最终新版报告质量仍属于研究闭环验收，不由该功能自动宣布完成。

资料集备份覆盖新表、所有已保存副本和ready财务映射，检查采用记录、集合完整性及原来源关系；新目录恢复重新绑定项目库。仍不包含原生运行服务checkpoint及费用/提交回执，不能单靠资料包恢复研究执行。接口为`GET/POST /api/v1/research-sessions/{thread}/asset-updates`，来源身份与`asset_context.v1`保持兼容。

状态：首版骨架实施合同，2026-09-16。资产工作区承担日常阅读、维护与问题准备；通用对话承担轻量问答；研究工作区承担明确任务。复用 HTTP/JSON、FastAPI/Pydantic OpenAPI、原生会话/任务接口、SQLite 事务与备份接口，不新建消息总线或 Agent 间 RPC 框架。

## 身份和数据库归属

- 用户身份由认证层提供，客户端不能传 owner。项目权限仍由 ProjectLibrary.scope 校验。
- `AssetRef` 包含 `project_id / kind / asset_id / version_id / digest`。文档 asset_id 是既有版本组 identity，version_id 是不可变 UPLOAD ID；SEC asset_id 是 CIK，version_id 是快照 UUID，digest 由原始来源 hashes 确定。展示用 v1/v2 不充当引用身份。来源时间、期间和单位仍由源记录拥有。
- 本版正式适配项目文档、保存报告、SEC 快照；公共知识库和财务数据库已在统一资产界面直接展示，复用既有查询接口；所选原文章节和财务记录可保存为项目内的固定来源快照，并沿 document 类型 AssetRef 进入研究或助手任务。未来增加 source adapter 时必须保留稳定版本/查询快照和权限，不允许仅用名称或“latest”作为任务输入。实时行情/新闻尚未接入此协议。
- 项目 SQLite 继续拥有正文/原件、项目与版本关系。新增 `asset_contexts` 保存用户明确提交的问题、精确 AssetRef、个人记忆快照及协议版本；不复制资产正文、不保存模型私有推理。个人偏好复用 WorkingMemory 版本存储，在同一项目库 SQLite 中使用 owner + 个人专属 workspace/actor 隔离，不创建第二套记忆引擎。
- 原生 Agent Server 继续拥有会话、运行、checkpoint。native thread metadata 记录服务端生成的 `asset_context` 快照；实际资料沿既有 task attachments / financial snapshots 复制，并以 preparing/ready 状态控制后续运行。

## 通信与版本规则

`POST /api/v1/asset-workspace/contexts` 接收 `schema_version=asset_context.v1`、一个项目中的 refs、question 和 memory_version。服务端重新检查身份、来源版本、摘要与当前记忆版本，生成不可变 context_id。`GET /contexts/{id}` 按 owner 回读，另投影当前资料是否已有新版本/被撤销。失败不改变源资产。

`POST /research-sessions` 与 `POST /conversations/drafts` 增加可选 `asset_context_id`，消费同一个已保存协议；客户端不能另外提供相互矛盾的 question/project_materials。服务端解析 refs，通过原有副本流程创建草稿，不调用模型。提交凭证沿用已有 Idempotency-Key/SubmissionReceipts，未知请求不自动重发。

初版一次交接限定同一项目，合计最多12个引用，其中最多1个SEC快照；页面可显式选择同一项目中的多份资产；每份选择具体版本，仍受上述总量限制。版本策略为 pinned：新任务使用用户明确选择的版本，后续上传或修改不会静默切换旧任务。启动/读取仍复查来源使用权限。接收方运行上下文得到问题、引用身份和个人记忆快照，用户记忆只表示偏好/假设，不授予权限或事实权威。当前任务明确要求优先于长期偏好。单 Agent 的财务工具优先使用本任务所选快照，避免误查部署默认库；回执和数字来源记录原项目及快照身份。

用户修改个人记忆采用 base_version 乐观并发；冲突返回409，保留输入，不覆盖他人新版本。清空通过既有版本化 tombstone。首版不自动从聊天推断个人信息；已提交任务保留提交时快照，自动增量同步及运行中采用更新的阶段规则后续独立实施。

## 首版可见流程与边界

独立 `/workspace/assets` 默认进入知识库，导航包含知识库、财务数据库和项目资料。知识库复用 DataLibrary 的目录、筛选、分页与原文阅读；财务数据库复用精确十进制数值、单位、期间、披露日期及来源表格。原 `view=library/financial-data` 链接跳转至资产区，`?project=...` 旧链接仍进入项目资料。界面复用研究区的字体、设计变量与主题，不复制数据存储。

研究页右侧“项目资料”面板可浏览同一 ProjectLibrary、选历史版本、刷新当前版本；完整编辑页携带项目、具体版本及 return_thread 返回原研究。保存后刷新仍保留新版本定位，旧研究任务的输入版本不改变。侧栏不代替原件权限校验。

项目资产列表按资产分组，正文居中；版本历史按需展开。小助手面板默认收起，按需打开后保存资产问题和版本化上下文，可准备研究草稿或准备通用对话；明确“准备未调用模型”，模型问答仍使用现有通用对话界面。先验证真实交接，不以伪造回答冒充助手能力。用户可主动维护个人记忆、添加Markdown资产及提交修订。

跨区后可回到原资产工作区和保存的问题；原生任务输出继续走已有报告保存路径。多轮助手对话自动提炼研究交接、所有资产类型统一编辑、实时行情/新闻、主动提醒、运行中自动定向重算尚不在本版骨架范围。

项目持久容量与单次任务输入分开：项目默认最多2000个文档版本、原文件合计2GiB，单文件20MiB；SEC默认最多200次更新（包含失败记录）。部署者可配置`FINSIGHT_PROJECT_MAX_VERSIONS`（1–10000）、`FINSIGHT_PROJECT_MAX_BYTES`（20MiB–1TiB）和`FINSIGHT_PROJECT_MAX_SEC_VERSIONS`（1–10000），所有写入实例须使用同一配置。此为本地工程默认值，不是套餐承诺或已验证负载上限。修订/撤销版本仍占容量，超限不清理历史；SEC原件、解析文本、检索索引另占磁盘，原文件配额不是全目录磁盘上限。降低配额不删除现有记录，只阻止继续超额写入。单次任务仍限制12份文档/80MiB，研究交接refs限制保持。

目录使用同库`attachment_summaries`及thread/access索引，升级时加性回填，插入正文和摘要同事务；浏览不加载历史正文。项目管理API默认每页50条、最多100条，返回total/offset/next_offset，前端每页30条、跨页保留明确选择。资产阅读区仍获取有界元数据目录，列表按30项渐进展开；历史版本按需展开。三字符及以上查找使用SQLite FTS5 trigram缩小候选，再执行原Unicode子串核对和当前使用权限校验；一至两字符保留项目内扫描。旧数据索引首次启动回填，内容不是新事实来源；部署SQLite须提供FTS5/trigram，升级前备份并协调重启写入实例。未增加语义检索服务，暂不承诺多机共享SQLite或无限规模目录。

## 本地持久化与恢复

新增数据落原项目数据库，利用原生事务/唯一约束/有界读取。备份使用 SQLite online backup，复制快照引用的不可变 SEC 原件并记录校验清单。恢复只到新目录，校验完整性后再由部署者切换；不覆盖运行中数据库。恢复验收覆盖项目、文档历史、个人记忆、交接记录及SEC原件。原生任务checkpoint和任务附件的生产级联合备份、跨机切换及存量绝对路径重绑定仍需另做部署资格，不能把项目库恢复称为整个研究系统容灾完成。

```bash
uv run --no-sync python -m sec_agent.research_foundation.asset_backup backup /path/to/project-library /path/to/new-backup
uv run --no-sync python -m sec_agent.research_foundation.asset_backup restore /path/to/new-backup /path/to/new-restored-project-library
```

路径必须由部署者指定；目标必须不存在，备份与恢复均拒绝覆盖。复制/校验失败保留现场，只有带完整清单且校验通过的目录可恢复。恢复不自动改应用配置，也不自动重启服务。

### 项目与任务资料集协调恢复（056）

`asset_set_backup.v1`在项目库和任务附件库同时持有SQLite写入保留锁，再分别使用online backup。期间仍可读取，写请求可能等待或超时；建议在维护窗口执行，锁等待有15秒上限。已提交的原件、批注、历史、个人记忆、资产交接、任务资料副本及ready财务映射一起保留；preparing/failed记录不升级为完成，不自动重试。备份核对原件摘要、项目引用及任务绑定，完成清单最后写入。任务引用其他未提供的项目库时明确拒绝，不生成不完整成功包。

可显式加入已配置的公共知识库JSONL和财务SQLite：前者复制前后核对摘要，后者使用SQLite备份。这两项是各自的保存时点，不声称与外部数据供应商或原生checkpoint同一全局事务。清单明确列出未包括的组件。恢复只创建新目录、先验证清单/数据库/必需原件，再复制和复验，随后把任务的宿主项目库路径绑定到新目录；完成标记`restore-result.json`最后写入。失败现场保留，缺少完成标记的目录不可启用。

```bash
uv run --no-sync python -m sec_agent.research_foundation.asset_set_backup backup /state/project-library /state/attachments /backup/new-set --public-library /state/attachments/public-library/retrieval_nodes.jsonl --financial-mart /data/financial-facts.sqlite
uv run --no-sync python -m sec_agent.research_foundation.asset_set_backup restore /backup/new-set /restore/new-state
```

恢复后的公共库位于`attachments/public-library/retrieval_nodes.jsonl`；财务库位于`library/financial-facts.sqlite`，实际路径写入恢复回执。部署者核对后配置BFF的任务根、项目根及`conversation_fact_mart`，先只读回验，再恢复写入。原有`asset_backup.v1`项目单库命令仍兼容。

**不包括原生threads/runs/checkpoints、提交幂等回执、供应商费用/派发账。** 因此不能单独用本包恢复或自动启动旧研究；这些服务仍须各自备份并完成联合演练。共享项目权限、跨机切换、异地副本、备份调度与保留策略仍是部署工作。当前工程验证包括旧库迁移、并发配额、1000合成版本/5并发读、真实已存70文档/2274财务行及跨目录恢复，不是生产SLA或金融质量验证。

基础设施依据：[SQLite Online Backup](https://www.sqlite.org/backup.html)、[FTS5 trigram](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)。FIN仅维护来源身份、版本语义、配额和恢复后的引用检查。

## 验收

真实BFF/SQLite/浏览器验证：资产分组阅读和修订；个人记忆跨浏览器读取/冲突；精确版本进入通用对话和研究草稿；另一owner拒绝；摘要伪造/未知协议拒绝；撤销后阻止交接；原生创建失败不启动模型；备份恢复到新目录后身份/版本仍一致。runtime消费使用脚本模型/定向测试，不恢复付费研究诊断。

统一资产区补充验收：通过显式本地设置接入已有公开资料和财务库的隔离快照，核对目录数量、分页、原文链接、财务精确值/单位/期间、截至日期空结果；研究侧栏阅读、完整页保存、刷新与返回、旧任务仍固定版本。桌面/窄窗/手机及明暗主题须与研究工作台一致。快照资料真实存在不代表每项金融结论已经审核，也不代表数据实时更新。生产库仍按部署配置连接；不自动导入开发者机器的私有路径。

## 知识库与财务选取进入项目（055）

使用现有项目附件作为不可变交付载体，`AssetRef.kind=document` 与 `asset_context.v1` 保持兼容；新增 `project_source_snapshot.v1` 描述原始来源选择，不另建数据库或消息协议。财务选取在界面归入“数据”，其研究读取方式是任务资料工具，并不冒充已经映射到标准指标 SQL 工具的完整财务库。

- 知识库：选择明确章节，保留原文 document/node 身份、URL、披露日期、期间、原始内容与来源库摘要；读取后来源变更则拒绝旧选择，不静默取最新版。
- 财务库：参数化只读查询与保存共用同一实现；count/rows/facets使用同一SQLite读取事务，保留精确十进制字符串、单位、期间、观测/申报身份、修订关系和来源校验值。浏览页返回查询与页内容摘要；保存时重新查询核对，再固定当前页中明确勾选的行。不是整个筛选结果，也不自动合并重复披露。原始捕获文件的宿主路径不进入公共API。
- `POST /asset-workspace/captures` 接收项目、标题、用户批注和受限选择模型，不接受客户端提供的原文、数字或权威角色。服务端校验项目权限、浏览摘要和所选身份。每次最多100个章节或100条当前页记录、来源负载2MiB，超限明确拒绝、不截断。
- 使用原附件事务原子保存正文/查找文本、紧凑来源manifest及`attachment_captures`中的来源负载和批注；相同项目/标题/正文/父版本的重复保存幂等。大段来源不进入任务目录与交接prompt，沿现有资料工具按需读取。
- `PUT /asset-workspace/captures/note` 使用完整base_ref乐观并发。只允许修改用户批注，生成新附件版本；原始快照摘要保持不变。普通文本修订/上传修订均不能改写固定来源快照。历史批注、旧任务副本及旧引用保持可回读。
- 原文与用户批注在工具正文中明确分区；任务副本的provenance保留原来源manifest。原始记录可读不等于金融判断已验证，上传资料工具不因此获得numeric_fact_authority。
- 两区使用同一项目版本库。项目页与研究侧栏显示固定来源范围、批注和财务表格；“浏览当前来源”返回当前知识库文档/财务筛选，“下载此版本”保留原快照。当前来源后来更新/移除，不覆盖已保存快照。
- 项目库的既有SQLite online backup覆盖新增表，无宿主来源路径依赖；新目录恢复后验证固定内容、批注、版本和交接仍可读。这不替代原生任务checkpoint联合恢复。

当前不包括任意文本拖选、跨页累计财务勾选、自动同步当前源、财务查询快照转完整指标mart、正在运行的任务自动采用新版本。批注可清空；用户仍需明确选择新版本进入后续任务。

## 原任务底稿与连接维护（059）

060接续核对补齐：原地对话交给研究时，同步固定该对话当前工作底稿的正文、身份、版本和摘要，包含最后一次对话后发生的人工修改。旧交接不变，后续修改产生新的交接快照；只读当前owner/workspace，作为未核验研究内容，不能代替原始来源。Lead/专家的结构化模型入口与复核/写作入口同样在下一次调用前刷新用户修订定位，不累积过期目录。

资产区“底稿与连接”复用既有 WorkingNotes 和 ProjectSecSource。项目任务目录分页，并同时核对项目 owner 与原生任务 owner；原生服务不可用时保留任务定位并显示不可读取。新资产对话归属原项目；原任务页仍可进入，正式报告不被工作笔记编辑覆盖。

工作笔记允许运行中以 base_version 保存，正文版本和用户修改记录在同一 SQLite 事务提交；旧版可回读，过期 Agent 写回被拒绝。下一次模型调用前，既有 CaseModelAudit 提供 owner/workspace 范围内的最新修改目录，要求依赖相关判断前 ReadWorkingNote 回读；目录最多20条，其余沿 SearchWorkingNotes(user_edits_only=true, offset=...) 分页。提醒本身包含定位与版本，不重复整稿。已发出的模型调用不追溯改变；用户输入仍是待判断的假设或意见，不升级为外部权威事实。模型是否正确处理修改及其金融影响须由真实研究验收。

## 公司关系的离线提取与检索（110）

原文段落、关系候选、经复核的关系和公司范围完成情况分别保存。研究 Agent 通过 `source_document` 的 `data_kind=relationships` 读取结构化关系，得到双方身份、方向、业务角色、产品、交易状态、期间、带口径的数值及原文回读定位；无须为每次研究重新从长段正文提取同一条关系。关系原文仍通过既有 library read 回读，不替代原始引用。

- `relation_extraction.v1` 候选必须绑定真实 source/passage 和连续原文；复核回执绑定候选摘要，逐条给出 approved/rejected/needs_revision 及原因。修改候选后不能复用旧摘要的通过结论。
- 导入在同一 SQL 事务写入关系、匿名集中度、证据、主体身份与处理记录。数值证据失败时整批回滚；不可变发布库拒绝原地修改。新增关系保持现有来源和旧资料身份兼容。
- 供应商指向采购方，投资人指向被投主体。计划、签约、已完成及历史关系分别保留。基金不替换成管理人，具名子公司不自动替换成控股公司。未知身份仍可查询，解决身份前不生成到另一家公司名下的确定关系边。
- 例如，年报的“前五大终端客户约占40%（全部渠道）”保存为匿名集合集中度；“经销商销售占48%”另存，不能相加。原文另有具名封测企业时，保存具名供应关系；不能用匿名客户披露规则解释漏提取的具名供应商。
- 数值披露按交易对手与期间独立记录。客户收入、采购金额分别保存货币、数值与倍率；收入占比、应收账款占比、采购占比及占销售成本比例使用不同指标。采购额不得默认当作当期成本。实益持股比例与投票权比例分别保存，股份类别、分母及截至日期保留在对应口径中。只披露“年初”“某季度”的事件不补造精确日期。
- 无发布日期的已核实原文以已知获取日期限定可检索时点，保留发布日期为空；图显示“截至某日已获取”。兼容旧边表的日期列仅作为可知时点，`date_basis` 与 `known_as_of` 明示依据。报告中子公司的交易也可从报告主体检索，但报告主体不因此替换成签约方。关系身份哈希不因这些检索属性变化而改变。
- 单条候选复核通过不代表公司范围完成。范围回执另行记录已查资料及章节、剩余来源、获取/解析/身份问题和独立覆盖结论；未复核范围不得升级成“已完成”。声明完成但仍有待处理来源或待解析类别时，导入拒绝该回执。

离线使用 `python -m scripts.data_retrieval.relationship_jobs --library <working.sqlite> --job <job.json>` 检查锚点和合同，加入 `--review <review.json>` 才导入。机械检查保障格式和出处绑定；财务语义、关系是否成立和抽取是否有遗漏仍须阅读原文复核。生成数据、模型运行与复核回执保存在部署者的私有工作目录，不进入 Git。

公司关系页默认展示业务、投资与隶属关系；管理人证券持仓申报和未核实共现线索单独选择。图按六个相邻主体分组，同方向、谓词和状态的记录合并成视觉连线，完整来源记录仍在列表和详情中保留。图的视觉合并不合并持仓数额、不把多个同源记录当成独立佐证。结构化关系查询和覆盖记录同时提供给资产区及研究工具；发布验收必须分别检查 SQL、前端和实际研究服务的版本绑定。

沿关系发现的新增主体标明“仅关系身份”，不把其零条缺口记录解释为资料完整。无发布日期的集中度记录同样按已知获取日查询，发布日期保持空值；按日查询的原文回读与结构化数据使用一致的日期粒度。发布检查除 SQL 完整性外，还应执行完整来源目录读取及带证据回读的正式工具检查，防止单条来源元数据不合规影响全库关联检索。

已审阅并绑定实名主体的供应商、直接客户、间接客户及实益股东事实，由确定性投影进入同一关系图。直接与间接关系使用不同谓词；同一来源多个期间保留逐项事实和期间，不合并比例。匿名集中度不生成实名边。图边保留事实 ID，具体数值仍通过披露查询读取。历史库可重放该投影，原供应关系边身份保持兼容。

新增主体按证据区分公司、基金、自然人、政府及产品或业务标识；自然人和政府等关联主体有独立导航入口，不计入经营公司。约数保留 `approximately` 运算符；不能为通过数值检查而将“约占”改成精确等式。

双向及并行关系使用两侧接口和分离曲线，避免反向边绕过节点或与另一条边重叠。关系详情的原文按钮按已验证的 passage 身份直接打开对应片段；跨来源的错误定位返回错误，不默默退回报告封面。结构化查询返回解析后的规范主体 ID，原候选中的临时 ID 仍保留在不可变提取回执中供审计。

交易所或公司提供的 `annual_report` 与监管申报中的年报具有一致的报告主体检索规则：报告中披露的业务出售或子公司交易可以从该报告主体查到，同时保持真实交易双方身份。关系标签显示“收购”，完成与否由独立的状态字段表达，避免将签约记录显示为“已收购”。

客户收入与供应商采购金额保留原披露币种和独立 `scale`，支持资料范围内的 USD、CNY、HKD、TWD、KRW、JPY、EUR、GBP、SGD、MYR、INR、AUD、CAD、CHF、AED、SAR。例如“10,902,817 百万韩元”记录为 `value=10902817, unit=KRW, scale=1000000`，不隐式换算成美元。百分比及股数仍不得附加金额倍率；金额和占比不能因扩充币种而混用。原有美元记录的字段与身份保持兼容。
## 项目工作区与全局资料目录

`/workspace/projects` 以项目归属组织研究、资料、成果和管理；`/workspace/assets?view=files` 是跨项目资料入口。全局资料库按项目、名称、类型筛选，并在进入原阅读/编辑器及返回时保留筛选和分页。项目 UUID 留在 URL 和合同中，日常界面显示名称与说明。

`GET /api/v1/asset-workspace/catalog` 接受可选 `project_id`、`query`（名称子串，最多 200 字符）、`role`（document/report/database）、`offset` 和 `limit`（1—100，默认 30）。响应提供当前版本族投影、原项目名称/归档状态、完整 AssetRef、版本数、`next_offset` 和项目索引 revision。查询限定当前 owner，并在每个项目复用原授权；响应 `no-store`。阅读、修订与交接仍重新校验原项目和精确版本，目录可见不等于资料可继续使用。

实现按项目 ID 稳定遍历既有 metadata 目录，找到一页加一条匹配后停止，不读取原文、不合并同名或同摘要资产。每个已访问项目仍加载其现有版本目录；offset 跨页不提供多项目事务快照，期间增删资料可能改变页边界。本批不宣称大规模目录性能验收，后续应按实际规模再扩展索引查询与游标合同。

当前资产必须归属一个项目。跨项目共享引用和全局未归类收件箱仍需独立数据/授权合同；本轮不伪造这两项能力。归档保留资料和原研究，不改变 ACL 或停止运行。

### 空间与资源权限的目标合同（部分实现）

统一资料入口需要空间、资源类型、项目关联三个正交维度。组织/租户、空间和项目不能共用一个ID或以项目代替租户隔离。目标上资源归个人/团队空间，项目引用获授权的资源及版本；文件、知识库集合、数据库数据集分别保留自己的能力和版本协议。当前 owner+project 存储不能通过增加前端筛选直接视为已支持这一模型。

接入 Java 时，空间成员、业务角色、资源授权与项目引用由一处业务权限权威管理；Python 保留文件处理、索引、检索、受控指标查询和执行。未来从当前 Python 项目授权切换至 Java 权威时须显式迁移并验收，不能长期维护两份可独立修改的 ACL。既有个人数据默认保留原隔离；旧 AssetRef/wire ID 通过兼容映射继续定位，不能静默扩大其可见范围。

Python 工具入口须根据可信身份上下文核验当前用户/空间/项目、资源和操作权限，不能接受模型自报身份或以宽权限后台服务账号代替授权。搜索和向量候选范围在返回内容前受权限约束；正文、财务查询、下载、导出和新运行同样校验。缓存须包含授权范围及其失效信息，不能只按问题或项目缓存。共享运行以明确执行主体和资源授权范围启动；不能只因创建者本人能读私有资料，就向项目全员输出其内容。

数据库授权对象优先为受控数据集和查询能力，必要时进一步限定行列范围；连接凭证只由后端保管，查询、导出、管理连接分权。知识库授权覆盖集合、文档和检索范围；“可检索”不自动等于允许对团队发布原文或衍生报告。撤销权限不重写历史证据身份，后续读取/运行重新核验，已生成成果的访问与发布须单独制定传播规则。

先验证成员A可用公开财务数据、成员B额外可用团队内部经营数据，且两人的Agent、搜索和导出均遵循相同差异，再推进成员交接和审批。用户已选择组织内个人工作区：组织拥有资产，个人区默认仅本人可读；组织身份、空间归属、上传者和当前授权主体须分开记录，离职后的组织接管不能依赖保留离职者登录凭据。管理角色的接管/移交/读取须显式授权并审计。

首条实现见[组织资料空间](../engineering/resource_spaces.zh-CN.md)：Java 维护组织/空间及发布资源权限，Python 在独立组织库保管明确发布的固定副本，每次阅读先核权。普通项目 AssetRef 仍按原 owner/project 权限读取。副本保存原 AssetRef 与来源负载；原文修改或撤销不自动覆盖、撤回明确发布的组织版本，须单独撤销发布。此语义仅适用于明确发布，原任务资料的授权复查规则不变。当前没有项目共享、Agent 交接、实时数据库 ACL 或个人区接管；不能将上述目标合同全部标记为已实现。

# 研究工具的公司菜单分页

`source_space=library, operation=company` 默认返回主体身份、可用数据入口及一页来源。财务科目、期间、关系目录、处理记录和缺口按 `company_section` 分开读取；返回的 `section_navigation` 提供各部分总数和可直接使用的请求。`offset/limit/next_offset` 针对所选部分，未返回的部分不是空数据或没有披露。前端公司详情仍使用完整展示接口。
