## 原始表格跨度与事实期间补充信息

2026-10-27 新增 `source-table-periods.v1`。旧采集的行文本只保存单元格原顺序，
丢失了 rowspan/colspan 和 inline XBRL 的 contextRef。日期行和金额行的单元格数
可能不同，不能按非空列序号配对，也不能用文件年份补事实期间。

`scripts/engineering/prepare_source_table_periods.py` 读取显式指定的旧 intake、
只读归档数据库及来源 ID 清单，按来源串行重放 HTML。只有原始字节摘要正确、
旧解析全文逐字重现、表格及单元格坐标一致，才生成补充目录。保留 DOM 行列位置、
跨度、显示文本和原始 concept/contextRef/unitRef/scale/decimals；期间来自明确
context 的 instant 或 startDate/endDate，连同 entity 和维度保存。没有把财年
转换成自然年，没有把单元格显示值直接转成权威数值。

嵌套表暂不绑定。跨度冲突保留错误状态和未知列号；单元格原始顺序与独立明确的
contextRef 仍可保存，不能把视觉布局不确定误报成所有期间都不可用。没有 context
的数字不猜期间。表头文字、正文日期的语义配对及未标记数值仍待后续处理。

新资料捕获可显式配置 `FINSIGHT_LIBRARY_TABLE_PERIOD_CATALOG` 及
`FINSIGHT_LIBRARY_TABLE_PERIOD_CATALOG_SHA256`。目录固定库摘要，每项固定
来源摘要及补充文件摘要；文件路径必须在目录内。未配置或来源不在目录中时沿用
现有行为。它只进入新捕获与随后发布的版本，不改写旧资产、冻结索引或模型输入。
新发布仍须经过正常索引准备／冻结流程，不能替换旧准备单的来源版本。

全量离线生产器在建立 HTML DOM 前先核验归档字节摘要。若原件没有 HTML
`table` 标签，明确记录 `source_original_has_no_html_tables`，不把整份 13F
XML 当 HTML 建树；含空字节的未知编码仍交原解析器判断。每份来源后回收
解析树循环引用。这里只跳过不适用的可选表格补充，不删除来源、不缩小检索
范围，也不将 XML 持仓的结构化查询能力计作 HTML 期间绑定已经通过。

含表格补充的新保存快照使用 `library-source-offset-bundle.v2`，仅把补充信息
作有界、带摘要的 zlib 压缩；原文、来源、分段身份和偏移不变。展开结果必须
逐字段等于压缩前的完整 bundle。无补充的旧快照继续使用 v1，原有 v1/v2
项目快照仍可读取。旧版 bundle 读取器不支持新的存储格式，因此必须先部署
兼容读取器再写入新快照，本轮没有转换已有部署或旧资产。

目录，保留 v1 输入文件。目录自身、压缩载荷、解压字节摘要和声明长度均校验；

## 金融证据需求、词法候选与精度评分

2026-10-27 在公司兼容修复之后，新增显式 `conservative.v4` 查询策略，沿用 v3
主体识别，接入 `organization-financial-needs.v2`。v1/v2/v3 的查询行为不改写。

- 查询中识别现金等价物、受限现金、股权承诺、投资容量、回购授权、融资、资本支出
  和经营现金流等不同证据需求。查询变体包含已定义的中英文及词形表达，不做金额、
  公司或答案 ID 硬编码；这些表达用于找候选，不表示金融概念之间等价。
- 回购授权到期使用 expire/expiration，债务到期使用 maturity；语义未知时保留
  原问题路线。非金融识别范围的问题仍走原有查询需求实现，不能因识别器不支持
  某个概念就删除它或缩小原授权范围。
- 多公司问题只有在每个明确主体后都能找到对应概念时，才按主体位置分配各自需求；
  共享问题保留共享需求。需要同时命中“股权＋承诺”等组成词的片段优先，其后保留
  部分匹配。读取已发布词频，不修改原文／向量／词法索引，不声称句法或语义蕴含证明。
- 每个需求有概念路线和原问题路线，前者占两次、后者一次候选机会，随后跨需求公平
  合并、去重。原问题路线保留日期和未识别条件。默认最多 48 个总候选保持不变：
  启用新金融需求时为 24 向量＋24 词法；未识别时保留 36＋12。显式图查询对应
  12 向量＋24 词法＋12 图，或旧的 24＋12＋12。诊断脚本、服务和配额校验使用
  同一个分配函数，策略及词法路线均参与排名缓存身份。
- 最终需求选择只在正文满足组成词、主体一致的候选中保留评分器的次序，避免再按
  原始词法次序把旧期间内容提到前面。候选状态仍是“需要原文回读核验”，不把词语
  同现当成答案，也不从文件年份推断每个事实的期间。完整事实级期间／表格列识别
  尚未实现；未经验证的期间不能宣称已正确。

## 数据、排序和缓存

1. Java 返回固定 manifest，Python 校验身份和摘要，并按现有原件存储校验每个 AssetRef。文档身份绑定资源和版本；索引准备使用当前组织导航的相同文本投影和节点 ID。
2. 服务器按规范组织 UUID 选择独立索引目录。发布记录模型、维度、节点/文档身份、正文摘要、向量矩阵摘要与来源说明；重复发布不覆盖旧目录，换版使用新 release root。准备工具不生成任何向量、不调用提供方。
3. 请求中的文档/节点过滤和固定输入集合共同确定可用节点。核对节点正文摘要及发布身份后，**先选取获准矩阵行，再计算余弦相似度与 top-K**。同索引内未选资料不能占用候选名额。
4. 复用现有 BM25，合并最多 24 个向量候选和 12 个词法候选，采用本地 RRF（常数 60）排序。没有远程 rerank；显式图发布与实体搜索额外提供上文的最多 12 个单跳图候选。可以搜索全部明确冻结且当前获准的候选资料，不等于无条件搜索整个宿主库。返回候选诊断只含本次获准 ID。
5. SQLite 排名缓存只保存三组 ID（向量、词法、最终顺序）。键包含当前完整授权响应摘要、执行/项目/固定输入、索引内容摘要、查询摘要、节点版本及排序策略版本。不同组织分目录，不同执行和查询范围分键。
6. 缓存命中仍须重新核权、检查原件数据库代次、发布身份和候选集合。当前查询可复用已验证的投影/响应；同一导航对象内发布完整校验按上文生命周期复用。缓存中的越界 ID 被拒绝，不做过滤后继续返回。引用读取仍逐次核权并检查原文身份；检索预览不能作为已读引用。

v2 索引 release 通过 BFF 校验原件投影和当前权限后在 Java 登记，准备单可选择 `retrieval_release_id`，固定模型、维度及索引/矩阵摘要；发布新版本不改写旧准备单。旧 v1 仍使用宿主显式配置，不能获得 v2 的发布版本保证。每次结果记录索引摘要，换 release 不复用旧排名缓存。索引目录需允许创建本地 ID 缓存；原件与源公共索引不被改写。

排序、缓存写入及最终输出前再次核权。扫描期间撤权导致整次工具失败；已返回的数据不能被撤回，也不声称消除了最后一次检查与响应之间的时间窗口。索引文件和缓存是宿主受控存储，不是模型可编辑的输入；本片不提供磁盘加密、恶意宿主防护或跨机器发布服务。

## 历史案例复现

`scripts/data_retrieval/prepare_organization_hybrid_cases.py` 从同一发布库的实际 `context + newline + body` 提取文本副本，并复用该索引的向量矩阵和成功查询回执。核验原库 SHA256、矩阵/映射摘要、候选正文摘要；源库、索引、提供方缓存只读。每题保留两个真实片段，挑选较弱匹配作为组织 A 的固定输入，较强匹配存在物理索引但未授权给本次执行。组织 B 固定另一个片段。

```bash
python -m scripts.data_retrieval.prepare_organization_hybrid_cases \
  --library <published-library.sqlite> --index <prepared-vector-directory> \
  --replay <historical-replay-result.json> --cases <historical-queries.json> \
  --output <new-case-directory>

python -m pytest -q tests/test_organization_hybrid_retrieval.py
# 按真实业务验收文档配置独立 Docker 子网、端口、jar、输出目录。
# FIN_ORGANIZATION_HYBRID_CASES=<new-case-directory>/cases.json
python -m pytest -q tests/integration/test_organization_hybrid_stack.py
```

真实服务案例覆盖 BFF、Spring Boot、PostgreSQL、组织发布原件、真实历史向量和本地缓存。两个组织使用独立发布身份；同查询不同结果，交叉读取拒绝，A 撤权后缓存及旧引用拒绝而 B 仍可用，首题另验自有 Java 重启恢复。原生 Agent 不启动，身份是验收替身。另用合成小向量验证缺失索引、缺失查询、错误组织、内容/矩阵损坏、缓存注入和执行中撤权，并在实际专家 MCP 组合消费该通道。

结果、失败尝试及机器路径保存在仓库外。知识质量、广泛召回率、实时任意查询和生产吞吐不由这些权限案例推断。

### 向量校验与排序的临时内存

固定发布的向量完整性仍按整个文件摘要核验；注册时的单位向量校验，以及查询时的授权候选校验／余弦计算，按最多 4,096 行分块处理。不会抽样、缩小候选范围或缓存正向权限。查询仅保存一维分数，避免同时构造全候选 float32 副本及整个 float64 校验数组。缓存命中仍校验全部已选向量；未命中时，参与点积的每个块再次校验有限性与单位长度。排序的前 24 向量候选、前 12 词法候选和 RRF 规则保持不变。

跨块测试覆盖打乱候选顺序、未授权行含坏值、末块零向量／NaN／无穷／非单位向量，并与原 NumPy 点积比较数值及前 24 排序。`scripts/engineering/qualify_organization_vector_blocks.py` 可用已核验输入包和固定成功查询向量逐源离线重放；输入摘要变化或排序不一致会失败并保留此前完成的来源。该脚本不是组织服务、全库排名、召回或并发验收，运行时间不能作为线上查询延迟。

## 2026-10-20 验收结果

四个历史题（OpenAI/Microsoft、Talen/Amazon、NVIDIA、SK hynix）共提取 8 个实际 1024 维文本向量和 4 个成功查询向量。每题创建两个独立组织，各自发布两份副本、只选一份；全部通过候选、摘要、原文、缓存、交叉读取与单边撤权检查。较高相似度的未选资料被排除在组织 A 的候选之外。实际分数和原文摘要保留在证据文件中。

相关组织/导航/MCP 回归 66 项通过；最终向量边界和共享读取协议回归 55 项通过，2 项既有外网探针因未授权而跳过。两组有重叠，不相加；新增权限用例没有跳过。基线、密钥扫描及 diff 检查通过。

## 非 XBRL 事实期间匹配（可选 conservative.v5）

在 v4 的公司范围、需求分解与候选预算上，v5 增加 `explicit-fact-periods.v1`。它只调整已经授权、已召回且满足该需求词项的候选顺序；优先选择有明确目标期间关联的片段，保留其他候选及其相对顺序。没有正向期间匹配时，单需求查询保留原排序。v1–v4 行为及现有默认配置不变，不根据文件年度补事实日期，也不把日期未知候选删除。

- 正文关联保留原句和字符坐标，区分余额时点、授权发生日、到期日及显式财年。表格是句子边界，不能跨表借用日期。多日期、简写的同期对比（如“December 31, 2025 and 2024”）、预测及未解析财季不生成单一余额日期。支持的是有限明确语法，不是通用财务事实抽取。
- 普通 HTML 表格复用经过原始 HTML 全文回放验证的行列跨度；显式矩形 Markdown 表也可定位。日期可以来自同一列路径的完整日期，或上层月日与下层年份。冲突表头、缺列跨度、仅有年份、日期区间、年度累计流量均不猜测。当前日期优先匹配只用于现金及现金等价物、受限现金、回购授权余额；完整流量区间仍需额外解析。
- XBRL 的显式 instant 可以提供同类余额关联；带维度的成员值不直接视作公司总额，duration 不转换为财年。期间匹配仅表示候选相关性，不证明金额、单位、归属和金融结论正确。
- 结构信息随来源核验缓存，缓存实现摘要包含期间解析和金融概念模块；原始正文、chunk ID、向量输入均不改写。部分字符窗回读清空期间与表格单元格补充信息，当前授权与撤权检查保持执行。普通 HTML 的新关联仍依赖受控原件 overlay；旧发布不会自动原地升级。

`retrieval_fact_requirements.py` 新增兼容的 `reviewed-fact-requirements.v2`：分离披露期间与事实期间，事实期区分 instant/event/duration/fiscal_year/unknown，明确期间必须附原文引用；继续保留来源版本、单位、精度和 OR/AND 证据规则。引用校验不能替代人工确认列归属。unknown 带原因，事实覆盖评分另外报告期间解析比例，不能把引用齐全等同于期间全部确认。v1 历史标签保持可读，旧指标不回写。

本阶段使用旧 80 问的既有成功重排结果进行选择层回放，属于已暴露回归。17 份原件的期间关联不是 1742 份资料的全量期间覆盖，也不是新独立召回评测。新的来源清单应先排除开发题及旧评测引用过的来源版本，再人工审核问题、事实、期间与单位，冻结索引、标签和策略后运行；不得把该清单或确定性测试当作独立准确率。

### 统一事实标注与独立评测边界

`scripts/engineering/retrieval_fact_annotation.py` 的 `retrieval-fact-annotation.v1` 将问题摘要、来源片段、证据要求与事实审核放进同一封装。旧标注保留 `clause_reviewed`，只有完成明确事实审核的条目才使用 `typed_fact_reviewed`；格式迁移不代表历史题全部经过逐值复核，也不回写历史指标。

事实审核记录报告主体与金额归属、来源版本、原始显示值、单位、事实期间、支持引文及错误前提的纠正理由。校验器检查引用身份、显示值与日期原文、单位数量级；分层表头允许保存多个原文日期组件。表头与数值的列归属仍须依据原件审核，校验通过不等于自动证明金融含义正确。文件披露日、余额时点、授权发生日及到期日不能互相代替。

新来源评测须在第一次检索前冻结问题、标签、候选策略、模型、索引及实现摘要。正向问题与错误前提问题分别报告完整证据覆盖；后者检验能否检索到纠正证据，不是空结果、拒答或 Agent 答案准确率。双语与负例变体按来源家族报告相关性，不能当作相同数量的独立样本。已暴露失败可用于根因修复和回归，但修复后重跑同一题集应标为暴露回归。

评测沿相同规则为所有实际候选核验原始结构，不仅给标签来源补充表格信息。原文回放、组织适配器回读、离线排序、当前 Java 授权和真实服务并发分别验收。付费失败保留请求回执及未知用量，停止自动重试；账户恢复后建立新的显式尝试，保留原冻结文件与失败记录。

审核区间与存储块不是同一概念。`retrieval_evidence_spans.cover_reviewed_span` 按原文坐标选择完整覆盖已审核区间的最小片段集合，不把每个相交窗口都变成额外 AND 条件；跨块的单位、表头与金额仍须覆盖，正文摘要错误或覆盖有缺口时失败。它不读取检索排名，不改写原审核区间。冻结后发现此类标注错误，应保留原始成绩并另外报告标注修正后的回归，不能把更正后的数字重新称为独立保留集成绩。

v5 的查询规划进一步区分明确报告期与财务事实日期：`10-Q for November 27, 2025` 或“截至某日的季度报告”可以约束已知报告期；`filed on`、裸财年、报告名称前的日期不据此推断期末。中英混写不再因中文紧贴公司名或 `10-Q` 而漏识别英文 token；“对比某个明确日期”不当作第二家公司。带日期的明确报告归属可用于选公司，但不代表该日期必然是报告期。未知元数据仍保留，v1–v4 的行为不改写。

v5 对同一 SEC 原件的不同解析记录提供有限身份兼容。`filing_document_identity.py` 从已核验来源的完整 SEC 原件 URL 提取文件身份，只在当前目录中对同一文件、已有明确公司 ID 的记录建立查询别名。不同 accession、不同附件、带参数或非 SEC URL 不关联；缺公司 ID 的记录不借此提升为公司专属候选。此规则不合并公司或来源数据库身份、不授予资料权限、不推断缺失期间，也不保证两次解析的内容完整性相同。显式公司过滤仍精确匹配，原文回读继续使用各自版本与摘要；来源核验缓存的实现摘要包含该模块。

冻结后的标签修正须区分三个层次：重叠窗口的最小覆盖、原审核范围误包含邻接章节、负例错误继承正向问题的额外要求。后两类需要重新审查问题与原文，不能由排序结果自动删减要求。旧标签、原始成绩和修订理由均保留；先用固定最终标签重评旧排名，再比较新排名，避免将标注变化算成检索算法收益。

原文定位也必须审核。`scripts/engineering/retrieval_review_locators.py` 拒绝有多个匹配的起止锚点；对于多张报表共用的单位表头，先提供唯一章节边界或完整表头，再定位目标行。不得用裸 `text.index` 默取全文第一个同名表头。表格闭合模式要求明确的表格起点，不接受嵌套或缺失闭合标记；定位保留原始字符坐标。这一检查不理解金融语义，仍需逐项审核期间、列归属和问题是否要求该段内容。

`scripts/engineering/summarize_reviewed_span_evaluation.py` 汇总单批冻结的原文区间覆盖：核对题集与计划摘要，拒绝重复或额外题目，缺失执行保留在原分母；正向问题和错误前提纠正题分别按家族汇总。发现标注缺陷时用 `label_review_errors` 明确记录，数值即使达到阈值也不能判定该批通过。它始终不签发 S2 通过：完整测试集覆盖、无答案题、当前授权、真实服务和固定资源并发仍须各自验收。

内存不足而分进程续跑时，保留失败尝试，只执行未完成问题；汇总前逐项核对完整冻结题集、索引、原件、排序实现和候选结构策略的摘要，确认每题恰好执行一次。执行驱动的进程组织变化与排序代码变化分别记录，禁止混合不同排序版本的成绩。此类离线逐题执行的耗时包含进程启动、审计和原件解析，不能作为在线查询 P95 或并发容量。

债务到期的词法导航包含 `maturity/maturities/mature/matures/matured`，中文“可转债／可转换债券”也可触发该需求。首条概念路线要求正文同时包含债务工具词和到期词，避免仅凭 `mature` 将普通应收款或产品生命周期当成债券证据；回购授权到期仍走独立路线。这只是查询词形和导航概念的兼容，不修改原件、数值、报告期或权限，也不解决跨块证据补全。一个问法重新获得候选并通过真实重排，不代表同组其他问法或独立保留集已经通过。

### 同一原件的分散证据（实验策略）

真实服务回放可在完整组织来源验收中显式提供
`FIN_COMPLETE_SOURCE_QUALITY_REPLAY`（已完成的冻结批次目录）及
`FIN_COMPLETE_SOURCE_QUALITY_DATASET_SHA256`。入口先核对题集摘要、原文区间、
来源版本、完整来源数量及离线批次门槛，再使用实际组织导航器、Java 当前授权和
服务器配置的 Qwen 模型执行。标签只用于评分，不进入查询规划、候选选择或模型输入。
每道题均回读前十原件并核对版本及正文摘要；两类问题沿用冻结门槛，执行失败保留记录。
每类付费请求最多为题数，网络放行仅存在于已计数的 embedding/rerank 调用期间，
失败后不再提交。默认验收仍只允许本机网络且不调用模型。
回放后还需证明非显式选中资料撤权会阻止已缓存查询。
这一入口的确定性测试不等于真实服务已通过；串行回放耗时也不是并发容量指标。

资源受限的串行验收可另外显式设置 `FIN_COMPLETE_SOURCE_COMPACT_PROFILE=1`，
必须同时启用串行配置。该配置仅作用于本次隔离服务：Java 最大堆 128 MiB、
BFF 单进程及最多 4 个并行连接、PostgreSQL 容器上限 192 MiB；数据库仍开启
`fsync`、`synchronous_commit` 和 `full_page_writes`。配置进入验收基线，
不改变默认部署，也不能据此报告生产并发能力。

该模式把准备阶段的完整组织检索块顺序写入本次专用 SQLite 暂存文件，
压缩保存全部字段及逐行摘要，避免将全部正文同时保留在 Python 列表中。
最终当前权限检查成功后才允许读取暂存内容；中途失败或撤权不产生可读输入。
发布仍校验原文和向量输入摘要，按同样顺序构建向量、词法及导航索引。
暂存与内存输入的索引产物一致性由测试验证；暂存文件保留供诊断，
不能将它当作长期授权凭据或自动恢复入口。该措施减少准备时的驻留副本，
并不证明后续加载和检索阶段的总内存已达标，真实服务仍需独立测量。

服务器可显式选择 `FINSIGHT_ORGANIZATION_CANDIDATE_POLICY=needs_window.v4`。
它在 `needs_balanced.v1` 的候选基础上，保留融合前 36 个候选，为语义前 6 个种子的
原件相邻块保留最多 12 个位置，总数仍不超过 48。相邻关系来自已核验的同版本原文坐标：
只允许重叠或完全连续，不跨缺失区间、文档、版本或当前检索范围。
授权范围外的邻块既不加载，也不出现在诊断回执中。没有已核验导航的入口拒绝启用。

相邻块参加同一次重排。返回选择保留重排及需求覆盖后的前 8 个候选，最多提升 2 个
补充块；只考虑这 8 个候选中种子的最佳排名邻块。若最佳邻块已经在前 8 中，
不再用更弱的邻块占位。因此原有前 8 个候选必然保留在前 10 中。
各块 ID、正文摘要、原始模型分数保持独立，`source_window_selection` 回执记录保护范围、
提升上限和实际提升项，模型排名与最终选择顺序分别保留。
这仍可能挤占原本第 9、10 名的位置，必须回归其他题，不能只看拆分证据题变好。
历史实验 `needs_window.v2` 为回放兼容保留：它逐种子插入全部邻块，已观察到将原本
第 6、7 名必要证据挤到第 10、12 名的退步，不作为新的质量验收候选。
它不表示相邻段必然回答问题，也不能取代按原件回读和事实核验。

`needs_window.v4` 在同样的前 8 个保护范围与最多 2 个补充位置中，先检查已核验的
表格与后置脚注关系：文档版本、表格原文区间及摘要必须相同，脚注必须有原文标号关联，
而且已经在当前获授权的候选池内。只补充尚未覆盖的原文区间，不额外取回候选。
同一脚注可能横跨多个重叠块；仅有元数据声明或脚注的开头，不能算作已覆盖整条脚注。
明确的表格依赖优先占用这两个位置，其余位置沿用 v3 的相邻块选择。回执分别记录依据。
该关系证明来源关联，不证明脚注回答当前问题；仍须独立质量验证。v3 与 v2 保留用于历史回放。

配合 `organization_metadata_policy=sec_cover.v2` 时，所有候选统一向重排传入已有的
核验文档报告期与表单类型。明确注明报告期不等于片段内每个数字的事实期间；
未知字段保持缺失。原来的向量输入不变，重排缓存则按实际新输入重新计算身份。
默认策略、旧发布和旧无上下文缓存语义保持兼容。本策略的回归、独立质量评测、
真实服务授权与固定资源并发分别验收，不能以离线成绩宣称产品部署已经切换。

事实标注的期间类型区分 `fiscal_year`、`year_to_date`、`fiscal_quarter` 与时点 `instant`。
年度收入或九个月累计收入不应为了适配日期校验而标为期末余额。持续期间保留原文期间引述与
审核解释，不凭财报发布日期推导起止日期；这些类型只服务于标注校验，不自动授予事实匹配。
