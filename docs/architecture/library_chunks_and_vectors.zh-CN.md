# 原文子块、图关系证据与向量检索

这一合同适用于包含 `retrieval_chunks` 的正式知识库版本。旧版本继续使用原有段落读取和文档导航卡检索；不能把旧文档卡向量覆盖率当作正文向量覆盖率。

后续查询与图上下文优化见[待审阅方案](retrieval_optimization_review.zh-CN.md)。该方案尚未实施，下面描述的已发布行为保持有效。

## 原文与最小检索单元

原始 `sources`、`passages`、图边、结构化事实及覆盖记录保持不变。新的子块表保存来源 ID、父节点 ID、字符起止范围、正文摘要、顺序、章节/表格定位上下文及处理标记。字符范围采用 Python Unicode 字符索引，作用于未经改写的父正文。

切分先识别已有 Markdown、PART/ITEM 和中文章节标题，再使用 LangChain 递归切分器沿段落、行、句子和空格分割；正文上限 4,200 字符，重叠目标 240 字符。原节点的标题/定位保留为上下文。对可识别的 Markdown 表格，在后续行组的上下文重复真实表头，并提示回看原表附注。上下文与正文分字段存储，不能把重复标题当成新增事实。

这不等于重新解析全部原 PDF。上游已经扁平化或缺失的表头不能靠切分恢复；可能切断的超长行明确标记。序列化 API/目录内容使用 `structured_text` 及 `raw_serialized_data_not_article`，不会升级为已取得的新闻正文。完整父原文仍可追溯。

`search` 返回子块定位；`read` 支持子块、邻块续读和旧父节点。旧父节点超过读取预算时返回可读取的子块入口。前端原文接口默认按子块分页，直接打开旧段落引用仍保留原文。预览不是完整证据，提取前应按返回 ID 读取上下文、单位与附注。

前端关系依据优先使用返回的子块回读 ID，保留旧父节点引用兼容。阅读器逐片渲染正文，并单独显示章节与表头上下文；不再按固定字符数裁剪、拼接不同原始段落。显式指定文档的搜索也将附带图关系限制在该文档内，不以其他文件的关系填充范围内的空结果。

## 图关系与原文的联系

`edge_chunk_links` 将已有图边绑定到子块，`edge_chunk_coverage` 记录绑定状态；二者不修改关系的事实状态。

| 状态 | 含义及使用方式 |
| --- | --- |
| `quote_bound` | 已有引文通过原字符范围、精确文本或仅空白差异匹配定位；跨块引文保留重叠子块。仍须核对关系方向、时期与条件。 |
| `parent_locator_bound` | 只有原段落位置可用，关联该段落的子块；它是较宽的定位，不能称为逐句引文验证。 |
| `partial` / `unresolved` | 部分依据未定位或完全未定位；记录具体原因，不能隐藏为零关系。 |

旧的文档级位置只能通过有来源的复核包补定位。`supplement_chunk_bindings` 在新副本中验证来源一致、引文唯一和子块存在，保留复核记录。实体未能确认的候选和 `needs_semantic_review` 共现线索不升级为已确认关系。

关系工具同时返回父证据、子块证据、绑定状态和回读参数。13F 等由结构化持仓记录生成的动态关系继续以原记录/文档回读路径提供依据，不把静态图边的绑定数量冒充全部持仓记录覆盖率。

## 持久向量与查询

正文 embedding 输入为完整的定位上下文与子块正文，支持 Qwen `text-embedding-v4` 与 `qwen3.7-text-embedding` 标准版，均采用 1,024 维。构建时显式选择模型，正式查询从已发布索引 manifest 读取同一模型；注入的查询客户端若模型不同则报错。相同模型、维度和完整文本使用同一缓存键；不能仅凭标题或文件名复用。即使维度相同，两个模型的向量也不能混合使用。

- SQLite 保存向量缓存、请求身份、状态及服务方实际用量。未确认用量的失败记录保留，默认拒绝重发。
- 完整向量矩阵以 float32 NumPy 文件持久化，子块映射与版本 manifest 同时保存。当前采用精确余弦搜索，不是 ANN 索引，也不依赖一次性内存向量库。
- 查询前核对来源库 SHA、索引模型/维度、矩阵和映射摘要。缺失或版本不一致是执行错误，不静默报成“没有资料”，也不在查询期间触发整库 embedding。
- 来源可知日期和指定文档范围先限制候选。混合检索合并最多 12 个 BM25、24 个稠密及 12 个图关系证据子块，再调用 Qwen rerank；不会只给 reranker 原章节的前 6,000 字符。图候选在已有证据关联中先排序再截取，并报告图窗口是否截断。
- 查询和 rerank 也保留缓存及调用记录。检索结果是候选证据，不能直接赋予财务事实权威。

此实现提供基础的图辅助检索。没有生成 GraphRAG 社区报告，也不声称完成跨社区全局回答或研究模型正确率验收。

## 构建与恢复

以下均为工程侧显式命令，研究读取工具不会自动写入或发布：

```bash
python -m scripts.data_retrieval.build_library_chunks --help
python -m scripts.data_retrieval.supplement_chunk_bindings --help
python -m scripts.data_retrieval.audit_library_chunks --original <old-library.sqlite> --candidate <new-library.sqlite> --output <audit.json>
python -m scripts.data_retrieval.index_library_chunks --library <new-library.sqlite> --cache <offline-index-directory> --audit <audit-directory>
```

最后一条默认只生成实际规模和 TokenBudgetBasis。明确授权后加 `--execute` 才调用服务。成功批次逐批保存；失败批次隔离且不自动重试。收到 429 限流或账户错误即停止新派发；其他错误连续 3 次或累计 10 次时停止，并收齐在途请求。`--skip-blocked` 只处理尚未提交的文本，保留失败/未知文本的缺口，不发布不完整索引。只有取得针对具体请求的补发授权后才使用 `--retry-request-id`，旧请求仍保留，授权不会变成无限重试。

构建器同时控制请求间隔和滚动一分钟的 Token 估计量，默认预留上限为 600,000，并按批次估计用量平滑派发。初始估计采用 UTF-8 字节数的一半，服务返回的实际用量若更高则提高估计系数；该估计仅用于调度，不作为计费记录。实际用量按回执保存。服务配额由同账户调用共享，因此本地限速不能保证完全避免限流；失败请求仍遵循逐项授权补发规则。

模型迁移使用 `--model qwen3.7-text-embedding` 和独立的 `--cache` 目录。v4 每批最多 10 条，3.7 每批最多 20 条；请求回执的模型标识必须与请求一致。既有命令默认仍为 v4，以免旧配置静默换模型。旧向量与请求账本保留，不能只修改旧 manifest 的模型名。先固定有原文答案的对照集及迁移通过条件，再执行付费比较；小范围比较通过只说明迁移门槛满足，不代表全库召回率或研究答案正确率已验收。

长任务可设置 `--stop-file <pause-file>`。需要暂停时创建该文件，构建器停止派发新请求，收齐并保存所有在途结果后退出，且不发布不完整索引。恢复前移走暂停文件并复用成功缓存；失败请求仍需单独处理。强制终止的在途请求只能记为用量未知，不能假定未计费。

新版本使用独立的索引发布目录；可以复用已取得的向量缓存，但必须按模型、维度和完整文本键核对，缺少的向量仍需显式准备。不得覆盖正在使用的旧版索引或仅修改版本摘要绕过核查。

发布前核查原有表未改变、子块覆盖全部非空白正文、字符范围/摘要一致、FTS 完整、边证据来源一致、向量齐全及维度有效。随后切换前端与正式研究 runtime 的同一版本，并实际执行关系查询、原文回读和有界混合检索。机械完整性、检索召回和研究结论正确性分别报告，不能用索引条数替代后两者。

若向量服务因账户或配额等外部问题中断，可以在完成原文、FTS、图绑定及旧数据兼容审计后，单独发布子块版本；必须显式关闭正文混合检索，并记录向量未完成的状态。此时可使用词法检索与关系回读，不能声明稠密检索验收通过。账户恢复后复用已有成功缓存，补发仍按具体失败请求授权处理，完整校验后再启用混合检索。
