## 1. 产品目标与目标用户

让专业用户在一个持续维护的项目中接入资料与数据，委派研究，修订和积累成果，并在新信息出现后以可控成本更新判断。Agent承担常规研究路径、检索、计算、纠错和交付；用户决定投资取舍、风险偏好及超出授权的资源使用。

首批用户建议聚焦持续跟踪少量公司或议题的独立研究者和小型团队。该细分定位及付费意愿仍待真实试用验证；多用户运行、成本模型、数据服务和成果维护是本版明确需求。

核心价值要通过持续使用验证：减少重复组织材料、重复计算、重复解释研究口径，以及人工修正重要错误的时间。与获得同等资料、工具和方法的通用Agent比较，不以角色数量、代码量或某一模型作为差异化证明。

## 2. 当前基础与问题

0.1.3已有本地工作台、混合检索、财务查询、底稿修订、报告导出和任务接续。现有评测证明了指定样本上的能力，同时留下金融语义错误、错误草稿影响、重复研究及原生报告未完成等问题；本机隔离与接续不等于多人部署已验证。

资料入口仍偏向已发布的本地快照，成果主要归属于单次任务。历史用量已有估算，但任务前预测、持续校准和多人总预算仍需实现。详见[实测报告](../public/technical-evaluation.zh-CN.md)及[成本模型](../architecture/economics/research_cost_model.zh-CN.md)。

## 3. 核心使用流程

1. 用户建立公司/议题项目，连接远程数据或导入文件，确认字段口径、访问范围与更新方式。
2. 用户提出问题、研究时点和交付要求，选择价格与服务范围明确的产品；系统在约定范围内组织运行，并复用项目内仍有效的成果。超出约定范围的服务或加量需明确说明并由用户选择。
3. Agent围绕关键判断取得支持与反证，调用适用方法和计算工具，逐步形成报告；用户可查看状态、暂停或追加要求。
4. 报告、计算、假设和底稿保存为项目资产。用户可编辑、查看版本及来源、分享或导出。
5. 新披露或用户修订到来，系统指出受影响判断并完成必要更新，展示判断变化及费用；未变化且仍适用的工作继续复用。

## 5. 用户控制与界面原则

项目是持续入口，任务是其中一次活动。建议包括资料与连接、指标与模型、研究成果、更新与待复核、任务与费用五个区域；具体布局根据首个使用切片调整，复用现有阅读器、表格和编辑组件。

接入需有样本预览和明确的可查询状态；编辑需区分正文已保存与检索索引已同步。原始披露保留，用户调整以自己的数据或假设版本表达。报告可检索不代表内容已核验，确认假设不代表成为外部事实。

Agent自行处理常规检索、替代证据、局部纠错和优先级。只有目标、费用/期限、权限的实质变化或用户专属信息才需要用户决定。合理假设不因暂未证实而一律删除，缺少依据的故事也不能成为风险结论。取消不能被表述为已发出的供应商请求必然停止计费。

## 6. 成功标准与商业验证

| 维度 | 观察指标 |
| --- | --- |
| 研究价值 | 关键错误、有效反证、判断变化依据、报告完成、用户实际修改时间 |
| 数据服务 | 原值/口径一致性、检索命中与定位、增量同步、修订/撤销生效、接入维护步骤 |
| 持续使用 | 首次与更新任务的重复读取、重算范围、成果复用正确性、用户回访 |
| 运行经济性 | 排队/执行时间、恢复和重复执行、含失败的合格交付成本、预测误差、尾部费用 |

按工作包在执行前确定样本与质量门槛，不预设缺少依据的节省比例、全局准确率或服务器容量。成本包含失败尝试，人工完成与自主完成分别记录；数据不足时不宣称统计推广。0.1.3、通用Agent与0.1.4候选使用同等资料/工具/方法进行比较。

内部应先维护“服务定义—实际能力—合格交付成本—候选价格”的对应关系，再决定上线范围；上线后按同一服务版本持续观察成本、质量、需求和续用情况。每档明确目标用户/任务、交付物、资料与研究范围、时效、包含修订/更新、验收标准及超范围处理。模型和Agent数量属于内部实现，不能代替用户价值定义；各档均须满足事实、引用与不确定性披露的基本要求，复杂度、覆盖和服务量可以不同。未达到可靠交付的能力不能仅通过提高售价视为已具备。

工作台订阅加有限研究额度、按次专题服务、BYOK或团队部署均为候选，不在样本不足时锁定档位、价格或毛利目标。内部成本公式提供价格可行性约束，最终定价还需用户价值和付费意愿验证。开发诊断成本与稳定服务运行中实际发生的失败/返修成本分开，不能把前者直接当正常报价，也不能从后者中删掉昂贵失败。用户侧不默认展示完整成本构成；必要费用告知不等于公开内部经营账。
