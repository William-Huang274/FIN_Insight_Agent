# 行业研究方法、执行合同与有界诊断

2026-09-17。对应[研究问题体系](../product/research_question_system.zh-CN.md)，承接0.1.4技术3.1/5.5。设计→方法资源→合同→节点消费→真实模型结果分别记录；当前生产研究图不因本文自动升级。

## 1. 成熟方法怎样适配

采用CFA的业务竞争边界与经营驱动分析，把同行定义落到业务/产品；使用量价组合、利润与现金桥接和有条件预测，不只堆五力/PESTLE标题。[CFA行业竞争分析公开纲要](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/industry-and-competitive-analysis)、[公司预测公开纲要](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/company-analysis-forecasting)。只读公开部分，不声称阅读付费完整课程。

借鉴PCAOB证据相关性/可靠性、支持与矛盾证据并存，以及分析程序中的预期、差异调查和记录。FIN适配为：对每条核心判断先说明需要核验什么；先列可区分解释，再选观察；发现异常回查附注和交易，不让管理层解释自动关闭问题。[AS1105](https://pcaobus.org/oversight/standards/auditing-standards/details/AS1105)、[AS2305](https://pcaobus.org/oversight/standards/auditing-standards/details/AS2305)。该借鉴不提供审计意见，不含企业内控测试、私人函证或法律认证。AICPA AU-C500官方PDF本次读取失败，仅作为待核参考，不将未读文本归为已吸收。

实际采用的研究检查断言由FIN定义：主体/发生与阶段、覆盖完整性、数值与估值口径、期间/版本、权利义务/合同、分类与因果表述。不是把审计断言机械改名后要求模型勾选。

## 2. 行业方法资源的组织

继续用现有 `get_research_method` 和包内Markdown，不另造Skill服务。保留六个角色方法，新增可组合的行业方法。Lead只加载问题地图与必要领域方法；领域负责人常驻当前方法，子任务仅拿自己步骤、资料范围和交付字段。

| 方法ID | 适配业务 | 必须做的操作 | 重要反证/分叉 |
| --- | --- | --- | --- |
| semiconductor_systems | 加速器/CPU/服务器/网络 | 选任务和系统边界→同口径规格/基准→软件迁移与客户采用→供给/财务兑现 | 性能强但未供货、峰值强但同SLO成本弱、收入受出口政策影响 |
| model_compute_demand | 模型训练/后训练/推理 | 固定质量任务→计算/内存/时延边界→每任务效率×任务量情景→云/硬件/电力兑现 | 稠密/MoE、训练/推理、峰值/实测不能混用；不预设需求弹性 |
| manufacturing_capacity | 晶圆/封装/内存/设备 | 工序依赖→名义/有效产能→认证/良率/产品分配→订单库存和资本周期 | 扩厂不等于有效产出；设备订单与终端使用有时滞 |
| cloud_infrastructure | 云/算力租赁 | 使用/合同→容量可用→价格成本→折旧/租赁/现金→利用率情景 | 承诺与实际使用不一；收现、收入、资产投入不同时 |
| software_platforms | 模型/企业软件/广告/电商 | 按收费模式分支→采用/付费/留存→毛利与服务成本→竞争/渠道 | 席位、调用、广告或交易量不能互代；GMV不能当收入 |
| power_projects | 电力/机房/能源设备 | 项目身份→许可/电网/合同有效状态→建设/投运→现金期限 | 规划、签约、审批和实际负荷不同；不能假定所有电力增长来自AI |
| financing_ownership | 融资/持仓/资本关系 | 身份与期限→承诺/到账/股数/市值→客户资本链→压力路径 | 13F不是资金流；关联不是造假；未披露动机不能编 |
| financial_quality | 全行业财务检查 | 分部/同期→经营/非经营→利润现金桥接→季节/交易→反证 | OCI重分类非自动现金出售；税费增加通常抵减净利润增量 |
| macro_valuation | 宏观/政策/市场定价 | 版本/生效→业务暴露→机制/时滞→事件窗口/反向估值→敏感性 | 当前修订值污染历史任务；价格变化不证明唯一原因 |

每份资源含触发条件、顺序动作、实际交付、下一轮触发与停止。没有样例公司结论，不把072答案放进方法。行业方法共用角色基础金融要求；Verifier不独占基础会计知识。

技术效率方法补充依据：[计算最优训练研究](https://arxiv.org/abs/2203.15556)、[考虑推理生命周期的扩展研究](https://arxiv.org/abs/2401.00448)、[MLCommons同任务基准规则](https://mlcommons.org/benchmarks/inference-datacenter/)。从技术效率到商业需求的情景与证据链是FIN适配，不能把论文结果当成企业收入或行业需求预测。

### 2.1 如何从问题选方法和工作产物

| 问题组合 | 主方法与必要补充 | 实际要交给下一角色的东西 |
| --- | --- | --- |
| Q01/Q02/Q05：需求增长传到谁的利润 | 先业务对应的cloud/software/semiconductor，再financial_quality；供给约束激活manufacturing | 同期经营底盘、业务差异、量价/组合已解释与未解释部分；不把不同环节收入相加成总需求 |
| Q03/Q07：技术更强是否会被采用 | semiconductor_systems/model_compute_demand→software_platforms或cloud_infrastructure | 同任务比较表、客户采用阶段、迁移/交付障碍；每项关键条件有判别观察 |
| Q04/Q08/Q09：扩张能否按时兑现 | manufacturing_capacity或power_projects→financing_ownership→financial_quality | 工序/项目依赖、有效许可/合同状态、资金期限与现金条件；承诺和实际分开 |
| Q06/Q12：高增长是否掩盖脆弱性 | financial_quality→相关经营方法；financing_ownership核资金责任 | 同口径利润现金桥、异常原因及反证、无法拆解的剩余；不凭单一财务比率指控 |
| Q10/Q11：宏观变化和市场要求什么 | macro_valuation→受影响业务方法及financing_ownership | 可用历史版本、政策适用/生效、暴露路径、相对价格观察与有条件估值 |

行业负责人收到的不是一整套行业百科，而是“总题的哪个前提、要区分的两种解释、当前适用步骤、资料及历史截止、必须交付的产物”。执行者可以指出假设错误或额外发现，但应先完成已分配的重要义务；新增观察交回Lead决定是否影响总题。一个来源缺失只阻断依赖它的判断，不应让整份研究停止，也不能让另外已有充分资料的判断降低标准。

例：问“云资本开支上升是否改善设备厂盈利”，初始任务先比较设备分部收入/利润，而不是直接派“论证AI利好”。若收入上升而利润下降，下一轮需区分产品组合、爬坡成本、政策库存费用与定价变化；若现金也背离，再查回款、营运资本和租赁。只有这些差异仍影响总答案时才继续激活任务。论文、客户评论或融资线索用于提出新分支，不能覆盖已经查明的报表事实。

## 3. 自然语言到机器合同

### 3.1 研究任务与证据要求

`ResearchObligation`至少包含ID、问题、关联总题、业务/实体范围、as_of、method_ids、适用步骤、验收预期(factual/conditional/exploratory)、重要性、所需资料类别、已有版本和依赖。每个步骤有要回答的区分问题，例如“增收是否来自量增或价格/组合”；不能只传“分析行业”。

生产映射目标的结果合同应包含已完成步骤、结论/公开依据说明、精确source_refs和calc_refs、仍缺资料、竞争解释、触发后续的观察，以及task_note的实际变更/卡点/交接对象。首轮实现 `MethodWorkResult` 的步骤、段落ID、公开依据、假设、竞争解释、未决与task_note；未实现完整生产计算引用绑定，不应误称已覆盖。结论状态与执行状态独立：一个成功执行可以反驳假设；工具失败不能生成未披露事实；达到预算上限不等于研究完成。

机器能核查ID/版本/时间/必填/算式/覆盖回执，不能靠字段齐全判定金融含义正确。自然语言分析交由领域负责人、独立复核和本轮人工诊断；不为语义错误堆伪客观关键词评分。

### 3.2 关系与投资视角

沿用已有typed relationship检索思想；统一实体至少区分公司、业务、产品、项目、机构、证券、政策/事件。别名解析不改原证据身份。边有方向、关系类型、产品/地区、valid_from/to、published_at、source_ref、assertion_status（披露/观察/推断/争议）、独立来源链。

供给边、客户/采用边、竞争/替代边、股权/债务边、项目/能源依赖边和政策适用边不能混用。多跳得到候选研究路径，不自动得到因果事实；A投资B且B购买C不能推出A控制C或需求造假。事实图、候选假设及任务依赖图分开存储。

投资视角用每个候选实体的暴露机制、方向、条件、时间、估值敏感项来投影；“受益”是有证据的研究判断，不是无条件图边。每个视角必须能退回源段和财务数据，关系摘要不是引用权威。

### 3.3 状态、责任与停止

`unread → read → compared/calculated → provisional → challenged → accepted/bounded`描述工作状态。`tool_failed/parse_failed/vintage_unknown/rights_blocked`是执行缺口，不折算成负面研究事实。只有原件/解析/工具结果/模型实际输入均核对，才将遗漏归到模型。

Lead每阶段看到总题、当前主张和竞争解释、重要义务、最新变更、未决/已否定项及下一决定；具体原文留子任务上下文，可按引用回读。阶段整理不删除刚返回的工具结果，跨阶段固定资产版本；新版引起重开而非静默替换。现有140k/272k方案不在本次擅自修改。

同一失败原因与同一资料版本重复且无新增证据，应向Lead报告无进展；Lead选择改变路径、缩小精度或停止该支。次数上限只是防失控，不是固定研究轮次。重要未决不能被“总计已调用N次”强行宣布解决。资源用完时交付部分研究及未决，不伪称完整。

## 5. 数据与GraphRAG选型

现有SQLite/FTS、sqlite-vec、DuckDB及typed relationship检索已能承担小规模证据、数值与邻接查询。先用这些成熟组件准备隔离研究快照：原文不可变；数值/持仓/规格作为有类型的观测；图边回指来源；FTS/向量只生成候选，原文回读才用于判断。旧数据通过原身份/源摘要映射进入新快照，不原地重建覆盖生产库。

Microsoft GraphRAG的local/global/DRIFT可作为候选。官方方案涉及实体关系抽取和社区摘要；这些摘要适合导航，但不能直接承担数值/法定状态权威。[查询概览](https://microsoft.github.io/graphrag/query/overview/)、[索引方法](https://microsoft.github.io/graphrag/index/methods/)。首轮不全库付费抽图；先检验现有检索是否能找齐指定关键路径、历史过滤与精确段落。如果需要跨大图社区主题总结而现有召回不足，再比较GraphRAG；不是因为用户提到图谱就换数据库。

首轮本地数据至少有：sources/passages、entities/aliases、typed_edges、numeric_observations、security_positions、product_specs、source_access_receipts、snapshot_membership。日期与单位不能塞进自由文本后丢失；当前修订贸易数据标vintage_unknown，拒绝冒充历史当时值。069已知缺口不得通过此诊断快照绕过后宣称生产已修。

## 6. 三个有界案例与归因

先冻结题目/数据/方法与检查点，再模型调用。三个候选：A 芯片/服务器竞争和利润兑现（事实+条件）；B 云、电力项目及融资依赖（条件+状态更新）；C 机构暴露/市场定价及宏观约束（事实+探索）。用新的组合问题，复用原始来源，不把宿主结论喂给模型。尽量保留既有库相关材料与干扰项，不能只给正确段落。

检查分三轴：方法是否理解（是否完成动作并解释差异）；编排是否执行（谁实际读取方法/资料、发起/消费子任务、依据新发现改变计划）；数据与工程（时间、源定位、数值、版本、工具失败传递）。空泛提到方法名不算使用，schema通过不算研究正确，宿主修正后不能称自主成功。

每案例限制为有界节点诊断，不交完整研报；每次调用前记录TokenBudgetBasis、输入规模、推理/输出预算与停止行为，保存准确输入、返回、工具及usage。不可重发未知费用请求。若基础语义/明确指令反复失败，依用户要求停止并归因，不继续同题提示词调参求绿。

阶段1/2的交付是此问题体系、行业步骤、责任映射和机器合同；阶段3必须引用其固定版本。数据读入/真实调用/结果在执行路线分别登记。

## 7. 首轮工程观察与验收边界

有界诊断使用 `method_diagnostic_graph.py`；原生Send将不同子任务交给独立模型上下文，结果再进入Lead条件路由，checkpointer保留暂停点。这里只做研究中段，不含最终Writer/独立Verifier闭环，也未复制生产专家子团队的完整层次。行业方法已通过现有方法工具可读，生产图尚未统一强制执行这套义务合同。

第一轮资料读取暴露了具体工程问题：按文档固定字符阈值后只取少量FTS命中，会遗漏同一文档中已经具备的可比分部表。即使模型知道某数值的导入观测，若观测没有精确原文引用绑定，仍无法符合引用合同。因此诊断已改为按整个子任务资料规模分配：完整范围能够容纳时全读；超出范围时显示未读覆盖。尚未完成期间/业务/段落绑定的数值导入隔离为待核回执，不能成为已验证计算输入。不能将这类取证缺口报告为免费资料不存在。

一个已完成的条件研究可以保留无法直接观测的变量；`execution=completed`表示已做完约定义务，不代表所有变量确定。反过来，必要的同比取数尚未完成时，不能仅因写完文字就标全部步骤完成。合同能检查明确的未完成状态，识别“写了completed却实质没做”仍需内容审查和后续工作产物约束。

当前SQLite关系快照和文档导航向量验证了技术底座的可复用性，但尚非全语料业务图谱：人工建立的代表性边与原始文档/历史身份保持相连；图候选、导入数值、检索命中均不自动取得事实资格。需要另外完成具体案例实体/业务/证券归一、原文表格数值绑定及关系召回验收，才能扩大到生产库重组。

### 7.1 诊断反馈给生产合同的具体要求

诊断中Lead能接收补查结果，但自由文本综合仍可能继承早期过强归因。生产接入不能只把所有旧结果和新结果一起塞给Lead。应映射现有底稿版本、Claim与修订机制，逐项维护：

- 数值观测：业务、指标定义、实际比较期、单位/缩放、来源版本、表头与数值段落；导入数值尚未绑定这些信息时保持待核。
- 判断版本：`claim_id/revision`、证据与计算引用、判断等级、假设、反证、`supersedes`及被更新的理由。原记录保留审计，最新有效状态不把被否定前提当默认真值。
- Lead采纳：所采用的子判断版本、接受/限定/反驳决定、保留条件，以及对总题影响。叙述综合不能把子判断的“未披露”改写成“未发生”。现有诊断`ProbeDecision.synthesis`还是自由文本，这项映射未完成。
- 后续任务：`as_of_research`与`future_monitor`分开。未来财报可以作为跟踪触发，不能作为历史截止日内“现在应补查”的可用证据；取不到未来材料不是获取失败。
- 完成含义：步骤执行状态、关键产物是否齐全、原文覆盖和结果置信分开；不能凭模型自报completed，自动接受缺少同期比较的财务结论。

固定事实不需要逐条编一个“如发生重述”的竞争解释。竞争解释与改变判断条件应集中于重要研究判断；直接观测保留口径和引用即可。首轮统一结果schema尚未充分区分两者，会造成重复表述，应在生产结果类型接入时收紧，而不是为了压低token删除必要研究。

### 7.2 资料阻碍与金融证据不能共用引用资格

真实持仓/贸易诊断进一步暴露：模型正确报告某JSON被历史版本门禁挡住，却把该文件ID放进了金融`source_ids`，机械合同因没有可读段落而拒绝。这里既有输出位置不符合约定，也有合同只提供金融段落引用、没有独立执行回执引用的缺口；不能将正确的失败说明归成捏造来源。生产接入须将`evidence_refs`与`execution_receipt_refs`分别绑定到已有来源和工具事件身份，阻碍进入执行状态，不能提高金融主张置信度。

当所有所选资料均无可用原文时，当前诊断图直接返回runtime生成的`tool_failed`和逐步骤blocked回执，不调用付费研究模型。只剩次要背景资料但关键数据不可用时，仍可能浪费一次分析调用；后续要在研究义务上区分必需操作数与补充背景，并按步骤判断可执行性，不能靠“至少有一篇可读文档”代表整个任务可做。贸易与行情历史版本缺口也需进入数据适配任务，金融专家不应靠反复说明空结果承担工程修复。

还要区分研究时间模式：严格复现“当时知道什么”需要当时版本；今天回顾一段历史，可以使用明确标注的后来修订序列，不能把它冒充当时信息。当前诊断默认前一种严格模式，没有实现后一种选择。它挡住已下载数据，不代表这些免费数据不值得研究；补工程时应同时修元数据与时间模式合同，不能一律放行或一律封死。

### 7.3 已执行诊断的解释

A（芯片与服务器）真实执行两轮分派、7个响应。Lead能从首轮利润分歧派出同比补查；修正资料交付后，专家取得原有表格中的分部利润并正确重算变化。但仍有把产品爬坡时点写成已确认利润拖累的过强归因，且Lead继承了它。结论是方法能驱动具体比较、工程交付影响明显，金融语义与综合尚未全通过；中间有工程修复，不能作为冻结配置自主通过案例。

C（持仓、市场与贸易）真实执行两轮分派、7个响应。专家正确区分期末股数、估值变化和实际交易现金，也完成公司指引下的条件性EPS计算。对没有返回的行情/贸易数值未编造结果，Lead最终保留具体历史版本和时间窗口阻碍。该样本仍有执行回执引用混入金融引用、元数据说明引用到无关财务段落、未查原字段却自报步骤完成的问题；模型拒绝编造不代表结果合同已经完善。条件EPS不是市场隐含估值，缺少价格时不得改名冒充后者。

这两例支持继续完善方法与合同，不能证明模型在广泛复杂金融任务上可靠。角色数、JSON通过率、单次算对均不提供这种证明。原Amazon停止点和生产历史数据问题保持开放。

诊断输入还有明确限制：执行者收到所选新行业方法，尚未统一装载旧角色方法的完整金融基础，也没有接入生产来源绑定计算工具；本次核算由模型产出、宿主抽查重算。不能将这种受限入口的表现直接等同于生产完整提示/工具条件下的模型能力。正式接入时须明确共享金融基础和可调用工具，记录实际装载内容及可用权限；仅在方法文字里写“同时使用finance”不会自动装载资源。

B（云、电力与机房）在首次调用前限定一轮分派、4个响应，补充领域覆盖。专家区分了集团资本开支与AWS、购电合同与实际交付、燃料批准与复运、总体规划与有效分区。但原文明确的SRBC仍被错误文件名和Lead指令中的DRBC带偏；专家自己引用真实机构全名，仍未纠正简称。最终Lead继承该错误，还将若干项目的“给定资料没有确认当前交付/批准”概括成统一的尚无投运状态，并将部分听证程序结束泛化为必需前置条件。此例不接受为金融/项目研究完成，不继续同题调参重试。

B另有准备范围不足：Talen只给了2025合同公告，宿主前轮已读到的2026后续披露没有全部进入冻结输入。模型据此请求补查是合理行为；不能把宿主准备缺口叫做免费源边界。后续用既有外源搜索/抓取另存2026官方材料，保持冻结输入与结果不变，不能回填后宣称原模型已读过。

三例合计18个实际DS响应，所有调用完成且无本轮未知费用或待结预留；公开定价与实际usage估算为USD 0.566208，不是完整研究成本或账单对账金额。另有13次Qwen文档导航embedding，57,298 tokens，费用未计入前述DS估计。实际运行与逐步审查保留本地记录；以上是有限样本的定性诊断，没有通过率统计意义。
