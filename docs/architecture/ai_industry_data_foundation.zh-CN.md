# AI 行业数据基座

对应 0.1.4 PRD 的长期资产、扩源研究和可追溯查询。交付是可被正式 runtime 与资产界面共同读取的数据版本，不是投资结论或少数检索示例。沿用既有原文身份、SQL、FTS5 和检索适配器。

## 范围与时间

以大模型及平台公司为起点，沿有来源的供应、客户、融资和产品关系扩展到相关行业，再选择行业主要公司进行第二次扩展。公司、品牌、模型、证券、基金、管理人和政策发布机构分别建模。入选理由和扩展父节点可回查；不把共同出现当交易关系，不把产品可比性当供货。

本次研究基准为 2026-09-20。滚动信息窗口为 2026-06-20 至基准日；财报窗口为最近三年。较早的关系原始公告可作为历史关系依据，显式标识历史背景，不能充当最近三个月新闻。无发布日期的当前产品页标记抓取时点，不能冒充发布日期。旧资料库保留，时效过滤不删除历史。

## 统一记录

- 公司菜单：稳定身份、别名、法人与品牌区别、业务/产品/地区标签、上市状态依据、交易代码、来源入口、纳入路径、卡片证据、各维覆盖与缺口。
- 关系：起终点、关系类型、产品/地区/期间、公告与生效时间、状态（计划、协议、已发生、待核实）、原文位置、有效区间；融资意向、承诺与到账分开。
- 材料：来源身份、官方/监管/公司观点/社区分类、发布与抓取时间、正文及摘要定位、内容摘要值、解析状态、适用实体。原文与结构化卡片可相互回查。
- 数值：主体、指标、数值、单位、期间、披露日、来源、版本、实际/指引等口径。行情交易日与财报期间、13F持仓日与披露日分开。
- 缺口：逐公司、逐资料类别记录尝试、错误归属、覆盖区间、可执行下一步。HTTP失败或解析失败不能被写成公司没有披露。

## 实施与验收顺序

1. 调研确定公司与资料入口，核实实体、两轮扩展和来源覆盖。
2. SEC/官方 API 优先采集，SQL 保存原始响应、解析文本、数值与关系；优先复用既有适配器。发布新版本并保留旧身份映射。
3. 正式 runtime 读取同一版本的菜单、关系、原文和数据；检索复用 BM25、Qwen embedding、rerank，图查询只提供有来源的候选路径。
4. 资产工作区公司网络、资料卡、材料阅读和数据库共用同一数据服务；禁止只有前端样例。
5. 检查每公司覆盖、日期/单位/身份、来源回读、旧库兼容、SQL恢复；真实 DS Flash 检查工具使用与证据定位。模型测试不替代数据覆盖验收。

## 已接入的实现

`industry_data` 是 runtime 与工作台共用的只读 SQL 投影。`company_cards` 保存公司菜单，`entity_sources` 关联材料；`financial_points`、`market_prices`、`institution_positions` 分别保留财务披露版本、日行情和持仓行，`position_issuers` 保存经核对的发行人映射。`raw_captures`、`collection_attempts` 和 `data_gaps` 分别记录原始响应、执行结果和逐公司缺口。既有 sources/passages/entities/edges 身份继续使用，不重建断开的样例库。

正式 `read_source_document` 的 library 空间支持 `catalog/company/related/data/search/read`。公司查询使用目录返回的精确 entity_id；不匹配时返回建议身份，不擅自改名。data 的 query 是指标/发行人等字段的字面筛选，行情通常留空；空筛选结果附可执行的恢复参数，不作为未披露证据。财务记录先按披露日、再按观察期间排序，抓取同日的宏观系列不会把最早观察误当最新值。时间截断可配置研究日期时区。

复用 SQLite FTS5 BM25、现有来源关系表、LangChain 向量检索和 Qwen embedding/rerank 适配器。向量索引覆盖每份可读文档的导航卡，全文段落全部保留在 SQL/FTS 中；向量召回、全文候选和来源关系可共同提供原文候选，再重排。**这不是每段全文均已 embedding，也不是自动抽取并核实了全库关系的 GraphRAG。** 未核实共现关系单独标记，前端默认隐藏；管理人持仓关系保留证券类别、期权和报告期，不净额相加。

资产区新增公司光谱，支持按行业/产品找公司、点击关系打开依据、分类原文分段阅读、财务/日行情/管理人持仓/反向持有机构/申报目录浏览、逐公司缺口。原知识库和财务库入口保留。公司区与数据库区消费同一发布文件；前端没有另外维护示例资料。

## 采集与发布

### 分类、资料归属与修复（2026-09-20）

资料菜单提供 `profile.type/roles/institution_type/country/jurisdiction/identity_basis`。经营公司、投资机构、基金、政策发布机构与跨机构宏观集合按不同资料卡展示；类型模型支持基金，但不把管理人的13F行自动当成旗下单只基金。旧实体ID和旧实体kind不原位迁移，新的导航身份由资料卡投影提供。

材料目录使用分组→类别→年份；同一原文可关联多主体，但在同一主体下只显示一次，保留全部分类及主归档/关联材料角色。发布机构由原始官方元数据识别，政策是否与研究主题相关另行审查；`needs_review/out_of_scope` 是特定研究范围下的适用性状态，不代表来源不权威或永久无价值。关系只有在具体原文及位置支持时才写入，通知、计划、附条件投资、担保和已发生事实保留不同谓词和状态。

财务数据导航将 `us-gaap/ifrs-full/DART-IFRS`、发行费用 `ffd`、薪酬 `ecd`、宏观 `FRED` 与其余原始数据分组。无显示名称时保留 `raw_label`，展示 `taxonomy:concept` 并标记 `runtime_compatibility_parse:original_concept_fallback`；不猜测中文指标含义。正式工具 `read_source_document(source_space="library", operation="data", entity_id=..., data_kind="financial", data_group="offering")` 可选相同分组。`data_group` 不填写时保持历史请求序列化；空查询反馈也保留原分组，不能为了返回结果偷偷扩大范围。

`organize_industry_foundation` 负责上述分类与经原文定位的关系评审导入；`repair_policy_sources` 将HTTP200反爬页标为失败历史，经Federal Register API定位到GovInfo官方原件。旧内容、摘要和URL不改写，新原文与旧失败记录相互关联。抓取成功不等于政策适用性已经通过。

`expand_reporting_managers` 从13F-NT原始XML的`otherManager`取得管理人CIK，逐一读取SEC目录和持仓表；建立`reports_via`关系，不推断股权母子关系，不跨管理人合并持仓。复用已有唯一CUSIP映射供反向机构查询，期权、证券类别和日期原样保留。没有可用表或失败时写逐管理人缺口。依据：[SEC Form 13F说明](https://www.sec.gov/pdf/form13f.pdf)。

台湾FinMind月营收的观察期间取`revenue_year/revenue_month`，不使用其记录`date`或`create_time`冒充营收期间和公司披露日。单位必须逐数据集/记录与原始披露核对；月营收的单位确认不能传播为季度损益、现金流或EPS全部已确认。

依赖使用项目的 `public-source-library`、`agent-runtime` 和 `external-search` extras。源计划、材料、API 凭证、运行记录与索引放在 Git 外。计划字段包括 `as_of/recent_since/filings_since/companies`；公司含稳定 entity_id、slug、名称、官网、行业、产品、扩展深度以及经核实的 CIK/交易代码和官方仓库入口。缺少身份时不猜代码。

1. `scripts.data_retrieval.build_industry_foundation` 在线备份既有库后采集公司/SEC 目录、财务、行情、申报原文与附件、13F。SEC/API 优先，官方 PDF 和带来源标记的镜像作补充。
2. `international_industry_sources` 接韩国 DART 和台湾财务 API、官方报告目录；`industry_community` 接近期官方仓库和模型卡、有限社区样本；`enrich_industry_foundation` 接关系公告、FRED、官方监管材料。新闻 RSS 明确是线索目录，未冒充文章正文；账户链接未冒充已采集社交帖子。
3. `reconcile_industry_catalogue` 对齐卡片、覆盖与候选关系。未核实单位和短上市历史保留缺口。HTTP 200 的反爬挑战页不会作为原文；SEC 附件解析兼容降级显式记录，合并单元格仍需核对原件。
4. `publish_industry_foundation --build BUILD --target NEW_RELEASE --as-of YYYY-MM-DD` 发布新文件并校验完整性与摘要，不覆盖旧版。
5. `index_industry_library --library RELEASE --cache CACHE --output NEW_AUDIT --execute` 是显式付费准备，精确相同文本复用已有向量。查询不会悄悄启动全库 embedding；失败/未知费用的请求不会自动重发。
6. `audit_industry_foundation --library RELEASE --previous PREVIOUS --output NEW_AUDIT --restore-target NEW_COPY` 生成逐公司 CSV/JSON、旧身份/内容校验、并发读取与恢复测试。恢复仅写新路径；同盘恢复测试不等于异地容灾。

宿主 `host-settings.json` 的 `research_library` 指向发布 SQLite，`research_library_hybrid=true`、`research_library_rag_cache` 指向已准备缓存；`research_date_timezone` 可设为 `Asia/Shanghai`。标准研究阶段创建时自动注入正式数据 composition。容器部署使用 `compose.research-library.yaml` 的只读资料库与 manifest 挂载，容器设置分别使用 `/run/fin-insight/research-library/library.sqlite` 和 `/run/fin-insight/library-rag`。Qwen key 通过现有环境机制提供。运行工作台不自动启动付费研究。

## 2026-09-20 r3 历史验收（r5 更新见下文）

最终发布 r3：74 个公司/法人条目及 1 个宏观政策入口，1,530 份可读材料、45,957 个当前可读段落、173,380 条带披露版本的财务观察、3,733 条日行情、64,714 条机构持仓、2,805 条申报目录。近三个月行情覆盖 59 个公司条目；40 个条目已按年度身份核实三年年报全文，其他公司的报告、上市历史或非 SEC 覆盖仍需逐公司看缺口，不能宣布所有公司的三年资料齐全。

关系包含 127 条带来源的公告/身份/持仓关系和 587 条明确未核实的原文关联候选。96 条为持仓关系；不能把这些统计说成已验证了 714 条供应链关系。BlackRock 现上市主体与 BlackRock Finance 的原主体分开，避免三年序列混入错误法人。

入库审计发现并修复了两类解析问题：SEC inline XBRL 自定义标签中的数字被通用正文提取器忽略，以及全文财务附录被文章正文选择排除。574 份报告重用原始 HTML，保留整份可解析正文和顺序表格单元格，并显式标记 `runtime_compatibility_parse`；旧解析版本归档而不覆盖引用身份。对五家公司十份报告抽查 1,000 个分布于全文的数字，均在新文本中保留；合并单元格几何关系仍需原件复核。DART 半年度 IS/CIS 的本期字段按单季保存，累计字段另存，避免将第二季度金额当成上半年金额。两类修复均有确定性回归。

旧库 156 个来源的身份、URL 和内容摘要全部保留；全文段落哈希、SQL 完整性、外键、6 路并发读取和恢复副本检查通过。正式 MCP 通路的 DS Flash 干净短测取得公司卡、官方合作原文、最新宏观观察和反向机构持仓，4 次响应、47,005 tokens；这一结果仅通过工具适配测点，未认证完整研究规划或金融报告质量。前两轮运行及其格式/目录/上下文遗留错误原样留存。r3 另经正式 MCP 五项无模型回读，包括修正后财报数字，未重复完整付费案例。最终快照的全部文档卡索引已就绪；58 个新增 embedding 批次用于变化的卡片，其他向量复用缓存。

仍有明确覆盖限制：部分非 SEC 年报获取失败或三年尚不齐；台湾 API 部分数值单位/累计口径待原件核对；未上市企业财务与融资条款不齐；Vanguard 母级 13F-NT 已记录委托申报管理人但尚未逐管理人展开；新闻正文和 X 帖子覆盖不足；产品参数跨公司统一数值表尚未建全。近期动态来源按日期筛选，旧关系公告仅作为历史依据保留。公司光谱入口已运行，本轮没有启动完整 Agent Server 研究报告任务。

## r6 资产可用性修复

r5 的少量页面检查没有覆盖不同身份的默认数据入口、目录原文和跨主体连续切换。用户反馈后，检查扩展到全部117个资料主体及其1493份关联可读材料，逐主体记录可用表与未接入项；这些计数不表示财务口径已经跨公司标准化。

存储合同统一的是实体、来源、原始指标身份、数值、单位、期间、版本和可获知日期。`display_label` 是单独的导航名称，不能替代 `taxonomy:concept` 或自动赋予跨公司可比性。ECD/FFD 常用指标提供有定义依据的导航译名，原 label 保留，中文名称可检索。未知指标仍需核实，禁止仅靠字符串近似合并。

`company_detail.data_channels` 根据真实数据与主体身份提供可用入口。经营公司优先财务/行情，申报管理人优先持仓，监管机构提供政策登记，宏观集合提供指标选择与时间序列。没有数据的类别不伪装为可用空表；无结构化财务时明确说明接入缺口，原始报告仍独立可读。切换主体重置分类、筛选与分页；展开目录和选择目录是两个独立操作。

`material_presentation` 按原文摘要核对重组带重叠的归档分块，再解析新闻、仓库、模型和社区目录，保留每条标题、来源、发布日期/创建/更新时间及正文有无。读取API和列表共用字段；正文使用现有Markdown渲染器，不执行原始HTML。预览只取明确标示的原文摘录或原有描述，不用模型编造摘要。目录的抓取日期不冒充每篇新闻的发布日期，只有链接的新闻不能算全文覆盖。

持仓关系图直接复用已核实的 `position_issuers` 映射，与正式 runtime 图检索共用；关系保留申报管理人、报告期、来源和原持仓行，不净额合并，不把管理人仓位分配给单只基金。当前公司范围外、尚无发行人映射的证券仍可在完整持仓表阅读。

非XBRL财务使用 `import_reviewed_financial_rows` 导入已核实的表格单元格，显式给出原行、页码、表头期间、单位倍率和会计口径；缺少原文支持的导入失败，日期未知时保存抓取可知日期并标记，不能伪造发布日期。本轮腾讯37条、软银12条核心指标只是有限结构化覆盖，不代表整套报表已标准化。腾讯8份旧中文PDF提取存在字体映射错误，旧内容/引用保留并标解析失败，已取得三年年报和2026中报的官方英文版本。

r6 保留旧来源ID/URL/摘要，当前1561份可读材料、173429条财务观察、88223条持仓。仍有16家经营公司未接入结构化财务指标；近期新闻全文、政策生效/发布日期核实、具体基金归属和完整财务映射继续作为覆盖缺口。54项定向回归、真实页面连续操作、正式工具六次回读验证工程接入，不等于金融结论质量验收。
# 2026-09-20：财务导航与预计算指标

公司菜单新增 `listing` 投影：`status` 为 `listed/unlisted/unknown`，`markets` 使用证券交易市场地区码，和法人注册地 `registration_country` 分开。上市申请、拟用股票代码不等于已上市；无代码也不自动推定为未上市。人工核实资料卡保留来源和核查日期，行情接口保留原交易所、证券类型与代码证据。

`financial_accounts.v1` 将明确的 US GAAP、IFRS 及已审核来源指标映射到报表／科目性质／子类路径。原始 taxonomy、concept、label 不改；未知自定义标签留在待归类。此目录不重建发行人 presentation linkbase，不可将父子行机械求和。`source_document` 的 `account_path` 取自公司卡的 `account_tree`；仅适用于公共库 financial 数据查询，按整棵子树过滤，失败重试也保留路径。前后端和模型使用同一映射。

`derived_financials.v1` 在可变构建库中预计算并持久化，查询不触发模型或临时运算。毛利率、经营利润率、期间净利率、流动比率、资产负债率、现金购建固定资产口径自由现金流，要求来源、申报修订、taxonomy、期间、币种一致；未知口径不拼接。保留所有计算版本及输入行身份、公式版本、可获知日期。默认展示各指标最新期间及修订，同期优先较短已披露期间，并明确展示起止日。

估值另要求审核证券、币种、单股单位与拆股覆盖。首批 PE 采用最新未复权收盘价／最近完整财年稀释 EPS，标签明确**非 TTM、非预测 PE**；亏损及零盈利返回不适用。参考市值用最新披露实际普通股数（含明确的 DEI 封面股数），不用加权平均股数；股数超过 120 日或冲突则保留缺口。多股类、ADR、币种或拆股依据不齐，不伪算总市值。每项保留日期、公式、来源和未计算原因；历史 SQL 版本不被覆盖。

前端默认金额／价格／倍数显示 2 位小数，可切换 4 或 6 位；成交量和股数显示整数。十进制字符串用整数运算舍入，SQL 原值和计算输入不截断。`data_kind=derived` 与报表科目过滤已接正式 source_document 和资产 API。工程测试证明格式、路由、计算约束与血缘，不替代原始报表审阅或研究质量验收。

经营公司的默认数据入口优先财务指标；管理人和基金优先申报持仓。查询响应绑定主体、数据类型、筛选及分页身份，切换类别时不将上一张表的结果交给新视图渲染。

## 财务期间、主表补录和股东／交易对手披露

`financial_periods` 是原始事实的导航投影。SEC 的 `fy/fp` 是申报财年，不能直接赋给同一申报中的比较期：以同一发行人、观察期末与当期申报建立锚点，再区分全年、单季、半年累计、前三季累计及期末余额。非自然年不按公历季度猜测。DART 使用已核对的业务年度及当前期间合同。台湾接口仅有观察日期、流量期间尚未核实的行保留“期间待核”；年份导航不解除单位或累计口径限制。模型可从 `company.reporting_periods` 选择 `fiscal_year/fiscal_period`，与资产页面共用查询；余额单独在“期末余额”查看。缺少期间投影的旧版库仍可不带筛选读取。

原始财务行继续保留，补录不覆盖旧版本。`import_statement_pages.import_plan` 接受已检查的 PDF 页、表头原文、列数、各列起止日期、单位倍率、会计科目路径和少量确切行名映射；多币种参考列不自动混用，破折号不强制变零，美分 EPS 单独换算。原行、页码、原数值和倍率可回查。原始自定义行名生成稳定身份，不能仅凭名称相似进入通用衍生计算。新数据完成后在可变库运行 `python -m sec_agent.research_foundation.reporting_periods --build <build.sqlite>`，再发布新版本；禁止修改已发布库。

`financial_accounts.v2` 可使用审核过的主表行路径；DART/台湾接口原有报表类型支持一级目录，只有确切标准概念再进入子类。这只是浏览分类，不代表所有附注已完成会计映射或所有年份完整。

`issuer_profiles` 为持仓原发行人名称附加行业、业务、主体身份和依据。基金信托与经营公司分开，证券类别、期权和持仓行不合并。`company_disclosures` 独立保存发行人披露的股东、客户和供应商栏目，以及来源、发布日期、定位、检查范围和状态；通过 `data_kind=disclosures` 进入正式数据工具。13F 申报持仓不替代实益所有权表。匿名集中度、前五合计、报告期尚未上市的说明均保留实际含义，不补写前十实名名单。未定位栏目与已证实未披露是不同状态；原文栏目也不冒充逐项标准化、全部审核通过的名单。

数据菜单与科目树置于同一滚动容器，避免两个 sticky 目录相互覆盖。期间、科目和文本筛选共同参与响应身份，切换公司重置筛选。

### 逐项交易对手披露，而非原文窗口（109）

`company_disclosures` 只完成栏目定位，不能当成结构化名单。新增 `counterparty_facts` 保存经原文复核的客户、供应商和实益股东：实名/匿名/合计/全体范围、直接/间接关系、职责、财年与期末、持仓观察日期、数量、各自/合计口径、数值与不等号、单位和分母、估计性质，以及精确段落ID和字符范围。实益股数所据13G的观察日可与委托书表头和比例分母日期不同，逐指标保存，不能由发布日期替代。

离线提取的候选先核对表头、脚注、身份和语义，再经 `python -m scripts.data_retrieval.import_counterparty_facts --build <unpublished.sqlite> --reviewed-pack <pack.json>` 导入。合同见 `counterparty_facts.ReviewedPack`。导入器检查原文锚点、数值、身份、关系类型、单位和期间；这些检查不能代替语义复核。数据包必须在Git外，导入器拒绝修改有manifest的已发布文件。不因形状合法自动认可模型抽取结果。

正式 `read_source_document` 的 `data_kind=disclosures` 按单条事实分页，返回条件和证据回读参数，不把整个披露窗口注入模型。资产页按报告展示同一批事实，原文依据折叠；客户匿名代号不生成实名关系，核实身份的供应关系按供应商→采购方进入共享图谱。未处理资料返回 `extraction_pending`，这是处理缺口而非未披露。

109当前资料包仅复核NVIDIA与AMD所列报告的50条事实，含匿名集中度、具名供应商及实益股东；不代表全库名单已提取，也不代表每份报告的全部客户或前十供应商。其他公司仍需按同一合同继续离线提取与复核。

### 按来源和类别记录核查范围

`disclosure_scope_reviews` 单独保存来源摘要、发行人、客户/供应商/股东类别、已读章节、核查范围、复核者、日期与精确原文锚点。`checked_no_explicit_fact` 只说明已核查范围内未发现可逐项提取的明确披露，不代表公司没有交易对手，也不代表其他资料未披露。客户比例上限、匿名和合计数据应先作为事实提取，不能以“未找到具名客户”代替核查结果。

旧版没有核查收据时继续显示待提取，不自动升级状态。收据只能关闭同一发行人、同一版本原文、同一类别的已核查范围；来源摘要变化使旧收据失效。新增事实优先显示，不能被先前的空结果遮住。前端与正式数据工具读取相同范围说明。机械检查验证来源与合同一致性，章节是否完整及结论是否正确仍由复核承担。

明确披露的控制关系可使用 `controls`，与 `parent_of` 和 `owns_equity_in` 分开。没有持股数量并不妨碍记录原文明确的实际控制者，但不能据此推断持股比例、经济权益或直接母子公司身份。

债务保证使用 `guarantees`，不能当作保证人实际放款或代偿。授信总额、提款余额、保证范围和承销/代理角色各自保留原始口径，不把整笔融资分配给每家参与银行。股东表的观察日、底层持仓日和比例分母日期分别保存；早期 13G 的股数不自动获得最新代理声明日期。

数值和具名对象的引文检查在候选准备与事务导入共用。金额允许明确币种紧邻数字的原文形式，仍禁止拼接相邻表格单元格或从型号标识中提取金额。同一事实内完全相同的指标、单位、倍率、分母与日期不能同时出现相互矛盾的确切值和界限。不同股类、期间与分母不互相约束；此检查不替代表头、脚注和交易语义复核。

未来采购承诺使用 `procurement_commitment_amount`，与当期发生的 `procurement_amount` 分开；保留承诺存量时点与未来履约期间。债券受托人使用 `acts_as_trustee`，不据此推断放贷、持债、承销或担保。


### 条件持股、承诺和金融服务角色

招股书假设发行完成后的股东表使用 `observation_basis=conditional_post_transaction`，不填造实际观察日或财年。持股类别比例与全部已发行股本比例分开保留，受控权益链中同一股份不相加。默认 `reported` 保持旧事实身份兼容；条件股东事实若附带实际日期，导入会拒绝。前端明确显示“条件情景 · 交易完成后”。

供应侧数值区分已发生采购额、`procurement_commitment_amount`（未来采购承诺）、`financial_guarantee_maximum_payment`（担保潜在付款上限）和 `restricted_investment_amount`（协议约定的受限投资余额）。合计与短期等组成部分分别保留分母和时点，不能累加或改称已支付金额。受托人 `acts_as_trustee`、资本市场服务 `provides_capital_markets_services` 均从提供服务的机构指向发行人；不据此推断贷款、持股或已执行发行。

PDF 跨页、跨行表格可增加与原始文件哈希、页码和渲染图哈希绑定的视觉核验转录。它是派生来源，原文件和原解析记录保持不变，原发布日期与本次核验可知日期分别保留；事实需同时锚定表头、单位、条件和数据单元格。格式检查、原文语义复核、数据覆盖与真实检索验证分别验收。

披露表默认直接展示对象、关系、期间、条件情景、数值及各自分母；完整适用条件与原文依据分别折叠展开。折叠不删除传给研究工具的条件，也不把有条件的交易情景转换成实际观察。

### 范围完成与检索验收分别记录

逐公司完成状态只适用于收据列明的来源、版本、章节和研究类别。公开可得性边界、私企没有公开报表系列以及其他六维覆盖缺口单独保留。实体数量和关系数量不代表全库已经整理充分。

发布验收比较既有来源身份和摘要、SQLite完整性、前端/正式工具实际读取版本及结构化记录身份。检索验收再分别检查召回、原文回读和模型理解：例如正确返回 `≤10%` 的记录，不意味着模型将其改写成 `<10%` 也能通过。测试题的人为读取上限若小于原文节点，应修正测试设置并保留原运行记录；确定性回读成功不能替代模型自主取证通过。

### 新报告处理方法的动态读取

`get_research_method(method_id="report_processing")` 提供新报告定位、表头/单位/附注核对、版式变化时的解析配置调整、条件与数值校验、处理交接及发布回读方法。正式 MCP 原文工具、通用来源请求 schema 和对话附件/公共副本读取工具都提示在新报告、修订报告或提取缺口出现时读取该方法；完整方法按需加载，不逐次塞入所有角色的上下文。

已有保存的编排配置可以缺少此新增辅助方法；读取时返回已打包的默认内容并标记来源，不改写旧配置、用户修改过的方法或原配置摘要。新配置包含此方法，可按现有方法编辑机制维护。

方法按 `library`、`local`、`uploads`、`web` 的真实操作范围说明用法，包含页码变化、单位变化、多期间和匿名比例上限示例。现有读取工具不执行解析脚本或写入 SQL；未授予处理工具时，模型交出带原文定位、表头、列映射和未决项的处理配置，不能声称入库。离线导入、语义复核与版本发布仍由现有工程流程完成。方法接入测试验证工具发现和方法读取，不替代真实模型处理陌生报告的质量验收。

### 基础衍生指标与历史期间（v2）

`financial_metric_contracts` 维护基础指标定义，`derived_financials` 在 SQL 构建库预计算，`valuation_history` 处理历史行情、证券单位、拆股和汇率。来源科目映射由审核包提供，不在公司代码分支里填入指标答案。运行入口：

```bash
python -m scripts.data_retrieval.materialize_financial_metrics --build <unpublished.sqlite> --as-of YYYY-MM-DD --scope <scope.json>
```

scope 使用 `{"entities":[{"entity_id":"NVIDIA"}]}`。命令重建期间投影并幂等追加同版本计算，不覆盖原始事实；有发布 manifest 或发布状态的文件拒绝写入。修改公式含义必须升级公式版本；发布、挂载和前端／正式工具回读是独立步骤。

基础范围包括盈利率、经营现金流收入比、现金购建固定资产强度、现金流转化、自由现金流、流动比率、现金比率、资产负债率、负债权益比、期间 ROA／ROE、周转率／天数、可比同期增长率，以及参考市值、完整财年 PE／PS、最新归母权益 PB。每家公司只计算已取得兼容输入的项目；未取得报表的私企不套用上市公司估值。

- 利润表及现金流指标要求同一来源、申报版本、taxonomy、起止期间和币种；主报告币种与便利换算列分开。明确的总收入优先于客户合同收入小计，避免把能源对冲等收入成分漏掉。
- 期初／期末平均余额来自同一报告修订；期间 ROA、ROE 和周转率不自动年化。余额缺失时不以期末值冒充平均值。只允许明确的流动／非流动总额相加，不机械求和会计目录。
- 自由现金流默认 CFO 减现金购建固定资产，不混入非现金购置或融资租赁新增额。包含投资物业和预付款等更宽支出的发行人口径单独命名。比较期亏损或为零时，不机械输出增长率。
- DART 仅采用主报表 BS／IS／CIS／CF，权益变动表 SCE 同名概念不混入。每股收益保留原接口单位并按其明确概念转换为货币／股。审核后的费用符号转换保留原值作为嵌套输入。
- 估值对每个价格日期选择当时已公开的财务输入；财报期末不能替代发布日期。API 整包抓取日期也不能覆盖其中的 SEC／DART 申报日。仅知抓取日的报告继续保留该限制，不把签字日猜成发布日期。
- PE 明确为最近完整财年稀释 EPS，**非 TTM、非预测 PE**。ADR 比例、EPS 对应证券单位、后续拆股、财报币种与行情币种、汇率日期均进入计算依据。价格使用未复权收盘价。
- 市值使用已披露实际股数，股数观察日距价格日期超过 120 日则不算；多股类须有经济权利依据。包含激励信托或回购未注销股的发行股数使用独立标签。PS／PB 在当前参考市值不可用时同步保留缺口，不静默回退到较早的数值。亏损 PE、非正权益 PB 明确不适用。

`source_document` 的 `data_kind="derived"` 可使用 `derived_view="history"`、`fiscal_year`、`fiscal_period`、`date_start`、`date_end`；`query="metric:gross_margin"` 为精确指标筛选。日期区间作用于价格日期或财务期末，`as_of` 仍是可获知截止日期。默认工具视图为 latest，前端默认 history。历史显示各观察期间在截止时点的最新可用修订，全部原始计算版本仍在 SQL。输入数组保留事实 ID、来源、单位、期间及嵌套计算；读取不调用模型现场算数。

本阶段不扩展行业专属运营 KPI、不推算缺失季度、不新增 TTM 或预测估值。行业指标、完整报表覆盖与检索质量仍需单独验收，不能用计算记录条数替代这些结果。
