# 原件结构修复后的检索归因验收

本轮检查此前反复失败的问题能否在恢复原件结构后改善。它是解析、分块、真实向量、候选和真实重排的离线对照，不等于组织 HTTP、实时权限、图检索或 Agent 研究验收。不得把剩余错误统一归为金融语义。

## 对照范围与边界

- 冻结库有 1,742 份资料、114,028 个旧检索块；只替换 34 份直接相关原件的表示，其他资料保留。
- 94 个已暴露问题来自当前 44 问与历史 50 问。两臂使用相同的全目录查询规划范围，旧向量与新向量均真实可用；不是新的独立保留集。
- 每题保留截断前的全部向量分数、各词法查询分数、候选顺序、重排输入和收费回执。固定向量 24、词法 24、回补 48 的诊断设置，没有执行完整生产需求调度、事实过滤、图通道。
- 早期 44 题对照仅使用历史候选出现过的文件范围，不能作为全库指标；最终对照重新使用完整目录规划范围。不得跨范围比较总体分数。
- 最终候选对照完成 188 组；重排可用 179 组，其中 44 组复用完全相同的成功请求。其余 1 组欠费失败、用量未知，8 组未提交。没有自动重试。
- 新旧分块边界不同，旧整块标签不能直接移植。必要事实、同表上下文、等价证据需重新审核，当前不发布总 Precision@10、nDCG 或全等价证据召回率。

## 已验证的因果证据

1. 原件中的 FPL 主体标题曾未进入表格输入。在同一局部范围的前后对照中，补回 `FLORIDA POWER & LIGHT COMPANY` 后，错误现金表向量分数从 0.872858 降到 0.796087、排名从 2 降到 45，退出重排池；其 BM25 分数保持 4.822019。此前错误不能完全归于重排的金融判断。
2. 原解析器会把 `At`、`The` 或单词片段识别成标题。现在仅在原始 HTML 存在唯一、完整、逐字一致的段落时恢复合并，保留 XPath 与摘要；不猜补单词。重复或不完整定位继续显式留存。
3. 中文“比较期间”曾误触发跨公司宽范围；公司名称的通用 `Company` 后缀兼容不完整。已修正并增加回归；全目录 248 个别名回查没有排除自身来源，但这仅是目录一致性，不能保证所有自然语言公司识别正确。
4. 表格前导说明曾因 500 字符界限丢失。改为保留有界的完整相邻块，超限显式记录。相邻不代表属于该表：Lumentum 的 2029 Notes 表仍可能带上前面 2024 Notes 的说明，需要进一步做结构归属，不能把该问题称为纯金融语义。
5. 最终 NextEra 对照：正确现金表向量第 1（0.866784）、重排第 1（0.993162），BM25 第 495（5.046312）；出售资产现金所得段落 BM25 第 1（28.678594）。checkbox `No ☐` 的 BM25 为 0、向量第 13、重排第 3（0.377936），证明非答案元素仍会占据主结果。
6. 表头进入向量和重排、但未进入 BM25，是另一处通道输入不一致。增加仅包含同表解析器声明表头的词法输入后，正确表 BM25 升到第 423（5.786332），仍明显落后。不得宣称补表头已解决词法排序；长表粒度和各词贡献还需继续定位。此项是免费单题反事实，未重跑付费重排。
7. Lumentum 的发行金额与净所得段落在新表示的四种问法均排第 1。到期日目标段落没有一致提升；另一条合同义务脚注实际也包含票息和到期日，必须计入等价证据审核。不能把目标块未出现直接当作事实未召回。
8. 对已完成的 89 个新表示问题逐一扫描，57 问的前十含标题或表单元素，共 153 项待角色审核，包含正常章节标题以及 `As of`、`N/A`、`No ☐`、截断日期等。该数量是审核队列，不是 153 条已判无关的标签，不能据此计算 Precision。

## 工具与复现合同

- `prepare_parser_retrieval_ablation.py` 固定原件与原范围；`restore_parser_paragraphs.py` 仅恢复唯一原文段落。
- `parser_retrieval_units.py` 生成带原件摘要、派生坐标、上下文及精确输入摘要的隔离单元。新 `lexical_input` 仅增加同表表头，不改变向量输入或既有派生 ID。
- `embed_parser_ablation.py` 按冻结计划生成缺失的精确输入向量，复用有证明的成功记录；失败不自动重提。
- `trace_parser_ablation.py` 校验旧向量和支持索引，逐查询保存全部通道分数，仅物化候选正文。`rerank_parser_ablation.py` 只有 query、候选 ID 和完整评分文本全部相同时才复用。
- 本轮收费成功请求累计报告 23,307,013 tokens（多次诊断，非单次评测费用）；另有一次欠费失败用量未知。原件、矩阵、收费回执和个人路径保存在本地，不进入 Git。

下一次付费前先收口不收费的结构归属和词法反事实，冻结新表示与事实标签。剩余九组是否重提依用户恢复计费答复执行；不能把补完旧轮九组理解为授权无界追加实验。

## 后续分工调整：正文、数值与原文关联

产品主路径调整为：正文恢复后按完整句子组成块；结构化数值优先查 SQL，缺失先检查已存 SEC API 和原件 XBRL；原表、脚注与定义作为带出处的关联证据。表格向量对照保留为诊断，不承担全部精确取数。

### 已实现与实测

- `retrieval.narrative_chunks.sentence_groups` 复用现有英文缩写边界逻辑，支持中文结束标点，保留原始文本和坐标；长单句不在空白处强切，超硬预算须显式处理。解析对照适配已调用它，未替换现有发布索引。34 份原件全部无损通过、没有超 6,000 字节单句，仅 2 个向量输入变化；没有重生成向量。这不证明解析器的假标题都已修复。
- `audit_structured_source_routes.py` 只读核查原件与 SQL 同申报版本覆盖。34 份中 26 份有同 accession SQL；32 份有 XBRL 标签，但只有 26 份包含带单位、非 DEI 的数值事实。标签存在不代表问题所需财务数据齐全。
- `financial_facts.source_links.match_original_fact` 要求主体、申报版本、指标、期间、单位、维度和 Decimal 数值一致，返回原件摘要与定位。不接受浮点数、缺维度或只有金额相同的关联；本函数验证调用方提供的事实身份，不负责自动抽取或授予访问权限，也不推断脚注适用范围。
- 七个原先审核过的真实事实，五个在本次 SQL 库中找到同版本关联；季度与九个月收入即使同一结束日期也分别匹配。两个 Micron 事实在该库中没有同版本记录，未伪造补齐。
- 当前七组现金问题、十四个时点事实：原 SQL 匹配 12/14，另外两个在原件与已存官方 CompanyFacts 响应中均存在。根因是入库代码使用 `filings_since` 同时过滤事实期间，旧计划为 2023-09-20，排除了 Arista 的 2022-12-31 与 Super Micro 的 2023-06-30 比较期。
- 入库器新增独立 `financial_period_since`，旧计划默认保持原行为，新计划可明确扩大事实期间而不扩大申报目录。隔离十四条 SQL 副本使用起点 2022-12-31，从已存官方响应补入两条，14/14 与原件核对成功；申报目录起点保持 2023-09-20，现有发布库未修改，没有网络或付费调用。

### 验收分离与未完成范围

数值通道以主体、概念、期间、单位、版本、Decimal 值和出处核对为准；解释性检索以相关性分级、Precision、nDCG、说明覆盖及回读为准。上述 14/14 是限定的结构化事实核验，不是 94 问完整产品通过，也不能改写为检索 Precision。

剩余 94 问中的需求要逐项冻结概念/期间/维度及等价证据；普通表格入库、脚注适用关系、所有标题角色、组织范围发布与真实工具路由尚未整体接通。当前新事实关联是离线核验组件，尚未接入 Agent。隔壁负责目录元数据路径，本切片不修改其导航入口。
