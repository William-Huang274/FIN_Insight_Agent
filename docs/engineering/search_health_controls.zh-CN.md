# 搜索通道故障隔离

源站返回 HTTP 200 仍可能忽略查询条件。复现时应保存原查询、引擎、语言、返回标题/地址、源站对照；这些记录属于部署验收，不进入研究模型的答案。

经核实存在持续质量故障的部署，可设置 `FIN_SEARCH_DISABLED_BACKENDS`（逗号分隔 `bing,bing_china,baidu,github,bilibili`）和简短的 `FIN_SEARCH_DISABLED_REASON`。停用在发出请求前生效，默认自动组合只保留未停用的 Bing 入口；全部停用则记录故障，由现有自动搜索链继续其他供应商。显式选择停用通道不会偷偷触发其他收费搜索。没有设置时保持兼容行为。

研究者在启动指引、`discover_source_tools` 以及无结果反馈中能看到停用状态与替代调用方式。`auto` 是继续使用现有供应商栈，不是保证资料已经检索完整；日期核验、原件读取和引用绑定仍独立执行。恢复通道前，须重复实际查询并检查相关性，不能只看状态码。

2026-11-12 验证：60 项相关测试通过，包含停用前拦截、保留其他入口、显式选择不转付费、目录与反馈披露，以及原有搜索和来源校验。Bing 源站、地区参数及 RSS 对照仍不相关，故隔离故障而非宣称修好上游。现有自动链实测取得中英文相关候选，部分源站访问/日期问题继续单独报告；搜索成功不代表研究质量通过。
