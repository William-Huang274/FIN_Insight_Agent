# DELL 价值与利润单元：Chat 与 Responses 同输入真实对照

日期：2026-08-14
状态：`两条传输均跑通 / 内容金融事实追溯未通过 / 五单元不放行`

## 这轮到底做了什么

这不是两次“一问一答”，而是让 DeepSeek V4 Pro 用两种 API 协议各自完成同一个研究小循环。两边看到完全相同的 Dell Evidence Pack、NumericFact、三个未解决缺口和四个金融工具。

每条路线都走完了五步：

1. 同时读取 Dell 本研究单元已经审核过的证据和权威数字；
2. 提出 AI 服务器 ASP 补证；
3. 提出出货台数或等价算力补证；
4. 提出价格—销量—配置组合桥和增量利润补证；
5. 提交“AI 服务器收入怎样转化为利润”的最终判断、机制、反方和后续观察项。

Chat 和 Responses 都是 5 次 Provider 调用、6 份工具 receipt；多出的 1 份 receipt 来自第一步并行读取两类只读数据。两边都是 0 retry、0 fallback、0 外源检索、0 embedding，也没有把结果发布到 Workbench。

## 好的地方

两边都没有把“收入大增”直接等同于“产品利润率已经被审计证明”。它们都抓住了现在真正缺的三块资料：

- AI 服务器到底卖了多少台，或交付了多少等价算力；
- 单机、单柜或配置层面的 ASP；
- 能把收入变化拆成价格、数量、配置 mix，并进一步连接到增量营业利润的桥。

两边也都保留了三个 gap，没有因为提交补证请求就假装已经找到了资料。最终判断引用的都是本案 reviewed Evidence 和 S2 NumericFact，没有跨公司、跨单元，也没有把候选冒充事实。

这说明统一 Tool Contract 已经解决上一轮“Schema 看起来合法、进本地必然失败”的问题；Responses API 也不是纸面兼容，而是已经真实完成了工具读取、连续多步调用和最终 Judgment。

## 为什么仍然不能放行五单元

### 1. 比较方向是真的可能性很高，但当前系统证明不了它是怎么得到的

Chat 写了“公司整体营业利润率同比上升”，Responses 写了“公司整体营业利润率正在扩张”。当前模型选中的 NumericFact 是 FY2027 Q1 和 FY2026 全年，而不是 FY2027 Q1 对 FY2026 Q1。

reviewed Evidence 的原始表格里确实有上年同期收入和营业利润，因此这个方向可能是正确的；问题不是简单说它“算错了”，而是最终判断没有绑定一条“同季度、同口径、同单位”的确定性比较关系。Harness 目前只能证明每个数字真实存在，不能证明一句“同比上升”到底用了哪两个期间、用了什么公式。

金融产品不能依赖“这次碰巧说对”。比较性语言必须绑定可复算的 relation trace；Q1 与全年也不能因为指标名称相同就被当成趋势对照。因此两条路线都没有通过 L1。

### 2. 模型提出的补证内容和系统真正能执行的来源路线不一致

当前 gap 明确提示可以寻找公司演示或行业出货资料。Chat 因此提出“可与 Dell 对照的行业 AI 服务器出货数据”。但本地编译后的请求只允许 10-K、10-Q 和 8-K。

也就是说，模型以为自己在请求行业数据，系统实际只会去 SEC 文件里找。这条请求字段合法、也被记录了，却无法按原意执行。原因是统一合同已经约束了 facet、target、metric 和长度，却还没有把“要找哪一类来源、当前路线是否具备”暴露给模型。

### 3. 研究机制仍有越界

Chat 把供应分配写成利润转换机制，但所选证据没有直接绑定这条因果链。Responses 的机制和反方写得略完整，却进一步说存在“来自 AI 服务器周期的真实经营杠杆”。现有材料同时提到存储盈利、定价、传统服务器、配置与规模等多项驱动，没有产品级 PVM 或利润桥，不能把公司／分部利润改善主要归给 AI 周期。

这部分不是 API 协议问题，也不能靠本地超级拼装替模型代写。后续可以用更明确的因果边界和 relation contract 拦住明显越界，但模型本身仍要在下一次自然输出中证明它能保持更审慎的归因。

Responses 比 Chat 多耗约 36% token、慢约 58%。它证明了新协议可用，但没有形成足以抵消成本和维护复杂度的内容优势。因此当前不切主链：Chat 继续作为临时主传输，Responses 保留为已经跑通的 shadow/candidate，Anthropic 继续只做协议 shadow。

## 决策与下一步

五单元当前不授权，也不再付费做第二组 Chat/Responses 对照。

下一项只做一个零模型结构包：

1. S2/S3 提供同口径可比期间 NumericFact 或确定性 relation fact；
2. “同比、环比、扩张、压缩”等比较词必须选择 relation/direction，并由本地验证和渲染；
3. EvidenceRequest 显式暴露来源类别和实际可用 route；gap 的补证提示必须与 route 一致；
4. 用保存的本轮输出、错误期间、错来源类别和 DELL/MU/NVDA mutation 做零调用证明。

该结构包通过后，最多只需要一条 Chat 单单元自然复验。只有它通过 L1、保持研究增益，才重新决定是否值得运行 Dell 五单元。
