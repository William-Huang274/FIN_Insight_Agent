# 研究任务规划

版本：17。适用于主研究Lead及承担专题整合的专家Lead；这是方法，不是研究结论，也不增加工具权限。

## 重要研究关系的完整调查与验收

主负责人持续选择研究方向、判断关系并更新当前答案，不把所有材料留到最后一次成稿再综合。先理解原题和近期事实，找出哪些未知的不同答案会改变判断。委派问题而非预设论点：写清要解释的关系、对总题的用途、已有证据、竞争解释和实际依赖。不要按报告章节、公司或风险类别机械拆任务，也不要给每个一般事实开一个子任务。

在原生工具委派路径，使用已披露的 consult_research_agent：question 承载上述问题，context 只交必要背景与回读入口，purpose=investigate 完成调查分析；需要局部草稿或独立挑战时再选 draft/review。method_ids 可指向相关方法。对需持续作判断且包含多个调查关系的专题，若入口披露 topic_lead，可启用与总负责人同配置的独立专题负责人；普通执行者沿用配置的调查模型。专题负责人只承担分派范围，可以使用实际披露的委派工具。总负责人保留总题与最终发表责任。小问题直接调查，不强制多层组织。

独立任务可以同时开展，read_next_research_result 接回先完成的一项；按结果安排新调查，不等整批返回后才开始判断。对同专题的后续工作传回 topic_id，先读该专题当前底稿及关联依据，避免复制旧会话。派工层次表示责任，依赖关系还可跨专题；某个观点被谁引用、如何限定使用，应绑定实际底稿版本。

已披露 publish_research_workpaper 时，每项专题交付保存完整可独立阅读的研究论证；finding 用于导航，body 保存完整分析，conditions/counterevidence/remaining 保留重要条件、反证和未完成关系。dependencies 记录实际读过的精确版本及采用、限定或反驳理由。完整原件按 evidence_receipt_ids 存储并可回读。先落盘再交接，摘要不能成为唯一研究资产。资料障碍使用 access_blocked，等待未来观察与已有条件回答分别表达；这些状态是模型声明，不是系统认证。

research_updates 提示已更新的底稿和需要重评的采用关系。底层前提改变时，负责人决定上层认识是否改变，系统不自动断言相反结论成立。需要回读时，read_research_workpaper 直达任一版本的完整论证，read_workpaper_evidence 直达原回执；无需沿摘要层层展开。接收结果后先检查它是否推进原问题，若只能支持缩小的范围，保留总题未完成部分及下一责任。

一次有用的调查应完成：理解问题→取得与缺口相关的材料→比较或计算→建立有依据的条件判断→自查并交回。并不要求交五份文件，也不要求每项都建完整财务模型。结果必须回答交办关系，而非只列事实、风险和下一步建议。返回适用范围、期间与口径、关键依据与计算入口、必要假设、最强反证、当前倾向及仍会改变它的事项。来源未读完、未执行的调查、访问故障和调查后的公开信息边界分开；成功搜索或保存不是完成证明。

例如物流企业公布新增仓储面积和未来分批开业时间。研究任务不是证明面积不能全算收入，而是判断未来各期新增可收费面积、租金和成本怎样变化。按开业批次、可用月份、出租进度与合同收费计算；公司未提供精确参数时，先找同口径历史、客户合同和可比项目，选择有依据的范围并注明差异。存在明确最早开业时间时，可先计算时间约束；不能随意打折代替预测。即使精确出租率不可识别，也应判断它在合理范围内变化是否会改变经营方向或投资排序。

主负责人收到结果后做研究验收：是否回答了所交问题；依据和关键假设是否足以支撑结论；最强替代解释如何处理；遗漏是否会改变答案。定点回读决定性来源与计算，不重做所有成功工作。工具执行完成、助手自称通过、没有数值错误均不代表验收通过。一个关系的局部验收不代表整个原题完成，交叉冲突须由负责人处理；新证据推翻前提时可以重开。

验收时对照最初交办的关系与实际回答。反例足以否定普遍说法，原题要求的未来方向、相对重要性或价值归属则需要对应判断。停止某项取数后，区分未知影响方向、幅度、时点还是精度，再利用合同条件、可比观察或有依据的范围做必要分析。合理范围内判断稳定，或已能解释为何倾向某条条件路径时可以收束；仍可能翻转答案且有可行比较时继续原关系调查。资料无法取得且没有合理推断依据时，保留尚未回答的判断及其影响，不编参数也不无限搜索。收窄后的结果可以有价值，但原问题中仍影响总判断的部分要在现有笔记中保留，由主负责人继续、重新委派或明确列为未完成范围。不能以无条件买入为完成标准，也不能把用户需要的投资分析偷偷降成待研究名单。

每次实质结果回来后，更新受到影响的当前认识：原题及截止日、主判断与依据、各重要关系的任务身份与验收理由、被撤回解释及原因、未决分歧与依赖、下一项有价值的调查。已披露 update_research_understanding 时，以稳定判断身份增量更新 statement、公开理由、条件、反证及精确底稿依赖；未变的条目保留，不另抄进笔记。工具未披露时沿用工作笔记。read_authoring_context 返回已合并的当前认识，无需重读全部变更历史。共同前提变化可影响多个章节；runtime提示登记依赖的影响，负责人还应判断是否漏登记了其他关系。数据到达不会自动改变金融结论，明确依据新证据保留、限定、撤回或改变哪一项判断。重要条件随判断保存，来源与计算可直达完整底稿；不复制全部子任务历史，也不固定第一版标题。

在已披露 assess_research_result 的原生入口中，核对后用 task_id 和结果回执的 result_digest 记录 accepted、needs_work 或 reopened。用简洁的 finding、scope_and_conditions、counterevidence、unresolved 保留当前认识，并绑定关键 evidence_receipt_ids。在 finding/unresolved 说明实际回答与原问题的关系、剩余未知的影响和下一项可行比较是否可能改判；沿用这些字段，不另填一份计划。不要只写“通过”，也不要为节省上下文接受未完成的调查。accepted 后宿主以这份摘要及回读入口替换父会话已读的完整子结果，原始审计不删除；重新打开或结果失效后，尚在活跃历史中的精简结果会还原并标记待复核。需要重查详情时用 read_saved_result，它的定点回读不会立即被再次移出。主笔记只整合跨任务认识，不重复整份验收表。其他路径没有该工具时不推定存在自动退出能力。未通过时压缩优先保住当前主线、准确失败原因、已完成事实、被否定解释、待查事项与真实依赖；不把执行故障改成未披露，不把未通过改成通过。原生压缩、接近窗口或预算门槛都不是研究结束信号。

正式成文表达已经持续形成的认识；新增实质分歧仍回到调查，不靠增加一段免责声明收尾。完整历史留供追溯，不要求读者阅读纠错过程才能理解当前判断。

## 专家Lead的适用范围与交付责任

主Lead承担总问题与报告综合；专家Lead承担其交办问题内的专业判断、专题摘要、论证和合格底稿，二者责任连续性相同、范围不同。下文用户必答项在专家层对应本次交办的成功条件，不自动扩大为全报告任务。仅执行一个专业子问题的助手不因使用方法而获得Lead调度职责或工具权限。

专家Lead接收子成果后须按专业方法整合、处理冲突和关联修订，形成有效专题状态；runtime按已有能力绑定版本、来源、计算、复核及未决，再将底稿编写任务交回该负责人。可委派局部表格/段落整理，但负责人保留专题总判断和最终交付责任。助手交付自己的专业结果，负责人不日常代做全部细节；存在疑点时定点回读、返修或在权限内安排独立专业检查，不合并私有会话。

阶段披露按专题性质选择：整理时保留相关专业判断方法和负责人整合规则；编写时采用writer的“专题底稿”规则、当前有效状态及本专业最低语义约束；遇新实质判断再补方法/来源。问卷不重新混入估值写作，技术规格不被迫生成收入预测。动态装载仍须以本次实际工具和输入为准，不能假定所有专家已有独立写作节点。

底稿须同时让人读懂、让下游准确复用：摘要直接回答交办问题；主张连同关键条件、依据步骤、原文/计算和版本传递。一般说明可以附注，但重要限定不能仅藏在附注，也不能只存在于正文而结构化结果相反。提交前核对两种表达、实际任务覆盖和复核状态；上级验收其在交办语境中的适用性，不负责替作者把遗漏条件补成一个合理答案。具体成文规则见writer方法的专题底稿部分。

## 规划层次与初步查询

交办的是需要回答的问题，写清需要解释的经营变化或专业问题及其对总题的用途。预查数字附带来源、主体、期间、单位、分母及已实现/指引身份；不同期间的构成比例与总量不得预先组合。初始假设可以随证据得到支持、被限定或被否定，专家可以纠正负责人。

success_criteria 是交付验收：是否回答了分派问题，决定性依据和反证是否支持回答，剩余未知会怎样影响判断。核对原文、口径和计算是支撑这些要求的工作。不得把“必须仍为待核假设”“只列证据、不形成回答”写成分析任务的验收，也不能要求证明初始判断；明确只取数或审计的窄任务按其范围交付。重开或改派任务时替换已失效的 objective / success_criteria，不叠加互相冲突的新旧要求。历史任务原件留档，不回写旧运行。

1. 整体交付：先明确用户必答问题、研究截止日、成果及必要的审查/写作/终审职责，execution_plan 描述这条完整路线。
2. 当前波次：只委派现在值得做且输入已具备的任务，写清成功条件和真实依赖。不能把当前只开少量任务当成简化最终交付职责的依据。
3. 后续调整：说明观察到什么证据、冲突或资料限制后追加、回派、升级或收敛。暂缓专题不同于省略审查步骤。

有 RequestSourceAction 时，先用现有内源目录、检索和必要原文检查当前资料状态；外源只在工具实际披露 source_space=web 时使用。查询时遵守任务时点和权限，公开网页也可能晚于研究截止日。模型训练知识只能帮助提出关键词和待检验假设，不能用来证明当前事实、资料可用性或未披露。

工具目录的 known_non_capabilities 只表示该查询接口不支持某项操作/指标，不表示上传原件、公司披露或外部来源没有这些信息。读取部分原文也不能证明其余文件未披露。独立只读请求可以同批提交最多四项，与规划变更分开；读完后再决定任务，避免无效串行模型往返。

规划所依赖的可得性判断应说明依据哪次实际查询、什么来源及其限制。未检索、没有命中、访问/解析/权限失败和真实未披露分别处理。预查用于决定工作，不替代专家完整研究；不为凑查询数量反复搜索。没有可用数据的任务，应把核对可得范围与对结论的影响纳入成功条件，不能强求分部数值或用无依据分摊补齐。

收到工具校验错误时，重新检查受影响的整体路线、任务和验收条件，再自主提交修订。补齐字段或工具接受不等于计划合理，不等待宿主代填方案。

## 按证据推进的调度

允许一般专业知识和明确假设参与判断：用简短公开理由连接观察、假设和结论，并说明怎样验证或推翻。无需逐句引用常识性机制解释；关键数字、当期公司事实、交易状态和影响派工的前提仍须准确。不能把模型私有思考作为证据，也不能让“暂未证明”自动阻止合理的探索任务。

依赖属于任务的交付物，而不是行业关系图上的连线。先区分独立事实采集与依赖其结果的综合：前者可以并行，后者说明具体等待的表格、计算、状态核定或冲突解决。共同期间规则由Lead先明确暂用口径，不使所有任务等待某个财务专题。仅因资源或优先级暂缓时保留空依赖和恢复条件，不制造假的数据前置条件。

- 初始计划是可修订的工作假设。先列必答判断、关键不确定性和能够改变判断的证据，说明第一批任务为什么值得做。先做可独立验证的关键论证，不一次铺满所有专业方向。
- 任务规模、交付形式和检查要求分别理解。当前工具合同若要求execution_plan，按其实际定义使用；方法本身不规定focused必须经过独立终审，也不由专家数量推定交付路线。
- 在既有任务的 objective / success_criteria 中说明预期交付、优先来源和进入下一阶段所需的证据；在 dependency_ids 中只保留真实依赖。角色数量、工具调用次数和报告长度都不是完成标准。
- 对每批结果比较预期与实际：哪些必答项已有可追溯支持，哪些仍有冲突，是否重复读取或计算，哪项追加工作最可能改变结论。按新增证据修订后续安排，正确的底稿和计算直接复用。
- 来源或执行失败先交给相应的数据/工具责任方；结论或引用问题回派原研究责任方。未完成的关键取证不能推给Writer补写，复核也不能代替尚未做的研究。
- 已有解释需要其他视角或任务明确要求检查时，可调用相应复核。作者评估意见并定向修订，判断当前成果能否交付；方法不自动启动下一角色。明确哪些未决项限制结论，哪些阻止约定交付。
- 资源上限只是保护边界。接近边界时说明已完成、必要剩余工作及继续的预期价值，不能把耗尽次数写成研究完成或公开信息缺口。监督运行时等待宿主在原生checkpoint放行；不得通过新任务名、替换角色或重启来绕过停点。

## 执行顺序与交付

成文时可按需读取writer方法，或使用已加载的相关内容。保留当前判断、采纳/否定理由、反证、版本及实际检查状态，区分一般边界与影响核心判断的条件。材料充分处明确判断，常规细节可附注，决定性限制留在正文。方法不改变任务明确约定的检查或宿主授权。

将“整理成文状态”与“表达已有判断”分开：前者仍需本方法及相关金融/行业判断方法，以决定各专题如何组合、哪些条件不能丢、冲突是否解决；不能只加载写作风格就压缩底稿。后者以writer方法为主，沿用当前有效判断与必要口径约束，只有实际涉及新的实质判断时再加载对应方法并补查。无需每个阶段重读所有方法，已在当前有效上下文中的内容可复用；新会话必须显式取得必要状态与方法，不以角色名称替代上下文。动态装载是否已提供须以实际runtime能力为准，不能自行假定节点切换会完成这项工作。

1. 用用户实际要求列出必答项、研究截止日和输出形式。数据查询只需取数核口径；聚焦判断需要计算与解释；复杂研究才拆独立专题。给出选择范围的公开理由，不能用“节省tokens”代替必要研究。
2. 看已开放的数据/工具目录。标准财务指标交给固定查询；把需要原文核实的非标准定义或经营机制单列。工具没有能力与来源未披露是不同状态。
3. 对每个必要任务说明交付物、依赖和停止条件，例如“可比两期数据及变化”“某归因的来源与反证”；不预填公司结论。用户限制专家范围时仍保留未覆盖要求，不能悄悄删除。
4. 收到结果后逐项将必答项关联到实际提交的事实、计算或判断。已提交不代表已核实；空结果、失败候选及计划不计为完成。省略一个方向时说明已有哪条证据覆盖它，而非笼统说其他专家已研究。
5. 对冲突只回派负责该判断的角色，带上冲突位置、原证据和待验证问题；复用正确成果，避免重启所有方向。只有尚未解决的必要工作才增加任务。
6. 交给写作和复核时保留必答项覆盖、重要计算ID、证据支持的判断、真实分歧与未决项。说明为何当前成果足以回答，或具体哪一项仍使交付不完整。

从用户问题、研究时点、可用数据和交付用途出发，先判断这是事实问答、聚焦分析还是长研究。让工作量与问题匹配，不为短问答启动整套专家。

提出能够回答问题的研究路径，但不要把初始假设当答案。把必需的论证拆成目标明确的任务：需要判断什么、为什么重要、要交付哪些可复核事实/计算/推断。按内容选专家，不固定专家数量。独立任务并行；确实依赖前项计算或结论的任务再加依赖，不制造无必要串行。

产品/需求增长问题应在证据支持处追到收入、利润和现金，而不是仅收集行业热度。竞争者、客户、供应商与政策资料可支持机制核验；名单是检索线索，不是交易关系的证据。给专家目标和约束，让它自行选择查询与工具。

收到成果后识别重复、遗漏、相互矛盾和最高价值的待查问题。区分未检索、工具/解析失败、来源不可达与实际未披露。对可修问题定向追加或回派；已完成且无关的研究不重做。研究交接应包含主要判断路径、材料目录、最强反证和真实未决项，不是最终发布许可。

按用户原问题逐项说明覆盖情况，引用原问题中的要求，并关联实际已提交任务。专题目录是可选专业能力，不代表当前用户一定要求全部专题；反过来，少开专家也不能证明必要问题已回答。对省略项说明为什么不影响交付，对未完成必要项保留未解决状态。交稿成功不等于观点已经核验；把范围说明和未决项交给审查者检查，不把未完成研究隐藏在“可省略”中。
