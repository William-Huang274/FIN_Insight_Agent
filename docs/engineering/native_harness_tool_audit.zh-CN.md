# 原生 harness 业务工具边界审查

本审查针对固定 DS Harness / ACP 所实际收到的 FIN 工具，不将旧系统全部工具
默认视为已接入。依据包括真实供应商请求、业务 checkpoint、上游 MCP 文本渲染代码、
维护代码和无模型回放。通过工程检查不等于研究判断正确或真实压缩已验收。

## 根因与职责

旧执行路径使用 `source_result_view` 生成模型视图；原生 MCP 桥直接返回完整业务
回执，绕过了该投影。上游负责消息历史和压缩，不知道 FIN 来源对象中哪些字段是
重复的目录元数据。修复是在工具边界复用同一个展示投影，而非恢复旧摘要调度或
按研究阶段删除历史。固定上游 MCP 客户端只向模型渲染 `content`，不能将
`structuredContent` 的磁盘重复算作模型输入重复。

原桥的回执 ID 只在 `structuredContent`，现在 `content` 中也包含 `receipt_id`、
状态、结果及实际可用的原始回读入口。原始 ToolMessage 与 artifact 不修改；
来源权限、计算和成果绑定仍消费原始记录。成功保存和接受/交付仍分别表示。

## 实际工具覆盖

原真实请求包含16个 FIN 工具，以及上游3个 MCP 资源工具。以下逐组审查了
参数、模型返回、原始存储、回读和权限/错误处理；不是每个工具都有本案例的真实
模型调用。未使用的写入能力由版本/故障/恢复夹具验证。

| 工具 | 检查与处置 |
| --- | --- |
| `read_source_document` | catalog/outline/search/read 共用来源展示。完全相同的组织来源、检索回执只出现一次；同文档原始来源的相同字段共享，差异、节点定位和读取参数保留。目录不变成证据。显式小窗口允许100字符起，保留分页/整块边界反馈。 |
| `calculate_research_metric` | 相同来源溯源对象按引用共享；每个操作数的原句、字面值、来源ID、期间/单位、表达式、结果和语义未验证标记保留。原计算artifact不去重、不改写。 |
| `read_research_source` | 只恢复选定来源及计算依赖，当前授权检查不省略；补入历史目录，使回执可发现。 |
| `browse_context`、`read_context_turn` | 元数据目录12项/页、公开消息6000字符/页；不展示私有推理，不执行检索API，不把历史助手文字当事实。 |
| `read_saved_result` | 按准确回执ID和可选JSON pointer读原始记录，默认6000、最多24000字符；不会重新执行原工具。指针/字符位置始终针对原始回执，不针对共享字段后的模型视图。 |
| `get_research_method` | 空ID返回方法目录，支持具体章节；方法与来源权限分离，不为减少体量删掉用户已要求的教学内容。 |
| `SearchWorkingNotes`、`ReadWorkingNote`、`WriteWorkingNote` | 当前接入禁用远程笔记向量调用。目录只带预览，正文分页；保存返回ID/版本，不回传整篇。保留同标题版本冲突与append/replace语义，不要求每步写笔记。 |
| `save_research_report`、`repair_report_fields` | 校验失败保存未接受草稿，只修变化字段；新增准确草稿回读，错误回执返回该入口。保存不代表交付或独立复核。 |
| `read_current_report`、`edit_research_report` | 区分已接受稿/待修草稿、版本和字段；默认返回未转义正文窗口，供精确局部替换，不再把序列化JSON片段当正文。仍保留field=all兼容读取。 |
| `deliver_working_note`、`deliver_current_report` | 仅按宿主已批准交付意图披露对应动作，避免向回答任务暴露必然失败的交付命令；不放宽准入。回答任务仍可保存有用底稿或报告草稿。 |

上游资源列表/模板/读取工具仍由上游维护。当前没有通过此表宣称额外开放外网、
SQL、按需委派或独立复核；这些需单独资格与授权。

## 查询前置延迟

原词法查询反复扫描 `nodes` 元数据，但同表携带大块 `counts`，只选择几列也会
访问大数据页。现在由已验证发布的准备阶段，用 SQLite/FileLock 建立很小的
只读派生元数据表，发布文件本身不写入。后续只从该表读取位置、身份和长度；
词频、postings、子集IDF继续使用原算法和原发布。原文不复制。

投影绑定原文件身份，由运行时缓存目录管理；文件变化拒绝旧投影。SQLite提交
头的100字节参与身份检查，避免Windows连接未关闭时文件时间戳不立即更新。
这不是每次重新哈希全库。当前Java授权独立检查，缓存不授予访问权。
首次投影构建有成本，安排在无模型准备阶段；后续恢复复用已发布投影。
词法统计/元数据缓存与检索生命周期共同交接，不能只预热一个对象而查询另一个。

## 验证与限制

`scripts/engineering/replay_harness_tool_views.py <messages.json> --output <audit.json>`
读取本机导出的原始ToolMessage记录，不调用模型或业务工具、不写入研究状态。
回放验证候选数、逐项原文/位置/读取参数、来源状态、完整计算操作数与结果。
重复字段恢复后必须相等；冲突字段不自动选择。

实际记录回放：53条来源回执从1,803,526到830,104字符；5条计算回执从66,957到
34,145字符。这是同记录的离线模型视图比较，包含旧历史；不是实际付费token或
整段ACP历史减少量。已经写入原生历史的旧大回执不被偷偷改写，将由上游正常
历史/压缩机制处理。真实摘要忠实性和后续研究质量仍须单独验证。

继续条件：相关回归、真实记录回放、固定原生进程与MCP组合，以及当前容器的
查询前置检查通过后，才恢复原任务。保留失败、未知用量与原始提案；不因更换
工具展示重新生成成果，不用放大超时掩盖查询延迟。
